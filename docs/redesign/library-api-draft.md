# 主制御のライブラリの API（検討中）

状態: **検討中**（2026-10-04 開始）。使う側のたたき台 [examples/omni_manual/src/main.cpp](../../examples/omni_manual/src/main.cpp)（オムニ 4 輪、エンコーダ付き MD、コントローラ、ESP32-S3、ATA6561）を書きながら決める。ライブラリの 2 層の構成は [requirements.md](requirements.md) の D3・D4。

- 置き場所は当面このリポジトリの `lib/`。ハードウェアに依存する層としない層を分ける。部の mas libraries に後で移す可能性がある（[md-firmware-draft.md](md-firmware-draft.md) §3）。

## 決まったこと

| # | 点 | 決定 | 日付 |
|---|---|---|---|
| A1 | 相手の指し方 | **バスから取っ手をもらう形**: `mas::Md w = can.md(ch);`。取っ手は軽く（どのバスの何番の ch かだけを持つ）、中身（指令の値、FB）はバスが持つ。同じ ch の取っ手が何個あっても食い違わない。`w.ch()` で番号を読める。**バスの型は `mas::CanBus`**（I2C や SPI のバスと分けるため） | 2026-10-04 |
| A2 | 単位 | **API に出る値は全部 SI**（ユーザ）。速度 rad/s、電流 A、設定の電流の上限 A・最高速度 rad/s・最大加速度 rad/s²、PID ゲインも SI（ライブラリが換算して書く）、速度の分解能は rad/s/LSB。プロトコル（仕様書、DBC）は rpm と mA のままで、換算はライブラリの中に隠す。**float の物理量が基本**で、生の整数は上級者向けに別名で出す（`setSpeedRaw(int16_t)` など）。**位置は積み上げたカウントの int64 だけ**（1 回転 ＝ 65536、電源投入時が 0）。double の rad は出さない（ユーザ）。rad への換算は小さな関数で添える。引き換え: 監視（DBC）で見える数字とコードの数字が一致しない（10 rad/s ≈ 95.5 rpm） | 2026-10-04 |
| A3 | 送受信のタイミング | **アプリが `can.update()` を呼ぶ形を基本にする**（ユーザ）。理由: 主制御は ESP32 だけとは限らない（ユーザ）。ライブラリはハードウェアと RTOS に依存しない作りにし、時間を進めるのはアプリ。`update()` の中で、受けたフレームの振り分け、期限の来た周期送信（指令 100 Hz、SYNC 20 Hz）、再起動の後始末を行う。コールバックも `update()` の中から呼ぶので、`loop()` と同じ流れで動き、排他は要らない。`loop()` が止まれば送信も止まり、基板は途絶判定（100 ms）で止まる（安全側）。そのため「アプリが呼ばなければ止める」仕組みは要らない。`loop()` は少なくとも約 20 Hz 以上で回す必要がある（説明書に書く）。CAN の送受信（ESP32 なら TWAI）と時刻は、移植の層（ポート）としてライブラリの下に分ける。ESP32 で裏のタスクに任せたい人向けの補助は、後で足せる | 2026-10-04 |
| A4 | 保存しない設定 | (1) ライブラリは、アプリが書いた保存しない設定（MD なら電流と速度の分解能 48、49）を覚え、基板の再起動（起動の知らせ、異常の詳細の bit 0）に気づいたら自動で送り直す。電源投入の直後も同じ流れ。(2) 再起動に気づいてから、設定の応答で書けたと確かめるまでは、その ch に止める値だけを送る（分解能が食い違ったまま動き出すのを防ぐ）。アプリからは `w.ready()` が false の間として見える。(3) 設定を書く関数は待たずに戻る。送信と応答の確認は `update()` の中で 1 つずつ進める。書けなかったときは A7 の異常の知らせと同じ道で伝える | 2026-10-04 |

### A1 の補足: メモリ

- 取っ手は「バスへのポインタ ＋ ch の番号」で 8 byte 程度。
- 中身はバスが種類ごとの最大の ch 数だけ持つ。MD 32 ch に、指令の値、FB、受けた時刻、保存しない設定（単位）、状態をまとめて 1 ch 60 byte 程度として約 2 KB。サーボ 64 ch、汎用 I/O、コントローラ、ToF などを全部足しても 10 KB 程度の見込み。ESP32-S3 の RAM（512 KB）に対して問題にならない。
- 基板のファーム（F042、RAM 6 KB）は、このライブラリではなく基板側のコアを使い、自分が受け持つ ch の分だけを持つので、影響しない。
- 使わない種類の分まで持つのが気になるなら、最初に使ったときに確保する形にもできる（後で決めればよい）。
