### A1 の補足: メモリ

- 取っ手は「バスへのポインタ ＋ ch の番号」で 8 byte 程度。
- 中身はバスが種類ごとの最大の ch 数だけ持つ。MD 32 ch に、指令の値、FB、受けた時刻、保存しない設定（単位）、状態をまとめて 1 ch 60 byte 程度として約 2 KB。サーボ 64 ch、汎用 I/O、コントローラ、ToF などを全部足しても 10 KB 程度の見込み。ESP32-S3 の RAM（512 KB）に対して問題にならない。
- 基板のファーム（F042、RAM 6 KB）は、このライブラリではなく基板側のコアを使い、自分が受け持つ ch の分だけを持つので、影響しない。
- ~~使わない種類の分まで持つのが気になるなら、最初に使ったときに確保する形にもできる（後で決めればよい）。~~
- **方針（2026-10-06、ユーザ。記録だけで未実装）: 主制御側の状態は、使うと宣言した ch の分だけ確保する。** → **2026-10-12: 目的（使う ch の分だけの RAM）は残し、手段を「確保」から「オブジェクト自身が持つ」に変えた（下の「A1 の見直し」）。以下の確保の仕組みは取りやめ。** 今は種類ごとの最大の ch 数を配列で持つ（実測で `Bus` が 3,240 B）ため、RAM が「使う ch の数」ではなく「プロトコルの大きさ」に比例し、種類を足すたびに増える。
  - `can.md(ch)` などを初めて呼んだとき（普通は setup の中）に、その ch の状態を確保する。解放はしない（断片化しない）。ch → 状態は、ポインタの表か確保した順のリストで引く。宣言していない ch の FB は捨てる。
  - ヒープの無い主制御のために、固定の領域で「最大 n ch」を取る方式をコンパイル時に選べるようにする。
  - loop の中で初めて呼んだときの確保の失敗（メモリ不足）の知らせ方は、実装のときに決める。
  - API（`can.md(ch)` の使い方）は変わらない。基板側（node）は受け持つ ch の数がファームで決まっているので、今の固定の形のまま（F042 に malloc を入れると 1〜2 KB 増える）。

### A1 の見直し（2026-10-12、ユーザ）

**前提**（2026-10-12 に測った）: 今の `Bus` は 3,256 B（MD 88 B × 32、コントローラ 28 B × 8、共通 216 B）。全種類を固定の配列で持つと 7〜10 KB の見込み。ESP32 系（空きヒープ 200〜300 KB）では 2〜4 % で実害は無いが、RAM が 16 KB 前後のマイコンを主制御にすると載るかどうかが決まる。使う ch の分だけにすると、`api_tour` 相当（MD 6、コントローラ 1）で約 1 KB 以下、全種類が揃った後の典型で 6〜9 KB 減る。ユーザはこの削減を取りたい。

**候補**:

| | (1) `can.md(0)` ＋ ヒープ | (2) `can.md(0)` ＋ `Bus<N>` の固定の領域 | (3) 自身が持つ `Md w(can, 0)` |
|---|---|---|---|
| RAM（MD 6、コントローラ 1） | 約 1,000 B | 約 1,000 B ＋ 余り | 約 830 B |
| 足りないと分かるとき | 実行中 | 実行中 | ビルド時（リンカ） |
| コードの分かれ方 | (2) と二通り（V4） | 一通り | 一通り |

**決定: (3)**（ユーザ:「きれい」）。

```cpp
mas::can::Bus can;
mas::can::Md wheel(can, 0);
mas::can::Md wheels[4] = {{can, 0}, {can, 1}, {can, 2}, {can, 3}};
```

- 作ったときに自分を `Bus` の一覧（連結リスト）に登録する。`Bus` は一覧をたどって FB を振り分け、指令を送る。確保の処理は無く、ヒープも ch → 中身の表も要らない。
- コピーはできない。関数には `Md &` で渡す。
- 影響: 10-06 の確保の方針は取りやめ。versioning.md の V4（静的と動的をコンパイル時に選ぶ）は不要になり、V5（動的確保の実装を優先）は (3) の実装に読み替える。

**細部**（2026-10-12、ユーザ）:

1. 同じ ch を 2 個作ったら、後から作った方は一覧に登録しない（動かない）。`can.begin(port)` が `false` を返して知らせる（グローバル変数は `setup()` より前に作られ、その場では知らせられないため）。
2. 壊したとき（ローカル変数など）は、自分を一覧から外す。その ch の指令は止まり、基板は途絶判定で止まる。
3. `Controller` も同じ形（`Controller pad(can, 0)`）。今後の種類もすべてそろえる。
4. 名前は今のまま（`mas::can::Bus` / `Md` / `Controller`、`<mas/can.h>`、`w.ch()`）。
5. **バスは渡す**（`Md w(can, 0)`）。渡さずに「最初に `begin()` したバス」に付ける形（`Md w(0)`）も検討したが、暗黙の決まりとバスに属さないグローバルな一覧が要り、バスが 2 本のときに間違えると黙って動かないため。ユーザ: 本当は `can.md(0)` が心地よいが、諦める。
