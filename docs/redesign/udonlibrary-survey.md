## 1. ドキュメントの作り方

| 項目 | 中身 |
|---|---|
| 道具 | **Doxygen** ＋ テーマ doxygen-awesome-css。出力は日本語 |
| 解説 | 手書きの Markdown（`docs/<分類>/<名前>.md`） |
| API の一覧 | ソースの `/// @brief @param @return` から自動で作る。Markdown の中のクラス名は、自動でそのクラスのページへのリンクになる |
| 公開 | GitHub Actions で master への push ごとに作り、GitHub Pages に出す |
| 入口 | README.md が目次（GitHub でもサイトでも同じ） |

**1 ページの型**（決まったテンプレートは無いが、だいたいこの順）:
1. 機能名と、1〜2 段落の概要
2. 個別のインクルード
3. 機能ごとの節。説明、最小のスケッチ全体、構造体の定義
4. 折りたたみ（`<details>`）に「詳細な設定」と「回路」（回路図と部品表）
5. デバッグ（`show()`）
6. スケッチ例をいくつか

**例の置き方**: `example/<分類>/<内容>/<役割>/`。送る側と受ける側を対で置く。

## 2. CAN の作り

- 3 層: **バス**（機種ごと）／**型付きの送り手・受け手**（`CanWriter<T>`、`CanReader<T>`）／**生のノード**（ID と受信のコールバック）。
- `bus.update()` を loop で呼ぶ形。受信は割り込みでためて、`update()` の中で振り分け、コールバックも `update()` から呼ぶ。→ **私たちの A3 と同じ考え方**。
- 送信は、全部の送り手の今の値を一定の間隔でまとめて送る（状態を流し続ける）。→ 私たちの周期指令と同じ。
- 受け手は `Optional<T> getMessage()` を返す。届いていない（100 ms 超え）か壊れていれば「空」。**成功と失敗を 1 つの if で書ける。**
- 複数のバスは、バスのオブジェクトを複数作り、送り手・受け手にどのバスかを渡す。→ 私たちの A9 と同じ。
- **ESP32 の TWAI、RP2040 の can2040、STM32 には対応していない**（Teensy と、SPI の MCP2515 だけ）。

## 3. モーターの FB の出し方（ロボマスのモーター）

- 1 モーターに 1 つのオブジェクト。指令は `setCurrent(mA)`。範囲外は丸める。
- FB は**ゲッタで返し、単位を関数のコメントに書く**（`getAngle()` [rad]、`getVelocity()` [rpm]、`getTorqueCurrent()` [mA]、`getTemperature()` [℃]）。
- 角度は「積み上げた角度」（`getAngle`）と「1 周の中の角度」（`getRawAngle`）を分けて出す。
- 電流の範囲を返すゲッタ（`getCurrentRange()`）があり、PID の出力の制限にそのまま使える。
- **モーターごとの「つながっているか」「値が新しいか」を返す API は無い**。途絶えても最後の値を返し続ける（バス全体の良し悪ししか分からない）。
- 例は PID と組み合わせ、「速度制御のクラスを自分で作る例」まで載せている。

## 4. コントローラ（PS5）

- ボタンは `Input{press, click, release, toggle}` の構造体で返す（押している／押した瞬間／離した瞬間／押すたびに切り替わる）。ソースのコメントに波形の図がある。
- スティックは −255〜255 の 2 次元ベクトル。`toOmni<4>()` でオムニの出力に直す補助がある。
- `if (pad)` で接続。`isOperable()` は「未接続なら停止、起動時は停止、× のトグルで解除」。

## 5. 開発の仕組み

- 命名の決まり（StyleGuide）: ファイルと型は UpperCamel、変数とメンバ関数は lowerCamel、インターフェースは `I` を付ける（`ICanBus`）、マクロは大文字のスネークケース。整形は clang-format。共通部は C++11。
- CI:
  - **ArduinoLint**: 対象のボードを並べて「コンパイルが通るか」だけを確かめる。
  - **単体テスト**: googletest。対象はシリアライズなど一部だけ。
  - ドキュメントの自動生成。
- 部員向けに、ブランチ → push → CI → PR → マージの手順を、VS Code の画面写真付きで説明している。

## 6. 取り入れたい点（私たちの API・ドキュメントとの対応）

| UdonLibrary | 私たちへの当てはめ（案。未決定） |
|---|---|
| `Optional<T>` で「届いた値か、届いていないか」を 1 つで返す | **FB をまとめて返す**案: `w.feedback()` が、値（電流、速度、位置、状態）と「新しいか」をまとめた構造体を返す。個別のゲッタ（今の案）も残す |
| ゲッタのコメントに単位 | 私たちは SI にそろえた（A2）。Doxygen のコメントにも単位を書く |
| 電流の範囲のゲッタ | 基板の電流の上限（設定 33）を読める関数（PID の出力の制限に使う） |
| `Input{press, click, release, toggle}` | 私たちの `held` / `pressed` / `released` に、**toggle** を足すか |
| `show()` でノードを一覧 | `can.print(Serial)` のような、全部の ch の状態を表示するデバッグ機能 |
| Doxygen ＋ doxygen-awesome ＋ GitHub Pages | ドキュメントの作り方の候補 |
| ページの型（概要 → 最小例 → 詳細は折りたたみ → デバッグ → 例） | ドキュメントのページの型の候補 |
| 対になった例 | 主制御の例と、PC からの監視の例など |
| ArduinoLint（コンパイルだけの CI） | PlatformIO で例をビルドする CI（ESP32 を対象に） |

## 7. 私たちが避けられている、または避けるべき落とし穴

| UdonLibrary の問題 | 私たち |
|---|---|
| モーターごとの接続状態が無い | `w.online()` がある（A1〜A2） |
| 受信のタイムアウトの値が実装ごとにずれている | 途絶の時間は仕様で決めている（指令 100 ms、コントローラ 200 ms） |
| 割り込みと loop が排他なしで同じバッファを触る | 受信はリングバッファに積むだけ、処理は `update()` だけ、で統一する |
| 送信のたびに `delayMicroseconds(200)` で止まる | 待たずに戻る（Port の `send`） |
| DLC が常に 8 | DLC を縮める規則がある（D9） |
| 分割したデータの順序や欠けを確かめない | 分割の共通の見出しに通し番号がある |
| 1 つのポートに 1 つのインスタンスしか作れない | ポートとバスを組にする（A9） |
| 非常停止の解除の状態が、切断をまたいで残る（再接続した瞬間に動ける） | 再接続したときの扱いを、説明書と例で明確にする（E-stop は A8 で決めた） |
| バージョンのタグが無く、PlatformIO で版を固定できない | タグを付ける。プロトコルの版（共通の項目 3）もある |
| 文書のコード片に誤り（そのままではコンパイルできない） | 文書のコード片も CI でコンパイルする |
