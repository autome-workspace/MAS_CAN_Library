# 設定項目の仕様（案 v0.1）

状態: **検討中**（2026-10-02 開始）。フレームの形（class 4）は [id-map-draft.md](id-map-draft.md)、値の決まり方（P9）と保存の基準（P10）は [requirements.md](requirements.md)。

進め方: 先に A（共通の枠組み）を決め、次に B（種類ごとの一覧）を埋める。

## A. 共通の枠組み

### A1. 設定項目の番号（決定 2026-10-02、ユーザ）

- 番号は 8 bit（0〜255）。
- 範囲で分けるのは、「全種類に共通の項目」と「種類ごとの項目」だけにする（境目は、共通の項目を決めるときに決める。例えば 0〜15 が共通）。
- 保存できるか、読み出し専用か、命令かといった**性質は、番号に持たせない**。一覧の表で決める。
  - 理由: 性質を変えても番号を振り直さずに済む（例えば 2026-10-02 に、エンコーダの 2 項目を「保存できない」から「保存できる」に変えた）。
  - 保存の操作を受けたときに保存できない項目を飛ばすのは基板の仕事で、基板は自分の項目の性質を知っているので、番号に頼る必要はない。
  - 監視する PC は、一覧（DBC など）で性質を知る。
- ~~上位の bit に性質を持たせる案（0x10〜 は保存できる、0x80〜 は保存できない、0xC0〜 は命令、など）~~ は採らない。
- 設定項目 0 は「確認」（固有 ID の 64 bit を返す）。決定済み（id-map-draft.md）。

### A2. 値の型（決定 2026-10-02、ユーザ）

- 値の欄（4 byte）の型は、**項目ごとに**整数（int32 か uint32）か小数（float32）かを決める。
- 周期（Hz）、電流（mA）、カウント数のような値は整数にする。PID ゲインのように桁が大きく変わる値だけを float32 にする。
- FPU の無いマイコン（RP2040、STM32F0、CH32V203）では、小数をソフトウェアで計算することになる。ただ、受け取るのは設定のときだけなので問題にならない。
- ~~整数だけにして、ゲインを固定小数点で送る案~~ は採らない（ゲインの範囲と細かさを項目ごとに決める必要があるため）。
- DBC では、項目の番号で中身を切り替える形（マルチプレクス）で表す。
- バイトの並びは、プロトコル全体で big-endian（requirements.md の D6）。float32 も big-endian で送る。


### A3. 結果の番号（検討中）

案（2026-10-02）:

| 番号 | 意味 | 例 |
|---|---|---|
| 0 | 成功 | |
| 1 | 知らない項目 | その種類に無い番号 |
| 2 | 範囲外 | 電流の上限に負の値を書いた |
| 3 | 実現できない | PWM を出せないピンに PWM 出力モードを設定した |
| 4 | ~~今はできない~~（要るかを検討中） | |
| 5 | その操作はできない項目 | 読み出し専用の項目に書いた。命令を読んだ |
| 6〜62 | 予約 | |
| 63 | その他の失敗 | 基板に固有の理由 |

- 失敗したときの応答の「今の値」には、変わっていない今の値を入れる。全種類で共通の番号。

### A3.1 保存と「既定に戻す」の範囲（決定 2026-10-02、ユーザ）

- 宛先は ch のまま、範囲として「宛先の ch を受け持つ基板の全 ch」も選べるようにする。
- 保存と「既定に戻す」は設定項目の欄（byte 2）を使わないので、この欄を範囲に使う: **0 ＝ その ch だけ、1 ＝ その ch を受け持つ基板の全 ch**。ID も操作の bit も増えない。
- 応答するのは宛先の ch を受け持つ基板だけなので、応答は衝突しない。
- **応答は、フラッシュに書き終えてから返す。** 応答の時点で結果が確定する。それまでの「応答はすぐに返す」「続けて届いた保存をまとめて書く（100 ms 待つ）」では、応答の時点でまだ書いておらず、書き込みに失敗しても知らせる手段が無かった（2026-10-02 に気づいた穴）。
- 「基板という軸を持ち込まない」という前の判断を、「宛先は ch のまま、範囲として基板を選べる」ところまで緩めた。
