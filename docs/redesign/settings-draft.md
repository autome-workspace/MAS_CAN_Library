# 設定項目の仕様（案 v0.1）

状態: **検討中**（2026-10-02 開始）。フレームの形（class 4）は [id-map-draft.md](id-map-draft.md)、値の決まり方（P9）と保存の基準（P10）は [requirements.md](requirements.md)。

## 全体像（2026-10-02 時点のまとめ。新しい決定は含まない）

### 何をする仕組みか

- 基板の「ロボットごとに変わる値」（P9 の (b)）を、読む、書く、フラッシュに保存する、初期化する（焼いた値に戻す）。
- 命令（位置の原点、ToF の開始と停止、再起動など）を送る。命令は「書くと動作する項目」として扱う。
- 基板の情報（固有 ID、種類、版など）を問い合わせる。

### 値の決まり方（P9、P10）

| 呼び名（2026-10-02） | どこにあるか | いつ決まるか |
|---|---|---|
| 焼いた値 | ファームウェアの中 | ファームウェアを書き込んだとき |
| 保存した値 | フラッシュの設定の領域 | 「保存」をしたとき（保存できる項目だけ） |
| 今の値 | RAM | 起動時と「書く」をしたとき（すぐ反映される） |

- 起動すると、保存した値があればそれを、なければ焼いた値を今の値にする。つまり「保存」は起動時の値を上書きする。
- 保存できない項目（P10 の「選択」）は、起動すると必ず焼いた値に戻る。主制御が起動時に毎回送る。
- それまで「ファームウェアの既定値」「既定値」と書いていたものは、焼いた値のこと。「既定」は「起動時の値」とも読めて紛らわしいので、以後は「焼いた値」と書く。

### フレーム（class 4）

`ID = 0x400 + 種類 × 16 + 向き × 8 + 束の中の ch`

| byte | 要求 | 応答 |
|---|---|---|
| 0 | 束の番号 | 束の番号 |
| 1 | 操作（bit 6–7）、0（bit 0–5） | 操作（bit 6–7）、結果（bit 0–5） |
| 2 | 設定項目の番号（保存と初期化では範囲） | 同じ |
| 3–6 | 値（big-endian） | 今の値 |
| 7 | 通し番号 | 同じ |

- 宛先は、種類（ID）、束の番号（byte 0）、束の中の ch（ID）の 3 つで、ch 1 つを指す。
- 応答するのは、その ch を受け持つ基板だけ。だから応答は衝突しない。
- 束ごとの設定（汎用入力の送る周期など）は、束の先頭の ch を宛先にする（2026-10-01）。

### やりとりの流れ

1. 主制御が要求を送る。
2. 宛先の ch を受け持つ基板が応答する。
3. 主制御は、応答を受け取ってから次の要求を送る（1 つずつ）。

- 応答は、要求と同じ通し番号で対応づける。
- 応答が来なければ、その ch を受け持つ基板がいない（または落ちている）。

### 操作（4 つ）

| 操作 | 動き |
|---|---|
| 読む | 今の値を返す |
| 書く | すぐ反映して、反映後の値を返す。動作中に書いてよいかは主制御の責任 |
| 保存 | 今の値をフラッシュに書く。保存できる項目だけが対象。範囲は「その ch」か「その ch を受け持つ基板の全 ch」。書き終えてから応答する |
| 初期化 | 範囲内の保存した値を消し、今の値も焼いた値に戻す（工場出荷に戻すのと同じ）。範囲は保存と同じ。書き終えてから応答する |

### 設定項目

- 番号は 8 bit。共通の項目と種類ごとの項目に分ける（境目は案で 0〜15 が共通）。
- 項目ごとに、一覧の表で次を決める（番号には持たせない）:

| 性質 | 選択肢 |
|---|---|
| 型 | int32、uint32、float32 |
| 読み書き | 読み書きできる、読み出し専用、命令 |
| 保存 | できる（事実）、できない（選択）。命令と読み出し専用には関係ない |
| ほか | 単位、既定値、範囲 |

- 項目 0（確認）だけは特別で、応答の data 部 8 byte すべてに固有 ID を入れる（束の番号や通し番号の欄は無い）。

### 結果

## A. 共通の枠組み

### A1. 設定項目の番号（決定 2026-10-02、ユーザ）

- 番号は 8 bit（0〜255）。
- 範囲で分けるのは、「全種類に共通の項目」と「種類ごとの項目」だけにする（境目は、共通の項目を決めるときに決める。例えば 0〜15 が共通）。
- 保存できるか、読み出し専用か、命令かといった**性質は、番号に持たせない**。一覧の表で決める。
  - 理由: 性質を変えても番号を振り直さずに済む（例えば 2026-10-02 に、エンコーダの 2 項目を「保存できない」から「保存できる」に変えた）。
  - 保存の操作を受けたときに保存できない項目を飛ばすのは基板の仕事で、基板は自分の項目の性質を知っているので、番号に頼る必要はない。
  - 監視する PC は、一覧（DBC など）で性質を知る。
- ~~上位の bit に性質を持たせる案（0x10〜 は保存できる、0x80〜 は保存できない、0xC0〜 は命令、など）~~ は採らない。
- 設定項目 0 は「確認」（固有 ID の 64 bit を返す）。決定済み（id-map-draft.md）。

### A2. 値の型（決定 2026-10-02、ユーザ）

- 値の欄（4 byte）の型は、**項目ごとに**整数（int32 か uint32）か小数（float32）かを決める。
- 周期（Hz）、電流（mA）、カウント数のような値は整数にする。PID ゲインのように桁が大きく変わる値だけを float32 にする。
- FPU の無いマイコン（RP2040、STM32F0、CH32V203）では、小数をソフトウェアで計算することになる。ただ、受け取るのは設定のときだけなので問題にならない。
- ~~整数だけにして、ゲインを固定小数点で送る案~~ は採らない（ゲインの範囲と細かさを項目ごとに決める必要があるため）。
- DBC では、項目の番号で中身を切り替える形（マルチプレクス）で表す。
- バイトの並びは、プロトコル全体で big-endian（requirements.md の D6）。float32 も big-endian で送る。


### A3. byte 1 と結果の番号（決定 2026-10-02、ユーザ）

**byte 1 の bit の割り当て**

| bit | 内容 |
|---|---|
| 6–7 | 操作 |
| 0–5 | 結果（要求では 0） |

- 種類を表す欄を上位に置く（NeoPixel の命令、分割の見出しと同じ並び）。16 進数で、上の桁が操作、下の桁が結果になる。

**操作の番号**

| 番号 | 操作 | byte 1 |
|---|---|---|
| 0 | 読む | `0x00` |
| 1 | 書く | `0x40` |
| 2 | 保存 | `0x80` |
| 3 | 初期化（焼いた値に戻す。A3.3） | `0xC0` |

- 「読む」を 0 にした。バグで中身が全部 0 のフレームが出ても「項目 0（確認）を読む」になり、何も変わらない。

**結果の番号**（全種類で共通）

| 番号 | 意味 | 例 |
|---|---|---|
| 0 | 成功 | |
| 1 | 知らない項目 | その種類に無い番号 |
| 2 | その操作はできない項目 | 読み出し専用の項目に書いた。命令を読んだ |
| 3 | 範囲外 | 電流の上限に負の値を書いた |
| 4 | 実現できない | PWM を出せないピンに PWM 出力モードを設定した |
| 5〜62 | 予約 | |
| 63 | その他の失敗 | 基板に固有の理由。フラッシュへの書き込みの失敗も含む |

- 基板は、項目がある → その操作ができる → 値が範囲内 → 実現できる、の順に確かめ、最初に引っかかったところの番号を返す。
- 失敗したときの応答の「今の値」には、変わっていない今の値を入れる。
- ~~2026-10-02 の最初の案（3 範囲外、4 今はできない、5 その操作はできない項目）~~ は、「今はできない」の削除に合わせて、確かめる順に並べ直した。

### A3.2 「今はできない」を削除（決定 2026-10-02、ユーザ）

- 保存は書き終えてから応答するので、基板は「書いた」か「書けなかった」かを返せば済む。主制御は応答を待ってから次を送るので、書いている途中に次の要求が来ることもない。
- 基板は、保存を頼まれたら動作中でも書く。動作中に書いてよいかは主制御の責任（動作中の値の書き換えと同じ考え方）。書いている間に制御が止まるかは、基板ごとの資料に書く。
- フラッシュへの書き込みの失敗は、63（その他の失敗）で返す。
- 応答までに数十 ms かかることがある（STM32F0 でページの消去に 20〜40 ms ほど）。ライブラリの応答待ちの時間は、それより長く取る。

### A3.3 「既定に戻す」を「初期化（焼いた値に戻す）」にする（決定 2026-10-02、ユーザ）

- 操作 3 は、範囲内の保存した値を消し、今の値も焼いた値に戻す（工場出荷に戻すのと同じ）。保存と同じく、書き終えてから応答する。
- 使う場面: 基板を別のロボットに付け替えたとき（古い設定が残る危険への対策）。
- ~~起動時の値に戻す案（今の値を保存した値に戻す。フラッシュには触らない）~~ は採らない。同じことは、再起動するか主制御が値を書き直せばできる。初期化は、この操作が無いとファームウェアを書き直すしかない。
- 呼び名は、「既定」が紛らわしいので「初期化」に変えた。

### A3.1 保存と初期化の範囲（決定 2026-10-02、ユーザ）

- 宛先は ch のまま、範囲として「宛先の ch を受け持つ基板の全 ch」も選べるようにする。
- 保存と初期化は設定項目の欄（byte 2）を使わないので、この欄を範囲に使う: **0 ＝ その ch だけ、1 ＝ その ch を受け持つ基板の全 ch**。ID も操作の bit も増えない。
- 応答するのは宛先の ch を受け持つ基板だけなので、応答は衝突しない。
- **応答は、フラッシュに書き終えてから返す。** 応答の時点で結果が確定する。それまでの「応答はすぐに返す」「続けて届いた保存をまとめて書く（100 ms 待つ）」では、応答の時点でまだ書いておらず、書き込みに失敗しても知らせる手段が無かった（2026-10-02 に気づいた穴）。
- 「基板という軸を持ち込まない」という前の判断を、「宛先は ch のまま、範囲として基板を選べる」ところまで緩めた。
