状態: **検討中**（2026-10-02 開始）。フレームの形（class 4）は [id-map-draft.md](id-map-draft.md)、値の決まり方（P9）と保存の基準（P10）は [requirements.md](requirements.md)。

## 全体像（2026-10-02 時点のまとめ。新しい決定は含まない）

### 何をする仕組みか

- 基板の「ロボットごとに変わる値」（P9 の (b)）を、読む、書く、フラッシュに保存する、初期化する（焼いた値に戻す）。
- 命令（位置の原点、ToF の開始と停止、再起動など）を送る。命令は「書くと動作する項目」として扱う。
- 基板の情報（固有 ID、種類、版など）を問い合わせる。

### 値の決まり方（P9、P10）

| 呼び名（2026-10-02） | どこにあるか | いつ決まるか |
|---|---|---|
| 焼いた値 | ファームウェアの中 | ファームウェアを書き込んだとき |
| 保存した値 | フラッシュの設定の領域 | 「保存」をしたとき（保存できる項目だけ） |
| 今の値 | RAM | 起動時と「書く」をしたとき（すぐ反映される） |

- 起動すると、保存した値があればそれを、なければ焼いた値を今の値にする。つまり「保存」は起動時の値を上書きする。
- 保存できない項目（P10 の「選択」）は、起動すると必ず焼いた値に戻る。主制御が起動時に毎回送る。
- それまで「ファームウェアの既定値」「既定値」と書いていたものは、焼いた値のこと。「既定」は「起動時の値」とも読めて紛らわしいので、以後は「焼いた値」と書く。

### フレーム（class 4）

`ID = 0x400 + 種類 × 16 + 向き × 8`（下位 3 bit は予約で 0）

| byte | 要求 | 応答 |
|---|---|---|
| 0 | ch の番号（1〜255。0 は予約） | ch の番号 |
| 1 | 操作（bit 6–7）、0（bit 0–5） | 操作（bit 6–7）、結果（bit 0–5） |
| 2 | 設定項目の番号（保存と初期化では範囲） | 同じ |
| 3–6 | 値（big-endian） | 今の値 |
| 7 | 通し番号 | 同じ |

- 宛先は、種類（ID）と ch の番号（byte 0）で、ch 1 つを指す（2026-10-02、ユーザ。~~束の番号と束の中の ch に割る形~~ は、束の無い種類で割り方が決まらないのでやめた）。
- 基板は、種類でハードウェアのフィルタを掛け、ch はソフトウェアで見る。
- 中身が全部 0 のフレームは ch 0 宛てになり、どの基板も応答しない。
- 応答するのは、その ch を受け持つ基板だけ。だから応答は衝突しない。
- 束ごとの設定（汎用入力の送る周期など）は、束の先頭の ch を宛先にする（2026-10-01）。

### やりとりの流れ

1. 主制御が要求を送る。
2. 宛先の ch を受け持つ基板が応答する。
3. 主制御は、応答を受け取ってから次の要求を送る（1 つずつ）。

- 応答は、要求と同じ通し番号で対応づける。
- 応答が来なければ、その ch を受け持つ基板がいない（または落ちている）。

### 操作（4 つ）

| 操作 | 動き |
|---|---|
| 読む | 今の値を返す |
| 書く | すぐ反映して、反映後の値を返す。動作中に書いてよいかは主制御の責任 |
| 保存 | 今の値をフラッシュに書く。保存できる項目だけが対象。範囲は「その ch」か「その ch を受け持つ基板の全 ch」。書き終えてから応答する |
| 初期化 | 範囲内の保存した値を消し、今の値も焼いた値に戻す（工場出荷に戻すのと同じ）。範囲は保存と同じ。書き終えてから応答する |

### 設定項目

- 番号は 8 bit。全体共通（0〜31）、種類共通（32〜127）、基板固有（128〜255）の 3 つの範囲に分ける（A1）。
- 項目ごとに、一覧の表で次を決める（番号には持たせない）:

| 性質 | 選択肢 |
|---|---|
| 型 | int32、uint32、float32 |
| 読み書き | 読み書きできる、読み出し専用、命令 |
| 保存 | できる（事実）、できない（選択）。命令と読み出し専用には関係ない |
| ほか | 単位、既定値、範囲 |

- 項目 0（確認）だけは特別で、応答の data 部 8 byte すべてに固有 ID を入れる（ch の番号や通し番号の欄は無い。主制御は 1 つずつ要求するので対応づけられる）。

## A. 共通の枠組み

### A1. 設定項目の番号（決定 2026-10-02、ユーザ）

- 番号は 8 bit（0〜255）。
- 範囲で分けるのは、「全種類に共通の項目」と「種類ごとの項目」だけにする（境目は、共通の項目を決めるときに決める。例えば 0〜15 が共通）。
- 保存できるか、読み出し専用か、命令かといった**性質は、番号に持たせない**。一覧の表で決める。
  - 理由: 性質を変えても番号を振り直さずに済む（例えば 2026-10-02 に、エンコーダの 2 項目を「保存できない」から「保存できる」に変えた）。
  - 保存の操作を受けたときに保存できない項目を飛ばすのは基板の仕事で、基板は自分の項目の性質を知っているので、番号に頼る必要はない。
  - 監視する PC は、一覧（DBC など）で性質を知る。
- ~~上位の bit に性質を持たせる案（0x10〜 は保存できる、0x80〜 は保存できない、0xC0〜 は命令、など）~~ は採らない。
- 設定項目 0 は「確認」（固有 ID の 64 bit を返す）。決定済み（id-map-draft.md）。
- **範囲は 3 つ**（2026-10-03、ユーザ。それまでの「共通と種類ごとの 2 つ」に「基板固有」を足した）:

| 範囲 | 中身 |
|---|---|
| 0〜31 | 全種類に共通（A4）。~~0〜15~~ から 2026-10-03 に広げた（余裕を倍に。ユーザ） |
| 32〜127 | 種類ごと。その種類のどの基板でも同じ意味を持つ項目だけを置く |
| 128〜255 | 基板固有。特定の基板だけが持つ項目（BLDC の転流の極対数など）。意味は基板ごとの資料に書く。基板の種類（共通の項目 1）が違えば、同じ番号でも意味が違う |

- 種類ごとの一覧は最小限にする。基板の中の事情（エンコーダの読み方、転流など）は基板固有の範囲へ回す。

### A2. 値の型（決定 2026-10-02、ユーザ）

- 値の欄（4 byte）の型は、**項目ごとに**整数（int32 か uint32）か小数（float32）かを決める。
- 周期（Hz）、電流（mA）、カウント数のような値は整数にする。PID ゲインのように桁が大きく変わる値だけを float32 にする。
- FPU の無いマイコン（RP2040、STM32F0、CH32V203）では、小数をソフトウェアで計算することになる。ただ、受け取るのは設定のときだけなので問題にならない。
- ~~整数だけにして、ゲインを固定小数点で送る案~~ は採らない（ゲインの範囲と細かさを項目ごとに決める必要があるため）。
- DBC では、項目の番号で中身を切り替える形（マルチプレクス）で表す。
- バイトの並びは、プロトコル全体で big-endian（requirements.md の D6）。float32 も big-endian で送る。


### A3. byte 1 と結果の番号（決定 2026-10-02、ユーザ）

**byte 1 の bit の割り当て**

| bit | 内容 |
|---|---|
| 6–7 | 操作 |
| 0–5 | 結果（要求では 0） |

- 種類を表す欄を上位に置く（NeoPixel の命令、分割の見出しと同じ並び）。16 進数で、上の桁が操作、下の桁が結果になる。

**操作の番号**

| 番号 | 操作 | byte 1 |
|---|---|---|
| 0 | 読む | `0x00` |
| 1 | 書く | `0x40` |
| 2 | 保存 | `0x80` |
| 3 | 初期化（焼いた値に戻す。A3.3） | `0xC0` |

- 「読む」を 0 にした。バグで中身が全部 0 のフレームが出ても「項目 0（確認）を読む」になり、何も変わらない。

**結果の番号**（全種類で共通）

| 番号 | 意味 | 例 |
|---|---|---|
| 0 | 成功 | |
| 1 | 知らない項目 | その種類に無い番号 |
| 2 | その操作はできない項目 | 読み出し専用の項目に書いた。命令を読んだ |
| 3 | 範囲外 | 電流の上限に負の値を書いた |
| 4 | 実現できない | PWM を出せないピンに PWM 出力モードを設定した |
| 5〜62 | 予約 | |
| 63 | その他の失敗 | 基板に固有の理由。フラッシュへの書き込みの失敗も含む |

- 基板は、項目がある → その操作ができる → 値が範囲内 → 実現できる、の順に確かめ、最初に引っかかったところの番号を返す。
- 失敗したときの応答の「今の値」には、変わっていない今の値を入れる。
- ~~2026-10-02 の最初の案（3 範囲外、4 今はできない、5 その操作はできない項目）~~ は、「今はできない」の削除に合わせて、確かめる順に並べ直した。

### A3.2 「今はできない」を削除（決定 2026-10-02、ユーザ）

- 保存は書き終えてから応答するので、基板は「書いた」か「書けなかった」かを返せば済む。主制御は応答を待ってから次を送るので、書いている途中に次の要求が来ることもない。
- 基板は、保存を頼まれたら動作中でも書く。動作中に書いてよいかは主制御の責任（動作中の値の書き換えと同じ考え方）。書いている間に制御が止まるかは、基板ごとの資料に書く。
- フラッシュへの書き込みの失敗は、63（その他の失敗）で返す。
- 応答までに数十 ms かかることがある（STM32F0 でページの消去に 20〜40 ms ほど）。ライブラリの応答待ちの時間は、それより長く取る。

### A3.3 「既定に戻す」を「初期化（焼いた値に戻す）」にする（決定 2026-10-02、ユーザ）

- 操作 3 は、範囲内の保存した値を消し、今の値も焼いた値に戻す（工場出荷に戻すのと同じ）。保存と同じく、書き終えてから応答する。
- 使う場面: 基板を別のロボットに付け替えたとき（古い設定が残る危険への対策）。
- ~~起動時の値に戻す案（今の値を保存した値に戻す。フラッシュには触らない）~~ は採らない。同じことは、再起動するか主制御が値を書き直せばできる。初期化は、この操作が無いとファームウェアを書き直すしかない。
- 呼び名は、「既定」が紛らわしいので「初期化」に変えた。

### A3.1 保存と初期化の範囲（決定 2026-10-02、ユーザ）

- 宛先は ch のまま、範囲として「宛先の ch を受け持つ基板の全 ch」も選べるようにする。
- 保存と初期化は設定項目の欄（byte 2）を使わないので、この欄を範囲に使う: **0 ＝ その ch だけ、1 ＝ その ch を受け持つ基板の全 ch**。ID も操作の bit も増えない。
- 応答するのは宛先の ch を受け持つ基板だけなので、応答は衝突しない。
- **応答は、フラッシュに書き終えてから返す。** 応答の時点で結果が確定する。それまでの「応答はすぐに返す」「続けて届いた保存をまとめて書く（100 ms 待つ）」では、応答の時点でまだ書いておらず、書き込みに失敗しても知らせる手段が無かった（2026-10-02 に気づいた穴）。
- 「基板という軸を持ち込まない」という前の判断を、「宛先は ch のまま、範囲として基板を選べる」ところまで緩めた。

### A4. 全種類に共通の項目（決定 2026-10-02、ユーザ）

番号 0〜31 を共通の項目にする（~~0〜15~~ から 2026-10-03 に広げた）。32〜127 が種類ごとの項目、128〜255 が基板固有の項目（A1）。

| 番号 | 項目 | 読み書き | 値 | ねらい |
|---|---|---|---|---|
| 0 | 確認 | 読み出し専用 | 固有 ID（data 部 8 byte すべて） | 重複の検知 |
| 1 | 基板の種類 | 読み出し専用 | uint32（基板の種類の番号） | 何の基板かを知る |
| 2 | ファームウェアの版 | 読み出し専用 | uint32（主・副・修正を 8 bit ずつ） | 書き込み忘れを見つける |
| 3 | プロトコルの版 | 読み出し専用 | uint32 | 仕様の版の食い違いを見つける |
| 4 | 受け持つ ch の範囲 | 読み出し専用 | 先頭の ch と ch の数 | 基板の境目を知る（基板の全 ch の保存、基板を自動で探すとき） |
| 5 | 異常の詳細 | 読み出し専用 | uint32（bit ごとの異常。意味は種類ごとに決める） | FB の「基板に異常あり」の bit が立ったら読む |
| 6 | 再起動 | 命令 | 書くと基板が再起動する | |
| 7〜31 | 予約 | | | |

- 送る周期は共通の項目に入れない（FB を送らない種類があるため）。FB を送る種類ごとの項目にする。

### A7. 起動の知らせ（決定 2026-10-03、ユーザ）

- FB の無い種類（サーボ、汎用出力、NeoPixel）は A6 では再起動を知らせられない。困るのは NeoPixel（記録した命令の列は保存しない＝P10 の「選択」なので、再起動で消える）。そこで、起動の知らせのフレームを足す。
- ID は class 0 の `0x010 + 種類の番号`。**DLC 0**。
- **全種類**の基板が、起動したときに 1 回だけ、受け持つ種類ごとに 1 本ずつ送る（CAN-Servo ならサーボとモーターの 2 本）。
- 意味は「**この種類のどれかの基板が再起動した**」。どの基板かは分からない。
  - 中身を空にしたのは、電源投入時に同じ種類の基板が同時に起動しても衝突しないため。同じ ID で違う中身を同時に送るとエラーになるが、まったく同じフレームなら 1 本として届く。
  - ~~区画ごと、基板ごとに知らせる案~~ は採らない。ID を増やすか、基板という軸を持ち込むことになるため。送り直しはめったに起きないので、種類ごとで足りる。
- **再起動したときの処理はライブラリが担う**（ユーザ）。その種類の全 ch に、保存しない設定と NeoPixel の記録を送り直す。どの基板が再起動したかを特定したいときは、A6 の bit（FB のある種類なら bit 0 が立っている ch）を見る。
- FB のある種類にも送らせる。A6 より早く気づけるため。A6 の bit は、この知らせを取りこぼしたときの確実な受け皿として残す。

### A6. 再起動を知らせる（決定 2026-10-03、ユーザ）

- それまでは、基板が再起動しても主制御は知る手段が無かった。静かな再起動では、保存しない設定が焼いた値に戻る、位置が 0 から始まり直す、保存していない書き込みが消える、NeoPixel の記録が消える、が起きる。
- **異常の詳細（共通の項目 5）の bit 0 を、全種類で共通の「再起動した」にする。** bit 1 以降の意味は種類ごとに決める。
- 基板は、起動したらこの bit を立てる。主制御がこの bit に 1 を書いて消すまで、FB の状態の bit 0（基板に異常あり）を立て続ける。
- ライブラリは、FB の bit 0 を見たら異常の詳細を読み、「再起動した」なら保存しない設定を送り直してから bit を消す。FB は 100 Hz なので約 10 ms で気づける。電源を入れた直後も同じ流れになり、「起動時に設定を送る」処理とひとつになる。
- 弱点: FB を返さない種類（サーボ、汎用出力、NeoPixel）は、この方法では知らせられない（下の未決）。
- 書いて消す操作の細部（1 を書いた bit を消す、など）は、仕様書にまとめるときに詰める。

- 細部（値の中の並び、版の書き方、再起動に書く値など）は、仕様書にまとめるときに詰める。
- 基板の種類の番号を誰がどう振るかは、下の A5。

### A5. 基板の種類の番号（決定 2026-10-03、ユーザ）

- **一覧表で管理する。** プロトコルの仕様書（または部の共有の場所）に一覧表を置き、新しい基板を作る人が、空いている番号を取って書き足す。
- 共通の項目 1 の uint32 は、上位 16 bit を「基板の種類」、下位 16 bit を「基板の版（回路の改版）」に分ける。同じ基板を作り直したときは、版だけを変える。
- ~~作る人が勝手に決める案（名前の文字列から計算した値など）~~ は採らない（まれに番号が重なり、番号から基板を調べられないため）。

## B. 種類ごとの一覧

### B1. MD（2026-10-03 検討中）

| 45 | 最大加速度 | 読み書き | uint32、rpm/s（0 ＝ 制限なし） | できる | 同上 |
| 46 | 原点 | 命令 | int32（今の位置をこの値とみなす） | — | |
| 47 | 電流の単位 | 読み書き | uint32、mA/LSB（1 または 2。既定 1） | **できない** | 主制御がこの値を前提にフレームを読む「選択」 |
| 48 | 速度の単位 | 読み書き | uint32、0.1 rpm 単位の LSB（10 ＝ 1 rpm/LSB、1 ＝ 0.1 rpm/LSB。既定 10。値の表し方は案） | **できない** | 同上 |

- **顔ぶれと「保存」の列は決定**（2026-10-03、ユーザ）。最高速度・最大加速度と、止めたときの止め方は「事実」として扱う。
- **速度ループの出力は、基本は電流**（2026-10-03、ユーザ。安全と性能のため）。つまり、電流ループの外側に速度ループを置く。電流を測れない基板（簡易な H ブリッジ）だけ、速度ループの出力が duty になる。
- 番号は 2026-10-03 の案。全体共通の範囲を 0〜31 に広げたので、16 から 32 に振り直した。
- **FB と指令の単位は出力軸のまま**（2026-10-03、ユーザが再確認。決定は 2026-10-01）。ループは基板の中でモーター軸のエンコーダで回し、FB の単位は報告の単位にすぎない。出力軸なら、減速比が基板の 1 か所（事実、P10）にだけあり、主制御のコードから消える。代わりに、遅い軸では速度（1 rpm/LSB）が粗い。速度の単位は別の論点として見直す。
- **エンコーダがモーター軸と出力軸のどちらに付くかは、プロトコルでは決めない**（2026-10-03、ユーザ）。
- **換算は 2 項目に分ける**（2026-10-03、ユーザ）: エンコーダ 1 回転のカウント数（uint32）と、エンコーダの軸から出力軸までの減速比（float32）。データシートとカタログの値をそのまま書ける。エンコーダが出力軸なら減速比は 1。基板はカウント数をそれ自体として使う（BLDC の転流など）。~~出力軸 1 回転あたりのカウント数を float32 1 つで持つ案~~ は採らない。
  - カウント数は、4 逓倍した後の数（CPR）。AMT10x の「2048 PPR」なら 8192。PPR（パルス数）と取り違えないよう、資料に書く。
  - 減速比は「エンコーダが何回転すると出力軸が 1 回転するか」（M3508 なら 3591/187 ≈ 19.2032）。
- 換算の精度: float32 で足りる（2026-10-03）。何万回転もする軸は無い（ユーザ）。100 回転でもずれは FB の 1 カウントより小さい。分数（分子と分母）で持つ案は採らない。
- **主制御はエンコーダを知らなくてよい**（2026-10-03、ユーザ）。主制御から見えるのは、出力軸の単位の位置（電源投入時は 0）と速度、同じ単位の指令だけ。基板を組んだ人が設定するのは encoder CPR と gear ratio の 2 つだけ。SPI か ABI か、周回の数え方、BLDC の転流（極対数、電気角のずれ）は基板の中の話で、必要なら基板固有の項目（128〜255）にする。
- ~~起動時に絶対角度を位置にする項目（起動時の位置、絶対角度の零点）~~ は今は足さない（2026-10-03、ユーザ）。電源投入時は 0（2026-10-01 の決定）のまま。需要がはっきりしたら足す。
- **PID ゲインの単位は、FB と同じ値の上で決める**（2026-10-03、ユーザ）。基板は FB のために出力軸の rpm と mA を計算しているので、PID をその値の上で回せば追加の換算は要らない。

| ループ | 誤差 | 出力 | Kp の単位 |
|---|---|---|---|
| 速度ループ | 出力軸の rpm | mA | mA/rpm |
| 位置ループ | 出力軸のカウント（1 回転 ＝ 65536） | 出力軸の rpm | rpm/カウント |
| 速度ループ（電流を測れない基板） | 出力軸の rpm | duty（指令の duty と同じ形。±16383 ＝ ±100%） | duty/rpm |

  - Ki は Kp に「/s」、Kd は Kp に「×s」を付けた単位。
  - ゲインの数字が物理的な意味を持ち（Kp ＝ 50 なら「1 rpm 遅れたら 50 mA 足す」）、基板の設計を替えても同じ数字が使える。
  - ~~単位を基板ごとの資料に任せる案~~、~~保留にする案~~ は採らない（プロトコルの完成後すぐに MD のファームウェアを作るため。ユーザ）。
- **電流の単位は ch ごとの設定（47）**（2026-10-03、ユーザ）。既定 1 mA/LSB（±32.767 A）、2 mA/LSB（±65.5 A）も選べる。指令と FB の両方に効く。保存しない。ライブラリと PC のツールは、指令を送る前に必ず書く。基板の再起動は起動の知らせ（A7）で気づき、ライブラリが送り直す。それまでの「2 mA/LSB に固定」（2026-10-01、2026-10-03 に一度再確認）から変えた。
- **速度の単位も ch ごとの設定（48）**（2026-10-03、ユーザ）。既定 1 rpm/LSB（±32767 rpm）、遅い軸のために 0.1 rpm/LSB（±3276.7 rpm）も選べる。指令と FB の速度の両方に効く。扱いは電流の単位と同じ（保存しない、指令の前に必ず書く、再起動で送り直す）。設定項目の値（最高速度など）と PID ゲインの単位は、この設定によらず物理の単位（rpm）のまま。
  - 背景: 出力軸の 1 rpm 刻みは遅い軸で粗い（10 rpm の軸で 10%）。範囲と分解能はトレードオフで、速いフライホイール（数千 rpm 以上を速度指令で回すのが普通）と遅い軸の両方を 1 つの固定の単位では覆えない。
- 実装の注意: 換算はサンプルごとに足していくと丸めの誤差が積み重なる。通算のカウントからまとめて換算する（基板の実装の手引きに書く）。
