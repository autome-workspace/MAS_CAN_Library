# 汎用 I/O の仕様（案 v0.2）

> **2026-10-01 の振り返りで決めたこと**
> - 要求は 4 つ: デジタル入力（リミットスイッチ、フォトセンサ）、アナログ入力（ポテンショメータ）、デジタル出力（電磁弁、リレー、LED）、中間の値の出力（LED の明るさ、ファン）。小電力用で、精度は 8 bit 程度でよい。数はまだ見えない。
> - 束は 4 ch（出力と入力で同じピンを指すように、全種類でそろえる）。
> - **汎用出力は 1 ch ＝ uint8（0〜255）**、DLC 4。外付けの汎用基板に高精度の PWM は要らないため（ユーザ）。
> - 入力も 8 bit でよい（ユーザ）。RP2040 の ADC は、実際に信頼できる分解能が 9 bit 弱なので、失うものはほとんどない。
> - **汎用は「出力／入力 × デジタル／アナログ」の 4 通り。通信では、デジタルをアナログの 0 と 255 に丸め込み、フレームは「汎用出力」と「汎用入力」の 2 種類にする（決定）。** デジタルかアナログかは、ピンごとのモードで決まる。
> - **汎用出力のフレーム**（主制御 → 基板、DLC 4）: 4 ch × uint8（0〜255。デジタル出力は 0 か 255）。
> - **汎用入力のフレーム**（基板 → 主制御、DLC 7）: byte 0 ＝ 状態（bit 0 ＝ 基板に異常あり）、byte 1–4 ＝ 4 ch × uint8（デジタル入力は 0 か 255）、byte 5–6 ＝ デジタル入力が最後に変化した時刻（共通の時刻の欄。束にデジタル入力のピンが無ければ、同期の bit を 0 にする）。
> - デジタル入力のチャタリング除去、変化したらすぐ送ること、変化した時刻の記録は、基板の中の処理として残る。
> - 束は 4 ch で確定（8 ch では入力のフレームが 8 byte を超える。5 ch は半端で、RP2040 の ADC 4 本とも合わない）。
> - RP2040 でアナログ入力に使えるのは GPIO26〜29 の 4 本だけ。基板を設計するときに 1 束へ割り当てればよい。
> - CH32V203 のような安いマイコンも使われうる（仕様上は問題ない）。

> **v0.2 の骨格（合意、2026-09-30）**: 下の v0.1 の内容は、この骨格で置き換える予定。細かい形式は、需要が見えてから決める。
>
> - **汎用 I/O 基板を 1 つのファームウェアで作る。** 実質的に「CAN 越しの pinMode、write、read」になる。ピンごとのモード（デジタル入力、デジタル出力、アナログ入力、PWM 出力）は、3 つ目の型で設定する。
> - **出力は 1 種類にまとめる。** 通信では、すべて uint16 の割合（アナログ）で送る。ライブラリの API は、digital と analog の両方の書き込みを受け付ける。digital は 0% と 100% に変換して送る。1 フレームに 4 ch。
> - **ピン番号は、出力の ch と入力の ch の両方に同じ番号で割り当てる。** DIP で k を選ぶと、出力の束 k と入力の束 k を同時に受け持つ。モードを切り替えても番号は変わらない（片方の slot は空きになる）。
> - **入力と出力は、それぞれ 32 ch（4 ch の束 × 8）。** 残りの ID は予約に戻す。
> - **PWM の資源の制約**（ユーザの懸念）: PWM を出せるピンの数と、周波数を共有する組は、MCU と基板の配線で決まる。
>   - RP2040 は PWM のスライスが 8 個で、1 スライスに 2 ch ある（計 16 ch）。同じスライスの 2 ch は、周波数を共有する。
>   - STM32 は、タイマーごとに ch が決まり、同じタイマーの ch は周波数を共有する。
>   - デジタル出力は普通の GPIO で出せるので、PWM の資源は使わない。PWM が要るのは、PWM 出力モードのピンだけ。
>   - 基板は、実現できない設定（PWM を出せないピンに PWM 出力モードを指定した、同じ組に別の周波数を指定した、など）を拒否し、3 つ目の型の応答でエラーを返す。
>   - ~~主制御がピンごとの能力を知る方法は、基板の資料に書く。問い合わせの仕組みは作らない~~ → **2026-10-01 に変更: 資料に書いたうえで、CAN でも問い合わせられるようにする**（ユーザの提案）。
>     - **読み出し専用の設定項目「モードごとの対応 ch」で問い合わせる**（ユーザ: これは設定項目の役割）。値の欄（32 bit）に、そのモードに対応している ch を bit で並べて返す。汎用 I/O の ch は最大 32 なので、32 bit で全部を表せる（bit n が ch n。2026-10-03 から ch は 0 始まり）。基板は、自分が受け持つ ch の分だけ bit を立てる。
>     - 対応できないモードを設定されたときは、「実現できない」を返すだけにする（~~応答に対応 ch を載せる案~~はやめた）。
>     - ライブラリは、起動時にこの項目を読んで設定を確かめ、使えないピンを利用者に知らせる。
>     - 要求は ch 1 つ宛てなので、応答するのはその ch を受け持つ基板だけで、衝突しない。バス全体の能力を知るには、主制御が基板ごとに 1 回ずつ問い合わせる。
> - **汎用 I/O 基板は、LED やスイッチなどの小電力用とする。** サーボとモーターは、電力が違いすぎるので別の基板に分ける（ユーザ）。そのため、周波数を共有する制約（サーボ 50 Hz とモーター 20 kHz の混在）は、汎用 I/O 基板では問題にならない。

## 共通の考え方

- ch は**種類ごとの列ベクトル**で数える（0 始まり。2026-10-03）。
- ch は**束**に分けて扱う。1 フレームが 1 束を運ぶ。
- 基板は、連続した束を 1 つ以上受け持つ。1 枚の基板が、複数の種類の束を持ってもよい（例: デジタル入力 2 束とアナログ入力 1 束）。
- **基板から送る束は、1 枚の基板がまるごと受け持つ**。2 枚の基板が同じ ID で送ると衝突するため。空いた ch は使わずに残す。
- 基板の位置は DIP で決める。DIP の値 k は「その基板の大きさで数えた k 番目の区画」を指す。
- 処理の置き場所の原則に従う。チャタリング除去や変化した時刻の記録は基板が行う。入力が何を意味するかは主制御が判断する。
- ロボットごとに変わる設定（プルの向き、反転など）は、P9 に従う（ファームウェアの既定値 → フラッシュに保存した値 → 主制御から 3 つ目の型で上書き）。ファームウェアは書き換えない。

## デジタル出力（エアー、リレー、LED など）

エアーの電磁弁も、実体はデジタル出力なので同じ種類にまとめる。

**フレーム**（主制御 → 基板、周期指令）
- 1 ch を 1 bit で表し、1 フレームで 64 ch 分を運ぶ。byte 0 の bit 0 が束の先頭の ch。
- 後ろが使われていなければ、DLC を縮めてよい。
- 送信の周期はライブラリが決める（例えば 50 Hz）。途絶判定（100 ms）に間に合う周期で送る。
- 指令を送るのは主制御 1 台だけなので、束を 1 枚の基板がまるごと受け持つ必要はない。複数の基板が、同じ束の別々の ch を読んでよい。

**途絶したとき**（指令の途絶 100 ms、SYNC の途絶 250 ms、E-stop）
- ch ごとに、設定した「途絶時の状態」（off／on／そのまま）にする。既定は off。
- 弁やリレーは、off が安全とは限らない（ばね戻りの有無などで変わる）ので、設定で選べるようにする。

**設定**（ch ごと、3 つ目の型で送る）

| 設定 | 選択肢 | 既定 |
|---|---|---|
| 途絶時の状態 | off／on／そのまま | off |
| 反転 | する／しない | しない |

## 汎用 duty（PWM 出力。LED の明るさ、ファン、比例弁など）（案、2026-09-30）

モーターの duty とは別の種類にする。モーターの duty は、H ブリッジ向けの符号付きの値で、減衰モードの bit を持つ。汎用 duty は、片側だけのスイッチ（ローサイドのトランジスタ、LED）向けの符号なしの値にする。

**フレーム**（主制御 → 基板、周期指令）
- 4 ch × uint16（0 ＝ 0%、65535 ＝ 100%）。後ろが使われていなければ、DLC を縮めてよい。
- 実際の分解能は、基板の PWM の段数で決まる（仕様は 16 bit で余裕を持たせる）。

**途絶したとき**: ch ごとに設定した「途絶時の値」にする。既定は 0%。

**設定**（ch ごと、3 つ目の型で送る）

| 設定 | 選択肢 | 既定 |
|---|---|---|
| PWM の周波数 | Hz | 基板の既定（例えば 20 kHz。LED なら 1 kHz 程度でもよい） |
| 途絶時の値 | 0〜100% ／ そのまま | 0% |
| 反転 | する／しない | しない |

サーボも実体は PWM 出力だが、パルス幅（500〜2500 µs）で指令するという独自の意味があり、よく使うので、別の種類のまま残す。

## デジタル入力（リミットスイッチ、フォトセンサなど）

**フレーム**（基板 → 主制御、周期データ、時刻重視の帯）

形式（DLC 3、決定 2026-09-30）:

| byte | 内容 |
|---|---|
| 0 | 下位 4 bit: 入力 4 ch<br>上位 4 bit: 状態（bit 4 ＝ 基板に異常あり、残りは予約） |
| 1–2 | 最後に変化した時刻。**共通の時刻の欄**を使う（bit 15 ＝ 同期している、bit 0–14 ＝ 同期した時刻の下位 15 bit、µs） |

- 同期の印は、時刻の欄の最上位 bit に入れる（ユーザの提案）。時刻を載せるすべてのフレーム（ToF など）で、同じ形式を使う。
- 時刻は約 32.8 ms で一周する。データの時刻は必ず受信時刻より過去なので、主制御は過去側に戻す一方向の計算で元に戻せる。遅延が 32 ms 未満なら正しく戻る。

**送るタイミング**
- 入力が変化したら、すぐに送る（チャタリング除去を済ませた後）。
- 変化がなくても、一定の周期（例えば 20 Hz）で送る。主制御は、これで基板の生存も確認できる。

**設定**（ch ごと、3 つ目の型で送る）

| 設定 | 選択肢 | 既定 |
|---|---|---|
| プル | 上げる／下げる／なし | 上げる |
| 反転 | する／しない | しない |
| チャタリング除去の時間 | ms | 5 ms |

- プルの既定を「上げる」にするのは、リミットスイッチを GND に落とす配線が多く、NPN オープンコレクタのフォトセンサにも合うため。
- MCU 内蔵のプル抵抗（数十 kΩ）は、長い配線ではノイズに弱い。外付けの抵抗を選べるようにするかは、ハードウェアの判断。

## アナログ入力（ポテンショメータなど）

**フレーム**（基板 → 主制御、周期データ、通常の帯）

| byte | 内容 |
|---|---|
| 0–5 | 4 ch × 12 bit（フルスケールに対する割合）。束の先頭の ch から順に詰める |
| 6 | 状態（bit 0 ＝ 基板に異常あり、残りは予約） |

- 12 bit にしたのは、RP2040 と STM32 の ADC が 12 bit だから。16 bit で送ると 4 ch で 8 byte を使い切り、状態を載せる場所が無くなる。
- 時刻は載せない。周期的に送る値なので、モーターの FB と同じ扱い（需要が出たら見直す）。

**送るタイミング**
- 周期送信。既定は 100 Hz で、設定で変えられる。

**設定**（束ごと、3 つ目の型で送る）

| 設定 | 選択肢 | 既定 |
|---|---|---|
| 送信の周期 | Hz | 100 Hz |
| 平均の回数（ノイズ対策） | 回 | 基板の既定 |
