# ToF の仕様（案 v0.1）

状態: **保留**（2026-10-01、ユーザ。重いので後で再開する）。**2026-10-01 追記: 1 フレームでも欠けたらその回は取得できなかった扱いでよい（ユーザ）。分割は id-map-draft.md の「分割の共通の見出し」を使う方向。下の独自の見出し案は、それに置き換える予定。**案の内容は下のとおり。「**要判断**」がユーザに決めてもらう点。
前提は [requirements.md](requirements.md) の §4 と §4.7。

## 2026-10-02 の追加の前提（ユーザ）

- **ToF は、時刻が付いていれば遅れてもよいデータ**。優先度を上げる（class 3 の先頭に置く）必要はない。
- **欠けても、残りのデータが生きていれば価値がある。** 1 フレーム欠けただけで、その回を丸ごと捨てない。各フレームを単独でも使える形にする必要がある（どの区画のデータかが、そのフレームだけで分かること）。

## 前提（おさらい）

- マトリクス型（VL53L8CX）は最大 8 個、普段は 4 個以下。単点型（VL53L1X など）もある。
- マトリクス型は 8×8 と 4×4 を選べるようにする。1 行だけを送れるようにする（実績では 1 行 8 点だけを使っていた）。
- 送る項目は、距離、target_status（ターゲット無しを含む）、sigma。signal や ambient などは診断用。
- target_status は、1 つの信頼度にまとめない。L1X と L8CX の状態値も、共通の値にまとめない（生の値を運ぶ）。
- 時刻は、測定の中点の時刻を、共通の時刻の欄（2 byte）で載せる。
- class 3 に置く（~~帯 2~~ は 2026-10-01 に変更。2026-10-02 に、先頭ではなく MD の FB などの後ろへ）。ID はセンサ 1 個（ch）ごとに 1 つ。
- 設定値は P9 に従う（ファームウェアの既定値 → フラッシュ → 主制御からの上書き）。

## マトリクス型（VL53L8CX）のフレーム（決定 2026-10-02。下の旧案を置き換える）

共通の見出しは使わず、ToF 専用の形にする。各データのフレームが単独で使えるようにするため。1 つ 1 つのフレームに時刻を付けるより合理的（ユーザ）。

**見出しのフレーム**（1 回に 1 本、フレーム番号 0）

| byte | 内容 |
|---|---|
| 0 | フレーム番号（0） |
| 1 | 測定の回の番号（0〜255 で折り返す） |
| 2–3 | 測った時刻（共通の時刻の欄。測定の中点） |
| 4 | 送っている範囲（全区画、何行目、何列目など。形は設定と合わせて決める） |

**データのフレーム**（フレーム番号 1 から）

| byte | 内容 |
|---|---|
| 0 | フレーム番号 k（1〜32） |
| 1 | 測定の回の番号 |
| 2–7 | 区画 2 つ分の記録（3 byte × 2）。区画の番号は k から決まる（2k − 1 番目と 2k 番目） |

- データのフレームは、それ 1 本だけで使える。回の番号で、見出しのフレーム（時刻）と結び付ける。
- 見出しのフレームが欠けても、センサは一定の周期で測るので、回の番号と前後の回の時刻から時刻を推定できる。
- フレームが欠けても、その回を丸ごとは捨てない。届いた区画だけを使う。
- 送る量: 1 行（8 区画）は 5 本、8×8 は 33 本（15 Hz で負荷は約 6%）。
- 優先度は上げなくてよい（時刻が付いていれば遅れてもよいため）。class 3 の中で、MD の FB やコントローラより後ろに置く。

## 旧案（2026-10-01、置き換え済み）



1 回の測定（スキャン）を、同じ ID の複数のフレームで続けて送る。

### 各フレームの形（DLC 8）

| byte | 内容 |
|---|---|
| 0 | bit 5–7: スキャンの通し番号（0〜7 で折り返す）<br>bit 0–4: スキャン内のフレーム番号（0〜31） |
| 1–7 | データの続き（7 byte ずつ） |

- 主制御は、フレーム番号の抜けと、スキャンの通し番号の変化から、欠けたスキャンを捨てられる。
- 同じ基板が同じ ID で送るので、フレームの順番は保たれる。

### 1 スキャン分のデータ（フレームをまたいでつなげたもの）

| 位置 | 内容 |
|---|---|
| 先頭 2 byte | 共通の時刻の欄（測定の中点。bit 15 ＝ 同期している） |
| 以降 3 byte ずつ | 区画ごとの記録（送る区画の順） |

区画の記録（3 byte ＝ 24 bit）:

| bit | 内容 |
|---|---|
| 12–23 | 距離（mm、0〜4095）。L8CX の最大は約 4000 mm なので収まる |
| 8–11 | target_status（0〜13 はセンサの値そのまま。15 ＝ ターゲット無し。nb_target が 0 のとき、センサの 255 もこれにする） |
| 0–7 | sigma（mm、255 で頭打ち） |

- target_status はセンサの値を 1 対 1 で置き換えているだけなので、情報は失われない（L8CX の値は 0〜13 と 255 だけ）。

### 送る量の目安

| 設定 | 区画数 | データ | フレーム数 | 周期 | バス負荷（1 個） |
|---|---|---|---|---|---|
| 1 行（8 区画） | 8 | 26 byte | 4 | 10 Hz | 約 0.5% |
| 4×4 | 16 | 50 byte | 8 | 60 Hz まで | 60 Hz で約 6% |
| 8×8 | 64 | 194 byte | 28 | 15 Hz まで | 15 Hz で約 5.5% |

### 判断 1（決定 2026-10-02）: 区画の記録は 3 byte に詰める

表現域: 距離 12 bit（0〜4095 mm、1 mm 刻み。L8CX の最大は約 4000 mm）、状態 4 bit（0〜13 はセンサの値そのまま、15 はターゲット無し、14 は未使用）、sigma 8 bit（0〜255 mm、255 で頭打ち）。4 byte 案（距離 16 bit、状態 8 bit）との違いは距離の余裕だけで、情報は失われない。

### ~~要判断 1: 区画の記録を 3 byte に詰めるか~~

- 詰める（おすすめ）: 上の形。距離は 12 bit、sigma は 8 bit、状態は 4 bit。
- 詰めない: 距離 2 byte、sigma 1 byte、状態 1 byte の 4 byte。読みやすいが、フレーム数は約 1.3 倍になる。

## 単点型（VL53L1X など）のフレーム（決定 2026-10-02）

1 回の測定を 1 フレームで送る（DLC 6）。

| byte | 内容 |
|---|---|
| 0–1 | 測った時刻（共通の時刻の欄。測定の中点） |
| 2–3 | 距離（mm、uint16） |
| 4 | range_status（センサの値そのまま） |
| 5 | sigma（mm、255 で頭打ち） |

- **ambient は載せない**（ユーザ: 需要を感じない）。有効 SPAD 数（実際に使った受光素子の数。光の強さの目安）も載せない。どちらも、必要なら診断用の出力で見る。

## 旧案（単点型、2026-10-01、置き換え済み）

1 回の測定を 1 フレームで送る（分割しない）。

| byte | 内容 |
|---|---|
| 0–1 | 共通の時刻の欄（測定の中点） |
| 2–3 | 距離（mm、uint16） |
| 4 | range_status（センサの値そのまま） |
| 5 | sigma（mm、255 で頭打ち） |
| 6–7 | ambient（センサの値。単位は L1X の kcps） |

### 要判断 2: 単点型に ambient を載せるか

実績の実装では、ambient と有効 SPAD 数も読んでいた。8 byte に収まるのは ambient までで、SPAD 数は診断用に回す案にした。

## 診断用の出力

- signal、ambient（マトリクス型）、SPAD 数などは、**設定で診断モードにしたときだけ**送る。形式は後で決める（普段の区画の記録とは別の形にする）。

## 動作

| 場面 | 動作 |
|---|---|
| 電源投入 | **保存された設定で、自動的に測定を始める**（決定 2026-10-02） |
| 設定の変更 | 3 つ目の型で送る。基板は測定を止め、設定を反映して再開する |
| 停止、再開、リセット | 設定のフレーム（class 4）の命令で行う（決定 2026-10-02） |
| SYNC が来ていない | 測定は続ける。時刻の欄の bit 15 を 0 にする |
| E-stop | 何もしない（センサは止めない。v0 の「センサは E-stop で止まらない」を引き継ぐ） |

### ~~要判断 3: 電源投入で自動的に測定を始めるか~~ → 自動で始める（決定）

- 始める（おすすめ）: 主制御は何もしなくてよい。P9 で設定をフラッシュに保存するので、前回と同じ設定で動く。
- 命令を待つ: 主制御が「開始」を送るまで測定しない。許可制と同じ性質になる。

## 設定（センサごと。P9 に従う）

| 設定 | 対象 | 既定 |
|---|---|---|
| 解像度（4×4 ／ 8×8） | マトリクス型 | 8×8 |
| 送る範囲（全区画 ／ 1 行 ／ 1 列）と、その番号 | マトリクス型 | 全区画 |
| 送る順番の反転 | マトリクス型 | しない |
| 測定の周期 | 両方 | センサの既定 |
| 積分時間 | マトリクス型 | センサの既定 |
| sharpener、target order | マトリクス型 | センサの既定 |
| 距離モード（Short ／ Long） | 単点型 | Short |
| 測定時間（timing budget） | 単点型 | 20 ms |
| ROI の大きさと中心（FoV） | 単点型 | 16×16、中央 |
| 診断モード | 両方 | しない |

- 実績の R2 では、行 5、転置なし、反転ありを使っていた。行か列かを選べれば、転置は要らない。
