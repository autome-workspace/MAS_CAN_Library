前提は [requirements.md](requirements.md) の §4 と §4.7。

## 前提（おさらい）

- マトリクス型（VL53L8CX）は最大 8 個、普段は 4 個以下。単点型（VL53L1X など）もある。
- マトリクス型は 8×8 と 4×4 を選べるようにする。1 行だけを送れるようにする（実績では 1 行 8 点だけを使っていた）。
- 送る項目は、距離、target_status（ターゲット無しを含む）、sigma。signal や ambient などは診断用。
- target_status は、1 つの信頼度にまとめない。L1X と L8CX の状態値も、共通の値にまとめない（生の値を運ぶ）。
- 時刻は、測定の中点の時刻を、共通の時刻の欄（2 byte）で載せる。
- 帯 2（時刻重視）に置く。ID はセンサ 1 個（ch）ごとに 1 つ。
- 設定値は P9 に従う（ファームウェアの既定値 → フラッシュ → 主制御からの上書き）。

## マトリクス型（VL53L8CX）のフレーム

1 回の測定（スキャン）を、同じ ID の複数のフレームで続けて送る。

### 各フレームの形（DLC 8）

| byte | 内容 |
|---|---|
| 0 | bit 5–7: スキャンの通し番号（0〜7 で折り返す）<br>bit 0–4: スキャン内のフレーム番号（0〜31） |
| 1–7 | データの続き（7 byte ずつ） |

- 主制御は、フレーム番号の抜けと、スキャンの通し番号の変化から、欠けたスキャンを捨てられる。
- 同じ基板が同じ ID で送るので、フレームの順番は保たれる。

### 1 スキャン分のデータ（フレームをまたいでつなげたもの）

| 位置 | 内容 |
|---|---|
| 先頭 2 byte | 共通の時刻の欄（測定の中点。bit 15 ＝ 同期している） |
| 以降 3 byte ずつ | 区画ごとの記録（送る区画の順） |

区画の記録（3 byte ＝ 24 bit）:

| bit | 内容 |
|---|---|
| 12–23 | 距離（mm、0〜4095）。L8CX の最大は約 4000 mm なので収まる |
| 8–11 | target_status（0〜13 はセンサの値そのまま。15 ＝ ターゲット無し。nb_target が 0 のとき、センサの 255 もこれにする） |
| 0–7 | sigma（mm、255 で頭打ち） |

- target_status はセンサの値を 1 対 1 で置き換えているだけなので、情報は失われない（L8CX の値は 0〜13 と 255 だけ）。

### 送る量の目安

| 設定 | 区画数 | データ | フレーム数 | 周期 | バス負荷（1 個） |
|---|---|---|---|---|---|
| 1 行（8 区画） | 8 | 26 byte | 4 | 10 Hz | 約 0.5% |
| 4×4 | 16 | 50 byte | 8 | 60 Hz まで | 60 Hz で約 6% |
| 8×8 | 64 | 194 byte | 28 | 15 Hz まで | 15 Hz で約 5.5% |

### 要判断 1: 区画の記録を 3 byte に詰めるか

- 詰める（おすすめ）: 上の形。距離は 12 bit、sigma は 8 bit、状態は 4 bit。
- 詰めない: 距離 2 byte、sigma 1 byte、状態 1 byte の 4 byte。読みやすいが、フレーム数は約 1.3 倍になる。

## 単点型（VL53L1X など）のフレーム

1 回の測定を 1 フレームで送る（分割しない）。

| byte | 内容 |
|---|---|
| 0–1 | 共通の時刻の欄（測定の中点） |
| 2–3 | 距離（mm、uint16） |
| 4 | range_status（センサの値そのまま） |
| 5 | sigma（mm、255 で頭打ち） |
| 6–7 | ambient（センサの値。単位は L1X の kcps） |

### 要判断 2: 単点型に ambient を載せるか

実績の実装では、ambient と有効 SPAD 数も読んでいた。8 byte に収まるのは ambient までで、SPAD 数は診断用に回す案にした。

## 診断用の出力

- signal、ambient（マトリクス型）、SPAD 数などは、**設定で診断モードにしたときだけ**送る。形式は後で決める（普段の区画の記録とは別の形にする）。

## 動作

| 場面 | 動作 |
|---|---|
| 電源投入 | **保存された設定で、自動的に測定を始める**（要判断 3） |
| 設定の変更 | 3 つ目の型で送る。基板は測定を止め、設定を反映して再開する |
| 開始、停止、リセット | 3 つ目の型の命令で行う |
| SYNC が来ていない | 測定は続ける。時刻の欄の bit 15 を 0 にする |
| E-stop | 何もしない（センサは止めない。v0 の「センサは E-stop で止まらない」を引き継ぐ） |

### 要判断 3: 電源投入で自動的に測定を始めるか

- 始める（おすすめ）: 主制御は何もしなくてよい。P9 で設定をフラッシュに保存するので、前回と同じ設定で動く。
- 命令を待つ: 主制御が「開始」を送るまで測定しない。許可制と同じ性質になる。

## 設定（センサごと。P9 に従う）

| 設定 | 対象 | 既定 |
|---|---|---|
| 解像度（4×4 ／ 8×8） | マトリクス型 | 8×8 |
| 送る範囲（全区画 ／ 1 行 ／ 1 列）と、その番号 | マトリクス型 | 全区画 |
| 送る順番の反転 | マトリクス型 | しない |
| 測定の周期 | 両方 | センサの既定 |
| 積分時間 | マトリクス型 | センサの既定 |
| sharpener、target order | マトリクス型 | センサの既定 |
| 距離モード（Short ／ Long） | 単点型 | Short |
| 測定時間（timing budget） | 単点型 | 20 ms |
| ROI の大きさと中心（FoV） | 単点型 | 16×16、中央 |
| 診断モード | 両方 | しない |

- 実績の R2 では、行 5、転置なし、反転ありを使っていた。行か列かを選べれば、転置は要らない。
