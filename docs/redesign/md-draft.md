# モータードライバー（MD）の仕様（案 v0.1）

状態: **合意（v1.0 候補）**。大枠で決まったことを、実装できる細かさまで詰めたもの（2026-09-30）。
「**要判断**」と書いた箇所が、ユーザに決めてもらう点。
ID の全体像は [id-map-draft.md](id-map-draft.md)、前提は [requirements.md](requirements.md)。

## 1. 決まっていること（おさらい）

- ch は、モーターの列ベクトルで数える（1〜32）。基板は、連続した ch を受け持つ（1 ch の MD、4 ch の MD、中継役など）。
- 指令は、4 ch 分を 1 フレームにまとめて送る。同じフレームに入る ch では、指令の種類を混ぜない。使っていない slot には、その種類の「止める値」を入れる（電流・速度・duty は 0、位置は `0x8000`。サーボは 255）。
- 指令の種類は ID で区別する（帯 1 の種類 0〜3）。
- 途絶判定は 2 つある。ch ごとの指令の途絶（100 ms）と、SYNC の途絶（250 ms）。
- FB は、ch ごとに 1 フレーム（8 byte）で送る。

## 2. 指令（主制御 → MD）

ID: `0x100 | (種類 << 3) | フレーム番号`。ch n は、フレーム番号 `(n-1)/4` の slot `(n-1)%4` に入る。1 slot は 2 byte（int16、big-endian）。

| 種類 | ID | slot の意味 | 0 の意味 |
|---|---|---|---|
| 0: 電流 | `0x100`〜 | 2 mA/LSB（±65.5 A） | 電流 0（止める） |
| 1: 速度 | `0x108`〜 | 出力軸の 1 rpm/LSB | 速度 0（止める） |
| 2: duty | `0x110`〜 | 下の「duty の bit の割り当て」を参照 | duty 0、空転（止める） |
| 3: 位置 | `0x118`〜 | 設定した範囲に対する割合（±32767）。`0x8000` は今の位置で保持 | 範囲の中央へ動く（止まらない。そのため使っていない slot には `0x8000` を入れる） |

### duty の bit の割り当て（提案）

| bit | 内容 |
|---|---|
| 0 | 減衰モード（0 ＝ 空転、1 ＝ ブレーキ） |
| 1–15 | 符号付きの duty（値を 1 bit 右にずらしたもの。±16383 が ±100%） |

- `0x0000` は「duty 0、空転」になり、「使っていない slot の 0 は止める」という規則と一致する。
- 「duty 0、ブレーキ」（`0x0001`）が短絡ブレーキになる。
- 減衰モードを最下位 bit に置くのは、符号（最上位 bit）を壊さないため。受け取った側は、値を算術右シフトすれば duty になる。

### 位置の割合（提案）

- int16 の −32767〜+32767 を、設定した範囲の下限〜上限に対応させる。
- 範囲（下限と上限）と、実際の単位（mm、度など）は、基板の設定で持つ。

**要判断 1: 位置の指令には「止める」値が無い。**
0 は「範囲の中央へ動く」という意味になり、他の種類の「0 は止める」という規則と食い違う。同じ組の ch はすべて位置の指令で動かすので、普段は問題にならない。ただし、使っていない slot に入る 0 で、その ch の基板が中央へ動き出す危険がある。対策の案は次のとおり。

- 案 A: 位置の指令に限り、`0x8000`（−32768）を「今の位置で保持する」と決める。使っていない slot には `0x8000` を入れる。
- 案 B: 位置の組では、使っていない ch を置かない（規則だけで防ぐ）。

→ **決定（2026-09-30）: 案 A。** 位置の指令を duty と同じ割合と捉え、「最大値 ＋ 1」を保持の値にする（ユーザ）。int16 では 32767 ＋ 1 が `0x8000` に当たる。位置の組の使っていない slot には、0 ではなく `0x8000` を入れる（「使っていない slot には 0」の規則の、位置だけの例外）。

## 3. FB（MD → 主制御）

ID: `0x300 + (ch - 1)`。8 byte。

| byte | 内容 |
|---|---|
| 0–1 | 速度（int16、出力軸の 1 rpm/LSB） |
| 2–3 | 電流（int16、2 mA/LSB。65.5 A を超える電流は頭打ちになり、状態の bit 1 が立つ） |
| 4 | 状態（下の表） |
| 5–7 | 位置（24 bit で折り返すカウンタ。出力軸 1 回転 ＝ 65536 カウント） |

### 状態の byte（決定）

| bit | 内容 |
|---|---|
| 0 | 基板に異常あり（詳細は 3 つ目の型で問い合わせる。全種類で共通の意味） |
| 1 | 電流の上限に当たっている |
| 2 | 速度と位置が無効（エンコーダが無い、または異常。中継役なら、下のバスで応答が途絶えた） |
| 3 | 出力を止めている（指令の途絶、SYNC の途絶、E-stop のどれか） |
| 4 | E-stop でラッチしている |
| 5–6 | 今従っている指令の種類（0 電流、1 速度、2 duty、3 位置） |
| 7 | 予約 |

- bit 2 は、CAN_MD のようにエンコーダが無い MD のために要る。そうした MD は、速度と位置の欄に 0 を入れ、bit 2 を立てる。
- bit 5–6 で、主制御は基板が今どの指令に従っているかを確かめられる。

### FB を送るタイミング（提案）

- 電源が入った後、**指令が来ていなくても**周期的に送る。主制御は、これで基板の生存を確かめる（基板専用の周期フレームは持たない、という決定に対応する）。
- 既定の周期は 100 Hz。設定で変えられる（0 にすると送らない）。

## 4. 動作の規則

| 場面 | 動作 |
|---|---|
| 電源投入 | 出力は止まっている。最初の有効な指令から、それに従って動く（許可制は入れない） |
| 指令の種類が変わった | その ch は、最後に受け取った種類に従う。前の種類の制御状態（積分項など）はリセットする |
| 指令の途絶（100 ms）、SYNC の途絶（250 ms） | 出力を止める。止め方（空転かブレーキか）は ch ごとの設定で決める（既定は空転）。ラッチはしない |
| E-stop | 出力を止めてラッチする。止め方は常に空転（駆動電源が切れる前提と合わせる）。解除は `0x001` か電源の再投入 |
| 範囲外の指令 | 基板の上限（設定またはハードウェア）で飽和させる。電流の上限に当たったら状態の bit 1 を立てる |

## 5. 設定（ch ごと。P9 に従い、ファームウェアの既定値 → フラッシュに保存した値 → 主制御からの上書き、の順で決まる）

| 設定 | 使う種類 | 既定 |
|---|---|---|
| 回転方向の反転 | 全種類 | しない |
| 電流の上限 | 全種類 | 基板のハードウェアの上限 |
| 停止時の止め方（空転／ブレーキ） | 全種類 | 空転 |
| FB の周期 | — | 100 Hz |
| 減速比、エンコーダの分解能 | 速度、位置 | 基板の既定（出力軸の単位に換算するために使う） |
| 速度ループの PID ゲイン | 速度、位置 | 基板の既定 |
| 位置の範囲（下限、上限）と、位置ループの PID ゲイン | 位置 | なし（設定するまで位置の指令は受け付けない） |

**要判断 2: 設定値を基板のフラッシュに保存するか。**
- 保存しない: 主制御が、起動するたびに全部送る。大元が主制御だけになり、食い違いが起きない。そのかわり、主制御が送る前は既定値で動く。
- 保存する: 電源を入れた直後から、設定どおりに動く。そのかわり、基板に古い設定が残る危険がある。

→ ~~保存しないをおすすめする~~ → **決定（2026-09-30）: 保存できるものは基板のフラッシュに保存し、基板だけで完結させる。これを既定の動作とする。** 主制御は、必要なら起動時に設定を送って上書きしてよい（起動時に全部送るかどうかは、ID の余裕しだい、とユーザ）。
- 注意: 基板を別のロボットに付け替えると、前のロボットの設定が残る。ライブラリには、設定を読み出して確かめる機能を用意する（3 つ目の型で）。
