# モータードライバー（MD）の仕様（v0.2）

状態: **合意（v1.0 候補）**。大枠で決まったことを、実装できる細かさまで詰めたもの（2026-09-30）。
「**要判断**」と書いた箇所が、ユーザに決めてもらう点。
ID の全体像は [id-map-draft.md](id-map-draft.md)、前提は [requirements.md](requirements.md)。

## 0. 主制御から見た位置と速度（全体像、2026-10-03）

- 位置は出力軸 1 回転 ＝ 65536 カウント。24 bit で折り返し、電源を入れたときは 0 から始まる。速度は出力軸の rpm。指令も同じ単位。
- 主制御は、エンコーダがどこに付いているか（モーター軸か出力軸か）、何の種類か（SPI の絶対角度か、ABI のインクリメンタルか）を知らなくてよい。
- 基板を組んだ人が一度だけ設定するのは、encoder CPR（エンコーダ 1 回転のカウント数）と gear ratio（エンコーダの軸から出力軸までの減速比）の 2 つだけ。どちらも事実なので保存する。
- それ以外（読み方、周回の数え方、BLDC の転流）は基板の中の話。基板ごとの資料に書き、必要なら基板固有の設定項目（128〜255）にする。
- 設定項目の一覧は [settings-draft.md](settings-draft.md) の B1。

## 1. 決まっていること（おさらい）

- ch は、モーターの列ベクトルで数える（0〜31。2026-10-03 から 0 始まり）。基板は、連続した ch を受け持つ（1 ch の MD、4 ch の MD、中継役など）。
- 指令は、4 ch 分を 1 フレームにまとめて送る。同じフレームに入る ch では、指令の種類を混ぜない。使っていない slot には、その種類の「止める値」を入れる（電流・速度・duty は 0、位置は `0x8000`。サーボは 255）。
- 指令の種類は ID で区別する（class 2 の種類 0〜3）。
- 途絶判定は 2 つある。ch ごとの指令の途絶（100 ms）と、SYNC の途絶（250 ms）。
- FB は、ch ごとに 1 フレーム（8 byte）で送る。

## 2. 指令（主制御 → MD）

ID: `0x210 + (種類 × 8) + フレーム番号`（class 2。DJI の ID を避けて `0x210` から）。ch n（0 始まり）は、フレーム番号 `n/4` の slot `n%4` に入る。1 slot は 2 byte（int16、big-endian）。

| 種類 | ID | slot の意味 | 0 の意味 |
|---|---|---|---|
| 0: 電流 | `0x210`〜 | 既定 1 mA/LSB（±32.767 A）。設定で LSB を自由に変えられる（float32。例えば 2 mA/LSB で ±65.5 A。2026-10-03） | 電流 0（止める） |
| 1: 速度 | `0x218`〜 | 出力軸の rpm。既定 1 rpm/LSB（±32767 rpm）。設定で LSB を自由に変えられる（float32。例えば 0.1 rpm/LSB で ±3276.7 rpm。2026-10-03） | 速度 0（止める） |
| 2: duty | `0x220`〜 | 下の「duty の bit の割り当て」を参照 | duty 0、空転（止める） |
| 3: 位置 | `0x228`〜 | 折り返しの目標位置（位置カウンタの下位 16 bit。出力軸 1 回転 ＝ 65536）。`0x8000` は今の位置で保持 | 0 は位置 0 付近へ動く（止まらない。そのため使っていない slot には `0x8000` を入れる） |

### duty の bit の割り当て（確定 2026-10-03、ユーザ）

| bit | 内容 |
|---|---|
| 0 | 減衰モード（0 ＝ 空転、1 ＝ ブレーキ） |
| 1–15 | 符号付きの duty（値を 1 bit 右にずらしたもの。±16383 が ±100%） |

- `0x0000` は「duty 0、空転」になり、「使っていない slot の 0 は止める」という規則と一致する。
- 「duty 0、ブレーキ」（`0x0001`）が短絡ブレーキになる。
- 自分の slot が DLC の外にあるとき（DLC を縮めたフレーム、奇数の DLC で欠けた slot）は、その ch は指令を受けていない扱いにする。途絶の時計は進み続ける（2026-10-03、ユーザ。requirements.md の D9）。
- 減衰モードを最下位 bit に置くのは、符号（最上位 bit）を壊さないため。受け取った側は、値を算術右シフトすれば duty になる。
- ブレーキはモーター端子の短絡（H ブリッジの下側 2 つ、または上側 2 つをオン）。電源の短絡（同じ側の上下を同時にオンにする貫通）ではない。
- bit 1–15 は −16384 も表せるが、これは −100% を超える。§4 の「範囲外の指令は飽和させる」に従い、−100% として扱う（2026-10-03、ユーザ）。

### ~~位置の割合（提案）~~（2026-10-01 に折り返しの指令へ変更。下の「位置の単位」を参照）

- int16 の −32767〜+32767 を、設定した範囲の下限〜上限に対応させる。
- 範囲（下限と上限）と、実際の単位（mm、度など）は、基板の設定で持つ。

**要判断 1: 位置の指令には「止める」値が無い。**
0 は「範囲の中央へ動く」という意味になり、他の種類の「0 は止める」という規則と食い違う。同じ組の ch はすべて位置の指令で動かすので、普段は問題にならない。ただし、使っていない slot に入る 0 で、その ch の基板が中央へ動き出す危険がある。対策の案は次のとおり。

- 案 A: 位置の指令に限り、`0x8000`（−32768）を「今の位置で保持する」と決める。使っていない slot には `0x8000` を入れる。
- 案 B: 位置の組では、使っていない ch を置かない（規則だけで防ぐ）。

→ **決定（2026-09-30）: 案 A。** 位置の指令を duty と同じ割合と捉え、「最大値 ＋ 1」を保持の値にする（ユーザ）。int16 では 32767 ＋ 1 が `0x8000` に当たる。位置の組の使っていない slot には、0 ではなく `0x8000` を入れる（「使っていない slot には 0」の規則の、位置だけの例外）。

## 3. FB（MD → 主制御）

ID: ch ごとに 1 つ（id-map-draft.md の class 3）。**2026-10-01 に並びを決め直した（確定）。**

| byte | 内容 |
|---|---|
| 0 | 状態（下の表） |
| 1–2 | 電流（int16、既定 1 mA/LSB、設定で自由に変えられる（float32）。指令と同じ）。**電流が無効なら duty** |
| 3–4 | 速度（int16、出力軸の rpm。既定 1 rpm/LSB、設定で自由に変えられる（float32）。指令と同じ）。**電流が有効で速度が無効なら duty** |
| 5–7 | 位置（24 bit で折り返すカウンタ。出力軸 1 回転 ＝ 65536） |

- 並びは「電流、速度、位置」の順にした。測れないものが後ろに来るので、DLC を縮められる（ユーザ）。DLC は後ろから削るので、状態は先頭に置く。
- duty の形式は、指令の duty と同じ（bit 0 が減衰モード、bit 1–15 が符号付きの duty）。**実際に出している値**を入れる。
- 測れる値は、測れる限り常に同じ位置にある。duty は空いた欄に入るだけ。

| 測れるもの | byte 1–2 | byte 3–4 | byte 5–7 | DLC |
|---|---|---|---|---|
| 全部 | 電流 | 速度 | 位置 | 8 |
| エンコーダだけ（電流が無効） | duty | 速度 | 位置 | 8 |
| 電流だけ（速度と位置が無効） | 電流 | duty | — | 5 |
| 何も無い（両方無効） | duty | — | — | 3 |

- エンコーダだけ測れる構成は実際にある（電流を測る抵抗の無い簡易な H ブリッジと、エンコーダ付きのギアモーターの組み合わせ）。
- duty 制御のときは、FB の duty が指令とほぼ同じ値になる。それでも残す。欄はどのみち空くので通信量は変わらず、加速度の制限、途絶、E-stop、電流の上限で指令と実際の出力がずれたときに役立つため。
- 何も測れない基板も FB を送る（生存確認を兼ねるため）。既定の周期は、基板のファームウェアが持つ（P9）。

### 状態の byte（2026-10-01 に組み替え、確定）

| bit | 内容 |
|---|---|
| 0 | 基板に異常あり（詳細は設定の読み出しで問い合わせる。全種類で共通の意味） |
| 1 | 速度と位置が無効（エンコーダが無い、または異常。中継役なら、下のバスで応答が途絶えた） |
| 2 | 電流が無効（電流を測れない） |
| 3 | 電流の上限に当たっている |
| 4 | 出力を止めている（指令の途絶、SYNC の途絶、E-stop、こなせない指令のどれか。最後は 2026-10-03 に追加） |
| 5 | E-stop でラッチしている |
| 6–7 | 今従っている指令の種類（0 電流、1 速度、2 duty、3 位置） |

- 2 つの「無効」の bit を並べた（ユーザ）。8 bit をちょうど使い切る。

### シリアルサーボ（2026-10-01）

- シリアルサーボ（Dynamixel、近藤の ICS、Feetech の STS など）は、位置、速度、負荷を返せる。実体は「位置制御ができる MD」なので、**MD として扱う**。新しい種類や ID は増やさない。
- 温度や電圧のように FB に入らない値は、設定の読み出しで取る。

### FB を送るタイミング（提案）

- 電源が入った後、**指令が来ていなくても**周期的に送る。何も測れない基板も送る。主制御は、これで基板の生存を確かめる（基板専用の周期フレームは持たない、という決定に対応する）。
- 既定の周期は 100 Hz。設定で変えられる（0 にすると送らない）。

### 位置の原点（2026-10-01 追加）

- インクリメンタルのエンコーダなど、絶対位置が分からないものは、原点を決める命令が要る（ユーザ）。
- 命令は「今の位置を値 N とみなす」の 1 つだけにし、3 つ目の型で送る。原点出し（リミットスイッチに当てるまで動かす、など）の手順は判断にあたるので、主制御が行う（処理の置き場所の原則）。
- **決定（2026-10-01）: 原点の既定値で足りる**（電源投入時の位置を 0 とする）。大会でも、起動時やアクションの区切りでは、手で位置を直す場面がほとんど。原点のずれは主制御が対処すべき課題でもある（ユーザ）。「原点が未設定」の bit は設けない。

### 位置の単位（**未決**、ユーザが悩んでいる点）

- 指令は「設定した範囲に対する割合」、FB は「出力軸の回転数（カウント）」で、単位が食い違っている。
- 制御対象はさまざまで、レールのように動く量が限られるものもあれば、無限軌道の運搬ベルトのように限りが無いものもありうる。単位を固定するべきではないかもしれない（ユーザ）。
- 案（2026-10-01、検討中）:

| 案 | 中身 | 限りのある対象（レール） | 限りの無い対象（ベルト） |
|---|---|---|---|
| 1. 割合（今の案） | 設定した範囲に対する割合 | ○ | ✕（範囲が無い） |
| 2. 単位を基板の設定にし、絶対値で指令 | int16 の値を、設定した単位で読む | ○（範囲は int16 の分だけ） | ✕ |
| 3. **折り返しの指令**（FB と同じ考え方） | 指令も、FB の位置カウンタの下位 16 bit と同じものと考える。基板は、今の位置から近い側の目標として解釈する | ○ | ○ |
| 4. 指令を 3 byte にする | 1 フレームに 2 ch になる | ○（範囲が広い） | △（いずれ溢れる） |

- 案 3 の制約: 1 回の指令で動かせるのは、今の位置から ±半周分（±32767 カウント）まで。主制御が 100 Hz で目標を少しずつ送る使い方なら、問題にならない。単位を FB と同じにすれば、指令と FB の食い違いも解消する。

**決定（2026-10-01）: 案 3（折り返しの指令）を採る。**
- 位置の指令の int16 は、目標位置のカウンタの下位 16 bit とみなす。基板は、今の位置（24 bit のカウンタ）から近い側の目標として解釈する。
- 単位は FB と同じ「**出力軸 1 回転 ＝ 65536 カウント**」に固定する。別付けのエンコーダは、8192 段階の AMT102 や、13 bit、14 bit の磁気エンコーダが多くなる見込み（ユーザ）。65536 は 8192 と 16384 のちょうど 8 倍と 4 倍なので、換算で誤差が出ない。
- モーター軸に付けるエンコーダは、基板の速度ループのためのもので、主制御は位置として使わない（ユーザ）。
- 1 回の指令で動かせるのは、±半回転（±32767 カウント）まで。10 ms ごとに送るなら、3000 rpm に当たり、十分に足りる。
- mm などへの換算（プーリーの径など）は、ライブラリで行う。
- 保持（`0x8000`）は、保持を始めた瞬間（その ch の前の指令が `0x8000` でなかったとき）に測った位置を目標として覚え、続く間はその目標を保ち続ける（2026-10-03、ユーザ。requirements.md の D11）。
- 保持の値 `0x8000` は残す。そのため、下位 16 bit が `0x8000` ちょうどの目標は指定できない。主制御は `0x7FFF` か `0x8001` を送る（1/65536 回転の差なので、実用上は問題ない）。
- ~~位置の割合（範囲の下限と上限）~~ の設定は不要になる。
- 参考: C610 のエンコーダは、モーター軸 1 回転が 0〜8191（13 bit）の単回転の角度。M2006（減速比 36）なら、出力軸 1 回転は 294,912 カウントになる。

### 移動のパラメータ（決定 2026-10-01）

- 最高速度と最大加速度は、ch ごとの設定（P9）として基板のファームウェアに持たせる。ハードウェアによって仕様が変わるため（ユーザ）。
- 基板は、目標へ向かう動きを常にこの制限の中に収める。主制御が細かく目標を送るなら安全の上限として働き、大まかに送るなら台形の動きになる。
- 速度制御でも、最大加速度を使える（急発進や急停止をなだらかにする）。
- 長い移動（±半回転を超える）は、ライブラリが途中の目標を刻んで送る API で扱う。

## 4. 動作の規則

| 場面 | 動作 |
|---|---|
| 電源投入 | 出力は止まっている。最初の有効な指令から、それに従って動く（許可制は入れない） |
| 指令の種類が変わった | その ch は、最後に受け取った種類に従う。前の種類の制御状態（積分項など）はリセットする |
| 指令の途絶（100 ms）、SYNC の途絶（250 ms） | 出力を止める。止め方（空転かブレーキか）は ch ごとの設定で決める（既定は空転）。ラッチはしない |
| E-stop | 出力を止めてラッチする。止め方は常に空転（駆動電源が切れる前提と合わせる）。解除は `0x001` か電源の再投入 |
| 範囲外の指令 | 基板の上限（設定またはハードウェア）で飽和させる。電流の上限に当たったら状態の bit 3 を立てる |
| こなせない指令（エンコーダの無い・壊れた基板に速度・位置、電流を測れない基板に電流） | すぐ出力を止める（止め方は設定 34）。状態の bit 4 を立て、bit 6–7 は受け取った種類を示す（2026-10-03、ユーザ。requirements.md の D10） |

## 5. 設定（ch ごと。P9 に従い、ファームウェアの既定値 → フラッシュに保存した値 → 主制御からの上書き、の順で決まる）

| 設定 | 使う種類 | 既定 |
|---|---|---|
| 回転方向の反転 | 全種類 | しない |
| 電流の上限 | 全種類 | 基板のハードウェアの上限 |
| 停止時の止め方（空転／ブレーキ） | 全種類 | 空転 |
| FB の周期 | — | 100 Hz |
| 減速比、エンコーダの分解能 | 速度、位置 | 基板の既定（出力軸の単位に換算するために使う） |
| 速度ループの PID ゲイン | 速度、位置 | 基板の既定 |
| 位置ループの PID ゲイン | 位置 | 基板の既定 |
| 最高速度、最大加速度 | 速度、位置 | 制限なし |

**要判断 2: 設定値を基板のフラッシュに保存するか。**
- 保存しない: 主制御が、起動するたびに全部送る。大元が主制御だけになり、食い違いが起きない。そのかわり、主制御が送る前は既定値で動く。
- 保存する: 電源を入れた直後から、設定どおりに動く。そのかわり、基板に古い設定が残る危険がある。

→ ~~保存しないをおすすめする~~ → **決定（2026-09-30）: 保存できるものは基板のフラッシュに保存し、基板だけで完結させる。これを既定の動作とする。** 主制御は、必要なら起動時に設定を送って上書きしてよい（起動時に全部送るかどうかは、ID の余裕しだい、とユーザ）。
- 注意: 基板を別のロボットに付け替えると、前のロボットの設定が残る。ライブラリには、設定を読み出して確かめる機能を用意する（3 つ目の型で）。
- 2026-10-02: 保存と「既定に戻す」は ch 単位。動作中の保存は仕様で禁止しない（安全に書けない基板は「今はできない」を返してよい）。詳細は requirements.md の論点の表。
