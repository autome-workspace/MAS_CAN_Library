# NeoPixel の仕様（案 v0.1）

状態: **案**（2026-10-02）。前提は [requirements.md](requirements.md)。

## 前提（ユーザ、2026-10-01〜02）

- NeoPixel（WS2812 など）のデイジーチェーンを CAN に載せたい。ほとんど指令だけ（主制御 → 基板）で、FB は要らない。
- 全画素を毎回送るとバスが重い（60 個を 30 Hz で流すと約 10%）。そこで、**「描き方の命令」を送る**。
- ch の考え方は残す。ch ＝ 列（1 本のデイジーチェーン）。
- 1 列の LED の数は uint8（最大 255 個）で足りる。

## ID

- class 2 に 1 つだけ置く（周期指令の種類 6、`0x240`）。
- FB が無く、送り手は主制御だけなので、ch を data 部に入れても衝突しない。

## data 部

先頭 2 byte は全命令で共通:

| byte | 内容 |
|---|---|
| 0 | bit 5–7: 命令の種類（3 bit、8 種類）<br>bit 4: この命令の後に反映する<br>bit 0–3: 予約 |
| 1 | ch（列の番号） |

- 基板は、変更を裏のバッファに溜め、**反映**で一度に LED へ表示する。描いている途中の半端な状態は見えない。
- LED の位置は 1 始まり。範囲の始め s ＝ 0 は「列の全部」を表す。

## 命令

| 番号 | 命令 | byte 2 以降 | DLC |
|---|---|---|---|
| 0 | 何もしない（反映の bit と組み合わせて、反映だけに使う） | — | 2 |
| 1 | **塗る**: s から t を色 C にする | s、t、R、G、B | 7 |
| 2 | **進める**: s から t の色の並びを n 個ずらす（回す） | s、t、n（int8、符号付き）、w（折り返し点） | 6 |
| 3 | **繰り返す**: n から m の模様を、s から t にかけて複製する | n、m、s、t | 6 |
| 4〜7 | 予約（明るさ、点滅など、時間で変わる効果の候補） | | |

### 進める（回す）と折り返し点

- s から t の範囲の中で、色の並びを n 個ずらす。あふれた色は反対側から戻ってくる（回す）。範囲の外は動かない。
- **折り返し点 w**: 反対側から戻ってくる色を、端からではなく w から取る。ループの長さを L ＝ w − s ＋ 1 とすると、新しい色は次の式で決まる。

  > 新しい色[i] ＝ 古い色[s ＋ ((i − s − n) を L で割った余り)]　（i は s から t）

- 周期の基準になる区間（s から w）を決め、割り切れずに余った部分（w より後ろ）の色も、その基準から計算する、という考え方（ユーザ）。模様の周期が L を割り切っていれば、列の長さが周期の倍数でなくても、端まで崩れずに流れる。
- w ＝ 0 なら w ＝ t、つまり普通に回す。
- 例: 59 個に 3 色を繰り返し、w ＝ 57 で右へ 1 ずつ進めると、59 個全部が崩れずに流れる。
- 理想は、裏で手本の模様を持っておくことだが、今回はそうしない（ユーザ）。

### 使い方の例

| 表示 | 送るもの |
|---|---|
| チームの色で全部を光らせる | 塗る（s ＝ 0、赤）＋反映: 1 フレーム |
| 赤と青を 3 個ずつ交互に並べる | 塗る（1〜3、赤）、塗る（4〜6、青）、繰り返す（1〜6 を 7〜60 へ）＋反映: 3 フレーム |
| その模様を流す | 進める（1〜60、n ＝ 1、w ＝ 60）＋反映: 1 歩ごとに 1 フレーム |

## 未決

1. 指令が途絶えたとき（100 ms）や SYNC が途絶えたとき、LED をどうするか（そのまま／消す／決まった表示にする）。NeoPixel は周期的に送らない使い方が中心なので、そもそも途絶判定を当てはめるか。
2. 設定項目: 列の LED の数、色の並び（RGB／GRB／RGBW）、明るさの上限（電源の容量を超えないため）。
3. 1 枚の基板につなぐ列の本数。
