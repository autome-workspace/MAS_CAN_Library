# 第 1 部 全体

| 項目 | 決まり | 出典 |

| CAN | 通常の CAN（FD ではない）。1 フレーム 8 byte まで | current-v0.md の A を引き継ぐ |
| ID | 11 bit（標準 ID） | id-map-draft.md |
| 速度 | 1 Mbps | requirements.md D7 |
| サンプル点 | 80%。can2040（RP2040 の PIO CAN）だけは 81.25% 固定（1 bit ＝ 32 tq、26 tq 目）を例外として認める | D7 |

## 2. 用語

| 用語 | 意味 |
|---|---|
| 主制御 | 指令を送る側（ESP32 など）。基板 1 台につき指令元は 1 つ。担当を分けた複数の主制御は認める（P2） |
| 基板 | 指令を受け、データを返す側 |
| 種類 | MD、サーボ、汎用出力などの区別 |
| ch | 種類ごとの列ベクトルの番号（0 始まり）。例: MD の ch 5、サーボの ch 3 |
| 束 | 周期指令や汎用入力で、1 フレームにまとめて運ぶ ch の組（MD は 4 ch、サーボは 8 ch、汎用 I/O は 4 ch） |
| slot | 束の中の位置（0 始まり） |
| 焼いた値 | ファームウェアの中の値（それまでの「既定値」） |
| 保存した値 | フラッシュの設定の領域にある値 |
| 今の値 | RAM の値。基板はこれで動く |
| 時刻の欄 | 時刻を載せる共通の 2 byte（§5.4） |

## 3. 基板と ch

- ch は種類ごとの列ベクトル。基板は、その**連続した範囲**を受け持つ入れ物。1 枚の基板が複数の種類の ch を持ってもよい（例: サーボ 8 ch とモーター 4 ch）。
- 基板専用の周期フレームは持たない。生存の確認は ch ごとの FB で代用する。
- 基板の位置は DIP で決める。DIP で決めるのは「主な種類の先頭の ch」だけ。
  - DIP の値 k は 0 から（すべて off で k ＝ 0）。**先頭の ch ＝ k × 基板の大きさ**（基板の大きさ ＝ その基板が受け持つ ch の数）。
  - 他の種類の ch の範囲は、基板の種類ごとに決まった規則で計算する。規則は基板の性質なので、ファームウェアが持つ。
  - DIP の bit 数はプロトコルでは決めない。推奨は「その種類の最大の ch 数を基板の大きさで割った区画を、すべて指せる bit 数」（MD の 32 ch なら、1 ch の基板で 5 bit、4 ch の基板で 3 bit）。実際の bit 数は基板ごとの資料に書く。
  - DIP を読む時点と、範囲外の値の扱いは書かれていない（→ 確認 Q24）。
- ch の受け持ちは重複しない前提。重複は設定の項目 0（固有 ID）で見つける。
- **基板から送る束（汎用入力）は、1 枚の基板がまるごと受け持つ**。2 枚の基板が同じ ID で送ると衝突するため。指令の束は、複数の基板が別々の ch を読んでよい。
- 番号の計算: フレーム番号 ＝ ch ÷ 束の大きさ（切り捨て）、slot ＝ ch を束の大きさで割った余り、ch ごとの ID ＝ 基点 ＋ ch。

## 5. 共通の規則

### 5.1 E-stop と解除

**E-stop**（`0x000`）

- 受信側は DLC を問わない。中身は見ない。
- 受けた基板は、種類ごとに決めた動作をしてラッチする（MD は §7.4、サーボは §8）。ToF は何もしない。汎用出力と NeoPixel は未決。

**E-stop の解除**（`0x001`、DLC 3）

| byte | 内容 |
|---|---|
| 0 | `0x63`（`c`） |
| 1 | `0x6C`（`l`） |
| 2 | `0x72`（`r`） |

- 署名が一致しないものは捨てる。DLC が 3 でないものの扱いは書かれていない（→ 確認 Q16）。
- ラッチは、解除か電源の再投入で解ける。解除の後の動きは（→ 確認 Q12）。

### 5.2 SYNC（`0x002`）

| byte | 内容 |
|---|---|
| 0–3 | 主制御の起動からの経過時間（uint32、µs、約 71 分で一周） |

- DLC は書かれていない（4 と読める。→ 確認 Q15）。
- **必須**。指令を送るもの（主制御でも PC のデバッグツールでも）は、必ず送る。周期は **20 Hz**。担当を分けた複数の主制御があるときは、そのうち 1 台（時刻の親）だけが送る。
- 主制御は、時刻をドライバに渡す直前（`twai_transmit` を呼ぶ直前）に取る。
- 基板の規則:
  - 最初の SYNC を受けるまでは、SYNC の途絶判定は働かない。時刻の欄には「同期していない」印を付ける。
  - 最初の SYNC を受けてからは、**250 ms** 届かなければ出力を止める（ラッチしない）。この判定は電源を切るまで有効のまま。
  - 時刻は、SYNC を受けた瞬間の自分の時計との差から換算する。周波数のずれも推定して補正する。遅れは必ず正なので、遅れの少ないもの（下側の包絡）を重く見る推定にする。
  - SYNC が途絶えても、補正を続けたまま時刻を出す。**数秒**途絶えたら「同期していない」扱いにする（秒数は未決。→ 確認 Q25）。

### 5.3 起動の知らせ（`0x010` ＋ 種類の番号）

- **DLC 0**。
- **全種類**の基板が、起動したときに 1 回だけ、受け持つ種類ごとに 1 本ずつ送る（CAN-Servo ならサーボとモーターの 2 本）。MD は `0x010`。
- 意味は「この種類のどれかの基板が再起動した」。どの基板かは分からない。中身を空にしたのは、同じ種類の基板が同時に起動しても衝突しないため（まったく同じフレームは 1 本として届く）。
- 送る時点（設定を受け付けられるようになってからか）は書かれていない（→ 確認 Q21）。
- 再起動の扱いの全体は §6.8。

### 5.4 時刻の欄（2 byte、big-endian）

| bit | 内容 |
|---|---|
| 15 | 同期している（1 ＝ 時刻が有効） |
| 0–14 | 同期した時刻の下位 15 bit（µs。約 32.8 ms で一周） |

- 「同期していない」は、まだ同期していない場合と、同期が落ちた場合の両方。
- 主制御は、受信時刻から過去側へ戻す一方向の計算で元の時刻を戻す。遅延が約 32 ms 未満なら正しく戻る。
- 使う種類: 汎用入力、ToF、エンコーダ。MD の FB には載せない。

### 5.5 周期指令（class 2）の共通の規則

- 1 フレームが 1 束を運ぶ。ch n は、フレーム番号 `n ÷ 束の大きさ` の slot `n % 束の大きさ` に入る。
- 同じフレームに入る ch では、指令の種類を混ぜない。
- **使っていない slot には、その種類の「止める値」を入れる**（MD の電流・速度・duty と汎用出力は 0、MD の位置は `0x8000`、サーボは 255）。
- 後ろの slot が使われていなければ、DLC を縮めてよい。
- **受け手は、自分の slot が DLC の外なら、その ch は指令を受けていない扱いにする**（何もせず、途絶の時計は進み続ける）。奇数の DLC で slot が半端なときも、欠けた slot だけを受けていない扱いにし、そろっている slot は有効にする（D9。class 2 の全種類で共通）。
- DLC を縮めるのは送り手の任意。主制御が知る必要があるのは「自分がどの ch に指令しているか」だけで、バスにどの基板がいるかは知らなくてよい。常に DLC 8 で止める値を詰めて送っても正しい。
- **ch ごとの指令の途絶判定は 100 ms**。NeoPixel だけは途絶判定が無い。
- 途絶判定（100 ms）と SYNC の途絶判定（250 ms）は両方とも持つ。SYNC だけでは、時刻の親でない主制御が落ちたことが分からないため。
- 送る周期（ライブラリ）: MD の指令 100 Hz、サーボ 50 Hz（D5）。汎用出力は未決。

### 5.6 FB の状態の bit 0

- 状態の byte（または bit）を持つ周期データでは、「**基板に異常あり**」を全種類で共通の意味にする: MD の FB の byte 0 bit 0、汎用入力の byte 0 bit 0、エンコーダの byte 0 bit 0、コントローラのボタンの bit 13。
- 立ったら、主制御は設定で「異常の詳細」（共通の項目 5）を読む。
- この bit と異常の詳細の関係（詳細のどれかの bit が立っていれば立てる、でよいか）は、再起動の場合しか書かれていない（→ 確認 Q6）。
- ToF のフレームには、この bit が無い（→ 確認 Q30）。

### 5.7 分割の共通の見出し（流しっぱなし）

1 フレームに収まらないデータを、同じ ID のフレームを続けて送って運ぶ形式。class ではない。使うのはコントローラの文字（class 5）だけ。ToF は専用の形式、NeoPixel は使わない。

| byte | 内容 |
|---|---|
| 0 | bit 7: 最後のフレーム<br>bit 5–6: メッセージの通し番号（0〜3 で折り返す）<br>bit 0–4: メッセージ内のフレーム番号（0〜31） |
| 1–7 | データ |

- 1 メッセージは最大 32 フレーム × 7 byte ＝ 224 byte。
- 受け手は、1 フレームでも欠けたらそのメッセージを捨てる。保証するのは「化けない」ことだけ。
- 受け手が送り手を待たせる仕組みは持たない（それが要るファームウェアの書き込みは ISO-TP、class 7）。

## 6. 設定（class 4）

### 6.1 何をする仕組みか

- 基板の「ロボットごとに変わる値」を読む、書く、フラッシュに保存する、初期化する（焼いた値に戻す）。
- 命令（位置の原点、再起動、ToF の開始と停止など）は「書くと動作する項目」として送る。
- 基板の情報（固有 ID、種類、版など）を問い合わせる。

### 6.2 値の決まり方（P9、P10）

- 基板の値は 2 種類。**基板の性質**（ピンの能力、複数の種類の ch 範囲の規則など）はファームウェアに固定する。**ロボットごとに変わる値**は、すべて「焼いた値 → 保存した値 → 主制御からの上書き」の順で決まる。後者で「ファームウェアに固定」「主制御だけが持つ」という例外は作らない。
- 起動すると、保存した値があればそれを、なければ焼いた値を今の値にする。
- 項目は「事実」と「選択」に分ける。**事実**（つながっている機器とその取り付け方）は保存できる。**選択**（主制御のプログラムがどう使いたいか）は保存できない。起動すると必ず焼いた値に戻り、主制御が毎回送る。

### 6.3 フレーム

`ID ＝ 0x400 ＋ 種類の番号 × 16 ＋ 向き × 8`

| ID の bit | 内容 |
|---|---|
| 10–8 | class 4（`100`） |
| 7–4 | 種類の番号（§4.2） |
| 3 | 向き: 0 ＝ 要求（主制御 → 基板）、1 ＝ 応答（基板 → 主制御） |
| 2–0 | 予約（0） |

MD なら要求 `0x400`、応答 `0x408`。

data 部（DLC 8。短いものの扱いは → 確認 Q17）:

| byte | 要求 | 応答 |
|---|---|---|
| 0 | ch の番号（0〜255） | 同じ |
| 1 | bit 6–7: 操作<br>bit 0–5: 0 | bit 6–7: 操作<br>bit 0–5: 結果 |
| 2 | 設定項目の番号（保存と初期化では範囲） | 同じ |
| 3–6 | 値（big-endian） | 今の値 |
| 7 | 通し番号 | 同じ |

- 宛先は「種類（ID）＋ ch の番号（byte 0）」で、ch 1 つを指す。基板は種類でハードウェアのフィルタを掛け、ch はソフトウェアで見る。
- **応答するのは、その ch を受け持つ基板だけ**。だから応答は衝突しない。受け持たない ch 宛ての要求には何も返さない。
- 束ごとの設定（汎用入力の送る周期など）は、束の先頭の ch を宛先にする。
- 中身が全部 0 のフレームは「ch 0 の項目 0（確認）を読む」になる。読むだけなので何も変わらない。
- 主制御は、応答を受けてから次の要求を送る（1 つずつ）。応答は通し番号で対応づける。応答が来なければ、その ch を受け持つ基板がいない（または落ちている）。
- 応答にかかる時間: 読む・書くはすぐ。保存と初期化は書き終えてから（数十 ms かかることがある。STM32F0 でページの消去に 20〜40 ms）。ライブラリの応答待ちはそれより長く取る。

### 6.4 操作

| 番号 | 操作 | byte 1（要求） | 動き |
|---|---|---|---|
| 0 | 読む | `0x00` | 今の値を返す |
| 1 | 書く | `0x40` | すぐ反映し、反映後の値を返す。動作中に書いてよいかは主制御の責任 |
| 2 | 保存 | `0x80` | 範囲内の、保存できる項目の今の値をフラッシュに書く。保存できない項目は書かない。書き終えてから応答する |
| 3 | 初期化 | `0xC0` | 範囲内の保存した値を消し、今の値も焼いた値に戻す（工場出荷に戻すのと同じ）。書き終えてから応答する |

保存と初期化の範囲（byte 2）:

| 値 | 範囲 |
|---|---|
| 0 | その ch だけ |
| 1 | その ch を受け持つ基板の全 ch |

- 0 と 1 以外の値の扱い、初期化で保存できない項目も焼いた値に戻るかは書かれていない（→ 確認 Q20）。
- 基板は、保存を頼まれたら動作中でも書く。書いている間に制御が止まるかは、基板ごとの資料に書く。
- 実装の手引き: 基板は保存した値の写しを RAM に持ち、宛先の分だけ更新してから写し全体をフラッシュに書く。

### 6.5 結果

| 番号 | 意味 | 例 |
|---|---|---|
| 0 | 成功 | |
| 1 | 知らない項目 | その種類に無い番号 |
| 2 | その操作はできない項目 | 読み出し専用に書いた。命令を読んだ |
| 3 | 範囲外 | 電流の上限に負の値を書いた |
| 4 | 実現できない | PWM を出せないピンに PWM 出力モードを設定した |
| 5〜62 | 予約 | |
| 63 | その他の失敗 | 基板に固有の理由。フラッシュへの書き込みの失敗を含む |

- 基板は「項目がある → その操作ができる → 値が範囲内 → 実現できる」の順に確かめ、最初に引っかかったところの番号を返す。
- 失敗したときの応答の値の欄には、変わっていない今の値を入れる。
- 命令の応答、保存と初期化の応答の値の欄に何を入れるかは書かれていない（→ 確認 Q18）。

### 6.6 設定項目の番号と性質

| 範囲 | 中身 |
|---|---|
| 0〜31 | 全種類に共通 |
| 32〜127 | 種類ごと。その種類のどの基板でも同じ意味を持つ項目だけ |
| 128〜255 | 基板固有。意味は基板ごとの資料に書く。基板の種類（項目 1）が違えば、同じ番号でも意味が違う |

項目ごとに、一覧の表で次を決める。**性質は番号に持たせない**。

| 性質 | 選択肢 |
|---|---|
| 型 | int32、uint32、float32（big-endian）。周期、電流、カウント数は整数。桁が大きく変わる値（PID ゲインなど）だけ float32 |
| 読み書き | 読み書きできる、読み出し専用、命令 |
| 保存 | できる（事実）、できない（選択）。命令と読み出し専用には関係ない |
| ほか | 単位、既定値（焼いた値）、範囲 |

### 6.7 全種類に共通の項目（0〜31）

| 番号 | 項目 | 読み書き | 値 |
|---|---|---|---|
| 0 | 確認 | 読み出し専用 | 固有 ID（下の特別な形） |
| 1 | 基板の種類 | 読み出し専用 | uint32: 上位 16 bit ＝ 基板の種類、下位 16 bit ＝ 基板の版（回路の改版） |
| 2 | ファームウェアの版 | 読み出し専用 | byte 3 ＝ 0、byte 4 ＝ 主、byte 5 ＝ 副、byte 6 ＝ 修正（1.2.3 なら `00 01 02 03`） |
| 3 | プロトコルの版 | 読み出し専用 | 項目 2 と同じ並び |
| 4 | 受け持つ ch の範囲 | 読み出し専用 | byte 3–4 ＝ 先頭の ch（uint16）、byte 5–6 ＝ ch の数（uint16） |
| 5 | 異常の詳細 | 読み書き（1 を書いた bit が消える） | uint32、bit ごと（§6.9） |
| 6 | 再起動 | 命令 | byte 3–5 に `"rst"`（`0x72 0x73 0x74`）を書いたときだけ再起動する |

- 送る周期は共通の項目に入れない（FB を送らない種類があるため）。FB を送る種類ごとの項目にする。

- 項目 6 で、応答を返してから再起動するか、署名が違うときの結果は書かれていない（→ 確認 Q19）。

**項目 0（確認）の応答だけは特別な形**: data 部 8 byte すべてが固有 ID（64 bit）。ch の番号、操作と結果、通し番号の欄は無い（主制御は 1 つずつ要求するので対応づけられる）。

- STM32 の 96 bit の固有 ID は「上位 32 bit と下位 32 bit を XOR して 64 bit に畳む」（どう畳むかの読み方 → 確認 Q13）。
- 重複の検知に使う。同じ ch を受け持つ基板が 2 枚あれば、違う固有 ID の応答が 2 本届く。

**プロトコルの版**: 仕様が固まるまでは 0.x.y。正本の仕様書を出した時点で 1.0.0。仕様書より先にファームウェアを作るなら、その時点の版（例えば 0.9.0）を入れる（→ 確認 Q14）。

| 番号（上位 16 bit） | 基板 |
|---|---|
| `0x0000` | 未登録（予約） |
| `0x0001` | 新しい MD の基板（名前は未定） |

### 6.8 再起動の扱い

基板が静かに再起動すると、保存しない設定が焼いた値に戻る、位置が 0 から始まり直す、保存していない書き込みが消える、NeoPixel の記録が消える。そこで 2 つの仕組みで知らせる。

1. **起動の知らせ**（§5.3）: 全種類が、起動時に種類ごとに 1 本送る。早く気づくための手段。
2. **異常の詳細の bit 0「再起動した」**: 基板は起動したらこの bit を立てる。主制御が 1 を書いて消すまで残り、その間は FB の状態の bit 0（基板に異常あり）を立て続ける。起動の知らせを取りこぼしたときの確実な受け皿。FB のある種類で、どの基板が再起動したかの特定にも使う。

- 再起動したときの処理はライブラリが担う: その種類の全 ch に、保存しない設定（MD なら電流と速度の単位）と NeoPixel の記録を送り直し、bit 0 を消す。電源投入の直後も同じ流れになる。

### 6.9 異常の詳細（項目 5）の bit

| bit | 意味 | 範囲 |
|---|---|---|
| 0 | 再起動した | 全種類共通 |
| 1 | 保存した設定が壊れていたので、焼いた値で起動した | 全種類共通 |
| 2 | CAN のエラーで通信から外れ、復帰した（バスオフからの復帰） | 全種類共通 |
| 3〜7 | 予約 | 全種類共通 |
| 8〜31 | 種類ごと（MD は §7.7） | 種類ごと |

- どの bit も、立ったら主制御が 1 を書いて消すまで残る。異常がまだ続いていれば、消してもすぐまた立つ。
- 測る手段の無い基板は、その bit を立てない。
- 値は BE の uint32（byte 6 が bit 0〜7）。
- FB の無い種類は、起動の知らせを受けたときや必要なときに読みに行く。
- bit 2 は、基板がバスオフから自分で復帰することを前提にしている（→ 確認 Q23）。

# 第 2 部 種類ごと

## 7. モータードライバー（MD）

### 7.1 全体像

- ch はモーターの列ベクトル（0〜31）。基板は連続した ch を受け持つ（1 ch の MD、4 ch の MD、足回りの中継役など）。
- 主制御から見えるのは、**出力軸の単位**の位置と速度、同じ単位の指令だけ。
  - 位置: 出力軸 1 回転 ＝ 65536 カウント。24 bit で折り返す。電源を入れたときは 0。
  - 速度: 出力軸の rpm（LSB は設定 49）。
  - 電流: mA（LSB は設定 48）。
- 主制御は、エンコーダがどこに付いているか（モーター軸か出力軸か）、何の種類か（SPI の絶対角度か ABI か）を知らなくてよい。基板を組んだ人が設定するのは、encoder CPR（36）と gear ratio（37）の 2 つだけ。エンコーダの取り付け位置はプロトコルでは決めない。
- 読み方、周回の数え方、BLDC の転流などは基板の中の話。必要なら基板固有の項目（128〜255）にする。
- 足回りの中継役（RP2040 ＋ C610 など）は「速度の指令を受ける 4 ch の MD」として振る舞う。シリアルサーボも MD として扱う（温度や電圧は設定の読み出しで取る）。

### 7.2 指令（主制御 → MD、class 2）

`ID ＝ 0x210 ＋ 指令の番号 × 8 ＋ フレーム番号`。フレーム番号 ＝ ch ÷ 4、slot ＝ ch % 4。

| 指令の番号 | 指令 | ID |
|---|---|---|
| 0 | 電流 | `0x210`〜`0x217` |
| 1 | 速度 | `0x218`〜`0x21F` |
| 2 | duty | `0x220`〜`0x227` |
| 3 | 位置 | `0x228`〜`0x22F` |

**フレーム**（DLC 2〜8。自分の slot が DLC の外なら受けていない扱い。§5.5）

| byte | 内容 |
|---|---|
| 0–1 | slot 0（ch ＝ フレーム番号 × 4 ＋ 0）、int16 |
| 2–3 | slot 1（＋ 1） |
| 4–5 | slot 2（＋ 2） |
| 6–7 | slot 3（＋ 3） |

**slot の中身**

| 指令 | 値の意味 | 止める値 |
|---|---|---|
| 電流 | int16 × 電流の単位（設定 48、既定 1 mA/LSB で ±32.767 A） | 0 |
| 速度 | int16 × 速度の単位（設定 49、既定 1 rpm/LSB で ±32767 rpm）。出力軸の rpm | 0 |
| duty | 下の bit の割り当て | `0x0000`（duty 0、空転） |
| 位置 | 折り返しの目標位置（下） | `0x8000` |

**duty の bit の割り当て**

| bit | 内容 |
|---|---|
| 0 | 減衰モード（0 ＝ 空転、1 ＝ ブレーキ） |
| 1–15 | 符号付きの duty（±16383 ＝ ±100%） |

- 受け取った側は、slot の値を算術右シフト 1 bit すれば duty になる。
- 「duty 0、ブレーキ」（`0x0001`）が短絡ブレーキ。短絡ブレーキ専用の指令は無い。
- ブレーキは**モーター端子の短絡**（H ブリッジの下側 2 つ、または上側 2 つをオン）。電源の短絡（同じ側の上下を同時にオンにする貫通）ではない。
- −16384（−100% を超える）は範囲外の指令として −100% に飽和させる（§7.4）。

**位置の指令**

- int16 は、目標位置のカウンタ（24 bit）の下位 16 bit とみなす。基板は、基準にいちばん近い候補を目標として選ぶ。基準は**前回の目標**（前回の指令から決めた 24 bit の目標）。ただし、前回の目標が無いか当てにならないとき（位置以外の指令から切り替えた直後、止めた後 ＝ `0x8000`・途絶・E-stop・こなせない指令、原点を書いた後）だけは、測った位置を基準にする（D14）。
- 1 回の指令で動かせるのは ±半回転（±32767 カウント）まで。10 ms ごとに送るなら 3000 rpm に当たる。長い移動は、ライブラリが途中の目標を刻んで送る。
- `0x8000` は「**止める**」。出力を止め、止め方は設定 34（D13）。そのため下位 16 bit が `0x8000` ちょうどの目標は指定できない（主制御は `0x7FFF` か `0x8001` を送る）。
- **その場に留まりたいときは、主制御が FB の位置を具体的な目標として送り続ける**（ライブラリの「今の位置で保持」の API）。止める（ブレーキを含む）は保持ではない。止まった物には力が出ないので、重力のかかる腕は下がる。
- 原点（47）を書いても目標の数字はずらさない（D12）。位置の制御中に書いたら、主制御は次の指令から新しい番号で送る。
- 位置 0 は「位置 0 付近へ動く」で、止める値ではない。

### 7.3 FB（MD → 主制御、class 3）

`ID ＝ 0x320 ＋ ch`。ch ごとに 1 フレーム。

| byte | 内容 |
|---|---|
| 0 | 状態（下の表） |
| 1–2 | 電流（int16、指令と同じ単位）。**電流が無効なら duty** |
| 3–4 | 速度（int16、指令と同じ単位）。**電流が有効で速度が無効なら duty** |
| 5–7 | 位置（24 bit で折り返すカウンタ。出力軸 1 回転 ＝ 65536） |

測れるものによって中身と DLC が変わる（状態の bit 1 と bit 2 で決まる）:

| 測れるもの | bit 1 | bit 2 | byte 1–2 | byte 3–4 | byte 5–7 | DLC |
|---|---|---|---|---|---|---|
| 全部 | 0 | 0 | 電流 | 速度 | 位置 | 8 |
| エンコーダだけ | 0 | 1 | duty | 速度 | 位置 | 8 |
| 電流だけ | 1 | 0 | 電流 | duty | — | 5 |
| 何も無い | 1 | 1 | duty | — | — | 3 |

- duty の形式は指令の duty と同じ（bit 0 が減衰モード）。**実際に出している値**を入れる。
- 値が int16 に収まらないときの扱いは書かれていない（→ 確認 Q8）。

**状態の byte**

| bit | 内容 |
|---|---|
| 0 | 基板に異常あり（全種類で共通の意味。§5.6） |
| 1 | 速度と位置が無効（エンコーダが無い、または異常。中継役なら、下のバスで応答が途絶えた） |
| 2 | 電流が無効（電流を測れない） |
| 3 | 電流の上限に当たっている |
| 4 | 出力を止めている（指令の途絶、SYNC の途絶、E-stop、こなせない指令、位置の止める値 `0x8000` のどれか） |
| 5 | E-stop でラッチしている |
| 6–7 | 今従っている指令の種類（0 電流、1 速度、2 duty、3 位置） |

- 起動直後（指令をまだ受けていない）の bit 4 と bit 6–7 の値は書かれていない（→ 確認 Q7）。

**送るタイミング**

- 電源が入った後、**指令が来ていなくても**周期的に送る。何も測れない基板も送る（生存の確認を兼ねる）。
- 周期は設定 35（既定 100 Hz、0 ＝ 送らない）。

### 7.4 動作の規則

| 場面 | 動作 |
|---|---|
| 電源投入 | 出力は止まっている。最初の有効な指令から、それに従って動く（許可制は無い）。位置は 0 から |
| 指令の種類が変わった | その ch は、最後に受け取った種類に従う。前の種類の制御状態（積分項など）はリセットする |
| 指令の途絶（100 ms）、SYNC の途絶（250 ms） | 出力を止める。止め方は設定 34（空転かブレーキか、既定は空転）。ラッチしない。状態の bit 4 を立てる |
| E-stop | 出力を止めてラッチする。止め方は**常に空転**（駆動電源が切れる前提と合わせる）。状態の bit 4 と bit 5 を立てる。解除は `0x001` か電源の再投入 |
| 範囲外の指令 | 基板の上限（設定またはハードウェア）で飽和させる。電流の上限に当たったら状態の bit 3 を立てる |
| 最高速度・最大加速度 | 速度と位置の制御で、目標へ向かう動きを常にこの制限の中に収める。主制御が細かく目標を送れば安全の上限として、大まかに送れば台形の動きになる |
| 位置の指令の `0x8000` | 出力を止める。止め方は設定 34。状態の bit 4 を立てる（D13） |
| こなせない指令 | エンコーダが無い（または壊れた）基板への速度・位置の指令、電流を測れない基板への電流の指令は、受けたらすぐ出力を止める。止め方は設定 34。状態の bit 4 を立て、bit 6–7 は受け取った種類を示す。理由は bit 1、bit 2 から読む（D10） |
| 異常の詳細の bit 8〜13 | 立てることだけが決まっている。そのときの動作は書かれていない（→ 確認 Q9） |

### 7.5 制御

- **速度ループの出力は、基本は電流**（電流ループの外側に速度ループを置く）。電流を測れない基板だけ、速度ループの出力が duty になる。
- 位置ループの出力は速度（位置 → 速度 → 電流の縦続）。
- **PID ゲインの単位は、FB と同じ値の上で決める**（電流と速度の単位の設定 48、49 にはよらず、物理の単位）:

| ループ | 誤差 | 出力 | Kp の単位 |
|---|---|---|---|
| 速度ループ | 出力軸の rpm | mA | mA/rpm |
| 位置ループ | 出力軸のカウント（1 回転 ＝ 65536） | 出力軸の rpm | rpm/カウント |
| 速度ループ（電流を測れない基板） | 出力軸の rpm | duty（±16383 ＝ ±100%） | duty/rpm |

- Ki は Kp に「/s」、Kd は Kp に「×s」を付けた単位。
- 実装の手引き: 換算はサンプルごとに足していくと丸めの誤差が積み重なる。通算のカウントからまとめて換算する。
- 原点出しの手順（リミットスイッチに当てるまで動かす、など）は主制御が行う。基板が持つのは「今の位置を N とみなす」命令（47）だけ。「原点が未設定」の bit は無い。

### 7.6 設定項目（種類の番号 0。要求 `0x400`、応答 `0x408`）

すべて ch ごと。既定値（焼いた値）は md-draft.md §5 から。B1 の表には既定値と範囲の列が無い（→ 確認 Q10）。

| 番号 | 項目 | 読み書き | 型・単位 | 既定 | 保存 |
|---|---|---|---|---|---|
| 32 | 回転方向の反転 | 読み書き | uint32（0/1） | 0（しない） | できる |
| 33 | 電流の上限 | 読み書き | uint32、mA | 基板のハードウェアの上限 | できる |
| 34 | 止めたときの止め方 | 読み書き | uint32（0 空転、1 ブレーキ） | 0（空転） | できる |
| 35 | FB の周期 | 読み書き | uint32、Hz（0 ＝ 送らない） | 100 | できる |
| 36 | エンコーダ 1 回転のカウント数（encoder CPR） | 読み書き | uint32 | 基板の既定 | できる |
| 37 | エンコーダの軸から出力軸までの減速比（gear ratio） | 読み書き | float32 | 1 | できる |
| 38 | エンコーダの向きの反転 | 読み書き | uint32（0/1） | 書かれていない | できる |
| 39〜41 | 速度ループの Kp、Ki、Kd | 読み書き | float32（§7.5 の単位） | 基板の既定 | できる |
| 42〜44 | 位置ループの Kp、Ki、Kd | 読み書き | float32（§7.5 の単位） | 基板の既定 | できる |
| 45 | 最高速度 | 読み書き | uint32、出力軸の rpm（0 ＝ 制限なし） | 0 | できる |
| 46 | 最大加速度 | 読み書き | uint32、rpm/s（0 ＝ 制限なし） | 0 | できる |
| 47 | 原点 | 命令 | int32（今の位置をこの値とみなす） | — | — |
| 48 | 電流の単位 | 読み書き | float32、mA/LSB（正の値） | 1.0 | **できない** |
| 49 | 速度の単位 | 読み書き | float32、rpm/LSB（正の値） | 1.0 | **できない** |

- **32 と 38 は別物**。38 はモーターの駆動とエンコーダのカウントの符号をそろえる（狂うと速度ループが暴走する）。32 は主制御の「正」が機構のどちら向きかを決め、駆動と FB の符号を両方とも反転させる。設定の順番は 38 → 32。BLDC のように向きが転流と一体の基板は、38 に「4 実現できない」を返し、基板固有の項目で扱う。
- 36 は 4 逓倍した後の数（CPR）。AMT10x の「2048 PPR」なら 8192。
- 37 は「エンコーダが何回転すると出力軸が 1 回転するか」（M3508 なら 3591/187 ≈ 19.2032）。エンコーダが出力軸なら 1。
- 33、45、46、PID ゲインは、48、49 によらず物理の単位。
- 48、49 は、LSB の大きさそのもの。基板は正の値かだけを確かめ、そのまま換算に使う。指令と FB の両方に効く。保存できない（主制御がこの値を前提にフレームを読む「選択」）。**ライブラリと PC のツールは、指令を送る前に必ず書く**。DBC は既定の単位で表示する（単位を変えた ch は表示がずれる。受け入れる）。
- 47 の int32 と 24 bit のカウンタの関係は（→ 確認 Q11）。

### 7.7 MD の異常の詳細（項目 5 の bit 8〜）

| bit | 意味 |
|---|---|
| 8 | 過電流（ハードウェアの保護が働いた） |
| 9 | 過熱 |
| 10 | 電源電圧の低下 |
| 11 | 電源電圧が高すぎる（回生など） |
| 12 | エンコーダの異常（読めない、値が飛んだ） |
| 13 | ゲートドライバの異常（フォルト信号） |
| 14〜31 | 予約 |

- 電流の上限に当たったことは FB の状態の bit 3 で見えるので、ここには入れない。

### 7.8 MD のファームウェアが実装するもの（第 1 部から）

- §1 のビットタイミング（SJW は取れる最大）。
- class 0: E-stop（`0x000`）、解除（`0x001`）、SYNC（`0x002`）の受信。起動の知らせ（`0x010`）の送信。
- class 2: `0x210`〜`0x22F` の受信（受け持つ ch のフレームだけ）。
- class 3: `0x320 ＋ ch` の送信。
- class 4: `0x400` の受信、`0x408` の送信。共通の項目 0〜6 と MD の項目 32〜49。保存と初期化（フラッシュ）。
- DIP からの先頭の ch の計算。

## 8. サーボ

**指令**（class 2、`0x230`〜`0x237`。束は 8 ch、最大 64 ch）

| byte | 内容 |
|---|---|
| 0〜7 | slot 0〜7（ch ＝ フレーム番号 × 8 ＋ slot）、各 1 byte |

| 値 | 意味 |
|---|---|
| 0〜200 | パルス幅 ＝ 500 ＋ 値 × 10 µs（500〜2500 µs） |
| 201〜254 | 予約（受け取ったら 255 と同じく止める） |
| 255 | パルスを止める（使っていない slot にも入れる） |

- 基板は、ch ごとの設定（32、33）でパルス幅を制限する。
- 送る周期は 50 Hz。後ろが使われていなければ DLC を縮めてよい。
- 角度からパルス幅への換算（反転を含む）はライブラリが行う。FB は無い。

**動作**

| 場面 | 動作 |
|---|---|
| 電源投入 | パルスを出さない。最初の有効な指令から動く |
| 指令の途絶（100 ms）、SYNC の途絶（250 ms） | パルスを止める（無力化）。保持する選択肢は無い |
| E-stop | パルスを止める（ラッチ） |

**設定項目**（種類の番号 1）

| 番号 | 項目 | 読み書き | 型・単位 | 既定 | 保存 |
|---|---|---|---|---|---|
| 32 | パルス幅の下限 | 読み書き | uint32、µs | 500 | できる |
| 33 | パルス幅の上限 | 読み書き | uint32、µs | 2500 | できる |
| 34 | パルスの周期 | 読み書き | uint32、µs | 20000（50 Hz） | できる |

- 34 は、同じ PWM の組（RP2040 のスライス、STM32 のタイマー）の ch で共有される。1 つの ch に書くと、同じ組のほかの ch も変わる。組の分け方は基板ごとの資料に書く。
- サーボ基板は、汎用 I/O 基板とは分ける（電力が違いすぎるため）。

## 9. 汎用出力と汎用入力

- 汎用は「出力／入力 × デジタル／アナログ」の 4 通り。通信では、デジタルをアナログの 0 と 255 に丸め込み、フレームは「汎用出力」と「汎用入力」の 2 種類にする。デジタルかアナログかは、ピンごとのモードで決まる。
- 束は 4 ch。出力と入力で同じピンを指すように、ピン番号を出力の ch と入力の ch の両方に同じ番号で割り当てる。DIP で k を選ぶと、出力の束 k と入力の束 k を同時に受け持つ。最大はそれぞれ 32 ch。
- 1 つのファームウェアで作る（実質的に CAN 越しの pinMode、write、read）。小電力用。
- エアーの電磁弁はデジタル出力の一用途。

**汎用出力**（class 2、`0x238`〜`0x23F`、DLC 4）

| byte | 内容 |
|---|---|
| 0〜3 | slot 0〜3、各 uint8（0〜255。デジタル出力は 0 か 255） |

- 止める値は 0。

**汎用入力**（class 3、`0x310`〜`0x317`、DLC 7）

| byte | 内容 |
|---|---|
| 0 | 状態（bit 0 ＝ 基板に異常あり、残りは予約） |
| 1〜4 | slot 0〜3、各 uint8（デジタル入力は 0 か 255） |
| 5–6 | デジタル入力が最後に変化した時刻（時刻の欄。束にデジタル入力のピンが無ければ、同期の bit を 0 にする） |

- チャタリング除去、変化したらすぐ送ること、変化した時刻の記録は基板が行う。変化がなくても一定の周期で送る（周期は未決）。

**能力の問い合わせ**: 読み出し専用の項目「モードごとの対応 ch」で問い合わせる。値の欄（32 bit）の bit n が ch n。基板は自分が受け持つ ch の分だけ bit を立てる。対応できないモードを設定されたら「4 実現できない」を返す。

**未決**: 設定項目の一覧（ピンのモード、プル、反転、チャタリング除去の時間、送る周期、PWM の周波数など。番号を含む）、出力と入力で一覧を共有するか（保留）、途絶時と E-stop のときの出力（途絶時に保持を許すか、保留）。

## 10. ToF

ch ＝ センサ 1 個。設定の種類の番号は 4（マトリクス型）と 5（単点型）。

### 10.1 マトリクス型（VL53L8CX）（class 3、`0x350 ＋ ch`）

1 回の測定を、見出し 1 本とデータ k 本で送る。各データのフレームは単独で使える。

**見出しのフレーム**（DLC 7）

| byte | 内容 |
|---|---|
| 0 | フレーム番号（0） |
| 1 | 測定の回の番号（0〜255 で折り返す） |
| 2–3 | 測った時刻（時刻の欄。測定の中点） |
| 4 | 窓の始めの行（4 bit）、始めの列（4 bit） |
| 5 | 窓の終わりの行（4 bit）、終わりの列（4 bit） |
| 6 | 向き（2 bit: 0°、90°、180°、270°）、解像度（1 bit: 4×4／8×8）、予約 |

**データのフレーム**（フレーム番号 k ＝ 1〜32、DLC 8）

| byte | 内容 |
|---|---|
| 0 | フレーム番号 k |
| 1 | 測定の回の番号 |
| 2–4 | 区画の記録（窓の中の番号で 2k − 1 番目） |
| 5–7 | 区画の記録（2k 番目） |

**区画の記録**（3 byte ＝ 24 bit、big-endian）

| bit | 内容 |
|---|---|
| 12–23 | 距離（mm、0〜4095） |
| 8–11 | target_status（0〜13 はセンサの値そのまま。14 ＝ 空き。15 ＝ ターゲット無し。nb_target が 0 のとき、センサの 255 もこれにする） |
| 0–7 | sigma（mm、255 で頭打ち） |

- 区画の数が奇数のとき、最後のフレームの余った記録の状態に 14（空き）を入れる。
- 送る区画: 向き（取り付けの回転、4 通り）を適用した後の長方形の窓。窓の左上から行の順に 1, 2, 3 … と番号を振る。「1 行だけ」「1 列だけ」は窓の特別な形。区画の番号はセンサの視点（センサから外を見た向き）で数える。
- 主制御は、窓と向きを設定で知っているので、見出しが欠けてもデータのフレームだけで区画を特定できる。フレームが欠けても、その回を丸ごとは捨てない。
- 量: 1 行（8 区画）は 5 本、8×8 は 33 本。

### 10.2 単点型（VL53L1X など）（class 3、`0x358 ＋ ch`、DLC 6）

| byte | 内容 |
|---|---|
| 0–1 | 測った時刻（時刻の欄。測定の中点） |
| 2–3 | 距離（mm、uint16） |
| 4 | range_status（センサの値そのまま） |
| 5 | sigma（mm、255 で頭打ち） |

### 10.3 動作

| 場面 | 動作 |
|---|---|
| 電源投入 | 保存された設定で、自動的に測定を始める |
| 設定の変更 | 基板は測定を止め、設定を反映して再開する |
| 停止、再開、リセット | 設定のフレームの命令で行う |
| SYNC が来ていない | 測定は続ける。時刻の欄の bit 15 を 0 にする |
| E-stop | 何もしない |

**設定**: 保存できないもの（選択）は、解像度、窓、単点型の ROI（大きさと中心）。保存できるもの（事実）は、向き、測定の周期、積分時間など。

**未決**: 設定項目の一覧と番号、診断用の出力の形式（signal、ambient、SPAD 数などを診断モードのときだけ送る）、見出しの byte 4–6 の bit の位置と行・列の数え方（→ 確認 Q29）。

## 11. コントローラ

**状態**（class 3、`0x340 ＋ ch`、DLC 8）

| byte | 内容 |
|---|---|
| 0 | 左スティック x（int8、−127〜+127、右が正） |
| 1 | 左スティック y（int8、上が正） |
| 2 | 右スティック x（int8） |
| 3 | 右スティック y（int8） |
| 4 | トリガー L2（uint8、0〜255） |
| 5 | トリガー R2（uint8、0〜255） |
| 6–7 | ボタンと状態（16 bit、下の表） |

| bit | 内容 |
|---|---|
| 0〜3 | 十字キー 上、下、左、右 |
| 4〜7 | 右側のボタン 上（△/Y）、下（×/A）、左（□/X）、右（○/B） |

| 9 | R1 |

- 無線が切れたら、bit 12 を 0 にし、スティックとトリガーを 0、ボタンを全部離した状態にして送る。最後の値を送り続けてはいけない。

**文字**: 双方向。UTF-8 を分割の共通の見出し（§5.7）で送る。上り `0x500 ＋ ch`、下り `0x508 ＋ ch`。

**未決**: 設定項目（種類の番号 6）。

## 12. NeoPixel

`0x240` の 1 つだけ（class 2）。ch ＝ 列（1 本のデイジーチェーン）で、data 部に入れる。**途絶判定も FB も無い**。

| byte | 内容 |
|---|---|
| 0 | bit 5–7: 命令の種類<br>bit 4: この命令の後に反映する<br>bit 0–3: 予約 |
| 1 | ch（列の番号） |
| 2〜 | 命令ごと（下の表） |

| 番号 | 命令 | byte 2 以降 | DLC |
|---|---|---|---|
| 0 | 何もしない（反映だけに使う） | — | 2 |
| 1 | 塗る: s から t を色 C にする | s、t、R、G、B | 7 |
| 2 | 進める: s から t の色の並びを n 個ずらす（回す） | s、t、n（int8）、w（折り返し点） | 6 |
| 3 | 繰り返す: n から m の模様を s から t に複製する | n、m、s、t | 6 |
| 4 | 待つ: 再生のときだけ効く | T（10 ms 単位、1〜255） | 3 |
| 5 | 記録: 始める／終える | 始める／終える | 3 |
| 6 | 再生: 覚えた命令を繰り返す。止める指示もこれ | 回数（0 ＝ 止めるまで）、または止める | 3〜4 |
| 7 | 予約 | | |

- LED の位置は 1 始まり。s ＝ 0 は「列の全部」。LED の数の上限は 255。
- 変更は裏のバッファに溜め、反映の bit で一度に表示する。
- 進める: 新しい色[i] ＝ 古い色[s ＋ ((i − s − n) を L で割った余り)]、L ＝ w − s ＋ 1。w ＝ 0 なら w ＝ t。
- 記録中に送った命令はその場でも実行する（「待つ」は記録するだけ）。覚えられるのは 1 列で 32 命令。記録はフラッシュに保存しない。再生中に塗るなどを送ってもよい。
- 色はプロトコル上 RGB の 3 byte。WS2812 の並び（GRB など）への並べ替えは基板の中で行う。明るさの上限は持たない。
- 1 枚の基板につなぐ列の本数はプロトコルでは決めない（基板の資料に書く）。

**未決**: 記録（5）と再生（6）の byte の値、E-stop のときの動作、設定項目の番号（列の LED の数 1〜255 は設定項目と決まっている）。

## 13. エンコーダ

class 3、`0x360 ＋ ch`（ch 0〜7）。DLC 6。設定の種類の番号は 8。

| 0 | 状態（bit 0 ＝ 基板に異常あり、残りは予約） |

| 設定 | 既定 | 保存 |
|---|---|---|
| 1 回転あたりのカウント数 | 基板の既定（AMT10x なら 8192 など） | できる |
| 回転方向の反転 | しない | できる |

**未決**: 設定項目の番号と型。
