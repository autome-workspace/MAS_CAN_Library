# ID の割り振り（叩き台 v0.2）

状態: **議論用の叩き台**。数字はすべて仮。
前提は [requirements.md](requirements.md) を参照。

v0.1 からの変更（2026-09-29）:
- SYNC を追加した。
- モーターの FB の形式を追加した。
- 足回りの中継役は新しい ID を使わない。
- 帯 4 を基板ごとの問い合わせと応答に割り当てた。
- 使っていない slot の規則を追加した。

## 考え方

- 11 bit の ID を、**上位 3 bit の「帯」**で大きく分ける。CAN では ID が小さいほど優先度が高いので、帯の順番がそのまま優先度の順になる。
- 帯の中は、**種類と番号**で分ける。
- ch は種類ごとの列ベクトルと考える。基板は、その連続した範囲にまたがる入れ物になる。
- DJI（C610 など）の固定 ID は、帯の切れ目にちょうど収まるので、そのまま予約する。
- 空きは多めに残す。

## 帯の割り振り

| 帯 | 範囲 | 用途 | 優先度 |
|---|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期 | 最高 |
| 1 | `0x100`〜`0x1FD` | 周期指令（主制御 → 基板） | 高 |
| — | `0x1FE`〜`0x20F` | **DJI 用に予約**（指令 `0x1FE`/`0x1FF`/`0x200`、FB `0x201`〜`0x20B`） | — |
| 2 | `0x210`〜`0x2FD` | 周期データのうち、時刻が重要なもの（ToF など） | 中の上 |
| — | `0x2FE`〜`0x2FF` | **DJI 用に予約**（GM6020 の指令） | — |
| 3 | `0x300`〜`0x3FF` | 周期データ（通常）: モーターの FB、コントローラ | 中 |
| 4 | `0x400`〜`0x4FF` | 個別のやりとり（基板ごとの問い合わせと応答） | 低 |
| 5 | `0x500`〜`0x5FF` | 予約 | — |
| 6 | `0x600`〜`0x6FF` | **自作フレーム**（利用者が自由に使う。D4） | 低 |
| 7 | `0x700`〜`0x7FF` | 予約（デバッグ用など） | 最低 |

## 帯 0: 安全と同期

| ID | 内容 | 状態 |
|---|---|---|
| `0x000` | E-stop。受信側は DLC を問わない | 決定 |
| `0x001` | E-stop の解除 | 決定（署名を付けるかは検討中） |
| `0x002` | SYNC（時刻の同期と、主制御の生存確認）。中身は主制御の起動からの経過時間（32 bit、µs）。20 Hz で送る。基板は周波数のずれも推定して補正する。250 ms 届かなければ出力を止める | 決定 |
| `0x003`〜`0x0FF` | 予約 | |

## 帯 1: 周期指令

`ID = 0x100 | (種類 << 3) | フレーム番号` とする。1 つの種類につき 8 フレーム分の枠を取る。

| 種類 | ID | 1 slot の中身 | 1 フレームの ch 数 | 最大 ch 数 |
|---|---|---|---|---|
| 0: 電流 | `0x100`〜`0x107` | int16、2 mA/LSB | 4 | 32 |
| 1: 速度 | `0x108`〜`0x10F` | int16、出力軸の 1 rpm/LSB（決定） | 4 | 32 |
| 2: duty | `0x110`〜`0x117` | int16。1 bit が減衰モード（ブレーキ／空転）、残りが符号付きの duty | 4 | 32 |
| 3: 位置 | `0x118`〜`0x11F` | int16、範囲に対する割合。実際の範囲は基板の設定に持たせる | 4 | 32 |
| 4: サーボ | `0x120`〜`0x127` | 1 byte（500 ＋ 値 × 10 µs、255 で停止） | 8 | 64 |
| 5: デジタル出力（エアー、リレー、LED など） | `0x128`〜`0x12F` | 1 bit（提案） | 64 | 512 |
| 6: 汎用 duty（PWM 出力、案） | `0x130`〜`0x137` | uint16、0〜100% | 4 | 32 |
| 7〜 | `0x138`〜`0x1FD` | 予約（将来用） | — | — |

規則:
- ch n（1 始まり）が入るフレーム番号は `(n - 1) / 4`（サーボは `/ 8`）。
- **同じフレームに入る ch では、指令の種類を混ぜない。** 使っていない slot には、その種類の「止める値」を入れる（電流・速度・duty・汎用出力は 0、位置は `0x8000`、サーボは 255）。
- 後ろの slot が使われていなければ、DLC を縮めてよい。自作の基板は、短い DLC も受け付ける。
- 足回りの中継役（RP2040 と C610）は、主バスから見ると「速度の指令を受ける 4 ch の MD」なので、種類 1 をそのまま使う。

## 帯 2: 時刻重視の周期データ

| ID | 内容 |
|---|---|
| `0x210`〜`0x217` | ToF（マトリクス型）ch 1〜8 |
| `0x218`〜`0x21F` | ToF（単点型）ch 1〜8 |
| `0x220`〜`0x2FD` | 予約 |

- 1 回の測定が複数のフレームに分かれる場合は、同じ ID で続けて送る。中身に通し番号を持たせる（形式は後で決める）。
- 時刻は、共通の時刻の欄（2 byte。bit 15 ＝ 同期している、bit 0–14 ＝ 同期した時刻の下位 15 bit）を先頭のフレームに載せる。

## 帯 3: 通常の周期データ

| ID | 内容 |
|---|---|
| `0x300`〜`0x31F` | モーターの FB（ch 1〜32）。指令の種類に関わらず、ch ごとに 1 つの ID |
| `0x320`〜`0x323` | コントローラ ch 1〜4。周期は、送り手のコントローラ基板が決める |
| `0x324`〜`0x3FF` | 予約 |

モーターの FB の形式（8 byte）:

| byte | 内容 |
|---|---|
| 0–1 | 速度（int16、出力軸の 1 rpm/LSB） |
| 2–3 | 電流（int16、2 mA/LSB） |
| 4 | 状態。1 bit が「基板全体に異常あり」。他に、電流の上限に当たった、下のバスが途絶えた、など |
| 5–7 | 位置。24 bit で折り返すカウンタ。出力軸 1 回転 ＝ 65536 カウント |

- 既定の周期は 100 Hz で、設定で変えられる。
- 基板の生存は、この FB が届いているかどうかで判断する（基板専用の周期フレームは持たない）。

## 帯 4: 個別のやりとり

- 基板ごとに、問い合わせ用と応答用の ID を 1 組持つ。
  - 問い合わせ: `0x400 + 基板の識別番号`
  - 応答: `0x480 + 基板の識別番号`
- 基板の識別番号は、「主な種類と DIP の値（主な種類の先頭 ch）」から計算する。案は次のとおり。

| 識別番号 | 主な種類 | 計算 |
|---|---|---|
| 0〜31 | モーター | 先頭 ch − 1 |
| 32〜39 | サーボ | 32 ＋ (先頭 ch − 1) / 8 |
| 40〜47 | エアー | 40 ＋ (先頭 ch − 1) / 8 |
| 48〜55 | ToF（マトリクス型） | 48 ＋ ch − 1 |
| 56〜63 | ToF（単点型） | 56 ＋ ch − 1 |
| 64〜67 | コントローラ | 64 ＋ ch − 1 |
| 68〜127 | 予約 | |

- 用途は、設定値の送信（中継役の上限、ToF の解像度と行の選択など）、開始やリセット、種類と版の問い合わせ、異常の詳細の問い合わせ。
- 手順とデータを分割して送る方法は後で決める。

3. エアーを 1 bit ずつにするか、1 byte ずつにするか。
4. 自作フレームの帯を、自作の優先度に合わせて複数の帯に分ける必要はあるか。

6. 4 ch 基板の DIP の意味。先頭 ch をそのまま設定するのか、4 ch 単位で設定するのか（DIP の bit 数に関わる）。

## 残りの論点への提案（2026-09-30）

| # | 論点 | 提案 | 理由 |
|---|---|---|---|
| 2 | ToF とモーターの FB の優先度 | 今のまま（ToF が上） | モーターのループは MD の中で閉じるので、主制御がモーターの FB を使うのはスリップの検知とテレメトリだけで、急ぐ必要がない。ToF の時刻は SYNC で確保するので、優先度はどちらでも大差ない |
| 3 | デジタル出力（エアーを含む）の形式 | **1 bit ずつ、1 フレームで 64 ch**。後ろが空いていれば DLC を縮める | on/off だけなら 1 bit で足りる。明るさなど中間の値が要る出力は、別の種類として足す |
| 3' | デジタル出力が途絶したとき | 基板の設定で「途絶時の状態」を決める（既定は off） | 弁やリレーは、off が安全とは限らない（ばね戻りの有無などで変わる） |
| 4 | 自作フレームの優先度 | 帯 6 の 1 つだけにする | 高い優先度が要る用途が出てきたら、それは自作ではなく仕様に種類として加える |
| 6 | 4 ch 基板の DIP の意味 | **DIP の値 k は「その基板の大きさの k 番目の区画」**とする。4 ch 基板で k=2 なら ch 5〜8。1 ch 基板で k=2 なら ch 2 | DIP の bit 数を最小にできる。3 bit なら、4 ch 基板で 32 ch 分、1 ch 基板で 8 ch 分を指せる。1 ch の MD で 32 ch まで使いたいなら、DIP は 5 bit 必要（ハードウェアの選択） |

### 新しく足す入力の種類（提案）

**基板から送る周期データを複数 ch 分まとめて 1 フレームにする場合、そのフレームは 1 枚の基板がまるごと受け持つ（規則）。** 2 枚の基板が同じ ID で送ると衝突するため。この規則は、送り手が複数になりうるセンサ系に特有のもの。

| 種類 | 帯 | ID | 1 フレームの ch 数 | 中身 | 送るタイミング |
|---|---|---|---|---|---|
| デジタル入力（リミットスイッチ、フォトセンサ） | 2（時刻重視） | `0x220`〜`0x23F`（4 ch の束 × 32 = 128 ch） | 4（決定。1 枚の基板が連続した束を複数持ってよいので、12 入力なら 3 束） | **DLC 3**。byte 0 は下位 4 bit が入力、上位 4 bit が状態（bit 4 ＝ 基板に異常あり）。byte 1–2 は最後に変化した時刻（共通の時刻の欄: bit 15 ＝ 同期している、bit 0–14 ＝ 時刻の下位 15 bit） | 変化したらすぐ送る。変化がなくても一定周期（例えば 20 Hz）で送る |
| アナログ入力（ポテンショメータなど） | 3（通常） | `0x324`〜`0x32B`（4 ch の区画 × 8 = 32 ch） | 4 | 4 ch × uint16（フルスケールに対する割合） | 周期送信（既定 100 Hz、設定で変更できる） |

帯 3 のコントローラ（`0x320`〜`0x323`）の直後に置く。

### デジタル入力の設定（提案）

プルアップ・プルダウンなどは、ロボットの配線で変わる。そのため、ch ごとに次の設定を 3 つ目の型で送る（P5 に従い、ファームウェアは書き換えない）。

| 設定 | 選択肢 | 既定 |
|---|---|---|
| プル | 上げる／下げる／なし | 上げる（リミットスイッチを GND に落とす配線が多い。NPN オープンコレクタのフォトセンサにも合う） |
| 反転 | する／しない | しない |
| チャタリング除去の時間 | ms | 例えば 5 ms |

MCU 内蔵のプル抵抗（数十 kΩ）は、長い配線ではノイズに弱い。基板の設計で外付けの抵抗を選べるようにするかどうかは、ハードウェアの判断になる。
