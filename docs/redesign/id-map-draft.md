# ID の割り振り（叩き台 v0.5）

状態: **議論用の叩き台**（2026-10-01 に v0.3 として書き直し、同日 v0.4 に更新。2026-10-02 に v0.5 に更新）。前提は [requirements.md](requirements.md)。
v0.5 の変更（他の文書の決定に合わせただけで、新しい決定は無い）: NeoPixel を「予定」から確定に直し、途絶判定と FB が無いことを書いた。分割の共通の見出しを使うものから NeoPixel を外した（命令は 1 フレームで完結する）。MD の FB と汎用入力の形式の要約を class 3 に加えた。設定の保存と「既定に戻す」が ch 単位であることを class 4 に書いた。
v0.4 の変更: 汎用 I/O を「汎用出力」「汎用入力」の 2 種類（8 bit）に整理した。class 5〜7 の用途を決めた。分割の共通の見出しを加えた。
v0.2 からの主な変更:
- 呼び名を「帯」から **class** に変えた（v0 の呼び名を引き継ぐ）。
- 周期指令を class 2 に移し、class 1 は予約にした。
- ToF とデジタル入力を class 3 の先頭に移した。
- class 4 をすべて設定に使うことにした。

## 考え方

- 11 bit の ID の**上位 3 bit を class** とする。CAN では ID が小さいほど調停に勝つので、**class の番号が小さいほど優先度が高い**。同じ class の中でも、ID が小さい方が優先される。
- class の中は、種類と番号で分ける。
- ch は、種類ごとの列ベクトルで数える。基板は、その連続した範囲を受け持つ。
- DJI（C610 など）の固定 ID は予約し、避けて置く。

## class の割り振り

| class | 範囲 | 用途 |
|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期 |
| 1 | `0x100`〜`0x1FF` | **自作フレーム（高い優先度）**。仮の決定（2026-10-02）。末尾の `0x1FE`〜`0x1FF` は DJI 用 |
| 2 | `0x200`〜`0x2FF` | 周期指令（主制御 → 基板）。NeoPixel もここに置く（`0x240`）。`0x200`〜`0x20B` と `0x2FE`〜`0x2FF` は DJI 用 |
| 3 | `0x300`〜`0x3FF` | 周期データ（基板 → 主制御） |
| 4 | `0x400`〜`0x4FF` | 設定（要求と応答） |
| 5 | `0x500`〜`0x5FF` | 分割（流しっぱなし）のうち、専用の居場所が無いもの（コントローラの文字など） |
| 6 | `0x600`〜`0x6FF` | 自作フレーム |
| 7 | `0x700`〜`0x7FF` | ファームウェアの書き込み（ISO-TP を使う予定。今は予約）。大量に流すので最も低い優先度に置く |

## class 0: 安全と同期

| ID | 内容 |
|---|---|
| `0x000` | E-stop。受信側は DLC を問わない |
| `0x001` | E-stop の解除。DLC 3、署名 `"clr"`（`0x63 0x6C 0x72`）。署名が一致しないものは捨てる |
| `0x002` | SYNC。主制御の起動からの経過時間（32 bit、µs）。20 Hz。必須。基板は 250 ms 届かなければ出力を止める（最初の SYNC を受けてから有効） |
| `0x003`〜`0x00F` | 予約 |
| `0x010`〜`0x01F` | **起動の知らせ**（`0x010` ＋ 種類の番号。種類の番号は class 4 と同じ）。DLC 0。基板は起動したときに 1 回だけ、受け持つ種類ごとに 1 本ずつ送る（2026-10-03、ユーザ） |
| `0x020`〜`0x0FF` | 予約 |

## class 2: 周期指令

`ID = 0x210 + (種類 × 8) + フレーム番号`（DJI の `0x200`〜`0x20B` を避けて、`0x210` から置く）。

| 種類 | ID | 1 ch の中身 | 1 フレームの ch 数 | 最大 ch | 止める値 |
|---|---|---|---|---|---|
| 0: MD 電流 | `0x210`〜`0x217` | int16、既定 1 mA/LSB、設定で自由に変えられる（float32）（ch ごと、保存しない） | 4 | 32 | 0 |
| 1: MD 速度 | `0x218`〜`0x21F` | int16、出力軸の rpm（既定 1 rpm/LSB、設定で自由に変えられる（float32）。ch ごと、保存しない） | 4 | 32 | 0 |
| 2: MD duty | `0x220`〜`0x227` | int16。bit 0 が減衰モード、bit 1–15 が符号付きの duty | 4 | 32 | 0 |
| 3: MD 位置 | `0x228`〜`0x22F` | int16、折り返しの目標位置（出力軸 1 回転 ＝ 65536） | 4 | 32 | `0x8000`（保持） |
| 4: サーボ | `0x230`〜`0x237` | 1 byte、500 ＋ 値 × 10 µs（0〜200。201〜254 は予約で、止める扱い） | 8 | 64 | 255 |
| 5: 汎用出力 | `0x238`〜`0x23F` | uint8（0〜255。デジタル出力は 0 か 255）。DLC 4 | 4 | 32 | 0 |
| 6: NeoPixel | `0x240` | 描き方の命令（ch は data 部の byte 1）。neopixel-draft.md | — | — | なし（途絶判定が無い） |
| 7〜 | `0x241`〜`0x2FD` | 予約 | | | |

- ch n（0 始まり。D8）が入るのは、フレーム番号 `n / 束の大きさ` の、`n % 束の大きさ` 番目の slot（slot も 0 始まり）。
- 同じフレームに入る ch では、指令の種類を混ぜない。使っていない slot には、その種類の止める値を入れる。
- 後ろの slot が使われていなければ、DLC を縮めてよい。
- ch ごとに 100 ms の途絶判定がある。NeoPixel だけは例外で、途絶判定も FB も無い（送り手は主制御だけなので、ch を data 部に入れても衝突しない）。
- 足回りの中継役（RP2040 と C610）は「速度の指令を受ける 4 ch の MD」に見えるので、種類 1 をそのまま使う。

## class 3: 周期データ

| ID | 内容 | 形式 |
|---|---|---|
| `0x300`〜`0x30F` | 予約（v0.4 までの ToF の位置。2026-10-02 に後ろへ移した） | |
| `0x310`〜`0x317` | 汎用入力（4 ch の束 × 8 ＝ 32 ch。デジタル入力とアナログ入力をまとめたもの） | io-draft.md |
| `0x318`〜`0x31F` | 予約 | |
| `0x320`〜`0x33F` | MD の FB（ch 0〜31。ID ＝ `0x320 + ch`） | md-draft.md |
| `0x340`〜`0x347` | コントローラの状態 ch 0〜7 | controller-draft.md |
| `0x348`〜`0x34F` | 予約（v0.3 のアナログ入力は、汎用入力にまとめた） | |
| `0x350`〜`0x357` | ToF（マトリクス型）ch 0〜7 | tof-draft.md |
| `0x358`〜`0x35F` | ToF（単点型）ch 0〜7 | 同上 |
| `0x360`〜`0x367` | エンコーダ ch 0〜7 | encoder-draft.md |
| `0x368`〜`0x3FF` | 予約 | |

- ToF は、時刻が付いていれば遅れてもよいデータなので、MD の FB などの後ろに置く（2026-10-02、ユーザ）。

### MD の FB（要約。詳細は md-draft.md）

| byte | 内容 |
|---|---|
| 0 | 状態（下の表） |
| 1–2 | 電流（int16、既定 1 mA/LSB、設定で自由に変えられる（float32）。指令と同じ）。電流が無効なら duty |
| 3–4 | 速度（int16、出力軸の rpm。既定 1 rpm/LSB、設定で自由に変えられる（float32）。指令と同じ）。電流が有効で速度が無効なら duty |
| 5–7 | 位置（24 bit で折り返すカウンタ。出力軸 1 回転 ＝ 65536） |

- 測れないものが後ろに来るので、DLC を縮める。全部測れるか、エンコーダだけなら DLC 8、電流だけなら DLC 5、何も測れなければ DLC 3。
- duty の形式は指令の duty と同じ。実際に出している値を入れる。

| bit | 状態の内容 |
|---|---|
| 0 | 基板に異常あり（全種類で共通の意味） |
| 1 | 速度と位置が無効 |
| 2 | 電流が無効 |
| 3 | 電流の上限に当たっている |
| 4 | 出力を止めている（指令の途絶、SYNC の途絶、E-stop のどれか） |
| 5 | E-stop でラッチしている |
| 6–7 | 今従っている指令の種類（0 電流、1 速度、2 duty、3 位置） |

### 汎用入力（要約。詳細は io-draft.md）

DLC 7。byte 0 ＝ 状態（bit 0 ＝ 基板に異常あり）、byte 1–4 ＝ 4 ch × uint8（デジタル入力は 0 か 255）、byte 5–6 ＝ デジタル入力が最後に変化した時刻（共通の時刻の欄。束にデジタル入力のピンが無ければ、同期の bit を 0 にする）。

### コントローラの状態（要約。詳細は controller-draft.md）

DLC 8。スティック 4 軸（int8）、トリガー L2・R2（uint8）、ボタンと状態（16 bit。bit 12 ＝ つながっている、bit 13 ＝ 基板に異常あり）。

### 注記

- 時刻の精度は SYNC の時刻の欄で確保するので、汎用入力は class を分けず、class 3 の先頭に置いた。
- まとめて送る束は、1 枚の基板がまるごと受け持つ。

## class 4: 設定

`ID = 0x400 + (種類 × 16) + (向き × 8)`（下位 3 bit は予約で 0。~~束の中の ch~~ は 2026-10-02 にやめた）

| 欄 | 大きさ | 内容 |
|---|---|---|
| 種類 | 4 bit | 下の表 |
| 向き | 1 bit | 0 ＝ 要求（主制御 → 基板）、1 ＝ 応答（基板 → 主制御） |
| 予約 | 3 bit | 0。~~束の中の ch（0〜7）~~ |

種類の番号:

| 番号 | 種類 |
|---|---|
| 0 | MD |
| 1 | サーボ |
| 2 | 汎用出力 |
| 3 | 汎用入力 |
| 4 | ToF（マトリクス型） |
| 5 | ToF（単点型） |
| 6 | コントローラ |
| 7 | NeoPixel |
| 8 | エンコーダ |
| 9〜15 | 予約 |

data 部（DLC 8）:

| byte | 要求 | 応答 |
|---|---|---|
| 0 | **ch の番号**（0〜255。2026-10-03 に 0 始まりへ。~~1〜255、0 は予約~~） | ch の番号 |
| 1 | bit 6–7: 操作（0 読む、1 書く、2 保存、3 初期化 ＝ 焼いた値に戻す）、bit 0–5: 0 | bit 6–7: 操作、bit 0–5: 結果（settings-draft.md の A3） |
| 2 | 設定項目 | 設定項目 |
| 3–6 | 値 | 今の値 |
| 7 | 通し番号 | 通し番号 |

- 要求の宛先は、必ず ch 1 つ。その ch を受け持つ基板だけが応答するので、応答は衝突しない。
- **宛先は「種類（ID）＋ ch の番号（byte 0）」**（2026-10-02、ユーザ）。それまでの「束の番号（byte 0）＋ 束の中の ch（ID）」に割る形は、束の無い種類（ToF、エンコーダ、コントローラ、NeoPixel）で割り方が決まらないのでやめた。基板は、種類でハードウェアのフィルタを掛け、ch はソフトウェアで見る（設定はめったに起きないので負担にならない）。~~中身が全部 0 のフレームは ch 0 宛てになり、どの基板も応答しない~~（2026-10-03 に ch を 0 始まりにしたので、全部 0 のフレームは「ch 0 の項目 0 を読む」になる。読むだけなので何も変わらない）。
- 命令（リセット、ToF の開始、位置の原点など）も、書くと動作する設定項目として扱う。
- 設定項目には「保存できない」という性質を持たせられる。**基準は「事実か選択か」**（2026-10-02）。つながっている機器とその取り付け方という「事実」（減速比、エンコーダの分解能、回転方向、ToF の向きなど）は保存できる。主制御のプログラムがどう使いたいかという「選択」（ToF の窓、解像度、単点型の ROI など）は保存できない。電源を入れると既定値に戻り、主制御が起動時に毎回送る。「保存」の操作では書かれない（2026-10-02）。
- 設定項目 0 は「確認」。読み出すと、data 部 8 byte すべてに固有 ID（64 bit）を入れて返す。重複の検知に使う。
- 応答はすぐに返す。
- 基板は、受け取った値をすぐに反映する。動作中に変えてよいかは、主制御の責任。
- 保存と初期化（2026-10-02 に「既定に戻す」から改名。保存した値を消し、焼いた値に戻す）は ch 単位（2026-10-02）。~~範囲の保存は、ライブラリが ch ごとの要求に分けて送る。基板は、続けて届いた保存をまとめて 1 回で書いてよい。~~
- **範囲として「宛先の ch を受け持つ基板の全 ch」も選べる**（2026-10-02、ユーザ）。保存と初期化では設定項目の欄（byte 2）を範囲に使う: 0 ＝ その ch だけ、1 ＝ その基板の全 ch。応答は、フラッシュに書き終えてから返す（応答の時点で結果が確定する）。詳細は settings-draft.md。
- 動作中の保存は仕様で禁止しない。~~安全に書けない基板は、結果に「今はできない」を返してよい。~~→ **「今はできない」は削除**（2026-10-02、ユーザ）。基板は動作中でも書き、書き終えてから応答する。動作中に書いてよいかは主制御の責任。settings-draft.md

## 分割の共通の見出し（流しっぱなし、決定 2026-10-01）

1 フレームに収まらないデータを、同じ ID のフレームを続けて送って運ぶ。**形式であって class ではない**。コントローラの文字（class 5）が使う。ToF は専用の形式を使う（各フレームを単独で使えるようにするため。tof-draft.md）。NeoPixel の命令は 1 フレームで完結するので使わない。

| byte | 内容 |
|---|---|
| 0 | 見出し: bit 7 ＝ 最後のフレーム、bit 5–6 ＝ メッセージの通し番号（0〜3 で折り返す）、bit 0–4 ＝ メッセージ内のフレーム番号（0〜31） |
| 1–7 | データ |

- 1 つのメッセージは、最大 32 フレーム × 7 byte ＝ 224 byte。
- **受け手は、1 フレームでも欠けたら、そのメッセージを取得できなかった扱いにして捨てる**。化けないこと（別のメッセージのフレームが混ざらないこと）だけを保証する。
- 受け手が送り手を待たせる仕組み（「待て」）は持たない。主制御（ESP32）は割り込みで受信キューに入れるので、制御周期と関係なく受け取れる。ライブラリは受信キューを長くし（例えば 128 本）、受信タスクで常に空にしておく。
- 「待て」が要るのは、小さな基板がフラッシュに書き込むとき（ファームウェアの書き込み）だけ。これは ISO-TP（class 7）で扱う。
