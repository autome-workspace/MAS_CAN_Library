# ID の割り振り（叩き台 v0.3）

状態: **議論用の叩き台**（2026-10-01 に全面的に書き直した）。前提は [requirements.md](requirements.md)。
v0.2 からの主な変更:
- 呼び名を「帯」から **class** に変えた（v0 の呼び名を引き継ぐ）。
- 周期指令を class 2 に移し、class 1 は予約にした。
- ToF とデジタル入力を class 3 の先頭に移した。
- class 4 をすべて設定に使うことにした。

## 考え方

- 11 bit の ID の**上位 3 bit を class** とする。CAN では ID が小さいほど調停に勝つので、**class の番号が小さいほど優先度が高い**。同じ class の中でも、ID が小さい方が優先される。
- class の中は、種類と番号で分ける。
- ch は、種類ごとの列ベクトルで数える。基板は、その連続した範囲を受け持つ。
- DJI（C610 など）の固定 ID は予約し、避けて置く。

## class の割り振り

| class | 範囲 | 用途 |
|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期 |
| 1 | `0x100`〜`0x1FF` | **予約**。高い優先度の自作フレームを置く候補（ユーザ）。末尾の `0x1FE`〜`0x1FF` は DJI 用 |
| 2 | `0x200`〜`0x2FF` | 周期指令（主制御 → 基板）。`0x200`〜`0x20B` と `0x2FE`〜`0x2FF` は DJI 用 |
| 3 | `0x300`〜`0x3FF` | 周期データ（基板 → 主制御） |
| 4 | `0x400`〜`0x4FF` | 設定（要求と応答） |
| 5 | `0x500`〜`0x5FF` | 分割して送るデータ（形式は後で決める）、コントローラの文字 |
| 6 | `0x600`〜`0x6FF` | 自作フレーム |
| 7 | `0x700`〜`0x7FF` | 予約 |

## class 0: 安全と同期

| ID | 内容 |
|---|---|
| `0x000` | E-stop。受信側は DLC を問わない |
| `0x001` | E-stop の解除。DLC 3、署名 `"clr"`（`0x63 0x6C 0x72`）。署名が一致しないものは捨てる |
| `0x002` | SYNC。主制御の起動からの経過時間（32 bit、µs）。20 Hz。必須。基板は 250 ms 届かなければ出力を止める（最初の SYNC を受けてから有効） |
| `0x003`〜`0x0FF` | 予約 |

## class 2: 周期指令

`ID = 0x210 + (種類 × 8) + フレーム番号`（DJI の `0x200`〜`0x20B` を避けて、`0x210` から置く）。

| 種類 | ID | 1 ch の中身 | 1 フレームの ch 数 | 最大 ch | 止める値 |
|---|---|---|---|---|---|
| 0: MD 電流 | `0x210`〜`0x217` | int16、2 mA/LSB | 4 | 32 | 0 |
| 1: MD 速度 | `0x218`〜`0x21F` | int16、出力軸の 1 rpm/LSB | 4 | 32 | 0 |
| 2: MD duty | `0x220`〜`0x227` | int16。bit 0 が減衰モード、bit 1–15 が符号付きの duty | 4 | 32 | 0 |
| 3: MD 位置 | `0x228`〜`0x22F` | int16、折り返しの目標位置（出力軸 1 回転 ＝ 65536） | 4 | 32 | `0x8000`（保持） |
| 4: サーボ | `0x230`〜`0x237` | 1 byte、500 ＋ 値 × 10 µs | 8 | 64 | 255 |
| 5: 汎用出力 | `0x238`〜`0x23F` | uint16、割合（デジタル出力は 0% か 100%） | 4 | 32 | 0 |
| 6〜 | `0x240`〜`0x2FD` | 予約 | | | |

- ch n が入るのは、フレーム番号 `(n − 1) / 束の大きさ` の、`(n − 1) % 束の大きさ` 番目の slot。
- 同じフレームに入る ch では、指令の種類を混ぜない。使っていない slot には、その種類の止める値を入れる。
- 後ろの slot が使われていなければ、DLC を縮めてよい。
- ch ごとに 100 ms の途絶判定がある。
- 足回りの中継役（RP2040 と C610）は「速度の指令を受ける 4 ch の MD」に見えるので、種類 1 をそのまま使う。

## class 3: 周期データ

| ID | 内容 | 形式 |
|---|---|---|
| `0x300`〜`0x307` | ToF（マトリクス型）1〜8 | tof-draft.md（保留） |
| `0x308`〜`0x30F` | ToF（単点型）1〜8 | 同上 |
| `0x310`〜`0x317` | デジタル入力（4 ch の束 × 8 ＝ 32 ch） | io-draft.md |
| `0x318`〜`0x31F` | 予約 | |
| `0x320`〜`0x33F` | MD の FB（ch 1〜32） | md-draft.md |
| `0x340`〜`0x347` | コントローラの状態 1〜8 | controller-draft.md |
| `0x348`〜`0x34F` | アナログ入力（4 ch の束 × 8 ＝ 32 ch） | io-draft.md |
| `0x350`〜`0x3FF` | 予約 | |

- 時刻の精度は SYNC の時刻の欄で確保するので、ToF とデジタル入力は class を分けず、class 3 の先頭に置いた。
- まとめて送る束は、1 枚の基板がまるごと受け持つ。

## class 4: 設定

`ID = 0x400 + (種類 × 16) + (向き × 8) + 束の中の ch`

| 欄 | 大きさ | 内容 |
|---|---|---|
| 種類 | 4 bit | 下の表 |
| 向き | 1 bit | 0 ＝ 要求（主制御 → 基板）、1 ＝ 応答（基板 → 主制御） |
| 束の中の ch | 3 bit | 0〜7（束の大きさは最大 8 ch） |

種類の番号:

| 番号 | 種類 |
|---|---|
| 0 | MD |
| 1 | サーボ |
| 2 | 汎用出力 |
| 3 | デジタル入力 |
| 4 | アナログ入力 |
| 5 | ToF（マトリクス型） |
| 6 | ToF（単点型） |
| 7 | コントローラ |
| 8〜15 | 予約 |

data 部（DLC 8）:

| byte | 要求 | 応答 |
|---|---|---|
| 0 | 束の番号 | 束の番号 |
| 1 | 操作（2 bit：書く、読む、保存、既定に戻す）、予約（6 bit） | 操作（2 bit）、結果（6 bit） |
| 2 | 設定項目 | 設定項目 |
| 3–6 | 値 | 今の値 |
| 7 | 通し番号 | 通し番号 |

- 要求の宛先は、必ず ch 1 つ。その ch を受け持つ基板だけが応答するので、応答は衝突しない。
- 命令（リセット、ToF の開始、位置の原点など）も、書くと動作する設定項目として扱う。
- 設定項目 0 は「確認」。読み出すと、data 部 8 byte すべてに固有 ID（64 bit）を入れて返す。重複の検知に使う。
- 応答はすぐに返す。
- 基板は、受け取った値をすぐに反映する。動作中に変えてよいかは、主制御の責任。
