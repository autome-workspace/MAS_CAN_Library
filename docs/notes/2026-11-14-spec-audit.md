# 2026-11-14 仕様書を作るときの点検で見つけたこと

`docs/spec/` を台帳から作り、別のサブエージェント 4 つで台帳とコードに突き合わせた（Claude）。仕様書は台帳どおりに書き、下のものは「台帳では未定。今の実装では …」と注を付けてある。決めたら台帳に書き、`docs/spec/` に連鎖させる。

## A. 台帳どおりにできていない（コード、ファーム）

| # | どこ | 内容 | 台帳 |
|---|---|---|---|
| A1 | CAN-Servo-v1 | サーボの設定の要求 `0x410` に一切答えない。共通の項目 0〜6 も無い（node は MD の種類だけ、ファームにも処理が無い）。サーボがいるかを設定で確かめられない | C-49、C-60、S-11 |
| A2 | CAN_MD | サンプル点 75%（16 MHz、Prescaler 1、BS1 11、BS2 4） | C-9（80%） |
| A3 | CAN_MD、node_md_rp2040 | `restart` ですぐ再起動し、応答を線に出し終えるのを待たない（micro-MD と CAN-Servo は待つ） | C-66 |
| A4 | CAN_MD | `AutoBusOff` は有効だが、復帰しても異常の詳細の bit 2 を立てない | C-68 |
| A5 | node | 空転を出せない基板（`md_has_coast` ＝ false）で、項目 34 の焼いた値を 1 にし、0 を書くと 1 に抑え、duty の bit 0 が 0 でもブレーキで出す。出荷中の MD 2 枚はどちらもこれ。台帳は 34 の既定 0、逆向きの丸め（M-51）しか無い | M-47、M-8、M-51 |
| A6 | node | FB の duty の bit 0 を常に 0 で入れる（ブレーキで出していても空転に見える） | M-16 |
| A7 | node | `restart` が NULL だと、項目 6 に成功を返して再起動しない | C-66 |
| A8 | node | 送る待ち行列（8 本）が溢れると、設定の応答、起動の知らせ、再起動の応答も黙って捨てる | C-49 |
| A9 | node | 39〜41 の「基板の既定」を渡す欄が無い。38 に結果 4 を返す道が無い | M-54、M-41 |
| A10 | node | 保存や初期化に失敗して結果 63 を返しても、RAM と保存の写しは書き換わったまま（10-30 の点検の B12） | C-56 |
| A11 | node | E-stop のラッチと異常の詳細を読む API が無く、ファームが `node.estop` などを直接読んでいる | — |
| A12 | node | 猶予が明けたことを MD の指令を受けたときにだけ記録する。起動から約 71.6 分、指令が 1 本も来ないと、µs の一周の直後 200 ms は指令を捨てうる | C-89 |
| A13 | host | 項目 3 を読まず、版の食い違いを知らせない | C-73 |
| A14 | host | 解除を 3 回送り直しても bit 5 が残るとき、知らせずに見張りをやめる | API-24 |
| A15 | host | `Md::stop()` が直前の brake を残し、`setDuty` の後だと `0x0001`（短絡ブレーキ）を送る | API-50、M-8 |
| A17 | CAN_MD | クロックが内蔵の RC（HSI）から。A2 と合わせて CAN の精度が足りない（README の既知の制約にもある） | C-10 |
| A18 | CAN-Servo-v1 | `md_has_coast` ＝ true だがブレーキを一度も出さない（M-51 の丸めの範囲）。33 は上限も焼いた値も 0 で、ポートは 33 を効かせない | M-47、M-51 |
| A16 | core | `md_frame.h` の位置の止める値 `0x8000` は取り消した決定の名残。ヘッダのコメントが `docs/redesign/` と旧番号を指す。`MAS_CAN_BOARD_MD_2CH` は名前が 2CH で中身は 1 ch | M-49、C-63 |

## B. 台帳で決まっていない

| # | 点 | 今の実装 |
|---|---|---|
| B1 | 起動の猶予の間と、E-stop の解除の後の出力の止め方（M-22、M-27 に無い） | node は項目 34 に従う |
| B2 | サーボの E-stop の解除の後（MD の M-27 にあたるもの） | CAN-Servo は新しい指令が来るまで動かない |
| B3 | 速度ループの Kp「duty/rpm」の duty の大きさ（M-33） | — |
| B4 | 値の欄: 結果 1、再起動の署名違い（結果 3）、項目 0 を書いたとき（結果 2）（C-56、C-57） | node は 0 |
| B5 | 項目 6 の byte 6 | node は見ない |
| B6 | 予約の項目（42〜44、47）を読み書きしたときの結果 | node は 1 |
| B7 | 電流を測れない基板の項目 33 の意味 | 上限の欄が 0 の基板は常に 0 を返す |
| B8 | 項目 5 は基板に 1 つか ch ごとか | node は基板に 1 つ |
| B9 | 保存と初期化の範囲 1 は、複数の種類を持つ基板でほかの種類の ch も含むか（C-53） | — |
| B10 | 設定の応答を待つ時間 | host は 50 ms × 3 回 |
| B11 | C-18 の「最大の ch」は 31 か ch の数 32 か（文言） | — |
| B12 | 止める値を受けたときの扱い（M-58 の理由に入っていないだけで明記が無い） | 普通の値として扱う |
| B13 | FB の bit 6–7 の値が指令の番号であること（M-18 に明記が無い） | 指令の番号 |
| B14 | 電源投入も「再起動した」（C-67 の bit 0）に含むか。C-94 はそれを当てにしている | node は電源投入でも立てる |
| B15 | サーボの指令の DLC の範囲（S-1） | — |
| B16 | reserved.md が無い。種類の番号 2〜8、コントローラの `0x340` はコードにだけある | frame.h、host.cpp |
| B17 | DBC を仕様と一緒に配布する（C-3）が、まだ無い | — |
| B18 | E-stop の解除の後の FB の bit 6–7 は、「起動直後」の 0（M-20）か「止まった後」の最後の形か（M-27 との間） | 最後の形のまま |
| B19 | 設定の通し番号（byte 7）の初期値と増やし方 | ライブラリは 1 から 1 ずつ。送り直しでも新しい番号 |
