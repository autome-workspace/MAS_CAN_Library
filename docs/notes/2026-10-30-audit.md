## C. 低・将来の罠

- node.c:441 FB duty の bit 0 が常に 0（M-16）
- node.c:29-33 送信の待ち行列 8 が満杯だと設定の応答を黙って捨てる
- node.c:93 C-18（ch 範囲超過）を確かめない。今のファームは各自で防いでいる
- node.c:42-51 速度ループの既定ゲインを渡す口が無い（M-54）
- node.c ブレーキを出せない基板を表せない（M-51）。CAN-Servo は項目 34=1 を受け付けるが常に空転
- node.c:69-82 保存を読むとき上限で抑え直さない（C-79）
- CAN_MD: サンプル点 75%（C-9 は 80%）、current_limited を立てない（M-28）、バスオフの bit 2 を立てない（C-68）、フラッシュ消去中の受信 FIFO 溢れ（推）
- CAN_MD DIP のビット割当がネットリストと逆に見える（推。実機確認の記録なし）
- 【未コミット】CAN_MD FIRST_CH 8：README は 0〜7 のまま、C-81「k × 大きさ」と食い違い、md_minimal 等は ch 0 前提
- CAN-Servo サーボの PIO が LED の GPIO16 を書く
- micro-MD platformio.ini のプラットフォーム未固定
- host: 設定送信の失敗が送り直し回数を食う、ClearFault 時間切れで hasFault() が消えない、waitReady の ms×1000 あふれ、Host より長生きする取っ手の clearFault()、inf の刻み、複数タスクからの呼び出しに守りが無い、rp2040 受信箱にコンパイラ壁なし、TWAI は APB 80 MHz 前提
- api.md の API-55 が「見本にまだ無い」のまま
