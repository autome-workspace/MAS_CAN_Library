# 2026-11-22 速度の指令とフィードフォワード（r2 の足回りで見つかったこと）

F3RC 2026 の r2 の足回りの調整で見つかった、MAS CAN（仕様、ライブラリ、XDrive の中継機）について直したほうがよいこと。ユーザが試し、Claude が値を出してログを読んだ。決定ではない。決めるものは台帳へ、未決は open.md へ。

## 機体と構成

- 5 kg、φ60 のオムニの X 配置（取り付け半径 15 cm）、4250 / 560 KV の直結（1:1）。機体は今は改造できない（ユーザ）。
- 主制御 ESP32（`r2_ps4`、v1.0.0 の `lib/mas`）→ 主バス → 中継機（`firmware/xdrive-relay`）→ 下のバス → XDrive（ODrive fw 0.5.1 系。版数は 0.0.0 の独自ビルド）× 4。
- 主制御は速度の指令（`setSpeed`）だけを使う。

## 経過

| 段 | XDrive | 中継機 | 結果 |
|---|---|---|---|
| 初め | `vel_gain` 0.05、`vel_integrator_gain` 0.1、PASSTHROUGH | 速度をそのまま渡す | 重い。浮かせると素直。床での時定数は計算で約 0.29 s |
| 1 | 0.3 / 1.0 | 同じ | 発振。浮かせた状態や、対角の輪が打ち消し合う動き（ローラーが空転する）では慣性が約 1/40 で、帯域がエンコーダの推定の 500 rad/s を超える |
| 2 | 0.1 / 0.3、VEL_RAMP、`inertia` 0.0145 | 同じ | 床で発振し、速度が出ない。中継機が `Set_Controller_Modes` で毎回 PASSTHROUGH を送っていて、VEL_RAMP は効いていなかった |
| 3 | 0.05 / 0.1、PASSTHROUGH | ランプ（10 turn/s²）と慣性の FF を中継機で作り、`Set_Input_Vel` の torque_ff に載せる | 動き出さない。離すと周期 2 s ほど振れて止まる（静止摩擦と弱い P） |
| 4 | 同じ | 摩擦の FF 0.04 Nm を足す | まだトルクが足りない（ユーザ）。慣性と摩擦の FF の合計が、電流の上限 12 A × Kt ＝ 0.177 Nm に当たっている |
| 5（途中） | `current_lim` 20 A にする予定 | `XD_CURRENT_LIMIT_MA` 20000 | ここで中断した |

ゲインで速さを出すと、軽い負荷の側で安定する限界（0.05 付近）に当たる。速さを出すには FF と電流の上限を使うしかない、というのがこの機体で分かったこと。

## MAS CAN に直したほうがよいこと

### 1. 速度の指令に FF を載せる道が無い

MD の指令は ch ごとに値が 1 つ（M-8 の形）で、速度の指令にトルクや加速度の FF を添えられない。今回は中継機の中でランプを作り、その傾きから FF を出した（ビルドの値で決める）。

- 基板の側で作る（今回の形）なら、線の上の形は変えずに済む。ただし、FF の大きさを決める値（慣性、摩擦）の置き場が要る（2）。
- 主制御から FF を送るなら、指令の形が変わる（v2 の話）。主制御の 20 ms の周期では、目標が階段になる問題（6）も残る。

### 2. 慣性と摩擦の FF の設定項目が無い

速度の制御の項目は 39〜41（ゲイン）、45（最高速度）、46（最大加速度）だけ。慣性と摩擦の FF は項目に無いので、中継機ではビルドの値（`XD_INERTIA`、`XD_FRICTION`）にした。変えるたびに書き直すことになる。

- 案 A: MD の項目（32〜127）に足す。速度の制御をする MD なら、どれも意味がある。
- 案 B: 中継機の基板固有の項目（128〜）に足す。仕様は変えずに済む。

### 3. 中継機が M-47 に合っていない: 設定 33 が速度の指令に効かない

M-47 では「33 は使う側の上限で、どの指令（duty、電流、速度、位置）にも効く」とある。ところが中継機は、33 を電流の指令にしか使っていない（README の「速度の指令のときに効くのは XDrive の `current_lim` だけ」）。XDrive の `current_lim` は fw 0.5.1 の CAN から変えられない（`0x00F` は電流の欄を読まない）。

- 速度の指令で 33 を守るには、中継機が XDrive の出すトルクを抑える道が要る。今あるのは、FF を 33 で抑えることだけ（今は 33 ではなく `XD_CURRENT_LIMIT_MA` で抑えている）。PI の出力までは抑えられない。
- 守れないなら、M-47 の例外として基板の資料に書く。

`XD_CURRENT_LIMIT_MA` は、33 の既定、33 に書ける上限（`md_current_limit_max_ma`）、FF の上限の 3 つを兼ねている。XDrive の `current_lim` と合わせる必要もある。主制御から 33 を書いても、これを超えては上げられない。

### 4. 中継機が M-38 に合っていない: 46 が 0 のときの加速度

M-38 では 46 の既定は 0（制限なし）。中継機は「46 が 0 なら `XD_ACCEL`」にしたので、主制御から見ると 46 は 0 なのに加速度が制限されている。

- 案: node の設定に 46 の既定を持たせる（33 の `md_current_limit_default_ma` と同じ形で、`md_max_accel_default`）。台帳の「既定 0」を「既定は基板の資料に書く」に変えることになる。
- 46 が 0（制限なし）のときは目標が飛ぶので、慣性の FF は出せない。FF を使うなら加速度の制限は必須。この関係も書いておく。

### 5. 主制御から MD の項目 32〜46 を書けない（API-59）

保存の API と一緒に決めることになっていて、今は無い。今回は加速度（46）、ゲイン（39〜41。中継機は 4 を返す）、電流の上限（33）のどれも主制御から変えられず、値を変えるたびに中継機か XDrive を USB で書き直した。走らせながら調整したい場面で困る。

- `Port::send()` は public なので、`mas_can_setting_encode()` で作ったフレームを主制御から送ることはできる。ただしライブラリの外の使い方で、応答は `Host` が受けてしまう。
- 保存の API を待たずに、書くだけ（保存しない）の `config` を先に出す、または開発者用の生の設定の API を出すかを決める。

### 6. 基板の側でランプを作るときの注意（中継機で踏んだもの）

基板の資料や雛形に書く材料。

- **目標が階段になる。** 主制御は 20 ms ごとに指令を送り、中継機も下のバスへ 20 ms ごとに送る。基板の中のランプで段差を詰めると、FF が段差ごとにパルスになる（XDrive の VEL_RAMP に任せたときがこれ）。中継機では、前に送ってからの平均の加速度で FF を出して避けた。
- **Closed loop に入る前にランプを進めない。** 中継機は Enabling の間も目標を進めていたので、Running に入った最初の指令で目標が飛んでいた（46 を使うと起きる。直した）。M-25（動き出しで制御の状態をリセットする）の具体例として書ける。
- **摩擦の FF の向きは目標で決める。** 測った速度で決めると、止まりかけで向きが振れる。0 の近くは比例で小さくする（中継機は 0.1 turn/s）。

### 7. XDrive（ODrive 0.5.1）の CAN で変えられないもの

中継機の資料に書く材料。

| | CAN から |
|---|---|
| `vel_gain`、`vel_integrator_gain` | 変えられない（`Set_Vel_Gains` は 0.6 系から） |
| `vel_ramp_rate` | 変えられない |
| `inertia` | `0x013`（揮発） |
| `current_lim` | 変えられない |
| `control_mode`、`input_mode` | `0x00B`（中継機が毎回送る。PASSTHROUGH） |
