# 全部入りの例を取り下げた記録（2026-11-15、Claude）

ユーザの言葉（11-15）:「最小構成とは別に、MAS CAN を存分に使った正しい実装例はあるべき」。Claude は機体 1 台ぶんの例（`examples/robot_full`、約 230 行。足回り 4 輪を速さ、昇降を電流、ローラーを duty、ハンドをサーボ。操作はシリアル）を書いた。ユーザ:「足りない。あるべきなのは、動かすだけじゃなく、こういう確認関数でデバッグできるよ、という糸口。初心者は情報量に埋もれて読めない」。

糸口は `examples/md_check`（48 行）として作り直した。`robot_full` はコミットせずに消した。経緯を知らないセッションの点検で 10 件出たため。実機で試していない手本は置かない。

いつか手本を作るときの材料として、点検の指摘を残す。

| # | 指摘 | 教訓 |
|---|---|---|
| 1 | ほかの主制御がかけた緊急停止が解除された瞬間、loop() が毎回置き直す目標（昇降 2 A など）で動き出す。自分の 'e'、'c' でしか目標を 0 に戻していなかった | 目標は `can.estopped()` の間ずっと 0 に戻す。ライブラリが解除で値を戻しても、アプリが毎回置けば無意味 |
| 2 | 車輪が使えるかを `online() && ready()` だけで見ていた。XDrive が過電流で止まった ch は online かつ ready のままなので、残り 3 輪が回り続ける | `hasFault()` も見る。`stopped()` は指令前も true なので条件に入れない（二度と動かなくなる） |
| 3 | 操作が途切れたら止めるのが足回りだけ。昇降とローラーは最後の値のまま続く。基板の線を挿し直すと、準備が済みしだい前の値で動く | 途切れと、基板が戻ったときの扱いは、軸ごとに決める |
| 4 | 小さな電流の指令（0 でない）で、CAN_MD は duty 0.345、micro-MD は 0.23 より下がらず、軽い昇降は端まで回り続ける。`setCurrent(0)` は問題ない（CAN_MD は目標 0 だけ下限を外す。micro-MD はブレーキ） | 電流で動かす軸の例には、この注意を書く |
| 5 | 昇降の「止める」を 0 A にしていた。0 A は力を抜くだけで、重さで下がる。緊急停止はブレーキなので、止まり方が違う | 保持が要る機構は別に考える |
| 6 | 「戻った基板の位置は 0 から」と表示していた。ライブラリは前の値に続けて数えるので、`position()` は 0 に戻らない。止まっていた間の分が数えられていないだけ | 表示の文も事実と合わせる |
| 7 | 足回りの値に上限が無い | 操作の値は、軸ごとに上限で抑える |
| 8 | XDrive の中継機は、速さ 0 の指令でも制御に入り、通電して保持する。最初の周から `setSpeed(0)` を置くと、誰も操作しなくても 4 台が保持に入る | 最初の操作が来るまで指令を置かない書き方もある |
| 9 | 「同じ番号の基板が 2 枚あると、どちらも動かない」と書いていた。実際は両方が同じ指令に従い、返事が混ざる | 「動かない」ではなく「正しく動かない」 |
| 10 | シリアルの行の長さに上限が無い。改行が来ないと緊急停止の命令も効かない、など | — |

確かめきれなかったこと（点検者の申告）: CAN_MD で 0 A のときに空転かブレーキか。中継機の減速比（主制御から書く関数が無い）。Serial.printf が何 ms 止まるか。
