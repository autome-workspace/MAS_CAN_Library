# v2 の紙の試作 2: 骨格の下書き（2026-11-15、Claude）

**決定ではない。** [v2-proposal](2026-11-15-v2-proposal.md) と [v2-scenes](2026-11-15-v2-scenes.md) の合意を 1 枚にまとめ、線の上の形まで詰めたもの。コードは書いていない。

印の意味:

- **【合意】** ユーザが 2026-11-15 に、紙の試作の前提としてよいとしたもの。
- **【Claude】** Claude が詰めて決めたもの。理由を添える。**覆してよい。**
- **【問い】** ユーザの判断が要るもの。末尾に 4 つだけ。

## 1. 考え方

- 【合意】宛先と API は（種類、ch）。`can.md(0)`、`can.servo(9)`。番号は種類ごとに 0 から。
- 【合意】線の上の単位は**ユニット**（種類、番号）。ユニットの中の ch の数は種類ごと（MD 1、サーボ 8）。ユニットは 1 枚の基板がまるごと受け持つ。大きさは、その種類の最初の基板を作るときに決める。
- 【合意】どのユニットも同じ 4 つのフレーム（状態、指令、データ、設定）を同じ決まりで使い、種類の違いはプロファイルの表に閉じ込める。核には種類の名前が出てこない。
- 【合意】主制御は複数いてよい。1 つのユニットの持ち主は 1 台。
- 【Claude】主制御を書く部員に見せるのは「種類と番号」「置いた値が送られる」「見えているか、止まっている理由」「値の 4 段」まで。ユニット、class、印、持ち主は、基板を作る人と線を読む人のもの。

## 2. ID

```
ID ＝ class × 256 ＋ 番地
```

| class | ID | 中身 | 送り手 |
|---|---|---|---|
| 0 | `0x000`〜 | 全体。`0x000` E-stop、`0x001` 解除、`0x008`〜`0x00B` 主制御の状態（主制御の番号 0〜3） | 主制御 |
| 1 | `0x100`〜 | ユニットの状態 | ユニット |
| 2 | `0x200`〜 | 指令 | 持ち主の主制御 |
| 3 | `0x300`〜 | データ（FB、センサの値） | ユニット |
| 4 | `0x400`〜 | 設定の要求 | 主制御 |
| 5 | `0x500`〜 | 設定の応答 | ユニット |
| 6 | `0x600`〜 | 自作、分割して流すもの | |
| 7 | `0x700`〜 | ファームの書き込み（予約） | |

番地は種類ごとに範囲を取る。

| 番地 | 種類 | ユニット | 例 |
|---|---|---|---|
| `0x00`〜`0x0F`、`0xFE`〜`0xFF` | 使わない（全体のフレームと、DJI の固定 ID を避ける。C-24） | | |
| `0x10`〜`0x2F` | MD | 32 個（32 ch） | MD の 0 番: 状態 `0x110`、指令 `0x210`、FB `0x310`、設定 `0x410`／`0x510` |
| `0x30`〜`0x37` | サーボ | 8 個（64 ch） | サーボの 9 番 ＝ ユニット 1: 状態 `0x131`、指令 `0x231` |
| `0x38`〜`0xFD` | 未割り当て | | 種類を作るときに取る |

- 【Claude】自己紹介を別のフレームにするのはやめた。種類は番地の範囲で決まるので、取り違えは起きない。基板の種類、ファームの版、固有 ID は、設定の共通の項目で読む（確認のときにどうせ設定を使う）。周期のフレームはユニットにつき状態の 1 本だけ。
- 【Claude】設定の応答を class 5 に分けた。番地を全 class で同じにするため（下 2 桁が同じなら同じユニット）。分割と自作は class 6 にまとめる。
- 枠を複数使う種類（ToF マトリクス、IMU）は、1 ユニットが番地を続けて複数取る。作るときに決める。

## 3. 全体のフレーム

| フレーム | 形 | 決まり |
|---|---|---|
| E-stop `0x000` | 中身は見ない | v1 のまま（C-28）。掛けた主制御が 10 Hz で送り続ける |
| 解除 `0x001` | DLC 3、`"clr"` | v1 のまま（C-29）。**解除を送るのは掛けた主制御だけ**（ライブラリの決まり。ほかの主制御の解除は、10 Hz の送り直しで 100 ms 以内にラッチし直される） |
| 主制御の状態 `0x008` ＋ 番号 | 20 Hz、DLC 7: byte 0–1 主制御の起動の印、byte 2–5 時刻（µs）、byte 6 bit 0 ＝ E-stop を掛けている | v1 の SYNC（`0x002`）を置き換える。時刻の親は、いる中で番号がいちばん小さい主制御 |

- 【Claude】主制御の番号は、マイコンの主制御が 0、PC が 1 を既定にする。同じ番号が 2 台いたら、自分の ID を他人から受けた側が指令をやめて知らせる（ユニットの番号の重複と同じ決まり）。
- 【Claude】起動の印は 2 byte。起動のたびに乱数で選び、0 は使わない（0 は「なし」）。

## 4. ユニットの状態

### 4.1 状態のフレーム（class 1、DLC 8）

| byte | 中身 |
|---|---|
| 0 | bit 0–3 状態、bit 4–7 理由 |
| 1 | bit 0–1 持ち主の主制御の番号、bit 2 持ち主がいる、bit 3 保存した値がある（焼いた値と違う） |
| 2–3 | ユニットの起動の印 |
| 4–5 | 持ち主の主制御の印（いなければ 0） |
| 6–7 | 異常の bit（bit 0–3 共通、bit 4–15 種類ごと） |

- 【合意】送るのは「変わったらすぐ」と「前に送ってから一定時間」。持ち主がいない間は 100 ms、いる間は 1 秒（設定で変えられる）。
- 【Claude】異常の共通の bit: 0 保存した値が壊れていた、1 バスオフから戻った、2 ウォッチドッグで再起動した、3 予約。「再起動した」の bit は印があるので要らない。異常は持ち主が設定で消す。
- 同じ基板の全ユニットは、同じ起動の印を使う。

### 4.2 出力を持つユニットの状態

| 状態 | 出力 | 入り方 | 抜け方 |
|---|---|---|---|
| 0 未許可 | 安全側 | 起動。持ち主の主制御の印が変わった。持ち主が手放した | 許可で「待機」へ |
| 1 待機 | 安全側 | 許可。途絶。こなせない指令。解除 | 有効な指令で「動作」へ |
| 2 動作 | 指令どおり | 有効な指令 | 100 ms 途絶、こなせない指令で「待機」へ |
| 3 保護 | 安全側 | 基板が異常を見つけた | 基板が決める |
| 4 非常停止 | 安全側、ラッチ | `0x000` | 解除で、許可済みなら「待機」、でなければ「未許可」へ |

理由（待機と未許可のとき）: 1 起動直後、2 許可の直後、3 途絶、4 こなせない指令、5 設定が足りない、6 解除の後、7 持ち主が替わった。

- 優先は、非常停止 > 保護 > 未許可 > 待機。
- 【Claude】出力を持たないユニット（センサ）は、状態 0 と 2 だけを使う（持ち主がいないか、いるか）。データは持ち主がいなくても送る。E-stop では止まらない。
- 【Claude】ウォッチドッグは基板の核の決まりにする。固まったら再起動し、異常の bit 2 を立てる。

### 4.3 握手

設定の共通の項目 7「持ち主」への書き込みで行う。値 ＝ ユニットの印（2 byte）＋ 主制御の印（2 byte）、副番号 ＝ 段階。

| 段階 | 意味 | ユニットが受ける条件 |
|---|---|---|
| 0 取る | この主制御が持ち主になる。状態は未許可のまま | ユニットの印が一致する。持ち主がいないか、今の持ち主の状態のフレームが 250 ms 来ていない |
| 1 許可 | 未許可 → 待機 | 持ち主からで、印が一致する |
| 2 手放す | 持ち主なしに戻る | 持ち主から |

- 【Claude】「取る」と「許可」を分けた。**設定を書けるのは持ち主だけ**にするため。順番は、取る → 設定を書く → 許可 → 指令。許可の前は指令に従わないので、「設定が入る前に動かない」をユニットが守る（主制御の行儀に頼らない）。
- 【Claude】ユニットは持ち主の主制御の状態のフレームを見ている。**持ち主が生きている間は、ほかの主制御は取れない**。PC の道具を後からつないでも、動いているロボットのユニットは奪えない。
- 【Claude】ユニットが未許可に戻るとき、RAM の値を「焼いた値 → 保存した値」で作り直す。前のプログラムが書いた値は残らない。
- 【Claude】持ち主の主制御のフレームが途絶えただけでは、未許可に戻さない（主制御の一瞬の遅れで握手をやり直さないため）。指令の途絶で止まる。持ち主が消えたままなら、ほかの主制御が取れる。
- CAN のフレームに送り主は載らないので、**指令を送っているのが持ち主かどうかは、ユニットには分からない**。持ち主でない主制御が指令しないことは、ライブラリの決まりで守る。

### 4.4 主制御から見たユニット

| 状態 | 意味 | 次へ |
|---|---|---|
| 未発見 | 状態のフレームを受けていない | 受けたら、持ち主がいなければ「確認中」、ほかの主制御のものなら「他人のもの」 |
| 確認中 | 取る → 版を読む → 宣言した設定を書く → 刻みを読む → 許可 | 終われば「使える」。断られたら「だめ」 |
| 使える | 指令を送る。データを有効として渡す | ユニットの印が変わった、持ち主が自分でなくなった → 「確認中」。状態が 2〜3 本来ない → 「消えた」 |
| 消えた | 見えない。指令は送り続ける | 受けたら、印が同じなら「使える」、違えば「確認中」 |
| 他人のもの | ほかの主制御が持っている。指令も設定も送らない。データは読める | 持ち主がいなくなったら「確認中」 |
| だめ | 版が合わない、設定を断られた | 1 秒おいて「確認中」からやり直す。理由を知らせる |

- 【合意】自動復帰。異常か、人が止めるまで粘る。「だめ」でも 1 秒ごとにやり直す。
- 【Claude】主制御は、起動したとき全ユニットを「未発見」から始める。
- 【Claude】データ（FB）の値は「使える」の間だけ有効として渡す。確認中のユニットの FB は、刻みが分からないので無効とする（v1 の API-65 と同じ考え）。位置は数え続ける。
- 【Claude】ユニットが再起動から戻ったとき、duty、電流、速度の指令は、アプリが置いた値のまま続ける。位置のカウンタは基板で 0 に戻るので、取っ手に「位置が切れた」の印を立て、アプリが消すまで残す。

## 5. 設定

### 5.1 フレーム（class 4 要求、class 5 応答。DLC 8）

| byte | 中身 |
|---|---|
| 0 | bit 0–1 主制御の番号、bit 2–3 操作（0 読む、1 書く、2 保存、3 初期化）、bit 4–7 結果（要求では 0） |
| 1 | 項目の番号 |
| 2 | 副番号（ユニットの中の ch。MD は常に 0） |
| 3–6 | 値（int32、uint32、float32） |
| 7 | 通し番号 |

結果: 0 成功、1 知らない項目、2 その操作はできない、3 範囲外、4 実現できない、5 持ち主でない、6 今はできない（動作中の保存）、15 その他。応答の bit 4–5 を「出どころ」に使う案は 5.3。

- 【Claude】要求は**ユニットごとに 1 つずつ**（v1 は線全体で 1 つずつ。C-51）。起動のたびに設定を書くので、並行しないと MD 24 台で約 3 秒かかる。
- 【Claude】書く、保存、初期化は持ち主だけ。読むのは誰でもよい。
- 【Claude】保存と初期化は、状態が「動作」の間は断る（結果 6）。フラッシュを消す間、指令も E-stop も見られないため。v1 の C-55（動作中でも書く）の見直し。
- 【Claude】項目 0（固有 ID）の特別な形（C-61）はやめ、副番号 0 と 1 で上位と下位を読む。

共通の項目: 0 固有 ID、1 基板の種類と版、2 ファームの版、3 プロトコルの版、4 この基板が受け持つ、この種類のユニットの範囲、5 異常の bit（1 を書いて消す）、6 再起動（署名つき。基板の全ユニットが再起動する）、7 持ち主（握手）、8 状態の周期。

保存と初期化の範囲は、項目の欄で 0 ＝ このユニット、1 ＝ この基板の全ユニット。

### 5.2 値の 4 段【合意】

| 段 | 何か | いつ決まるか |
|---|---|---|
| 0. 基板の限界 | ハードウェアの上限。変えられない | 基板を設計したとき |
| 1. 焼いた値 | ファームの既定。これだけで回ること | ファームを焼いたとき |
| 2. 保存した値 | ファームを焼き直さずに既定を変えたもの | 机の上で調整したとき |
| 3. 主制御が書いた値 | アプリが必要なときに使う窓口 | 握手のたび。再起動や主制御の交代で消える |

- 【合意】分からなくなったら初期化する。初期化して困るものは、焼いた値にしておく。
- 【合意】向き、上限などは、統合のプログラムが明示して書く。モーターの回転方向は、どのみちアプリが決めるもの。
- 【Claude】**初期化は 2 段だけを消す。ユニットの番号（k）は消さない。** 番号はフラッシュにあっても「保存した値」ではなく、基板の身元として別に持つ。これで「初期化はいつしても安全」が成り立つ。
- 【Claude】v1 の「保存できない項目」（C-80）の区別はやめ、全部の項目を保存できるようにする。握手があるので、アプリは前提にする値を毎回書く。
- 【Claude】3 段は、どの項目にも書ける。ライブラリは、アプリが `config…` で宣言した値を覚え、確認のたびに書く。宣言していない項目は 2 段か 1 段のまま。
- 【Claude】保存は、今の RAM の値（3 段を含む）を 2 段に写す。机の上で `config…` で合わせ、良ければ保存する、という使い方になる。

### 5.3 どの段から来た値か

- 【Claude】状態のフレームの「保存した値がある」の bit は入れる（1 bit で足りる）。
- 【Claude】項目ごとの出どころ（1 段か 2 段か 3 段か）を読む応答で返す案は、**基板の核を書くときに大きさを見て決める**。入れるなら、応答の byte 0 の結果の上位 2 bit。

## 6. プロファイル: MD

ユニット ＝ 1 ch。

### 指令（class 2、DLC 5）

| byte | 中身 |
|---|---|
| 0 | bit 0–2 種類（0 止める、1 duty、2 電流、3 速度、4 位置（予約））、bit 7 止め方（0 空転、1 ブレーキ） |
| 1–4 | 値（float32）。duty は −1〜+1、電流は A、速度は rad/s（出力軸） |

- 【Claude】値は SI の float。v1 の mA、rpm と int16 はやめる（問い 2）。
- 【Claude】「止める」を種類の 1 つにした。v1 は種類ごとの止める値で、`stop()` が直前の種類を引きずった（11-14 の A15）。
- 【Claude】止め方の bit は、duty の PWM を切っている間と、「止める」のときに効く（M-8、M-46 のまま）。
- 【Claude】NaN、無限大、知らない種類、DLC が 5 未満は、こなせない指令（待機へ。理由 4）。DLC が 5 より長いのは許す（位置やフィードフォワードを足す余白）。
- 【Claude】電流を測れない基板への電流の指令、エンコーダが無い基板への速度の指令は、こなせない指令（M-30 のまま）。**エンコーダの分解能か減速比が入っていない（0 のまま）のに速度の指令が来たら、理由 5「設定が足りない」**（問い 3）。
- 位置（種類 4）は予約。中身は作るときに決める。

### データ（FB。class 3、DLC 8 固定）

| byte | 中身 |
|---|---|
| 0 | bit 0 電流が無効、bit 1 速度と位置が無効、bit 2 電流の上限に当たっている、bit 3–5 今従っている種類 |
| 1–2 | 電流（int16 × 電流の刻み） |
| 3–4 | 速度（int16 × 速度の刻み） |
| 5–7 | 位置（24 bit で折り返す。1 回転 ＝ 65536） |

- 【Claude】止めているか、E-stop か、異常があるかは、状態のフレームに移した。FB に残すのは、100 Hz で見たいものだけ。
- 【Claude】長さは 8 で固定。測れない欄は 0 にして無効の bit を立てる。v1 の「空いた欄に duty を入れる」（M-15）はやめる。
- 【Claude】刻みは普通の設定の項目（既定は焼いた値）。持ち主しか書けず、主制御は確認のときに読むので、v1 の「基板が再起動して刻みが食い違う」は起きない（再起動すれば未許可で、FB は無効として扱う）。
- FB の周期は設定（既定 100 Hz、0 で送らない）。未許可でも送る。

### 設定の項目

番号は v1 を引き継ぐ（M-47、M-36、M-54、M-38、M-56）。単位は SI にそろえる。

| 番号 | 項目 | 焼いた値 |
|---|---|---|
| 32 | 回転方向の反転 | 0。統合のプログラムが明示して書く |
| 33 | 電流の上限（A） | 基板の資料 |
| 34 | 安全側の止め方（0 空転、1 ブレーキ） | 1（問い 1） |
| 35 | FB の周期（Hz） | 100 |
| 36 | エンコーダ 1 回転のカウント数 | 基板に決まったエンコーダがあればその値、無ければ 0（未設定） |
| 37 | 減速比 | 1 |
| 38 | エンコーダの向きの反転 | 0 |
| 39〜41 | 速度ループのゲイン | 基板の既定（これだけで回ること） |
| 45、46 | 最高速度、最大加速度 | 0（制限なし） |
| 48、49 | FB の電流の刻み、速度の刻み | 基板の既定 |

## 7. プロファイル: サーボ

ユニット ＝ 8 ch。

- 指令（class 2、DLC 1〜8）: 1 ch ＝ 1 byte。0〜200 はパルス幅 500 ＋ 値 × 10 µs、255 は止める、201〜254 は止める（S-2、S-3 のまま）。DLC の外の ch は止める。
- データは無い。いるか、止めているか、ラッチしているかは、状態のフレームで分かる。
- 設定（副番号 ＝ ch 0〜7）: 32 パルス幅の下限、33 上限、34 周期（S-11 のまま）。
- 状態はユニットに 1 つ。8 ch のうち 1 つでも有効な値（0〜200）があれば「動作」。

【Claude】サーボは v1 の形をほぼそのまま使う。1 ch が 1 byte で種類が 1 つしかないので、束で困ることが無い。

## 8. 線の上の例

MD の 0 番を、主制御 0 が見つけて回すまで。

```
ユニット → 0x110  10 00 3A 7C 00 00 00 00   未許可（起動直後）、印 3A7C、持ち主なし   （100 ms ごと）
主制御   → 0x008  51 E2 00 12 D6 87 00      主制御 0、印 51E2、時刻                   （20 Hz）
主制御   → 0x410  持ち主 ← 取る（3A7C、51E2）
ユニット → 0x510  成功
ユニット → 0x110  10 04 3A 7C 51 E2 00 00   未許可、持ち主は主制御 0（印 51E2）
主制御   → 0x410  版を読む、反転 ← 1、電流の上限 ← 3.0、… 刻みを読む
主制御   → 0x410  持ち主 ← 許可
ユニット → 0x110  21 04 3A 7C 51 E2 00 00   待機（許可の直後）
主制御   → 0x210  01 3E 99 99 9A            duty 0.3、空転                            （100 Hz）
ユニット → 0x110  02 04 3A 7C 51 E2 00 00   動作                                      （以後 1 秒ごと）
ユニット → 0x310  08 03 20 …                FB                                        （100 Hz）
```

基板が瞬停すると、次の状態のフレームは印が変わり、未許可に戻っている。主制御は同じ手順をやり直す。その間、流れている指令にユニットは従わない。

## 9. v1 から消えるもの

| 消えるもの | 代わり |
|---|---|
| 起動の知らせ（C-36）、起動の猶予（C-89） | 状態のフレームと握手 |
| 誰が再起動したかの推理（C-94）、異常の詳細の読み直し（API-66） | 起動の印 |
| プログラムの値と機体の値の区別（C-80）、先に送り直す（C-88） | 値の 4 段と、確認のたびに書く |
| `ready()` の刻みの 2 つ持ち（API-43、44、62、65） | 主制御から見たユニットの状態 1 つ |
| MD の指令の束、`CommandConflict`（API-52）、止める値を詰める、DLC を縮める | 1 ch 1 本 |
| 束は 1 台の主制御だけ（C-76） | ユニットの持ち主 |
| SYNC（C-32〜35） | 主制御の状態のフレーム |
| FB の長さ 8、5、3（M-15）、FB の状態の bit の大半（M-18） | 固定の 8、状態のフレーム |
| FB の無い種類の生存は確かめない（C-15、Q40） | 状態のフレーム |
| 許可制は入れない（C-4） | 握手（ライブラリが自動で行う） |
| 項目 0 の特別な形（C-61）、動作中の保存（C-55） | 副番号、動作中は断る |

## 10. 弱い所

- **握手の一手が増え、生のフレーム 1 本ではモーターが回らない。** 基板を作る人の単体の確認には、PC の道具（取る → 許可 → 指令）が要る。この道具は試作の早い段階で作らないと、基板を作る部員が困る。
- **「回らない」の原因が増える。** 持ち主でない、設定を断られた、版が合わない、設定が足りない。全部、状態のフレームと「だめ」の理由に出るが、読む道具（`can.print()`）が無いと追えない。
- **ユニットが主制御の状態のフレームを見る**ので、基板の核に「持ち主が生きているか」の時計が 1 つ増える。
- **指令が持ち主から来たかを、ユニットは確かめられない。** 行儀の悪い主制御（自作のスクリプト）は、他人のユニットを動かせる。
- 線の使用率は v1 より増える（MD 16 台、100 Hz で 24% → 35%）。
- 2 台の主制御の場面は、紙の上でしか確かめていない。往復テストで最初に試す。
- 共通の決まりの数は、v1 より減ったとは言い切れない。握手、持ち主、状態の表が足された。減ったのは、種類ごとに繰り返していた分と、取りこぼしを拾う仕組み。

## 追記（2026-11-15）: v1 に戻すもの

本文は直さず、ここに足す。ユーザの指摘:「微妙。単位は、握手をすると決めた今、float にする理由が薄い、など」。

そのとおりで、v1 の刻みが危なかった理由（再起動で黙って 1.0 に戻る）は、握手で塞がっている。見直すと、同じ種類の変更（v1 の歪みを直すのに必要ではなく、Claude の好みで変えたもの）がほかにもあった。**全部 v1 に戻す。**

**決まり【Claude】: v1 の決定は、歪みを直すのに必要なものだけ変える。** 歪みは 3 つ（種類ごとに誂えている、基板に名前と状態が無い、見えない設定を主制御が追いかけている）。これに効かない変更は入れない。

| 本文 | 戻す先 |
|---|---|
| 6 節: 指令の値は float、SI | int16 × 刻み、mA と rpm（M-7、M-56 のまま） |
| 6 節: 設定の単位を SI にそろえる | v1 のまま |
| 6 節: 指令の種類に「0 止める」 | 足さない。種類は v1 と同じ（0 電流、1 速度、2 duty、3 位置）。止めるのは値 0 |
| 6 節: 止め方の bit を byte 0 の bit 7 に | duty の int16 の bit 0 のまま（M-8） |
| 6 節、問い 1: 安全側の止め方を設定 34 にまとめる | 「E-stop は常にブレーキ」のまま（M-51）。34 の既定も v1 のまま（0） |
| 6 節、問い 3: 設定が足りないと速度の指令を断る（理由 5） | 入れない。36 の焼いた値は基板の既定（M-36 のまま） |
| 4.4 節、問い 4: 「位置が切れた」の印 | 入れない。v1 と同じくつなぎ直す。位置の指令を作るときに考える |
| 問い 2: 単位を SI の float に | 取り下げ |

**MD の指令（class 2、DLC 3）の形:** byte 0 ＝ 種類（v1 の番号）、byte 1–2 ＝ int16（v1 と同じ形。duty は bit 0 が止め方、bit 1–15 が符号付きの duty）。DLC が 3 より長いのは許す（位置などを足す余白）。

**8 節の例の指令の行:** `0x210  02 26 66`（duty 0.3、空転）。

**MD について v1 から変わるのは 4 つだけ:**

1. 指令は 1 ch 1 本で、種類を中身に持つ（ユニットは 1 枚の基板がまるごと受け持つので、MD のユニットは 1 ch）。MD 16 台、100 Hz で線の 4.8% → 12.2%。
2. FB は 8 byte 固定。止めている、E-stop、異常の bit は状態のフレームに移す。
3. 刻み（48、49）は、保存できる普通の設定になる。
4. 起動の知らせと猶予が、状態のフレームと握手に替わる。

MD のフレームの符号化と、基板側の MD の動作（M-22〜M-31）の大半は、v1 のコードをそのまま使える。**問いは残っていない。**

## 追記 2（2026-11-15）: 前提の点検

ユーザの問い:「なぜこうも見落としが多いのか。ここをなんとかできなければ、私抜きでの正常な判断が続かない」。

原因（Claude）: 決定に前提を付けていなかった（float は握手が無い時点の決定で、握手を採った後に見直さなかった）。変える基準が無いまま好みで変えた。1 回に出す決定が多すぎた（本文は約 30 個）。設計には走らせて確かめる手段が無い。

本文と追記 1 に残る【Claude】の決定を、「v1 のままではだめな理由は何か。その理由は今も生きているか」で点検した結果:

| 決定 | 前提 | 結果 |
|---|---|---|
| ユニットは 1 枚の基板がまるごと受け持つ | 状態のフレームの送り手は 1 台でなければ衝突する | 生きている |

| 持ち主が生きている間は取れない | ユニットが主制御の状態のフレームを見ている | 生きている |

**これからの進め方（Claude の案）:**

- 決定に前提を 1 行書く。前提が変わったら、乗っている決定を全部見直す。台帳にも「前提」の欄を足せば、機械で洗い出せる。
- v1 から変えるものには、どの歪みに効くかを書く。書けないものは入れない。
- 1 回に出す決定は、1 つの話題で 5 個程度まで。
- 場面の表を設計のテストとして使い、早めに PC の往復テストに落とす。
- 台帳に書く前の節目では、経緯を知らない別のセッションに「理由の無い変更を探す」点検をさせる。
