## やったこと

経緯を知らないセッション（Sonnet）8 つに、人物と状況を与えて、README から読んでもらった。事実の正しさではなく、読んで迷わず進めるかを見た。

| 場面 | 着けたか | いちばん重かった所 |

| 2 年生、大会前日に 3 つの不具合 | 3 つ中 2 つ半 | 症状から直接引けない。`mixed` で、どのモーターが止まるかが読み取れない。モーターが複数のときの `check()` の使い方 |

うまくいっていた所（残す）: 「知っておくのは 3 つだけ」。成功と失敗の表示をそのまま載せること。`md_check` の 1 語から同じ名前の節へ。「今ある基板」のこなせる指令の一覧。「やりたいこと別」の「気をつけること」。「守ること」の点検表。「まだ書いていないこと」の節。仕様書の、実バイトを byte ごとに分解した例。

## 分かったこと

1. **足しすぎも引きすぎも、読む人の場面を見ずに決めた結果だった。** 午後は足しすぎ（全部入りの例、症状 9 つ）、その後は引きすぎた（サーボの入口、症状からの索引、Pico の設定）。物差しは「場面ごとに、1 ページで用が足りるか」。
2. **配線は、文章では直せない。** 3 つの場面が同じ所で止まった。実物の事実（写真か、ピンの対応の表）が要る。書ける場所を 1 つ決めて、空いている所を見えるようにしておく。
3. **仕様書の `board.md` は、仕様と、ライブラリの使い方と、現状の報告が混ざっている。** 案内の 3 ページと重なる。基板を作る人は、案内と仕様書を行き来した。
4. **`pc.md` と、基板を作る人の案内は、仕様書へ「丸投げ」している所で止まる。** 読む人が要る分は、その場面のページに写してよい（決まりの正本は仕様書の 1 か所、という原則より、場面で用が足りることを先に取る。写した所には、正本の場所を書く）。

## 方針

**案内（`docs/guide/`）は、場面ごとに 1 ページ。そのページだけで、その場面の用が足りる。** 引くもの（基板の一覧、仕様書）は別に置く。

| 場面 | ページ | 状態 |
|---|---|---|
| はじめてモーターを回す | `host/first-run.md` | ある。Pico の設定を完全な形で載せる |
| はじめてサーボを動かす | `host/first-servo.md` | **作る** |
| つなぎ方（トランシーバ、終端、電源） | `wiring.md` | **作る。** 分かっていることと、空いている所の一覧。実物の事実はユーザから |
| 動かない | `host/troubleshooting.md` | ある。冒頭に「症状から引く表」を戻す。サーボと中継機の人への 1 行。`mixed` の例。複数のモーター |
| 機体を組む | `host/robot.md` | **作る。** 番号の割り当て（完成した表、CAN-Servo の罠）、要る書き方への道、コントローラなしの緊急停止 |
| 書き方を引く | `host/howto.md` | ある。目次を、飛べるリンクにする。番号の節は「機体を組む」へ移す |
| しくみ | `host/how-it-works.md` | ある。そのまま |
| 基板を引く | `boards.md` | ある。CAN-Servo の番号の既定と注意、micro-MD の電源の確かめ方、中継機の既定の番号と事前の設定 |
| 基板を作る | `board/start.md`、`rules.md`、`test.md` | ある。モーターが複数のとき、DIP のときを足す |
| 基板を作る: ライブラリの基板側の関数と欄 | `board/node.md` | **仕様書の `board.md` から移す** |
| 基板を作る: マイコンごとの組み込み | `board/ports.md` | **仕様書の `board.md` の「ビルドへの組み込み」から移す**（共通の部品ができるまでは、今ある 3 つのやり方を書く） |
| PC で線を読む、PC から送る | `pc.md` | ある。FB の byte と状態の bit、読み下しの例、送るための最小の手順を足す |

**仕様書（`docs/spec/`）は、線の上の決まりだけ。**

| ファイル | 中身 |
|---|---|
| `README.md` | 入口 |
| `overview.md` | **入門として書き直す。** 仕組みを線の上の形で順に説明する（ユーザが編集していた `intro.md` を材料にする。stash に退避してある）。用語集 |
| `flows.md` | 場面ごとの、フレームの並び |
| `bus.md`、`ids.md`、`md.md`、`servo.md`、`settings.md` | 辞書 |
| `board.md` | **基板が守ることの確認表、基板の資料に書くこと、受信フィルタだけにする。** ライブラリの使い方、ビルド、試し方、既存のファームの一覧は、案内へ移す |

台帳の決定が仕様書に引かれているか（`spec_check.py` の「網羅」）は、移した後に確かめ、引用が減った分は辞書の側に足す。

**入口**

- `README.md`: 状態（どこまで出来ているか）を 2 行。「どこを読むか」に、サーボと PC の行。Pico の設定を完全な形に。
- `docs/internal/README.md`: 引き継ぐ人のために、今の課題の置き場（open.md、各ファームの TODO、versioning の未定、最新の点検のメモ）、v2 は保留であること、フックの有効化、ファームのビルド、ブランチの決まり。
