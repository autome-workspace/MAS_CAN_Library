# リポジトリ運用方針（版とブランチ）

このリポジトリの版の付け方とブランチの使い方を決める文書。再設計の記録（`docs/internal/archive/redesign/`。2026-11-15 に `docs/redesign/` から移した）とは分けて、長く使う方針だけを置く。決定の文には日付と「ユーザ」を添える。取り消した決定は消さず、取り消し線で残す。

## 決定

| V8 | `next` には、いつ `main` に入れてもよいものだけを置く。実機で試す必要のある変更は短命の作業ブランチ（例: `fix/audit-1030`）で進め、確かめてから `next` に入れる。`main` へは `next` を早送りで入れ、`main` に直接コミットしない。V8 より前に `next` に入った 10-30 の点検の修正（`bec935a`）は巻き戻さず、実機で確かめるまで `next` を `main` に入れない（2026-11-09、ユーザ） |
| V9 | 版は変更の性質で上げる（V3 の SemVer）。互換のある修正は修正の版（`1.0.1`）、互換のある追加（新しい基板、API）は副の版（`1.1.0`）、線の上の形や API の互換が切れる変更は主の版（`2.0.0`）。利用者に届くのはタグで、`main` は最新の版の置き場。互換の無い版の作業は、その話が出たときに `main` から `v1.x` の保守ブランチを切り、`next` をその開発に使う（v0 → v1 と同じ形）。先回りしてブランチを分けない（2026-11-09、ユーザ） |
| V10 | `next` を `main` に入れ、版を `1.1.0` にする（V9: 互換のある追加と修正）。V8 の条件の実機の確認は、CAN_MD と micro-MD で行った（[notes/2026-11-16-next-hw-test.md](notes/2026-11-16-next-hw-test.md)）。CAN-Servo のファームの修正は実機で確かめずに入れる（その旨を CAN-Servo の README に書く）。プロトコルの版（項目 3）は `1.0.0`（`0x010000C1`）のまま。**プロトコルの版は線の上の形が変わったときだけ上げ、ライブラリとタグの版とは別に数える**（U1、U7 の一部）。`core/board.h` の旧名 `MAS_CAN_BOARD_MD_2CH` は別名として残す（C-97）（2026-11-16、ユーザ） |
| V11 | `next` ブランチを廃止し、`main` 1 本を現行 v1 の最新（実機確認済み・PC テスト通過）の軸にする（V2、V8、V9 の `next` を `main` に統合）。実機未確認や仮実装は作業ブランチ（`feat/`、`fix/`、`wip/`）に置き、確認後に `main` へ統合して削除する。旧版で構成された機体はタグ（`#v1.0.0`、`#v1.1.0` 等）で固定する。将来 v2 を始めるときは `v2` ブランチを切り、正式版に移行する時点で保守用の `v1.x` ブランチを残して `main` を切り替える（2026-11-26、ユーザ） |
