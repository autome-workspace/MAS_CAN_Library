## 登場するもの

プログラムに出てくるものは 2 種類です。

- **`Host`**（例では `can`）は、主制御として線の上で話す役です。送ることも受けることも、全部これが行います。線 1 本につき 1 つ作ります。
- **取っ手**（`Md`、`Servo` など）は、「モータードライバーの 0 番」のように、相手を指すものです。`can.md(0)` で受け取ります。

取っ手は、値を覚える場所を指しているだけです。場所そのものは `Host` が持っています。そのため、同じ番号で 2 回 `can.md(0)` と書いても、同じ相手を指す取っ手が 2 つできるだけです。取っ手は、変数に入れても、関数に渡しても、コピーしても構いません。

## 値を置くことと、送ること

`motor.setDuty(0.3f)` は、値を置くだけです。この時点では、何も送られていません。

送るのは `can.update()` です。`update()` は、呼ばれるたびに、次のことを順に行います。

1. 届いているものを全部受け取り、取っ手ごとの場所に入れます。
2. しばらく声が届いていない基板を、「つながっていない」とします。
3. 置いてある値を、決まった間隔で送ります。モーターは 1 秒に 100 回、サーボは 1 秒に 50 回です。
4. 基板への設定の書き込みや問い合わせを、1 つずつ進めます。

大事なのは 3 です。**値が変わっていなくても、同じ値を送り続けます。** 基板は、指令が 0.1 秒届かないと、主制御が止まったと見て、安全のためにモーターを止めるからです。

このため、`update()` は途切れずに呼ばれる必要があります。1 秒に 100 回以上が目安で、1 秒に 20 回が下限です。それより遅いと、間隔が 0.1 秒を超えることがあり、基板が止まります。`loop()` の中の `delay()` や、時間のかかる処理が、`update()` の間隔を広げます。

置いた値をすぐ送りたいときは、`can.flush()` を呼びます。値が変わったものだけを、その場で送ります。いくつかの取っ手に値を置いてから、最後に 1 回呼びます。

## 4 個ずつ、まとめて送っている

モーターへの指令は、番号の順に 4 個ずつまとめて送られます。0〜3 番が 1 組、4〜7 番が次の 1 組、という分け方です。

**1 組の中では、指令の種類を 1 つにそろえる必要があります。** 種類とは、duty（`setDuty`）、電流（`setCurrent`）、速度（`setSpeed`）のことです。

同じ組の中で種類を混ぜると、番号がいちばん小さいモーターの種類だけが送られます。同じ種類のモーターは動きますが、違う種類のモーターは回りません。たとえば、0 番に `setSpeed`、1 番に `setDuty` を使うと、1 番は回りません。

混ざっているかどうかは、プログラムから確かめられます。

- 指令が送られていない取っ手は、`motor.commandConflict()` が `true` になります。
- `can.error()` が `Error::CommandConflict` を返します。

種類の違うモーターは、別の組になるように番号を決めてください。たとえば、速度で回す車輪を 0〜3 番、電流で回す昇降を 4 番、duty で回すローラーを 8 番にします。

サーボは 8 個ずつまとめて送られます。サーボには指令の種類が 1 つしか無いので、この心配はありません。

## 「つながっている」と「準備ができた」

モーターの取っ手には、似た確かめ方が 2 つあります。

| 関数 | `true` の意味 |
|---|---|
| `motor.online()` | 基板の声が、0.2 秒以内に届いています |
| `motor.ready()` | 基板との間で、数の読み方を合わせ終えました |

`online()` が `false` なら、基板と話せていません。電源、線、番号を疑います。

`ready()` は少し分かりにくいので、説明します。電流と速度は、線の上では「刻み × 整数」の形で送られます。この刻みが、主制御と基板で食い違うと、指令が何倍にもずれます。そこでライブラリは、基板の声が初めて届いたときに、自分の刻みを基板に書き込み、基板の返事で確かめます。

**確かめ終わるまでは、プログラムが何を置いていても、ライブラリは「止まれ」を送ります。** この間、`ready()` は `false` です。電流と速度の読み取り（`motor.current()`、`motor.speed()`）も、確かめ終わるまでは 0 を返します。

`setup()` の中の `can.waitReady(1000)` は、使っているモーター全部が `online()` かつ `ready()` になるまで、最大 1000 ミリ秒待つ関数です。コントローラの取っ手を作っていれば、それがつながるのも待ちます。待ちきれなければ `false` を返します。サーボは返事をしないので、数えません。

刻みは、変えられます。

```cpp
wheel.configSpeedResolution(0.01f);   // 速度の刻みを 0.01 rad/s に
lift.configCurrentResolution(0.002f); // 電流の刻みを 0.002 A に
```

刻みを細かくすると、送れる最大の値が小さくなります。何も指定しないときの刻みは、電流が 0.001 A、速度が約 0.105 rad/s（毎分 1 回転）です。今の刻みで送れる最大は、`wheel.speedRange()` と `lift.currentRange()` で分かります。

## 基板がモーターを止めるとき

基板は、次のときにモーターを止めます。どれも、基板が自分で判断します。

| 止まる理由 | 動き出す条件 |
|---|---|
| 指令が 0.1 秒届かない | 次の指令が届く |
| その基板にはできない指令が届いた（電流を測れない基板に電流の指令、など） | できる指令が届く |
| 電源が入ってから、まだ指令が届いていない | 指令が届く |
| 起動してから 0.2 秒たっていない | 0.2 秒たつ |
| 緊急停止がかかっている | 主制御が解除する |
| 基板が自分を守っている（過電流、過熱など。基板による） | 基板による |

止めている間、`motor.stopped()` が `true` になります。緊急停止で止まっているときは、`motor.estopLatched()` も `true` です。

基板ごとに、できる指令は違います。[今ある基板](../boards.md) の一覧で確かめてください。

## 基板が途中で再起動したとき

電源の瞬断などで、動いている最中に基板が再起動することがあります。**プログラムは何もしなくて構いません。** ライブラリと基板が、次のように片付けます。

1. 基板は起動すると、起動したことを知らせます。その後 0.2 秒は、指令が届いても動きません。
2. ライブラリは知らせに気づき、刻みを書き直します。
3. 書き直しが済むと、プログラムが置いている値で、また動き出します。

位置（`motor.position()`）は、基板の側では 0 から数え直しになります。ライブラリは、再起動の前の値に続けて数えます。ただし、基板が止まっていた間にモーターが動いた分は、数えられません。原点を決めて使っているなら、再起動の後は合わせ直す必要があります。

## 異常

基板は、過電流や過熱などに気づくと、異常があることを知らせます。ライブラリは、その中身を基板に問い合わせます。

| 関数 | 中身 |
|---|---|
| `motor.hasFault()` | 異常があります |
| `motor.faultDetail()` | 異常の中身を表す数です。数の読み方は、[仕様書の設定のページ](../../spec/settings.md) にあります |
| `motor.clearFault()` | 異常を消します |
| `can.onFault(関数)` | 新しい異常が見つかったときに、その関数を呼びます |

異常は、消すまで残ります。原因が続いていれば、消してもまた立ちます。

`can.error()` は、基板ではなく、主制御の側で起きたことを返します（線の開始に失敗した、指令の種類が混ざった、など）。覚えているのは最後の 1 つだけで、消えません。

## 緊急停止

`can.estop()` を呼ぶと、線につながっている全部の基板が止まり、止まったままになります。

- 緊急停止の間、ライブラリは「止まれ」を送り続けます。プログラムが何を置いても、動きません。
- `can.clearEstop()` で解除します。**解除のとき、ライブラリは、置いてあった値を全部「止まれ」に戻します。** 解除した瞬間に、前の値で動き出さないようにするためです。動かすには、解除の後で、もう一度値を置きます。`loop()` の中で毎回値を置いているプログラムなら、次の周から動きます。
- `can.estopped()` は、緊急停止の間 `true` です。線の上のほかの誰かがかけた緊急停止でも、`true` になります。
- **解除の前に、誰が、なぜかけたのかを確かめてください。** `loop()` で毎回値を置いているプログラムは、解除した次の周から動き出します。

知っておくこと: 緊急停止の間に、主制御だけが再起動した場合です。基板は止まったままですが、再起動した主制御の `can.estopped()` は `false` を返すはずです（コードを読んだ限りの話で、実機では確かめていません）。モーターの基板なら、`motor.estopLatched()` で分かります。この場合も、止まっている理由を確かめてから、`can.clearEstop()` を呼んでください。

## 設定の値は、どこから来るか

基板は、電流の上限や回転の向きなどの値を持っています。値の決まり方は、4 段になっています。下の段ほど、後から効きます。

| 段 | 何か | いつ決まるか |
|---|---|---|
| 0. 基板の限界 | 部品で決まる上限。変えられません | 基板を設計したとき |
| 1. 焼いた値 | ファームに書いてある既定の値 | ファームを書き込んだとき |
| 2. 保存した値 | 基板に覚えさせた値。電源を切っても残ります | 誰かが書いて、保存したとき |
| 3. 主制御が書いた値 | 動いている間だけの値。基板の電源を切ると消えます | プログラムが書いたとき |

今のライブラリで、プログラムから書けるのは、刻み（`configSpeedResolution`、`configCurrentResolution`）だけです。電流の上限や回転の向きを書く関数は、まだありません。

そのため、2 段の「保存した値」に気をつけてください。別の機体で使っていた基板は、前の機体の値を覚えているかもしれません。

## サーボ

サーボは、モーターより単純です。

- サーボの基板は、主制御に返事をしません。`online()` も `ready()` もありません。
- `arm.setAngle(...)` で置いた値を、ライブラリが 1 秒に 50 回送り続けます。
- 指令が 0.1 秒届かないと、基板はサーボの力を抜きます。
- `arm.release()` は、自分から力を抜く指令です。
