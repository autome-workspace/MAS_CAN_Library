# はじめてサーボを動かす

| | |
|---|---|
| 読む人 | 主制御のプログラムを書く人（MAS CAN がはじめてで、サーボの基板を渡された人） |
| 前提 | PlatformIO で、LED を点滅させるプログラムを書いて、マイコンに書き込める |
| 読むとできること | CAN-Servo の基板につないだサーボを 1 個動かし、2 個目も動かす |

CAN という通信の中身は、このページでは知らなくて大丈夫です。知っておくのは次の 3 つだけです。

- **主制御と基板を、2 本の線（H と L）でつなぎます。** 基板が何枚あっても、同じ 2 本につなぎ足します。
- **線の両端に、終端抵抗が要ります。** 無いと通信が不安定になります。
- **サーボには番号があります。** プログラムは「サーボの 0 番」のように、番号で相手を選びます。番号は、サーボを差した端子で決まります。

## 用意するもの

| もの | 補足 |
|---|---|
| 主制御にするマイコン | ESP32、ESP32-S3、Raspberry Pi Pico のどれか |
| CAN のトランシーバ | マイコンの信号を、CAN の線の信号に変える部品です。部でよく使うのは ATA6561 です |
| CAN-Servo の基板 | サーボを 8 個までつなげる、部の基板です |
| サーボ | 1 個か 2 個 |
| 電源 | CAN-Servo に入れる電圧と、サーボの電源をどこから取るかは、まだ書けていません。先輩に確かめてください |
| PC と USB ケーブル | PlatformIO が入っているもの |

サーボは、このページの最後で実際に動きます。動いても何かにぶつからないように、腕などは付けずに置いてください。

## 1. つなぐ

配線の詳しいことは [つなぎ方](../wiring.md) にあります。まだ書けていない所があり、そこには「先輩に確かめてください」と書いてあります。**書いていないことは、推測でつながないでください。** 電源を逆につなぐと、基板が壊れることがあります。

1. **マイコンとトランシーバをつなぎます。** このページの例では、ESP32 が TX を GPIO 5、RX を GPIO 4 に、Pico が TX を GPIO 0、RX を GPIO 1 につなぎます。
2. **トランシーバと CAN-Servo を、H どうし、L どうしでつなぎます。** CAN-Servo の CAN の線の端子は、まだ書けていません。先輩に確かめてください。
3. **終端抵抗を、線の両端の 2 か所に入れます。** 基板 1 枚と主制御だけなら、CAN-Servo の側と、主制御（トランシーバ）の側です。CAN-Servo は、基板のスライドスイッチ（SW3）で入り切りします。どちら側が「入」かは、先輩に確かめてください。
4. **サーボを、CAN-Servo の J2 に差します。** サーボの線を差す向きは、まだ書けていません。先輩に確かめてください。
5. **CAN-Servo に電源を入れます。** 基板の LED が緑に点きます。

H と L を逆につなぐと、主制御の指示が基板に届きません。動かないときに、最初に疑う所です。

## 2. サーボの番号を確かめる

CAN-Servo は、サーボの番号を端子で決めます。J2 が先頭で、J3 がその次です。

| 端子 | J2 | J3 | J4 | J5 | J6 | J7 | J8 | J9 |
|---|---|---|---|---|---|---|---|---|
| サーボの番号 | 先頭 | ＋1 | ＋2 | ＋3 | ＋4 | ＋5 | ＋6 | ＋7 |

**先頭の番号は、基板のファームで決まります。** 何も変えていないファームでは 0 なので、J2 がサーボの 0 番、J3 が 1 番です。このページは、先頭が 0 の基板で進めます。

基板にスイッチは無く、主制御から先頭の番号を読む方法もありません。先頭を変えたファームかもしれないときは、ファームを書き込んだ人に確かめてください。変え方は [今ある基板](../boards.md#can-servo) にあります。

CAN-Servo は、モーターの 0〜3 番も受け持っています（何も変えていないファームのとき）。同じ線にモータードライバーの基板もつなぐときは、その基板を 4 番以上にしてください。同じ番号の基板が 2 枚あると、どちらも正しく動きません。

## 3. プロジェクトを作る

PlatformIO で新しいプロジェクトを作り、`platformio.ini` を次のようにします。使う主制御の分だけを書きます。

ESP32:

```ini
[env:esp32]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
lib_deps = https://github.com/autome-workspace/MAS_CAN_Library.git#v1.0.0
build_flags = -D CAN_TX=5 -D CAN_RX=4
```

ESP32-S3 は、`board` の行を `esp32-s3-devkitc-1` に変えます。

Raspberry Pi Pico:

```ini
[env:pico]
platform = https://github.com/maxgerhardt/platform-raspberrypi.git#9c167c6b8aac4f4cfa6d55a0c4e5b848795150c0
board = pico
board_build.core = earlephilhower
framework = arduino
monitor_speed = 115200
lib_deps =
    https://github.com/autome-workspace/MAS_CAN_Library.git#v1.0.0
    https://github.com/obdevel/ACAN2040.git#1.0.6
build_flags = -D CAN_TX=0 -D CAN_RX=1
```

`lib_deps` の行が、取り込むライブラリの指定です。1 行目が MAS CAN のライブラリです。Pico は、CAN を扱うためのライブラリ（ACAN2040）も取り込みます。

`build_flags` の行は、手順 1 でつないだピンの番号です。プログラムの `CAN_TX`、`CAN_RX` に、この番号が入ります。別のピンにつないだなら、ここを変えます。

## 4. プログラムを書く

`src/main.cpp` を次のようにします。[`examples/servo_minimal`](../../../examples/servo_minimal/src/main.cpp) から、コメントを 2 行除いたものです。

```cpp
#include <Arduino.h>
#include <mas/can.h>

namespace mcan = mas::can;

mcan::Host can;
mcan::Servo arm = can.servo(0); // ch 0 のサーボ

void setup() {
    Serial.begin(115200);
    if (!can.begin(CAN_TX, CAN_RX)) Serial.println(mcan::toString(can.error()));
    arm.configCalibration(-1.57f, 1.57f, 500, 2500); // -90° で 500 µs、+90° で 2500 µs
}

void loop() {
    can.update();

    float t = millis() * 0.001f;
    arm.setAngle(sinf(t) * 1.0f); // ±1 rad をゆっくり往復
}
```

登場するものは 3 つです。

- **`can`** は、主制御として線の上で話す役です。送ることも受けることも、これがまとめて行います。
- **`arm`** は、「サーボの 0 番」を指す取っ手です。`can.servo(0)` の 0 が、手順 2 で確かめた番号です。コメントの「ch」は、この番号のことです。
- **`can.update()`** が、実際に送り、受けます。`loop()` の中で毎回呼びます。`arm.setAngle(…)` は値を置くだけで、その値を基板に届けるのは `update()` です。

`loop()` の中に、`delay(100)` のような長い待ちを入れないでください。主制御はサーボへの指示を 0.02 秒ごとに送り、基板は 0.1 秒指示が来ないと、安全のためにサーボの力を抜きます。長く待つと、サーボの力が抜けたり入ったりします。

### 角度はラジアンで渡す

`setAngle` には、角度を度ではなく**ラジアン**で渡します。ライブラリの角度は、どこでもラジアンだからです。度からは「度 × 3.14 ÷ 180」で直せます。

| 度 | ラジアン |
|---|---|
| 0° | 0 |
| 30° | 0.52 |
| 45° | 0.79 |
| 60° | 1.05 |
| 90° | 1.57 |
| −45° | −0.79 |
| −90° | −1.57 |

たとえば 45° に向けるなら `arm.setAngle(0.79f);` です。例の `sinf(t) * 1.0f` は、−1 から +1 ラジアン、つまり約 −57° から約 +57° の間を動きます。

### `configCalibration` で、角度とパルス幅の対応を教える

サーボは、基板から来る短い電気の合図（パルス）の長さで、向く角度を決めます。この長さを**パルス幅**と呼び、µs（100 万分の 1 秒）で数えます。

サーボは機種によって、同じパルス幅でも向く角度が違います。そこで `configCalibration` で、角度とパルス幅の対応を 2 点で教えます。4 つの引数は次のとおりです。

| 引数 | 例の値 | 意味 |
|---|---|---|
| 1 つ目 | `-1.57f` | 1 点目の角度（ラジアン） |
| 2 つ目 | `1.57f` | 2 点目の角度（ラジアン） |
| 3 つ目 | `500` | 1 点目の角度のときのパルス幅（µs） |
| 4 つ目 | `2500` | 2 点目の角度のときのパルス幅（µs） |

例は「−90° で 500 µs、+90° で 2500 µs」と教えています。その間の角度は、2 点を結ぶ直線でパルス幅に直します。外の角度は、500 µs か 2500 µs で止まります。

`configCalibration` を呼ばなくても、同じ「−90° で 500 µs、+90° で 2500 µs」で動きます。サーボの向きを逆にしたいときは、3 つ目と 4 つ目を入れ替えます（`arm.configCalibration(-1.57f, 1.57f, 2500, 500);`）。

## 5. 書き込んで、動くのを見る

1. プログラムを書き込みます。
2. サーボが、約 −57° と約 +57° の間を、約 6 秒で 1 往復します。これで成功です。
3. CAN-Servo の LED が、緑から青に変わります。青は「主制御の指示で、サーボを動かしています」という意味です。

シリアルモニタ（115200）には、うまくいっているときは何も出ません。`port start failed` と出たら、主制御が CAN を始められていません。`platformio.ini` の `build_flags` のピンの番号を見てください。

**止めるには**、`arm.release();` を呼びます。サーボへのパルスが止まり、力が抜けます。もう一度 `setAngle` を呼ぶと、また動きます。力が抜けると、付けたものの重みでサーボの軸が回ることがあります。急ぐときは、主制御の USB を抜きます。指示が途切れるので、基板は 0.1 秒でサーボの力を抜きます。

## 6. 2 個目を動かす

2 個目のサーボは、J3 に差します。J3 はサーボの 1 番なので、プログラムでは `can.servo(1)` です。

手順 4 のプログラムに、次の 3 か所を足します。

```cpp
mcan::Servo hand = can.servo(1); // J3 のサーボ。arm の行の下に足す

// setup() の中に足す
hand.configCalibration(-1.57f, 1.57f, 500, 2500);

// loop() の中、arm.setAngle の下に足す
hand.setAngle(0.79f); // 45° で止めておく
```

書き込むと、1 個目は往復を続け、2 個目は 45° を向いて止まります。`configCalibration` は、サーボ 1 個ずつに教えます。機種の違うサーボを混ぜるときは、それぞれに合う値を入れます。

1 枚の CAN-Servo には、J2 から J9 までの 8 個（0〜7 番）をつなげます。9 個目からは 2 枚目の CAN-Servo を使い、2 枚目のファームの先頭を 8 にします（[今ある基板](../boards.md#can-servo)）。

## 動かないとき

**サーボの基板は、主制御に返事をしません。** そのため、主制御のプログラムからは、指示が届いているかが分かりません。モーターのときに使う `md_check`（基板の返事を見て、回らない理由を表示する例）は、サーボには使えません。代わりに、CAN-Servo の LED の色を見ます。

| LED | 意味 | 確かめること |
|---|---|---|
| 消えている | 基板が動いていません | 基板の電源。基板にファームが入っているか |
| 緑のまま | 基板は動いていますが、主制御の指示が届いていません | 下の 1〜4 |
| 青 | 指示は届き、サーボにパルスを出しています | 下の 5 |
| 赤 | 緊急停止がかかっています | 下の 6 |

緑のままのときは、次の順に確かめます。

1. **H と L。** 入れ替わっていると、指示が届きません。
2. **終端抵抗。** 線の両端の 2 か所に入っているかを見ます。
3. **主制御のピン。** `platformio.ini` の `CAN_TX`、`CAN_RX` が、つないだピンと合っているか、入れ違っていないかを見ます。
4. **サーボの番号。** ファームの先頭が 0 でないと、`can.servo(0)` の指示は、この基板に向いていません。手順 2 を見てください。

青なのにサーボが動かないときは、次を確かめます。

5. **サーボの差し場所と電源。** 番号に合う端子（0 番なら J2）に差しているかを見ます。サーボの線の向きと、サーボの電源は、先輩に確かめてください。

赤のときは、主制御か、同じ線の別の主制御が、緊急停止をかけています。

6. **誰が、なぜかけたのかを確かめてから**、`can.clearEstop()` で解除します。解除した直後のサーボは、力が抜けています。次の `setAngle` で、また動き出します。

配線の確かめ方は [つなぎ方](../wiring.md) に、LED の色の意味は [今ある基板](../boards.md#can-servo) にもあります。
