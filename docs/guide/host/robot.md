# 機体を組む

| | |
|---|---|
| 読む人 | 機体 1 台ぶんの主制御のプログラムを任された人 |
| 前提 | [はじめて回す](first-run.md) を済ませ、モーターを 1 個回した |
| 読むとできること | 機体の全部のモーターとサーボに、ぶつからない番号を割り当て、基板をその番号に合わせてから、プログラムを書き始められる |

書き始める前に、番号の割り当てを紙に書いて決めます。後から番号を変えると、基板の設定とファームの書き込みをやり直すことになるからです。

## 番号は、4 個ずつの組で決める

**モーターの番号は、4 個ずつの組で、指令の種類をそろえて決めます。** 0〜3 番、4〜7 番、8〜11 番、のように 4 個ずつが 1 組です。指令の種類とは、速さ（`setSpeed`）、電流（`setCurrent`）、duty（`setDuty`）のことです。

ライブラリは、1 組の 4 個への指令を、1 つにまとめて送ります。そのため、1 組の中では種類を 1 つにしかできません。混ぜると、指令を置いた中で番号がいちばん小さいモーターと同じ種類のものだけが動き、違う種類のものは回りません。しくみは [しくみ](how-it-works.md) の「[4 個ずつ、まとめて送っている](how-it-works.md#4-個ずつまとめて送っている)」にあります。

**同じ組に、違う基板が入っても構いません。** 指令の種類がそろっていればよいです。基板は、まとめて届いた指令の中から、自分の番号の分だけを読むからです。たとえば、4 番を CAN_MD、5 番を micro-MD にして、両方を電流で動かせます。

**サーボの番号は、モーターとは別に数えます。** 「モーターの 0 番」と「サーボの 0 番」は、同じ線の上に同時にいて構いません。サーボには指令の種類が 1 つしか無いので、組の心配はありません。

**使える番号は、モーターが 0〜31、サーボが 0〜63 です。** `can.md(32)` のように範囲の外を求めると、何もしない取っ手が返ります。その取っ手の `ch()` は 255 です。

**同じ種類で同じ番号の基板を、2 枚つながないでください。** 2 枚とも同じ指令に従い、主制御に届く返事が混ざるので、どちらも正しく動きません。

## 割り当ての例

足回りを XDrive 4 台、昇降を 1 個、ローラーを 1 個、ハンドをサーボ 2 個で動かす機体の例です。

| 動かすもの | 基板 | 指令の種類 | 番号 |
|---|---|---|---|
| 足回り（4 輪） | XDrive の中継機 | 速さ（`setSpeed`） | モーター 0〜3 |
| 昇降 | CAN_MD | 電流（`setCurrent`） | モーター 4 |
| ローラー | micro-MD | duty（`setDuty`） | モーター 8 |
| ハンド | CAN-Servo | 角度（`setAngle`） | サーボ 0 と 1 |
| （使わない） | CAN-Servo のモーター | duty だけ | モーター 12〜15 |

組で見ると、0〜3 番が速さ、4〜7 番が電流、8〜11 番が duty、12〜15 番が CAN-Servo のモーターです。5〜7 番には電流で動かすモーターを、9〜11 番には duty で動かすモーターを、後から足せます。

いちばん下の行が、次の節の罠です。CAN-Servo は、モーターを使わなくても、モーター 4 個ぶんの番号を取ります。

プログラムでは、取っ手を次のように作ります。モーターの 3 行は [`examples/api_tour`](../../../examples/api_tour/src/main.cpp) と同じ番号です。サーボの 2 行は、`api_tour` の `can.servo(0)` を 2 個にしたものです。

```cpp
mcan::Md wheel[4] = {can.md(0), can.md(1), can.md(2), can.md(3)}; // 足回り。速さ
mcan::Md lift = can.md(4);   // 昇降。電流
mcan::Md roller = can.md(8); // ローラー。duty
mcan::Servo hand[2] = {can.servo(0), can.servo(1)}; // ハンド
```

## CAN-Servo と XDrive の中継機は、そのままだと番号がぶつかる

**CAN-Servo の基板は、モーターを 1 個も使わなくても、モーター 4 個ぶんの番号を取ります。** 何も変えずに書き込んだファームでは、その番号は 0〜3 です（[`firmware/CAN-Servo-v1/platformio.ini`](../../../firmware/CAN-Servo-v1/platformio.ini) の `MD_FIRST_CH=0`）。

**XDrive の中継機も、何も変えなければ 0〜3 番です**（[`firmware/xdrive-relay/platformio.ini`](../../../firmware/xdrive-relay/platformio.ini) の `MD_FIRST_CH=0`）。そのため、2 つを同じ線につなぐと、0〜3 番の基板が 2 枚になり、足回りが正しく動きません。

直し方は、CAN-Servo のファームの番号を、使っていない組に変えて書き込み直すことです。

1. [`firmware/CAN-Servo-v1/platformio.ini`](../../../firmware/CAN-Servo-v1/platformio.ini) の `-D MD_FIRST_CH=0` を、`-D MD_FIRST_CH=12` に書き換えます。値は 4 の倍数にします。
2. `firmware/CAN-Servo-v1` のフォルダで `pio run -t upload` を実行し、CAN-Servo に書き込みます。

サーボの番号（`SERVO_FIRST_CH`）は、モーターとは別に数えるので、0 のままで構いません。CAN-Servo のほかに、モーター 4 個ぶんの番号を取る基板（XDrive の中継機、2 枚目の CAN-Servo）があれば、それぞれ別の組にします。

## 基板ごとに、先にしておくこと

割り当てが決まったら、基板の番号を割り当てに合わせます。番号の決め方は基板ごとに違い、詳しくは [今ある基板](../boards.md) にあります。

| 基板 | 番号の決め方 | 上の例では |
|---|---|---|
| [XDrive の中継機](../boards.md#xdrive-の中継機) | ファームを書き込むときに決めます。XDrive の側にも、先にしておく設定があります | 何も変えずに 0〜3 |
| [CAN_MD](../boards.md#can_md) | 基板の DIP スイッチ | 4。DIP スイッチの 3 だけを ON にして、電源を入れ直します |
| [micro-MD](../boards.md#micro-md) | 基板のスイッチを押して決めます | 8。長押し、短く 8 回、長押し |
| [CAN-Servo](../boards.md#can-servo) | ファームを書き込むときに決めます | サーボは 0 のまま。モーターは 12 に変えます（上の節） |

番号を合わせたら、1 枚ずつ確かめます。CAN_MD と micro-MD は、LED の点滅の回数が番号です。回らない基板があれば、[動かないとき](troubleshooting.md) の `md_check` を、その番号に合わせて書き込みます。

## コントローラなしで、緊急停止を入れる

**コントローラが無くても、PC のシリアルモニタから緊急停止をかけられるようにしておきます。** 機体を初めて動かすときに、止める手段が要るからです。最小の組み合わせは、1 文字で `can.estop()`、別の 1 文字で `can.clearEstop()`、異常の知らせをシリアルに出す、の 3 つです。

次は [`examples/md_serial_test`](../../../examples/md_serial_test/src/main.cpp) の書き方から、この 3 つだけを抜き出したものです。文字は `md_serial_test` と同じく、`e` が緊急停止、`c` が解除です。`md_serial_test` は 1 行ずつ読みますが、ここでは改行を待たずに 1 文字ずつ見るように変えています。改行が届かなくても、緊急停止が効くようにするためです。

```cpp
void onFault(mcan::Device &dev, uint32_t bits) {
    Serial.printf("! MD %d fault 0x%08lx\n", dev.ch(), (unsigned long)bits);
}

void setup() {
    // ...
    can.onFault(onFault);
}

void loop() {
    can.update();
    while (Serial.available()) {
        char c = (char)Serial.read();
        if (c == 'e') can.estop();
        if (c == 'c') can.clearEstop();
    }
    // ...
}
```

`e` を送ると、線につながっている全部の基板が止まります。CAN-Servo の LED が赤になれば、緊急停止は届いています。

シリアルから数字を打って値を渡す書き方（`d 0.3` で duty を 0.3 にする、など）も、`md_serial_test` にあります。1 行を読んで、頭の 1 文字で分ける書き方です。

## 機体を組むときの注意

ここに書くのは、機体 1 台ぶんの例を書いて点検したときに見つかったことです。

**緊急停止の間は、アプリの側の目標も 0 に戻しておきます。** ライブラリは、解除のときに、置いてあった値を全部「止まれ」に戻します。しかし、`loop()` が毎回目標を置き直していると、解除した次の周に、その目標で動き出します。ほかの主制御がかけた緊急停止が解除されたときも同じです。`can.estopped()` が `true` の間は、目標の変数を毎周 0 にしておきます。

```cpp
if (can.estopped()) lift_target = 0.0f; // lift_target は、アプリが持つ昇降の目標
lift.setCurrent(lift_target);
```

**車輪が 1 つ使えないときに足回りを全部止めるなら、`online()`、`ready()`、`hasFault()` で見ます。** XDrive が過電流で止まった車輪は、`online()` も `ready()` も `true` のままです。そのため、`hasFault()` も見ないと、残りの 3 輪だけが回り続けます。`stopped()` は条件に入れません。`stopped()` は、まだ指令を置いていない間も `true` なので、入れると一度も動き出せなくなります。

```cpp
bool wheelsOk() {
    for (auto &w : wheel) {
        if (!w.online() || !w.ready() || w.hasFault()) return false;
    }
    return true;
}
```

**初めて回すときは、車輪を床から浮かせ、小さい値から試します。** 速さなら `setSpeed(1.0f)`（約 6 秒で 1 回転）からです。XDrive の中継機で最初に渡してよい速さは、まだ書けていないので、小さい値から上げていきます。

**操作が途切れたら、全部の軸を止めます。** コントローラの無線が切れたときや、PC からの操作が来なくなったときです。止めないと、最後に置いた値で回り続けます。足回りだけでなく、昇降やローラーも、軸ごとにどうするかを決めます。基板の線を挿し直したときも、準備が済みしだい、置いてある値で動き出すことを覚えておいてください。

**電流の指令の 0 A は、力を抜く指令です。その場に保つ指令ではありません。** 重さのかかる昇降を 0 A にすると、重さで下がることがあります。緊急停止のときは、CAN_MD も micro-MD もブレーキで止めるので、0 A とは止まり方が違います。保持が要る機構は、別に考えます。

**小さな電流の指令は、思ったとおりに出ません。** CAN_MD は duty 0.345 より、micro-MD は duty 0.23 より下がらないからです。軽い昇降を小さな電流で動かすと、端まで回り続けることがあります。0 A の指令は、この下限にかかりません。詳しくは [今ある基板](../boards.md) と、各基板の資料（[`firmware/CAN_MD/README.md`](../../../firmware/CAN_MD/README.md)、[`firmware/micro-MD/README.md`](../../../firmware/micro-MD/README.md)）にあります。
