# 確かめ方

> **下書き（2026-11-15）。** 手順は、例のプログラム（`examples/`）のコードと突き合わせました。実機では確かめていません。

| | |
|---|---|
| 読む人 | 基板のファームを作る人 |
| 前提 | ファームが書き込めて、基板が CAN の線につながっている。[守ること](rules.md) を読んだ |
| 読むとできること | 主制御のプログラムを自分で書かずに、作った基板が決まりどおり動くかを確かめられる |

確かめ方は 2 段あります。先に PC の上で、次に実機で確かめます。

## PC の上で確かめる

基板が無くても、ライブラリの基板側（node）の動きは PC で確かめられます。

```sh
make -C lib/mas/test
```

4 つのテストが走り、それぞれ `all ... tests passed` と出れば成功です。ライブラリを触っていなければ、ここは通るはずです。

自分のファームの中の判断（番号が範囲の外のときの扱いなど）を PC で確かめたいときは、その部分をハードウェアに触らない関数に分けて、node と一緒にコンパイルします。

```sh
gcc -std=c11 -I lib/mas/include my_test.c \
    lib/mas/src/can/node.c lib/mas/src/can/core/md_frame.c lib/mas/src/can/core/setting.c
```

書き方の見本は [`lib/mas/test/test_node.c`](../../../lib/mas/test/test_node.c) です。

## 実機で確かめる

主制御にするマイコン（ESP32 か Raspberry Pi Pico）が 1 つ要ります。プログラムは書かなくて構いません。用意してある例を書き込んで使います。

線には、確かめたい基板と主制御だけをつなぎます。モーターは、回っても危なくないようにしておきます。

### 1. 見えるかを確かめる

[`examples/md_serial_test`](../../../examples/md_serial_test/) を主制御に書き込み、シリアルモニタ（115200）を開きます。この例は、シリアルから 1 行ずつ命令を送って、基板を試す道具です。最初は 0 番の基板を見ています。自分の基板が別の番号なら、`ch 3` のように送って切り替えます。

状態は、0.2 秒ごとに 1 行で出ます。

```
[3] on  0.000 A duty +0.00 stop fault 0x0
```

確かめること:

- [ ] `on` と出る。`--` のままなら、主制御に声が届いていません。[動かないとき](../host/troubleshooting.md) の「`offline`」を見ます。基板の側では、通信の速さ、`mas_can_node_ready()` を呼んでいるか、を疑います。
- [ ] `on` の後ろの `(wait)` が、すぐ消える。消えないなら、設定への返事ができていません。
- [ ] `stop` と出ている。指令を送っていないので、止まっているのが正しい動きです。

### 2. 動かして確かめる

同じ例のまま、命令を送ります。

| 命令 | すること |
|---|---|
| `ch 3` | 相手を 3 番にする |
| `d 0.3` | duty 0.3 で回す |
| `i 0.5` | 電流 0.5 A で回す |
| `s` | 止める |
| `e` / `c` | 緊急停止 / 解除 |
| `x` | 異常を消す |

確かめること:

- [ ] `d 0.3` で回る。`d -0.3` で逆に回る。`s` で止まる。
- [ ] 回している最中に、CAN の線を抜く。**0.1 秒ほどで、モーターが止まる。** 線を戻すと、また回る。
- [ ] `e` で止まる。表示に `estop` と出る。この間、`d 0.3` を送っても回らない。
- [ ] `c` で解除する。解除しただけでは回らない。もう一度 `d 0.3` を送ると回る。
- [ ] 回している最中に、基板の電源を入れ直す。何もしなくても、また回り出す。
- [ ] 電流を測れない基板に `i 0.5` を送る。回らず、表示に `stop` と出る。できない指令で止まるのが、正しい動きです。
- [ ] 表示の電流や duty が、実際の動きと合っている。

サーボの基板は、[`examples/servo_minimal`](../../../examples/servo_minimal/) で確かめます。サーボは返事をしないので、動きと LED を目で見ます。指令の線を抜いて、サーボの力が抜けることを確かめます。

### 3. 基板の情報を読む

基板の種類の番号やファームの版が正しく返るかは、今の主制御のライブラリからは読めません。USB-CAN のアダプタなどで、線に直接送って確かめます。送る中身は、仕様書の [基板の情報を生のフレームで読む](../../spec/board.md#基板の情報を生のフレームで読む) にあります。

## 最後に

[守ること](rules.md) の点検表を、上から順にもう一度見ます。実機で確かめにくい項目（フラッシュに書いている間の出力、番号が範囲の外のとき）は、その場面をわざと作って確かめます。
