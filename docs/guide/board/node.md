## node がすること、ファームがすること

ここでの「ファーム」は、あなたが書く、ハードウェアに触る部分です。

| node が自動でやること | ファームがやること |
|---|---|
| 緊急停止（E-stop）のラッチと解除。リモートフレームの `0x000` も緊急停止として扱う | CAN の初期化（速さ、受信フィルタ）と送受信。受けたフレームの `rtr` を埋める |
| MD の指令の読み取り。DLC の外の slot、こなせない指令の扱い | 時刻（µs）を渡す |
| 指令の途絶（0.1 秒）で止める | 基板の番号（スイッチの値）を読み、範囲を確かめる |
| 起動の知らせ（MD の分）と、起動の猶予（0.2 秒） | 固有 ID、基板の種類、ファームの版、できることを `cfg` で渡す |
| FB を、設定の項目 35 の周期で組み立てる | フラッシュの読み書き（`load`、`save`） |
| 設定への返事（共通の項目 0〜6、MD の項目 32〜41、45、46、48、49） | 再起動（返事を線に出し終えてから） |
| 書かれた値の範囲を確かめ、できることの上限で抑える | node の出力を受けて、モーターに出す |
| 保存と初期化（保存する中身を組み立て、CRC を付ける） | 電流の上限（duty を含むどの指令にも）、最高速度、最大加速度、速度ループの PID を効かせる |
| 項目 48、49（指令の刻み）を保存せず、起動で 1.0 に戻す | エンコーダの換算（項目 36、37、38）。位置、速度、電流を測る |
| 回転方向の反転（項目 32）を、指令と FB の両方にかける | 電流の上限に当たったこと、保護で止めていることを渡す |
| 指令の刻み（項目 48、49）の換算 | バスオフからの復帰と、基板の異常（過電流など）を知らせる |
| 異常の詳細の「再起動した」「保存した設定が壊れていた」と、FB の「異常あり」の bit | サーボなど、node が持たない種類の全部 |

## 呼ぶ順

起動のときは、次の順に呼びます。順番を変えると、準備が済んでいないのに主制御が話しかけてくるからです。

1. **出力を止めた状態で、モーターを用意します。** 電源を入れた直後に、モーターが動き出さないためです。
2. **基板の番号を読み、範囲を確かめます。** 番号は、このとき 1 回だけ読みます。
3. **`mas_can_node_config_t` を埋めて、`mas_can_node_init` を呼びます。** node はこの中で `load` を呼び、保存した設定を読みます。
4. **CAN を初期化します。**
5. **`mas_can_node_ready` を呼びます。** node が起動の知らせを積み、ここから FB を送り始め、0.2 秒の起動の猶予を数えます。

その後のメインのループでは、受けたフレームを `mas_can_node_on_frame` に渡し、`mas_can_node_tick` を呼び、モーターごとに `mas_can_md_output` で出すべきものを受け取って出し、測った値を `mas_can_md_set_measure` で渡し、`mas_can_node_peek_tx` と `mas_can_node_drop_tx` で送ります。形は下の [メインのループの形](#メインのループの形) にあります。

## 基板の性質を渡す（mas_can_node_config_t）

`mas_can_node_init` は `cfg` の中身を node の中に写します。そのため、呼んだ後に `cfg` を捨てて構いません。使わない欄は 0 にしておきます（C なら `memset`、C++ なら `= {}`）。

| 欄 | 入れるもの | 0 のままだと |
|---|---|---|
| `uid` | 基板ごとに違う番号（固有 ID）。マイコンに書かれた番号から作ります。作り方は仕様書の [基板の情報](../../spec/board.md#基板の情報設定の共通の項目) にあります | どの基板も、固有 ID として 0 を返します |
| `board_type` | 基板の種類の番号と版。`MAS_CAN_BOARD_TYPE(種類, 版)` で作ります。番号の取り方は仕様書の [基板の種類の登録の手順](../../spec/board.md#基板の種類の登録の手順) にあります | 種類 `0x0000`、版 0 を返します。版は 1 から数えるので、0 は正しい値ではありません |
| `fw_version` | ファームの版。`0x00MMmmpp`（上から 0、大、中、小）。`0x00000100u` なら 0.1.0 です | 版 0.0.0 を返します |
| `md_first_ch` | 受け持つ MD の先頭の ch。決め方は [雛形から始める](start.md#モーターが複数のときの番号) にあります | ch 0 から受け持ちます。node は範囲を確かめないので、確かめるのはファームです |
| `md_count` | 受け持つ MD の数。0〜4（`MAS_CAN_NODE_MD_MAX`） | MD を受け持ちません。MD の起動の知らせも送りません。4 を超える値は 4 に切られます |
| `md_has_current` | 電流を測れるなら true | FB で「電流は無効」と知らせ、電流の指令は、こなせない指令として止めます |
| `md_has_speed` | 速度と位置を測れるなら true | FB で「速度と位置は無効」と知らせ、速度の指令は、こなせない指令として止めます |
| `md_has_coast` | 空転を出せるなら true | 空転を出せない基板として扱います。止め方（項目 34）はいつもブレーキになり、0 を書かれても 1 に抑えて返します。duty の指令の `brake` も、いつも true になります |
| `md_no_duty` | duty を出せない基板（中継役など）なら true | duty を出せる基板として扱います |
| `md_current_limit_max_ma` | 電流の上限（項目 33）に書ける最大。部品の限界です | **主制御が項目 33 に何を書いても、0 に抑えられます。** 抑えるのは書かれたときだけで、焼いた値と保存した値はこの上限で抑えません。下の `md_current_limit_default_ma` 以上にします |
| `md_fb_rate_max_hz` | FB の周期（項目 35）に書ける最大（Hz） | **主制御が項目 35 を書いた時点で 0（送らない）に抑えられ、FB が止まります。** 焼いた値の 100 は抑えないので、書かれるまでは FB が出ます。100 以上にします |
| `md_current_limit_default_ma` | 項目 33 の焼いた値（基板の既定）。部品の限界以下にします | 項目 33 の焼いた値が 0 になります |
| `md_encoder_cpr_default` | 項目 36（エンコーダの 1 回転のカウント数）の焼いた値 | 1 になります |
| `load` | 保存した設定を `buf` に `len` byte 読む関数。読めたら true | 保存した設定を読まず、焼いた値で起動します。下の [フラッシュ](#フラッシュload-と-save) |
| `save` | `buf` の `len` byte をフラッシュに書く関数。書けたら true | 保存と初期化の求めに、失敗（結果 63）を返します。false を返したときも同じです |
| `restart` | 再起動する関数 | **必ず渡します。** 渡さないと、主制御の再起動の求めに成功を返したうえで、再起動しません。下の [再起動](#再起動restart) |
| `ctx` | `load`、`save`、`restart` の最初の引数にそのまま渡すもの | NULL を渡します |

電流を測れない基板では、`md_current_limit_max_ma` と `md_current_limit_default_ma` を 0 のままにして構いません。理由は [雛形から始める](start.md#電流を測れない基板の電流の上限) にあります。

node が持つ焼いた値（ファームから変えられないもの）は次のとおりです。項目 32 は 0、34 は 0（空転を出せなければ 1）、35 は 100、37 は 1.0、38 は 0、39〜41 は 0、45 と 46 は 0、48 と 49 は 1.0 です。速度ループのゲイン（39〜41）の焼いた値を基板ごとに渡す欄は、今はありません。

## 関数

| 関数 | いつ呼ぶ | すること |
|---|---|---|
| `mas_can_node_init(node, cfg, now)` | 起動のときに 1 回。CAN を始める前 | `cfg` を写し、`load` で保存した設定を読み、異常の詳細の「再起動した」を立てる |
| `mas_can_node_ready(node, now)` | CAN を初期化した後に 1 回 | MD の起動の知らせを積む。ここから FB を送り、0.2 秒の起動の猶予を数える |
| `mas_can_node_on_frame(node, f, now)` | 受けた標準 ID のフレームごと | `0x000`、`0x001`、`0x210`〜`0x22F`、`0x400` を処理し、ほかは捨てる。設定への返事と保存は、この中で行う |
| `mas_can_node_tick(node, now)` | メインのループで毎回 | 指令の途絶を判断し、FB を送る時刻が来ていれば FB を積む |
| `mas_can_node_peek_tx(node)` | 送るとき | 送る待ち行列の先頭を返す。無ければ NULL |
| `mas_can_node_drop_tx(node)` | 先頭を CAN のコントローラに渡せた後 | 先頭を消す。再起動を求められていて、待ち行列が空になったら `restart` を呼ぶ |
| `mas_can_md_output(node, local)` | モーターごとに、ループ 1 周に 1 回 | 出すべきものを返す（下）。`reset_ctrl` は読むと消える |
| `mas_can_md_set_measure(node, local, m)` | モーターごとに、ループ 1 周に 1 回 | 測った値を渡す。次の FB に載る |
| `mas_can_md_settings(node, local)` | 制御に設定の値を使うとき | 設定の今の値を返す（下）。範囲の外の `local` には NULL |
| `mas_can_node_raise_fault(node, bits)` | 基板が異常に気づいたとき | 異常の詳細の bit を立てる（下） |
| `mas_can_node_in_grace(node, now)` | 指令を自分で受けるとき（サーボなど） | `ready` の前と、その後 0.2 秒の間は true |

`local` は、基板の中のモーターの番号です。0 から `md_count` − 1 まであり、そのモーターの ch は `md_first_ch` に `local` を足した値です。時刻はすべて µs の `uint32_t` です。一周して 0 に戻っても構いません。

`mas_can_node_t` は `static` に 1 つ置きます。中身が `node.h` で見えているのは、静的に置けるようにするためで、欄を直接触ってはいけません。ただし、緊急停止のラッチ、起動を知らせた後か、`cfg` を読む関数はまだ無いので、`node.estop`、`node.ready`、`node.cfg` は読んで構いません（書かないでください）。既存のファームも読んでいます。CAN-Servo のファームは `node.estop` と `node.ready` を、CAN_MD と micro-MD は `node.cfg.md_first_ch` を読んでいます。

## 出すべきもの（mas_can_md_output_t）

`mas_can_md_output()` が返す値です。ファームは、判断し直さずにそのまま出します。止めるかどうかは、node がもう決めているからです。

| `mode` | `value` | `brake` |
|---|---|---|
| `MAS_CAN_MD_OUT_STOP` | 0 | true ならブレーキ（短絡）、false なら空転。緊急停止のときは、いつも true |
| `MAS_CAN_MD_OUT_DUTY` | duty（−1.0〜+1.0） | PWM を切っている間をブレーキにするか。空転を出せない基板では、いつも true |
| `MAS_CAN_MD_OUT_CURRENT` | 電流（mA） | 使わない |
| `MAS_CAN_MD_OUT_SPEED` | 出力軸の速度（rpm） | 使わない |

- **値は、そのまま使います。** 指令の刻み（項目 48、49）と回転方向の反転（項目 32）は、node がかけ済みです。ファームがもう一度反転をかけると、元に戻ってしまいます。
- **止める理由は、全部 `STOP` になります。** 途絶、緊急停止、起動の猶予、こなせない指令、保護で止めている間（`protecting`）、位置の指令です。
- **`reset_ctrl` が true なら、制御の状態を消します。** 積分の値や、加速度を抑える起点などです。止まっていた後や、指令の形が変わった後に、古い状態のまま飛び出さないためです。
- **電流の上限（33）、最高速度（45）、最大加速度（46）、速度ループの PID（39〜41）は、node はかけません。** ファームが [設定の今の値](#設定の今の値mas_can_md_settings) を読んで効かせます。電流の上限は、duty の指令にも効かせます。

## 測った値（mas_can_md_measure_t）

`mas_can_md_set_measure()` で渡す値です。次の FB に載ります。

| 欄 | 中身 |
|---|---|
| `current_ma` | 電流（mA）。モーターの巻線の電流です。`md_has_current` が true のときだけ意味があります |
| `speed_rpm` | 出力軸の速度（rpm）。`md_has_speed` が true のときだけ意味があります |
| `position` | 出力軸の位置。1 回転を 65536 として数え、24 bit で折り返します。電源を入れたときが 0 です |
| `duty` | 実際に出している duty（−1.0〜+1.0） |
| `current_limited` | 電流の上限に当たっているか。FB の「電流の上限」の bit になります |
| `protecting` | 基板を守るために止めているか。FB の「止めている」の bit になり、true の間、node の出力は `STOP` になります |

- **向きは、基板から見た向きで渡します。** エンコーダの反転（項目 38）はファームがかけ、回転方向の反転（項目 32）はかけません。32 は node が FB にかけます。
- **エンコーダのカウントから、出力軸の位置と速度への換算は、ファームが行います。** 使う値は、項目 36（1 回転のカウント数）と 37（減速比）です。
- **測れない欄は 0 のままで構いません。** ただし `duty` は、測れるものによらず、いつも入れます。電流か速度を測れない基板では、duty が FB に載るからです。

## 設定の今の値（mas_can_md_settings）

`mas_can_md_settings(&node, i)` は、モーター `i` の設定の今の値（`mas_can_md_settings_t`）を指すポインタを返します。主制御が設定を書くと値が変わるので、使うたびに読みます。micro-MD と CAN_MD は、毎周 `motor_command(&out, mas_can_md_settings(&node, 0))` のように渡しています。

| 欄 | 設定の項目 | 誰が使うか |
|---|---|---|
| `reverse` | 32 回転方向の反転 | node が指令と FB にかけ済み。ファームはかけない |
| `current_limit_ma` | 33 電流の上限（mA） | ファームが、duty を含むどの指令にも効かせる |
| `stop_brake` | 34 止め方（true でブレーキ） | node が `brake` に反映済み |
| `fb_rate_hz` | 35 FB の周期（Hz） | node が使う |
| `encoder_cpr` | 36 エンコーダの 1 回転のカウント数 | ファームが換算に使う |
| `gear_ratio` | 37 減速比 | ファームが換算に使う |
| `encoder_reverse` | 38 エンコーダの反転 | ファームが測った値にかける |
| `speed_kp`、`speed_ki`、`speed_kd` | 39〜41 速度ループのゲイン | 速度を制御するファームが使う |
| `max_speed_rpm` | 45 最高速度（0 は制限なし） | ファームが使う |
| `max_accel_rpm_s` | 46 最大加速度（0 は制限なし） | ファームが使う |
| `current_lsb_ma`、`speed_lsb_rpm` | 48、49 指令の刻み | node が換算済み |

## 異常を知らせる（mas_can_node_raise_fault）

基板が異常に気づいたら、`mas_can_node_raise_fault(&node, bits)` で異常の詳細の bit を立てます。立てた bit は、主制御が消すまで残ります。立っている間、FB の「異常あり」の bit が 1 になります。

| bit | 意味 | 渡す値 |
|---|---|---|
| 2 | バスオフから復帰した | `MAS_CAN_FAULT_BUS_OFF` |
| 8 | 過電流 | `1u << 8` |
| 9 | 過熱 | `1u << 9` |
| 10 | 電源電圧の低下 | `1u << 10` |
| 11 | 電源電圧が高すぎる | `1u << 11` |
| 12 | エンコーダの異常 | `1u << 12` |
| 13 | ゲートドライバの異常 | `1u << 13` |

bit 0（再起動した）と bit 1（保存した設定が壊れていた）は、node が立てます。測る手段の無い異常は、立てなくて構いません。

バスオフの手本は、micro-MD の `watch_bus_off()` です。立っていたバスオフの印が消えたら、自動の復帰が済んだとして知らせます。

```c
static void watch_bus_off(void) {
    static bool was_off;
    bool off = CAN_GetFlagStatus(CAN1, CAN_FLAG_BOF) == SET;
    if (was_off && !off) mas_can_node_raise_fault(&node, MAS_CAN_FAULT_BUS_OFF);
    was_off = off;
}
```

can2040（RP2040）にはバスオフの仕組みが無いので、RP2040 の基板は何もしなくて構いません。

## フラッシュ（load と save）

- **中身は `mas_can_node_saved_t` で、今は 172 byte です。** `len` はいつもこの大きさです。ファームは中身を解釈せず、そのまま書き、そのまま読みます。
- **`load` は、読めたら true を返します。** 何も書いていないフラッシュでも構いません。node が中身の印と CRC を確かめるからです。印が無ければ（消したままのフラッシュなど）、黙って焼いた値で起動します。印があって CRC か中身の形の版が合わなければ、異常の詳細の bit 1 を立てて、焼いた値で起動します。
- **`save` は、書き終えてから返します。** node は `save` が返ってから、主制御への返事を積みます。書き終える前に返すと、まだ書けていないのに「保存した」と返事をすることになります。保存と初期化の求めのたびに、全部のモーターの分を丸ごと書きます。
- **書いている間に出力がどうなるかを決めて、基板の資料に書きます。** 消去や書き込みの間に CPU が止まるマイコンでは、その間は出力を変えられず、途絶も緊急停止も見られません。既存のファームは分かれています。CAN_MD（`App/app.c` の `flash_save`）と micro-MD（`flash_write_page`）は、書く前にブレーキにします。CAN-Servo のファーム（`settingsSave`）は全部の出力を Low にし、雛形（`settingsSave`）は 2 本の入力を 0（空転）にします。

## 再起動（restart）

- **node が `restart(ctx)` を呼ぶのは、再起動の返事を積んだ後、待ち行列が空になった `mas_can_node_drop_tx` の中です。** 主制御が項目 6 に `"rst"` を書いたときです。
- **この時点では、返事は CAN のコントローラに渡っただけで、線に出たとは限りません。** すぐ再起動すると、返事が主制御に届かないことがあります。返事を線に出し終えるのを待つのは、ファームです。
- **手本は 3 つあります。** micro-MD の `restart` は、送信の箱が空くまで最大 10 ms 待ちます。CAN-Servo のファームと雛形の `restart` は、送り終えの知らせを数え、最大 10 ms 待ちます。CAN_MD の `restart` は待たずに再起動するので、写さないでください（仕様書の [既存のファームが決まりと違う所](../../spec/board.md#既存のファームが決まりと違う所)）。

## メインのループの形

雛形（RP2040）のループは [雛形から始める](start.md#メインのループloop) にあります。C で書く基板の手本は、micro-MD の `main()` のループです。受ける、時間を進める、出す、測った値を渡す、送る、の順は雛形と同じで、バスオフの見張りと、電流の上限と、保護（番号を設定している間）が加わっています。

```c
        while (rx_tail != rx_head) {
            mas_can_node_on_frame(&node, &rxq[rx_tail % RXQ], now);
            rx_tail++;
        }
        watch_bus_off();
        mas_can_node_tick(&node, now);

        mas_can_md_output_t out = mas_can_md_output(&node, 0);
        if (setup_active) out.mode = MAS_CAN_MD_OUT_STOP;
        bool limited = motor_command(&out, mas_can_md_settings(&node, 0));

        mas_can_md_measure_t m = {0};
        m.current_ma = read_current_ma();
        m.duty = read_duty();
        m.current_limited = limited;
        m.protecting = setup_active;
        mas_can_md_set_measure(&node, 0, &m);

        const mas_can_frame_t *f;
        while ((f = mas_can_node_peek_tx(&node)) && can_send(f)) mas_can_node_drop_tx(&node);
```

`setup_active` は、micro-MD でスイッチから番号を設定している間 true になります。その間は出力を止め、`protecting` で主制御に知らせています。モーターが 2 個以上のときの形は、[雛形から始める](start.md#モーターが複数のときの-loop) にあります。

## 気をつけること

- **受信は、割り込みで輪に積みます。** 割り込みで `mas_can_frame_t` の輪に積み、メインのループで `mas_can_node_on_frame` に渡します。既存のファームは、すべてこの形です。拡張 ID のフレームは積まず、`rtr` を必ず埋めます。
- **緊急停止で止まるのは、次の `mas_can_md_output` からです。** ループが遅いと、その分だけ遅れます。CAN-Servo のファームは、受信の割り込みの中で `0x000` を見て、すぐ出力を切っています。
- **ループは、FB の周期よりずっと速く回します。** node は、途絶（0.1 秒）と FB の周期（項目 35）を、`mas_can_node_tick` を呼んだ時刻で数えるからです。
- **送る待ち行列は 8 本（`MAS_CAN_NODE_TXQ`）です。** 溢れた分は捨てられます。捨てられるのは FB だけではなく、設定への返事、起動の知らせ、再起動の返事も同じです。FB は次の周期にまた積まれますが、ほかは失われます。毎周、送れるだけ送ってください。
- **`mas_can_md_output` を 1 周に 2 回呼ばないでください。** `reset_ctrl` は、読むと消えるからです。
- **時計が粗くても動きます。** ms の時計に 1000 を掛けた値でも構いません（CAN_MD は `HAL_GetTick() * 1000`）。FB の周期は、その刻みに丸まります。
- **node の保存の中身の形が変わると、前に保存した設定は使われません。** `node.c` の `SAVED_VERSION` が上がると、印はあって版が合わないので、異常の詳細の bit 1 が立ち、焼いた値で起動します。

## node が持たない種類（サーボなど）を自分で書く

node が受け持つのは MD（種類の番号 0）だけです。サーボなどを受け持つ基板は、その種類の分をファームで書きます。MD の分は node が受け持つので、同じ基板に MD があれば、両方を使います。

1. **起動の知らせを送ります。** サーボなら `0x011` です。MD の分は node が送ります。
2. **起動の猶予の間は、指令に従いません。** `mas_can_node_in_grace(&node, now)` が true の間です。
3. **緊急停止でラッチしている間は、指令に従いません。** `node.estop` で見ます。
4. **DLC の外の slot は、受けていない扱いにします。** サーボの予約の値（201〜254）は、止める値（255）と同じに扱います。
5. **ch ごとに、指令が 0.1 秒届かなければ止めます。**
6. **その種類の設定に答えます。** サーボなら、要求 `0x410` に応答 `0x418` で、共通の項目 0〜6 とサーボの項目で答えます。

手本は CAN-Servo のファーム（`firmware/CAN-Servo-v1/src/main.cpp`）の `servoReceive()`（2〜4）、`servoUpdate()`（5）と、`loop()` の中のサーボの起動の知らせ（1）です。ただし、このファームはサーボの設定の要求（`0x410`）に一切答えません（6 が無い）。決まりの全部は、仕様書の [基板が守ること](../../spec/board.md#守ることの確認表) にあります。
