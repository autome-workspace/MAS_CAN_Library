# 守ること

| | |
|---|---|
| 読む人 | 基板のファームを作る人 |
| 前提 | 作る基板のマイコンで、モーターやサーボを動かすファームを書ける。[雛形から始める](start.md) を読んだ |
| 読むとできること | 自分のファームが決まりを満たしているかを、点検表で確かめられる。基板の資料に何を書くかが分かる |

このページは、仕様書の [守ることの確認表](../../spec/board.md#守ることの確認表)（決まりの正本）を、ファームが受け持つ所に絞って簡潔にした点検表です。

## 先に知っておくこと

決まりの大半は、ライブラリの基板側（**node** と呼びます）が受け持ちます。指令の受け取り、途絶で止める判断、緊急停止、主制御への知らせ、設定のやりとりは、node が行います。

あなたのファームが受け持つのは、**ハードウェアに触る所**です。このページの点検表は、その部分だけを並べています。node が受け持つ分まで含めた全部の決まりは、仕様書の [守ることの確認表](../../spec/board.md#守ることの確認表) にあります。

今の node が受け持つのは、モータードライバーだけです。サーボなど、ほかの種類は、自分で書くことになります。指令の受け取りと途絶の判断のほかに、起動の知らせ、緊急停止、起動の直後に動かない時間、設定への返事も要ります（CAN-Servo のファームが例です。設定への返事は、まだ書かれていません）。書くことの一覧は、[node の関数と欄](node.md#node-が持たない種類サーボなどを自分で書く) にあります。

## 点検表

### 通信

- [ ] 速さは 1 Mbps、サンプル点は 80% にしている。RP2040 の can2040 は 81.25% で固定なので、そのままで構いません。
- [ ] 同期の幅（SJW）を、取れる最大にしている。
- [ ] 発振子は、水晶か、誤差 ±0.5% 以内のセラロックを使っている。マイコンの内蔵の発振器は、精度が足りません。
- [ ] 拡張 ID のフレームは、node に渡さずに捨てている。
- [ ] 受けたフレームがリモートフレームかどうかを、必ず node に伝えている（`rtr` の欄）。伝えないと、node がリモートフレームを指令として受けてしまいます。

### 番号（ch）

- [ ] 番号は、電源を入れたときに 1 回だけ読んでいる。動いている途中で変わらない。
- [ ] モーターを 2 個以上受け持つなら、先頭の ch を、スイッチの値に受け持つ数を掛けた値にしている。決め方は [雛形から始める](start.md#モーターが複数のときの番号) にあります。
- [ ] 番号が範囲の外（モータードライバーなら、最後の ch が 31 を超える）のときは、何も送らず、何も受けず、出力を止めたままにしている。ほかの基板の信号とぶつかるためです。スイッチの値が最大のときでも範囲に収まる基板では、この扱いは要りません（[スイッチから番号を読む](start.md#スイッチから番号を読む)）。
- [ ] そのとき、LED などで人に知らせている。

### node に、基板のことを伝える

node は、起動のときに渡された設定（`mas_can_node_config_t`）で、基板に何ができるかを知ります。各欄の意味と、0 のままにしたときの動きは、[node の関数と欄](node.md#基板の性質を渡すmas_can_node_config_t) にあります。

- [ ] できることを、正しく渡している。電流を測れるか（`md_has_current`）、速度を測れるか（`md_has_speed`）、空転を出せるか（`md_has_coast`）、duty を出せないか（`md_no_duty`）。
- [ ] 上限を渡している。電流の上限の最大（`md_current_limit_max_ma`）と、主制御に様子を知らせる回数の最大（`md_fb_rate_max_hz`）。**回数の最大を 0 のままにすると、主制御が回数を設定した時点で、知らせが止まります。** 電流を測れない基板は、電流の上限の最大を 0 のままにして構いません（[電流を測れない基板の、電流の上限](start.md#電流を測れない基板の電流の上限)）。

### 起動の順

- [ ] 電源が入った直後は、出力を止めている。
- [ ] 通信の初期化、保存した設定の読み込み、番号の読み取りが**全部済んでから**、`mas_can_node_ready()` を呼んでいる。この関数が、主制御に「起動した」と知らせます。早く呼ぶと、準備ができていないのに主制御が話しかけてきます。

### 動かす

node は、「今、モーターに何を出すべきか」を返します（`mas_can_md_output()`）。ファームは、それをそのまま出します。

- [ ] 返ってきた形（止める、duty、電流、速度）のとおりに出している。
- [ ] 「止める」のときは、一緒に返る止め方（空転かブレーキか）に従っている。その止め方を出せない基板は、出せるほうで止める。
- [ ] `reset_ctrl` が立っていたら、制御の状態（積分の値など）を消している。止まっていた後や、指令の種類が変わった後に、古い状態で飛び出さないためです。
- [ ] 指令の値を、設定の電流の上限と、基板の部品の限界で抑えている。電流の上限は、duty の指令のときにも効かせる。電流を測れない基板は、上限を効かせられないので、この項目は当てはまりません（[電流を測れない基板の、電流の上限](start.md#電流を測れない基板の電流の上限)）。
- [ ] 回転の向きの反転を、ファームでかけていない。反転は node が済ませています。もう一度かけると、元に戻ってしまいます。
- [ ] 速度を制御する基板は、設定の最高速度と最大加速度の中に収めている。

### 測って返す

ファームは、測った値を node に渡します（`mas_can_md_set_measure()`）。node がそれを主制御に送ります。

- [ ] 値は、出力軸で表している。エンコーダがモーターの軸に付いているなら、減速比で換算する。
- [ ] 位置は、出力軸 1 回転を 65536 として数えている。電源を入れたときが 0。
- [ ] 実際に出している duty を、いつも渡している。電流や速度を測れる基板でも、渡します。
- [ ] 電流の上限に当たっているときは、そのことを渡している（`current_limited`）。
- [ ] 基板を守るために止めているときは、そのことを渡している（`protecting`）。

### 異常

- [ ] 基板が見つけた異常（過電流、過熱、電源の電圧、エンコーダ、ドライバ）を、node に知らせている（`mas_can_node_raise_fault()`）。測る手段の無いものは、知らせなくて構いません。
- [ ] 通信の途絶（バスオフ）からは、マイコンの自動の復帰で戻している。戻ったら、node に知らせている。can2040 にはこの仕組みが無いので、何もしなくて構いません。

### 設定の保存と再起動

- [ ] フラッシュへの読み書きの関数（`load`、`save`）を node に渡している。`save` は、書き終えてから成功を返す。
- [ ] フラッシュに書いている間、出力をどうするかを決めている。書いている間は割り込みも止まるマイコンが多いので、先に出力を止めます。
- [ ] 再起動の関数（`restart`）を node に渡している。**渡さないと、主制御には「再起動した」と返事をするのに、実際には再起動しません。**
- [ ] 再起動は、返事を線に出し終えてから行っている。すぐ再起動すると、返事が主制御に届きません。

### 基板の身元

- [ ] 基板ごとに違う番号（固有 ID）を、マイコンに書かれている番号から作って渡している。作り方は、仕様書の [基板の情報](../../spec/board.md#基板の情報設定の共通の項目) にあります。
- [ ] 基板の種類の番号を取って、渡している。番号は一覧に書き足して取るので、作者に頼みます。取るまでは、仮の番号（`MAS_CAN_BOARD_RESERVED`）のままにします。手順は、仕様書の [基板の種類の登録の手順](../../spec/board.md#基板の種類の登録の手順) にあります。
- [ ] ファームの版を渡している。

### 決まりではないが、勧めること

- **ウォッチドッグを入れる。** ファームが固まると、最後に出していた強さのまま、モーターが回り続けます。途絶で止める判断も、ファームが動いていてこそです。
- **緊急停止は、割り込みの中ですぐ出力を切る。** メインのループを待たずに止められます。CAN-Servo のファームがこうしています。

## 基板の資料に書くこと

基板を使う人は、あなたのファームの中を読みません。基板のフォルダの README に、次のことを書いてください。上の表は、使う人が最初に知りたいことです。下の表は、決まりが「基板の資料に書く」としていることです。

**使う人が最初に知りたいこと**

| 書くこと | 例 |
|---|---|
| 何を動かす基板か | モーター 1 個。マイコンとドライバの名前 |
| こなせる指令 | duty と電流。速度はできない |
| 主制御に返すもの | 電流と、実際に出している duty |
| 番号（ch）の決め方と、確かめ方 | DIP スイッチ。LED が番号の回数だけ点滅する |
| 終端抵抗 | 載っているか。どのスイッチで入れるか |
| 端子 | 通信の線（どちらが H か）、電源、モーター |
| LED の意味 | 色や点滅が何を表すか |
| 止め方 | 空転とブレーキの、どちらを出せるか |
| ビルドと書き込みの手順 | コマンド。必要な道具 |
| 知っておくこと | できないこと、癖、まだ直していないこと |

**決まりが、基板の資料に書くとしていること**

| 書くこと |
|---|
| 番号の決め方と、選べる範囲 |
| 番号が範囲の外のときの知らせ方 |
| 固有 ID に、マイコンのどの番号を使ったか |
| 部品の限界（電流など）と、電流の上限の既定の値 |
| フラッシュに書いている間、出力がどうなるか |
| 基板を守る動き（異常に気づいたとき、どうするか） |
| サーボの基板: 信号の周期を共有する端子の組 |

書き方の見本は、[`firmware/micro-MD/README.md`](../../../firmware/micro-MD/README.md) です。
