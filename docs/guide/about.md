# MAS CAN とは

| | |
|---|---|
| 読む人 | MAS CAN という名前をはじめて聞いた部員 |
| 前提 | Arduino などで、マイコンのプログラムを書いたことがある。CAN は知らなくてよい |
| 読むとできること | MAS CAN が何をするものかを人に説明でき、次に読むページを選べる |

## 何をするものか

MAS CAN は、ロボットの中で、指示を出すマイコンからモーターやサーボの基板を動かすための、部で共通の決まりとライブラリです。MAS は Meiji Autome Standard の略です。

指示を出す側のマイコン（ESP32 や Raspberry Pi Pico）を、**主制御**と呼びます。主制御と基板は、**CAN** という 2 本の線（H と L）でつながります。基板が何枚あっても、同じ 2 本の線につなぎ足していきます。モーターを 1 個増やすたびに主制御のピンを使うことはありません。

```
主制御 ── トランシーバ ══ H、L ══ モーターの基板 ══ H、L ══ サーボの基板
```

**トランシーバ**は、マイコンの信号を CAN の線の信号に変える部品です。主制御のマイコンだけでは、CAN の線に直接つなげません。

## プログラムの形

主制御のプログラムは、基板の**番号**を指定して、値を置きます。次は、0 番のモーターを 30% の強さで回し続けるプログラムの中心です（全体は例の `md_minimal` にあります）。

```cpp
mcan::Host can;
mcan::Md motor = can.md(0);   // モーターの 0 番

void loop() {
    can.update();             // 送ることも受けることも、この中で行う
    motor.setDuty(0.3f);      // 30% の強さで回す
}
```

番号は、基板の側でスイッチなどを使って決めます。決め方は基板ごとに違い、[今ある基板](boards.md) に書いてあります。

`can.update()` は、`loop()` の中で毎回呼びます。基板は、主制御からの指示が 0.1 秒届かないと、安全のためにモーターを止めるからです。`update()` が同じ値を送り続けることで、基板は動き続けます。

## できること、できないこと

今できることは、次のとおりです。

- **モーター:** 強さ（duty）、電流、速さを指定して回す。回転した量、速さ、電流を読む。どれができるかは基板によります。
- **サーボ:** 角度を指定して動かす。力を抜く。
- **全体:** 線の上の全部を緊急停止する。基板の過電流や過熱などの異常を知る。

できないことも、先に知っておいてください。

- **市販のモータードライバーは、そのままつなげません。** 相手にできるのは、MAS CAN を話すファームが入った基板だけです。今あるのは、部で作った 4 種類です。
- **主制御は、ESP32（ESP32-S3 を含む）と Raspberry Pi Pico だけです。**
- **汎用のピン、エアー、ソレノイドは、まだ使えません。** 基板と話すための決まりが、まだできていないからです。
