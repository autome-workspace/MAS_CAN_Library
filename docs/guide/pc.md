# 線を見る、PC から使う

| | |
|---|---|
| 読む人 | Linux で USB-CAN を使い、MAS CAN の線を見る人。PC から基板を動かしたい人 |
| 前提 | CAN の ID、データフレーム、DLC、ビットレートが分かる。`candump` で流れているフレームを表示できる。MAS CAN の決まりは初めて |
| 読むとできること | 流れてきたフレーム 1 本を、byte ごとに読み下せる。基板の異常の中身を読み出せる。PC から基板を動かし、緊急停止をかけて解除できる |

このページは、ID とフレームの形をそのまま扱います。決まりの正本は仕様書（`docs/spec/`）です。ここには、線を読むときと PC から送るときに要る分を写し、写した所に仕様書の場所を書いています。

言葉を 3 つだけ先に決めます。**主制御**は、ロボットのマイコンで指令を出す側です。**基板**は、指令を受けてモーターやサーボを動かす側です。**ch** は、モーターとサーボ 1 個ずつに振った番号です。モーターは 0〜31、サーボは 0〜63 で、種類ごとに 0 から数えます。

## 設定

| | |
|---|---|
| 速さ | 1 Mbps |
| ID | 11 bit の標準 ID。拡張 ID は使いません |
| データ | 1 本 8 byte まで（CAN FD ではありません）。データフレームだけを使います |
| byte の並び | 2 byte 以上の値は、上位の byte が先（big-endian）。int16 の −100 は `FF 9C`、float32 の 1.0 は `3F 80 00 00` |

Linux（SocketCAN）では、この速さで口を開きます。`can0` は、USB-CAN の口の名前です。

```sh
sudo ip link set can0 up type can bitrate 1000000
candump can0
```

このページは、フレームを `0x325 DLC 5 : 82 05 DC 33 32` の形で書きます。`candump` の表示では `can0  325   [5]  82 05 DC 33 32`、`cansend` で送るときは `cansend can0 325#8205DC3332` の形です。

## よく見る ID

| ID | 誰が送るか | 何か | 普段の間隔 |
|---|---|---|---|
| `0x000` | 主制御 | 緊急停止 | かかっている間、0.1 秒ごと |
| `0x001` | 主制御 | 緊急停止の解除 | 解除のときだけ |
| `0x002` | 主制御 | 時刻合わせ（SYNC） | 0.05 秒ごと |
| `0x010`、`0x011` | 基板 | 起動の知らせ（モーター、サーボ） | 基板が起動したときに 1 本 |
| `0x210`〜`0x217` | 主制御 | モーターへの電流の指令。4 個で 1 本 | 0.01 秒ごと |
| `0x218`〜`0x21F` | 主制御 | モーターへの速度の指令。4 個で 1 本 | 0.01 秒ごと |
| `0x220`〜`0x227` | 主制御 | モーターへの duty の指令。4 個で 1 本 | 0.01 秒ごと |
| `0x230`〜`0x237` | 主制御 | サーボへの指令。8 個で 1 本 | 0.02 秒ごと |
| `0x320`〜`0x33F` | 基板 | モーターの様子（FB）。`0x320` ＋ ch | 0.01 秒ごと（基板の設定で変わります） |
| `0x400`、`0x408` | 主制御、基板 | モーターの側の設定の、要求と応答 | 必要なときだけ |

全部の ID は、仕様書の [ID の一覧](../spec/ids.md) にあります。場面ごとのフレームの並びは [flows.md](../spec/flows.md) にあります。

## 見て分かること

- **主制御が動いているか。** `0x002` が 0.05 秒ごとに流れていれば、主制御のライブラリが動いています。
- **どのモーターがいるか。** `0x320`〜`0x33F` のうち、流れている ID がそのモーターの ch です。`0x325` が流れていれば、5 番がいます。基板は、指令が来ていなくても FB を送ります。
- **基板が再起動したか。** `0x010` や `0x011` が、動いている途中で流れたら、どれかの基板が再起動しています。このフレームは中身が空なので、どの基板かは分かりません。
- **指令が届いているか。** たとえば 5 番のモーターを duty で回しているなら、`0x221`（4〜7 番の組）が流れているはずです。
- **主制御が刻みを書いているか。** 主制御のライブラリは、プログラムが使う ch の FB を初めて受けると、その ch に `0x400` で「刻み」（下の「線の上の単位」）を書きます。起動の直後に `0x400` と `0x408` が数本ずつ流れるのは、これです。

## モーターの様子（FB）を読む

FB は、基板が ch ごとに送るフレームです。ID は `0x320` ＋ ch です。byte 0 が状態で、その後ろに測った値が続きます。基板が何を測れるかで、byte の割り当てと DLC が変わります。どの形かは、状態の bit 1 と bit 2 で決まります。

| 基板が測れるもの | bit 1 | bit 2 | byte 1–2 | byte 3–4 | byte 5–7 | DLC |
|---|---|---|---|---|---|---|
| 電流、速度、位置 | 0 | 0 | 電流 | 速度 | 位置 | 8 |
| 速度と位置（エンコーダ）だけ | 0 | 1 | duty | 速度 | 位置 | 8 |
| 電流だけ | 1 | 0 | 電流 | duty | — | 5 |
| 何も測れない | 1 | 1 | duty | — | — | 3 |

状態の byte（byte 0）の bit:

| bit | 1 のときの意味 |
|---|---|
| 0 | 基板に異常あり（下の「異常を見つけたとき」） |
| 1 | 速度と位置が無効（測れない） |
| 2 | 電流が無効（測れない） |
| 3 | 電流の上限に当たっている |
| 4 | 出力を止めている |
| 5 | 緊急停止で止まったまま（ラッチ） |
| 6–7 | 今従っている指令の形。0 電流、1 速度、2 duty、3 位置 |

| 値 | 形 | 単位と刻み |
|---|---|---|
| 電流 | int16 | 値 × 電流の刻み ＝ mA。モーターの巻線の電流で、電源から入る電流ではありません |
| 速度 | int16 | 値 × 速度の刻み ＝ 出力軸（減速機の後の軸）の rpm |
| 位置 | 24 bit、符号なし | 出力軸 1 回転 ＝ 65536。電源を入れたときが 0。256 回転で 0 に戻ります |
| duty | int16 | 1 bit 算術右シフトした値が duty で、±16383 ＝ ±100%。bit 0 は減衰の形（指令の節） |

刻みは、基板の設定で選ぶ「int16 の 1 が表す量」です。既定は電流 1 mA、速度 1 rpm です。電流と速度は ±32767 で頭打ちになります。詳しい決まりは、仕様書の [モータードライバー](../spec/md.md) の 3 節にあります。

### 読み下しの例: `0x325 DLC 5 : 82 05 DC 33 32`

| byte | 値 | 読み |
|---|---|---|
| ID | `0x325` | ch 5 の FB |
| 0 | `0x82` | bit 6–7 ＝ 2 で、duty の指令に従っている。bit 1 ＝ 1 で、速度と位置は測れない。bit 0、4、5 は 0 なので、異常は無く、出力を出している |
| 1–2 | `0x05DC` | 電流 1500。刻みが既定なら 1500 mA |
| 3–4 | `0x3332` | duty。13106 を 1 bit 右シフトして 6553、6553 ÷ 16383 で約 +40% |

DLC が 5 なのは、bit 1 が 1、bit 2 が 0 で、電流だけを測れる形だからです。

### 止まっている ch と、指令の形を見分ける

**bit 4 が 1 の ch は、出力を止めています。** 止めた理由を区別する bit はありません。次の順に見ると、理由を絞れます。

1. **bit 5 も 1。** 緊急停止で止まっています。
2. **起動の知らせから 0.2 秒以内。** 起動の猶予です。基板はこの間、指令に従いません。
3. **その ch の指令が線に流れていない。** まだ指令を受けていないか、指令が 0.1 秒途絶えています。指令のフレームの DLC が短く、その ch の分が欠けているときも同じです。
4. **bit 6–7 の形を、その基板がこなせない。** たとえば、bit 1 が 1（速度を測れない）なのに bit 6–7 が 1（速度）なら、こなせない指令を受けています。
5. **bit 0 も 1。** 基板が自分を守るために止めているかもしれません。異常の中身を読みます。

電流 0 や duty 0 の指令に従っているときは、bit 4 は 0 です。0 は普通の指令として扱われます。

**bit 6–7 は、最後に受けた指令の形です。** 止まった後も、その形のままです。ただし起動の直後は、指令をまだ受けていなくても 0 です。bit 4 が 1 で bit 6–7 が 0 なら、「電流の指令」ではなく「まだ受けていない」と読んでください。

## 指令を読む

### モーターの指令

モーターの指令は、連続した 4 個の ch を 1 本で運びます。ID の下の 3 bit がフレーム番号（0〜7）で、フレーム番号 × 4 から 4 個の ch を運びます。`0x221` なら duty の指令のフレーム番号 1 で、ch 4〜7 です。byte 0–1 が先頭の ch、byte 2–3 がその次の ch と、2 byte ずつ並びます。

各 ch は int16 です。電流の指令は値 × 電流の刻み（mA）、速度の指令は値 × 速度の刻み（出力軸の rpm）です。duty の指令は、bit 1–15 が符号付きの duty（±16383 で ±100%）で、bit 0 が PWM を切っている間の止め方（0 空転、1 ブレーキ）です。

止める値は、どの形でも `0x0000` です。送り手は、使わない ch に `0x0000` を入れます。後ろの ch を使わなければ、DLC を縮めてもかまいません。DLC が短くて自分の 2 byte が欠けた ch は、指令を受けていない扱いになります。そのまま 0.1 秒経つと、その ch は止まります。詳しい決まりは、仕様書の [モータードライバー](../spec/md.md) の 2 節にあります。

### 読み下しの例: `0x221 DLC 6 : 00 01 33 33 E0 01`

| byte | ch | 値 | 読み |
|---|---|---|---|
| ID | — | `0x221` | duty の指令、フレーム番号 1（ch 4〜7） |
| 0–1 | 4 | `0x0001` | duty 0、bit 0 ＝ 1。端子どうしをつないで止める（短絡ブレーキ） |
| 2–3 | 5 | `0x3333` | 13107 を 1 bit 右シフトして 6553（約 +40%）。bit 0 ＝ 1 でブレーキ |
| 4–5 | 6 | `0xE001` | int16 で −8191。右シフトで −4096（約 −25%）。ブレーキ |
| 6–7 | 7 | 無い | DLC 6 なので、ch 7 は指令を受けていない扱い |

### サーボの指令

サーボの指令は `0x230` ＋ ch ÷ 8 で、連続した 8 個の ch を 1 本で運びます。1 個が 1 byte です。値 0〜200 はパルス幅 500 ＋ 値 × 10 µs で、255（`0xFF`）がパルスを止める値です。201〜254 は送りません。基板は受けたら 255 と同じく止めます。

`0x231 DLC 2 : FF 64` は、ch 8 がパルスを止め、ch 9 が 1500 µs（値 100、`0x64`）です。ch 10〜15 は欠けているので、指令を受けていない扱いです。詳しくは仕様書の [サーボ](../spec/servo.md) の 2 節にあります。

## 異常を見つけたとき

**FB の bit 0 が 1 になったら、設定の項目 5（異常の詳細）を読みます。** FB には「異常あり」の 1 bit しか無いので、何の異常かは設定で読む必要があります。設定のフレームは、要求が `0x400`、応答が `0x408` で、どちらも DLC 8 です。

| byte | 要求 | 応答 |
|---|---|---|
| 0 | 宛先の ch | 同じ ch |
| 1 | 操作。`0x00` 読む、`0x40` 書く | 操作 ＋ 結果。`0x00`、`0x40` なら成功 |
| 2 | 項目の番号 | 同じ番号 |
| 3–6 | 値（書くときだけ） | 今の値。書いたときは、基板が反映した後の値 |
| 7 | 通し番号（送る側が選ぶ） | 同じ番号 |

応答の byte 1 の下 6 bit が結果です。0 成功、1 知らない項目、2 その操作はできない、3 範囲外、4 実現できない、63 その他の失敗です。その ch を受け持つ基板だけが応答します。DLC が 8 でない要求は捨てられ、応答は返りません。

例: ch 5 の異常の詳細を読みます。過電流の bit 8 が立っていた場合です。立った bit は、主制御が 1 を書くまで残ります。後の 2 本は、bit 8 に 1 を書いて消す要求と、消した後の値を返す応答です。

```
要求  0x400 DLC 8 : 05 00 05 00 00 00 00 01     ch 5、読む、項目 5
応答  0x408 DLC 8 : 05 00 05 00 00 01 00 01     値 0x00000100（bit 8）
要求  0x400 DLC 8 : 05 40 05 00 00 01 00 02     ch 5、書く、項目 5、bit 8 に 1
応答  0x408 DLC 8 : 05 40 05 00 00 00 00 02     消した後の値 0
```

| bit | 意味 |
|---|---|
| 0 | 再起動した |
| 1 | 保存した設定が壊れていたので、焼いた値で起動した |
| 2 | バスオフから復帰した |
| 8 | 過電流 |
| 9 | 過熱 |
| 10 | 電源電圧の低下 |
| 11 | 電源電圧が高すぎる |
| 12 | エンコーダの異常 |
| 13 | ゲートドライバの異常 |

bit 8〜13 はモーターの基板のものです。測る手段の無い基板は、その bit を立てません。今の基板は、異常の詳細を基板に 1 つだけ持ちます。どの ch 宛てに読んでも同じ値が返り、消すとその基板の全部の ch の分が消えます。主制御のライブラリは、FB の bit 0 が立っている間、約 0.1 秒ごとにこれを読みます。ライブラリが自分で消すのは bit 0 だけです。詳しくは仕様書の [設定](../spec/settings.md) の 7、8 節にあります。

## サーボの基板を見分ける

**サーボの基板は、線を見ているだけでは見つかりません。** サーボには FB が無く、起動の知らせ `0x011` を 1 本出すだけです。決まりでは、サーボの設定（`0x410`）を ch ごとに読めば、いるかが分かります。しかし今の CAN-Servo の基板は、`0x410` の要求に一切答えません。

**今の CAN-Servo は、モーターの側の設定で見分けます。** CAN-Servo はモーター 4 個ぶんの ch も持ち、その FB を DLC 3（何も測れない形）で送っています。その ch に項目 1（基板の種類）を読む要求を送り、値の上の 16 bit が `0x0002` なら CAN-Servo です。下の 16 bit は基板の版です。ほかの番号は、`0x0001` が CAN_MD、`0x0003` が micro-MD です。今の XDrive の中継機のファームは番号をまだ取っておらず、`0x0000`（予約）を返します。

```
要求  0x400 DLC 8 : 00 00 01 00 00 00 00 03     ch 0、読む、項目 1
応答  0x408 DLC 8 : 00 00 01 00 02 00 01 03     CAN-Servo、版 1
```

サーボの ch の範囲は、[今ある基板](boards.md) の CAN-Servo の節で分かります。

## 線の上の単位

**主制御のライブラリの関数は A と rad/s ですが、線の上は mA と rpm です。** プログラムの値と線の値を見比べるときは、換算してください。

| 量 | ライブラリ（`Md` の関数） | 線の上 |
|---|---|---|
| 電流 | A（`setCurrent`、`current()`） | int16 × 電流の刻み（mA） |
| 速度 | 出力軸の rad/s（`setSpeed`、`speed()`） | int16 × 速度の刻み（出力軸の rpm） |
| 刻み | `configCurrentResolution` は A、`configSpeedResolution` は rad/s | 項目 48 は mA、項目 49 は rpm（どちらも float32） |

例: 刻みが既定のとき、`setSpeed(10.0)` は 10 × 60 ÷ 2π ≈ 95.5 rpm なので、線の上は 95（`00 5F`）になります。ライブラリは四捨五入して int16 にします。

## PC から動かす

### 守ること

**モーターが回っても危なくないようにしておく。**
車輪は床から浮かせ、機構は外すか固定します。最初は小さい値から試します。手元に、機体の電源を切る手段を置いてください。

**主制御と同時に指令しない。**
1 つの線で指令を出すのは 1 台だけにしてください。主制御のライブラリは、指令のほかに、時刻合わせと、基板の設定の書き込みも行っています。2 台が同時に行うと、同じ ID のフレームがぶつかったり、基板の設定が食い違ったりします。PC から動かすときは、ロボットの主制御を止めます。

**0.1 秒以内に、送り続ける。**
基板は、指令が 0.1 秒届かないと止まります。PC は、マイコンほど時間を正確に守れません。ほかの処理で送るのが遅れると、モーターが一瞬止まります。止まって困るものは、マイコンの主制御に任せるほうが確実です。

**決まりどおりに送る。**
電流と速度の値は、基板の「刻み」の設定で読み方が変わります。PC も、主制御のライブラリと同じく、指令の前に刻みを書きます（下の手順の 4）。

### 最小の手順

ここでは、モーターの ch 5 を duty で回します。

1. **主制御を止める。** 電源を切るか、線から外します。`0x002` が流れなくなれば止まっています。
2. **時刻合わせを 0.05 秒ごとに送り始める。** `0x002`、DLC 4 で、中身は PC のプログラムが起動してからの µs（uint32）です。1234567 µs なら `0x002 DLC 4 : 00 12 D6 87` です。決まりでは、指令を送るものは PC も含めて必ず送ります。今のモーターとサーボの基板はこれを使わないので、途絶えても止まりはしません。
3. **動かす ch の FB を見る。** `0x325` が流れていれば、ch 5 がいます。指令をまだ受けていないので、byte 0 の bit 4 が 1 です。
4. **刻みを書く。** 速度の刻み（項目 49、byte 2 は `0x31`）と電流の刻み（項目 48、`0x30`）に、1 本ずつ書きます。応答を受けてから次を送ります。刻みは基板に保存されず、前の主制御が書いた値が残っていることがあるので、既定の 1.0 で使うときも書きます。決まりでは、duty の指令だけを送るときも、指令の前に書きます。

   ```
   要求  0x400 DLC 8 : 05 40 31 3F 80 00 00 03     ch 5、書く、項目 49、1.0
   応答  0x408 DLC 8 : 05 40 31 3F 80 00 00 03
   要求  0x400 DLC 8 : 05 40 30 3F 80 00 00 04     ch 5、書く、項目 48、1.0
   応答  0x408 DLC 8 : 05 40 30 3F 80 00 00 04
   ```

   応答の byte 1 が `0x40` で、値が書いた値と同じなら書けています。`0x43` は範囲外（0 以下の値）で、基板の値は変わっていません。応答が来なければ、通し番号を変えて送り直します。主制御のライブラリは、0.05 秒待って 2 回まで送り直します。
5. **再起動の印を消す。** 起動した基板は、異常の詳細の bit 0 を立てています。`0x400 DLC 8 : 05 40 05 00 00 00 01 05` で消します。消しておくと、次に基板が再起動したとき、FB の bit 0 で気づけます。
6. **指令を 0.01 秒ごとに送る。** ch 5 だけを約 +40%、ブレーキで回すなら `0x221 DLC 4 : 00 00 33 33` です（ch 4 は止める値）。FB の bit 4 が 0 になり、bit 6–7 が 2（duty）になれば従っています。
7. **止めるときは、止める値を送ってから、送るのをやめる。** `0x221 DLC 4 : 00 00 00 00` を送ります。送るのをやめるだけでも、基板は 0.1 秒後に止まります。

### 基板が再起動したら

`0x010` が流れたら、どれかのモーターの基板が再起動しています。再起動した基板は、刻みが 1.0 に戻り、位置が 0 から数え直しになり、緊急停止のラッチも消えます。基板は、起動の知らせから 0.2 秒は指令に従いません。この間も設定の要求には答えます。

PC は、この 0.2 秒の間に、指令しているすべての ch に刻みを書き直します。起動の知らせでは、どの基板かが分からないからです。刻みを 1.0 以外で使っているなら、書けたと確かめるまで、その ch には止める値を送ります。主制御のライブラリも、こうしています。どの基板だったかは、起動の知らせの後で最初に受けた FB で、bit 0 が立っている ch です。最後に、手順の 5 で再起動の印を消します。決まりの詳しい中身は、仕様書の [共通の決まり](../spec/bus.md) の 7 節にあります。

### 緊急停止

1. **かける。** `0x000` を送ります。中身と DLC は見られないので、`0x000 DLC 0` でかまいません。全部の基板が止まり、そのまま止まり続けます（ラッチ）。FB の bit 4 と bit 5 が 1 になります。
2. **かけている間は、0.1 秒ごとに送り続ける。** 再起動した基板はラッチを忘れます。送り続けていれば、その基板にも起動の猶予の 0.2 秒の間に届きます。
3. **解除の前に、送る指令を止める値に戻す。** モーターの基板は、解除の後、次の有効な指令ですぐ動きます。解除の後には猶予がありません。
4. **解除する。** `0x001 DLC 3 : 63 6C 72`（`clr`）を送ります。DLC が 3 でないか、中身が違うと、基板は捨てます。
5. **確かめる。** FB の bit 5 が 0 になれば解けています。主制御のライブラリは、0.1 秒後も bit 5 が残る基板があれば、3 回まで送り直します。モーターは、次の指令を受けるまで bit 4 が 1 のままです。今の CAN-Servo のサーボは、解除の後、新しい指令が来るまでパルスを出しません。フレームの形は、仕様書の [共通の決まり](../spec/bus.md) の 3 節にあります。
