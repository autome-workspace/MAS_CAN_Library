# 決定の台帳

MAS CAN プロトコル v1 と、主制御のライブラリの**今の決定**を 1 行ずつ置く。仕様の正本はこの台帳で、仕様書・説明書・DBC は後でここから作る（2026-10-14、ユーザ）。

## 台帳

| ファイル | 番号 | 中身 |
|---|---|---|
| [common.md](common.md) | C- | 共通の土台（物理層、ID の骨格、E-stop、SYNC、起動の知らせ、周期指令の共通の規則、設定の仕組み） |
| [md.md](md.md) | M- | モータードライバー |
| [servo.md](servo.md) | S- | サーボ |
| [api.md](api.md) | API- | 主制御のライブラリ |
| reserved.md | R- | 他の種類。ID と種類の番号の予約だけ（作成予定） |
| [open.md](open.md) | — | 未決の一覧 |

## 書き方

- 1 行 1 決定。決めた内容だけを書き、理由は 1 行まで。長い検討はメモ（下）に書いて参照する。
- **戻せるか**: 「戻せない」＝ 線の上の形と意味（基板に焼いた時点で固まる）。「戻せる」＝ 設定で変えられる既定値、ライブラリの中、文書の言い回しなど。
- 日付は 2026 年。「ユーザ」はユーザが決めたもの、「合意」は元の文書が文書単位で合意としているもの。
- 旧番号（P、D、Q、A、settings の A など）と出典を残す。出典の文書名は `docs/redesign/` の中のもの。
- 変えるときは、古い行を取り消し線で残し、「→ 番号」で新しい行を指す。
- 写しただけでユーザが見ていない節は、台帳の冒頭に「未確認」と書く。確認が済んだ節の見出しに「（確認済み 日付）」を付ける。
- 未決は open.md にだけ書く。決まったら台帳に行を足し、open.md の行を取り消し線にする。

## メモと記録

- 検討、比較、試算は `docs/notes/` に日付を付けたファイルで書き、**書いた後は直さない**（古くなっても困らないように）。
- `docs/redesign/` は 2026-10-14 までの記録で、**凍結**した。直し漏れ（spec-draft.md の Q26）も直さない。食い違ったら台帳が正しい。
