## メモ（決定ではない、2026-10-15 ユーザ）

- PC でデバッグするときの扱い。主制御がいるなら PC は監視だけ、になりそう。今は決めない（C-78）。
- 主制御に設定を要求できるようにする案（主制御がバスの上で名前を持つことになる）。
- 正式版の後、更新の開発は `dev/v1.0.1` のようなブランチに伸ばすかもしれない（versioning.md）。
- 全基板の帯域の使用率の目安は、ユーザがまとめる予定。DJI のモーターを同じバスに載せると 1 台 1 kHz の FB で重い（C-24）。
- 位置の指令を作るときの材料（M-49）: 旧 M-9、M-10 の形（下位 16 bit、前回の目標にいちばん近い候補）は、1 周期に半回転近く動かすと、指令を 1 本落としただけで逆に回りうる。ライブラリが 1 周期の量を 1/4 回転までに抑えれば防げる（100 Hz なら出力軸で 1500 rpm まで）。
- 足す候補の種類（2026-10-16、ユーザ。今は使う予定なし）: 電源の監視（いずれ足す。電圧、電流、主電源、非常停止ボタン）、ステッピングモーター（あるべき。位置の指令 M-49 と一緒に考える）、IMU（入れたい）。色センサ、表示・ブザーは今は要らない。CAN 越しのファームの書き込み（class 7）も中身が無い。
- CAN 越しの I2C、SPI（ブリッジの種類）の案（2026-10-16、ユーザ）。自前のファームなしでセンサを使える。1 回のやりとりごとに往復が入るので、速いものや時間に厳しいものには向かない。手元の I2C-CAN モジュールが候補。
- 位置の指令（M-49）を作るときの参考: ODrive（XDrive）の位置まわり。入力のモード（POS_FILTER、TRAP_TRAJ）、軌道の速度・加速度の上限、速度とトルクのフィードフォワード、速度の上限（`~/dev/Eugene_Ramirez/archive/F3RC_2026/docs/xdrive_protocol.md`、2026-10-16、ユーザ）。
- k の決め方の代案を探したい（DIP の他に）。基板ごとに決めてよい（C-75）。
- 部の mas libraries（作成予定、organization の private）に移すときの置き方。`lib_deps` の git の URL はリポジトリ直下のライブラリしか取り込めないので、ライブラリごとにリポジトリ（`lib/mas/` がそのまま直下になる）か、1 つにまとめてサブモジュールと `lib_extra_dirs` か。部員は SSH 鍵か HTTPS のログインが要り、`#v1.0.0` で版を固定する。トークンを URL に書かない（2026-10-15）。
- 起動直後に動かない形は、CANopen、ODrive、Dynamixel が採り、DJI、VESC は採らない（Q38 の材料）。

## 他の種類と API

- 他の種類の未決（Q27〜Q31、Q37 など）は、reserved.md を作るときにここへ移す。それまでは `docs/redesign/spec-draft.md` の確認事項 D。
- API の保留（2026-10-15 に api.md を作った。`waitReady`、刻みの既定値、`stop`／`commandConflict`／`onSettingError`、A11 は決めた）: A10（`setSyncSource`。SYNC の送り手が 2 台になる穴と同じ）、loop の中の確保の失敗の細部（`error()` の `OutOfMemory` で知らせる方向。API-38）、汎用ピン、エアー、ソレノイドの未決（ソレノイドの `pulse(ms)` をどちらが計るか、`read()` の閾値、汎用出力と汎用入力の設定の種類をまとめるか）、保存の API（A5、API-59）。
- `can.error()`（API-47）がいくつの異常を、いつまで持つか。最後の 1 つだけか、履歴を持つか、読んだら消えるか（2026-10-15、ユーザ: 検討の余地あり）。
- 実装（2026-10-15、Claude）で台帳に無いまま仮に決めたもの。確かめて台帳に書くか、直す:
  - サーボの較正の既定（`configCalibration` を呼ばないとき）は ±π/2 rad ↔ 500〜2500 µs。
  - 範囲外の ch（MD の 32 以上など）を求めると、何もしない取っ手（`ch()` が 255）を返し、`error()` には残さない。
  - `flush()` の「時計を数え直す」は束ごと（送った束だけ、その束の周期を数え直す）。全部を数え直すと、毎回 `flush()` したときに変わらない束が送られなくなるため。
  - 汎用ピン、エアー、ソレノイドの取っ手は、値を覚えるだけで送受信しない（線の上の形が未決）。
  - バスの使用率のスタッフィングは、詰める部分の 1 割と見積もる。
  - FB を切った MD（設定 35 ＝ 0）は、刻みを書けないので ready にならず、止める値を送り続ける。
- SYNC の送り手が 2 台になる穴（2026-10-15、ユーザ: 遭遇が稀なので保留の穴とする）: ライブラリが SYNC を自動で送る限り、2 台目がいれば衝突しうる。止める関数は A10 の `setSyncSource(false)`。CAN のコントローラは自分の送ったフレームを受けないので、`0x002` を受けたら他の送り手がいると分かる（A10 の材料）。
