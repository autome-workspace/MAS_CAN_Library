# はじめに

MAS CAN の仕組みを、前提から順に軽く説明します。

細かい仕様は、各節の終わりのリンク先にあります。

## 1. MAS CAN とは

ロボットには、モーターやセンサーを動かす基板と、それらを利用しロボットを操作する制御系(ESP32など)がいくつも載ることになります。MAS CAN は、それらを 1 本の CAN の線でつないで話させるための、部で共通の規格（プロトコル）です。MAS は Meiji Autome Standard の略です。

なぜ共通規格が要るのか。CANは通信と、その内容の正しさを保証します。しかし、そもそもの通信内容が基板ごとにばらばらだと、プログラムを基板ごとに書き分けることになり、新しい基板を足すたびに主制御の側も直すことになります。話し方をそろえておけば、主制御は 1 つのライブラリで全部の基板を扱えますし、基板を作る人もこの決まりに合わせるだけで済みます。

このリポジトリには、次の 3 つが入っています。

| テーマ | 内容 |
|---|---|
| 規格 | この仕様書 |
| 主制御のライブラリ | `lib/mas`。主制御はこれを利用して通信する |
| 基板のファーム | `firmware/`。今ある基板（MD、サーボ）のファーム |

## 2. CAN の基本

MAS CAN は CAN 通信を前提としています。これについて、ここで知っておくことは 3 つだけです。

- **1 本の線(CAN BUS)に何台でもつながり、誰かが送ったものを全員が聞きます。** 宛先という考えは無く、受け手が「自分に関係あるか」を見て拾います。
- **1 回に送る単位を「フレーム」と呼びます。** フレームは、**ID**（11 bit の番号）と、最大 8 byte のデータ部、その他でできています。
- **ID が小さいフレームほど優先されます。** 2 台が同時に送ろうとしたら、ID の小さいほうが先に線を通ります。

MAS CAN は、この ID に「何についての話か」を割り当てて使います。

## 3. 登場するもの

| 言葉 | 意味 |
|---|---|
| 主制御 | ロボットのプログラムを動かすマイコン。基板に指示を出す |
| 基板 | モーターやせんさーを実際に動かすマイコンの基板 |
| 種類 | 基板が動かすものの区別。**MD**（モータードライバー）、**サーボ**など
| ch | 種類ごとの通し番号。「MD の 3 番」「サーボの 3 番」は別物。MD は 0〜31、サーボは 0〜63。 |

基板は、ある種類の ch をいくつか受け持ちます。1 ch だけの MD の基板もあれば、サーボ 8 ch と MD 4 ch を両方受け持つ基板もあります。何番から受け持つかは、基板の上のスイッチなどで決めます。

主制御のプログラムは、基板を意識せず「MD の 3 番」「サーボの 5 番」と ch で指示します。どの基板がその ch を受け持っているかは、気にしなくて構いません。

## 4. 何を話すか

主制御と基板が交わす話は、次の 5 つに分かれます。どの種類の基板でも同じです。

| 内容 | 向き | 例 |
|---|---|---|
| 指令 | 主制御 → 基板 | 「MD の 0 番、30% の力で回れ」 |
| FB（フィードバック） | 基板 → 主制御 | 「MD の 0 番、今 0.8 A 流れている」 |
| 設定 | 主制御 → 基板 → 主制御（聞いて答える） | 「MD の 0 番、電流の上限を 3 A に」「MD の 3 番を受け持つ基板の種類は？」 |
| E-stop（緊急停止） | 主制御 → 全部の基板 | 「全部止まれ」 |
| 起動の合図 | 基板 → 主制御 | 「今起動した」 |

ID は、この話の分け方に沿って割り当ててあります。ID の上の桁が話の区分（class）です。

| ID | 区分 |
|---|---|
| `0x000`〜`0x0FF` | 安全と同期（E-stop、起動の合図など） |
| `0x200`〜`0x2FF` | 指令 |
| `0x300`〜`0x3FF` | FB など、基板から周期的に流れてくるデータ |
| `0x400`〜`0x4FF` | 設定 |
| ほか | 予約、自作用 |

ID が小さいほど優先されるので、E-stop が一番先に通り、指令はどの FB よりも先に通ります。

詳しく: [ids.md](ids.md)。

## 5. 種類ごとの違い

指令と FB の中身の形は、種類ごとに違います。ここだけは種類ごとに覚える必要があります。

| | MD | サーボ |
|---|---|---|
| 指令の中身 | 電流、速度、duty（力の割合）のどれか。1 ch あたり 2 byte | パルス幅。1 ch あたり 1 byte |
| 1 本のフレームに入る ch | **4 ch** | **8 ch** |
| FB | ある（ch ごとに 1 本） | 無い |

指令は ch 1 つごとではなく、何 ch 分かをまとめて 1 本のフレームで送ります。1 本に 8 byte まで入るので、MD は 2 byte × 4 ch、サーボは 1 byte × 8 ch がちょうど収まります。まとめて送ると線を流れる本数が減り、そのぶん速く回せます。このまとまりを**束**と呼びます。

### 例: MD を 1 つ回す

主制御のプログラムでは、こう書きます。

```cpp
mcan::Md motor = can.md(0);   // MD の 0 番

void loop() {
    can.update();              // 送受信は毎回これが行う
    motor.setDuty(0.3f);       // 30% の力で回す
}
```

線の上では、こう流れています。

```
主制御 → 基板   0x220  26 66            MD の duty の指令。ch 0〜3 の束
基板 → 主制御   0x320  82 03 20 26 66   MD の ch 0 の FB。電流 0.8 A、duty 0.3
```

- `0x220` は「MD の ch 0〜3 の duty の指令」です。ch 4〜7 なら `0x221` です。中身が 2 byte だけなのは、ch 1〜3 を使っていないので後ろを省いたからです。
- `0x320` は「MD の ch 0 の FB」です。ch 1 なら `0x321` と、ch の数だけ ID がずれます。

MD の FB は、指令が来ていなくても基板が自分から周期的に送ります。なので、`0x320`〜`0x33F` を聞いていれば、どの ch の MD がいるかが分かります。

詳しく: [md.md](md.md)。

### 例: サーボを動かす

```cpp
mcan::Servo arm = can.servo(9);   // サーボの 9 番
arm.setPulseUs(1500);             // パルス幅 1500 µs
```

```
主制御 → 基板   0x231  FF 64   サーボの指令。ch 8〜15 の束
```

ch 9 は束の 2 つ目なので、2 byte 目に値が入ります。1 byte 目の `FF` は「使っていない」という印です。サーボには FB が無いので、基板からの返事は流れてきません。

詳しく: [servo.md](servo.md)。

## 6. 止まる仕組み（全種類共通）

モーターやサーボが勝手に動き続けないように、止める仕組みが 2 つあります。

**指令が途絶えたら止まる。** 主制御は指令を周期的に送り続けます（MD は 100 回／秒、サーボは 50 回／秒くらい）。基板は 0.1 秒指令が来なければ、自分で出力を止めます。主制御のプログラムが固まったり線が抜けたりしても、止まります。

**E-stop。** 主制御が `0x000` を送ると、全部の基板が止まり、解除されるまで止まったままになります。解除は `0x001` です。

```cpp
can.estop();       // 全部止める
can.clearEstop();  // 解除
```

詳しく: [bus.md](bus.md)。

## 7. 電源を入れたとき（全種類共通）

基板は起動すると、まず起動の合図を 1 本送ります。ID は種類ごとで、MD なら `0x010`、サーボなら `0x011` です。

その後の 0.2 秒は、指令が来ても動きません。主制御が、その基板に必要な設定を送る時間を取るためです。0.2 秒たつと、次の指令から動き出します。

起動の合図は中身が空で、どの基板かは分かりません。同じ種類の基板が同時に起動しても、ぶつからないようにするためです。

動いている途中で基板が再起動したときも、同じ合図が流れます。主制御のライブラリはそれに気づいて、必要な設定を送り直します。プログラムを書く人は何もしなくて大丈夫です。

詳しく: [flows.md](flows.md) の 1 と 5。

## 8. 設定（全種類共通）

設定は、主制御が聞いて基板が答える形です。基板の種類を聞いたり、電流の上限のような調整値を読み書きしたりするのに使います。

ID は種類ごとに、聞くものと答えるものの 2 つがあります。

| | 聞く | 答える |
|---|---|---|
| MD | `0x400` | `0x408` |
| サーボ | `0x410` | `0x418` |

宛先は、指令と同じく「どの種類の何番か」です。種類は ID で、番号は中身の 1 byte 目で決まります。その ch を受け持つ基板だけが答え、ほかの基板は黙っています。

基板そのもののこと（種類、版、固有 ID）を聞くときも、その基板が受け持つ ch に宛てて聞きます。ch 0〜3 を受け持つ基板なら、0 番に聞いても 3 番に聞いても、同じ基板の答えが返ってきます。

中身の形は、どの種類でも同じです。例えば、MD の ch 3 を受け持つ基板に「基板の種類は？」と聞くと、こうなります。

```
主制御 → 基板   0x400  03 00 01 00 00 00 00 01
基板 → 主制御   0x408  03 00 01 00 03 00 01 01   種類 0x0003（micro-MD）、版 1
```

| byte | 意味 | この例 |
|---|---|---|
| 0 | どの ch に聞くか | 3 |
| 1 | 読む／書く／保存 | 0（読む） |
| 2 | 何を聞くか（項目の番号） | 1（基板の種類） |
| 3〜6 | 値 | 答えで `00 03 00 01` |
| 7 | 通し番号（答えと対応させる） | 1 |

**基板の種類や版を知りたいときは、この設定で聞きます。** FB の `0x300` 台は周期的に流れてくるデータだけで、そこに問い合わせても何も返りません。

（今のサーボの基板のファームは、まだ設定に答えません。）

詳しく: [settings.md](settings.md)。

## 9. まとめ

| やりたいこと | 全種類共通の考え方 | MD | サーボ |
|---|---|---|---|
| 動かす | 指令を束で周期的に送る | `0x210`〜`0x22F`（4 ch ずつ） | `0x230`〜`0x237`（8 ch ずつ） |
| 様子を知る | FB を聞く | `0x320`〜`0x33F` | 無い |
| 全部止める | E-stop と解除 | `0x000`、`0x001` | 同じ |
| 起動を知る | 起動の合図 | `0x010` | `0x011` |
| 基板に聞く、調整する | 設定 | `0x400`、`0x408` | `0x410`、`0x418` |
