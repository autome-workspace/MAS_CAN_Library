# 共通の決まり

全種類の基板と主制御が守る決まり。物理層、ch の数え方、E-stop、SYNC、起動の知らせ、起動の猶予、周期指令の共通の規則、再起動の扱い。全体像は [overview.md](overview.md)、場面ごとの流れは [flows.md](flows.md)、種類ごとの形は [md.md](md.md)、[servo.md](servo.md)、設定は [settings.md](settings.md)。

起動の知らせ、起動の猶予、再起動の扱いは、この文書が詳しい置き場所。ほかの文書はここへリンクする。

読み方: 表の「番号」の列と文末の番号は台帳の決まり。「今の実装では」と書いた文は、`lib/mas` の node（基板側）と主制御のライブラリ（`Host`）の今の動きで、台帳の決まりではない。台帳で決まっていないことは「台帳では未定」と書き、今の実装の動きを添える。

## 1. 物理層と基本

| 項目 | 決まり | 番号 |
|---|---|---|
| CAN | 通常の CAN（FD ではない）。1 フレーム 8 byte まで | C-8 |
| ID | 11 bit の標準 ID | C-8 |
| 速度 | 1 Mbps | C-9 |
| サンプル点 | 80%。can2040（RP2040 の PIO で作る CAN）だけは 81.25% 固定（1 bit ＝ 32 tq、26 tq 目）を例外として認める | C-9 |
| SJW | 取れる最大（フェーズセグメント 2 と同じ長さ） | C-9 |
| 発振子 | 水晶を推奨。セラロックなら ±0.5% 級 | C-10 |
| フレームの形式 | データフレームだけを使う。リモートフレームは使わず、受けても何もしない。ただし `0x000` はリモートフレームでも E-stop として止める | C-11 |
| バイトの並び | big-endian。2 byte 以上の値はすべて上位の byte が先 | C-12 |
| 番号の数え方 | ch と基板の位置 k は 0 から数える | C-13 |

big-endian の例（C-12）:

| 値 | 型 | 線の上の byte |
|---|---|---|
| 100 | int16 | `00 64` |
| −100 | int16 | `FF 9C` |
| 1234567 | uint32 | `00 12 D6 87` |
| 1.0 | float32 | `3F 80 00 00` |

## 2. ch と基板の位置 k

### ch

- ch は種類ごとの列ベクトルの番号。基板は、その連続した範囲を受け持つ入れ物。1 枚が複数の種類の ch を持ってもよい（C-14）。
- ch の範囲は MD が 0〜31（M-1）、サーボが 0〜63（S-1）。

### 番号の計算

束の大きさは MD が 4（M-6）、サーボが 8（S-1）。

| 量 | 式 | 番号 |
|---|---|---|
| フレーム番号 | ch ÷ 束の大きさ（切り捨て） | C-21 |
| slot | ch を束の大きさで割った余り | C-21 |
| ch ごとの ID | 基点 ＋ ch（MD の FB は `0x320`＋ch） | C-21、M-14 |
| 周期指令の ID | `0x210` ＋ 周期指令の番号 × 8 ＋ フレーム番号 | C-25 |

周期指令の番号は 0〜3 が MD（電流、速度、duty、位置）、4 がサーボ（C-25）。種類の番号（MD 0、サーボ 1）とは別の番号（C-26）。

| 例 | フレーム番号 | slot | ID |
|---|---|---|---|
| MD の ch 5 の速度の指令 | 1 | 1 | `0x219`（＝ `0x210` ＋ 1 × 8 ＋ 1） |
| MD の ch 5 の FB | — | — | `0x325` |
| サーボの ch 10 の指令 | 1 | 2 | `0x231`（＝ `0x210` ＋ 4 × 8 ＋ 1） |

### 基板の位置 k

| 決まり | 番号 |
|---|---|
| k で決めるのは主な種類の先頭の ch だけ。先頭の ch ＝ k × 基板の大きさ（受け持つ ch の数） | C-81 |
| 他の種類の ch の範囲は、基板のファームが持つ規則で計算する | C-81 |
| k の決め方（DIP、LED とスイッチなど）はプロトコルで決めない。基板ごとの資料に書く。プロトコルが求めるのは「起動時に k が決まっている」ことだけ | C-75 |
| k の bit 数（DIP なら本数）はプロトコルで決めない。推奨は、その種類の ch の数を基板の大きさで割った区画をすべて指せる数。実際の数は基板ごとの資料に書く | C-82 |
| k は起動時に 1 回だけ読む | C-18 |
| 受け持つ範囲がその種類の ch の範囲からはみ出すなら、CAN に何も送らず何も受けず、出力を止めたままにする。知らせ方（LED など）は基板の資料に書く | C-18 |

C-82 の推奨の例: MD は 32 ch なので、1 ch の基板なら 32 区画で 5 bit、4 ch の基板なら 8 区画で 3 bit。

C-18 の例: 4 ch の MD で k ＝ 8 なら先頭の ch は 32 で、MD の範囲（0〜31）を超える。この基板は線に何も出さない。

### 受け持ちの重なり

- ch の受け持ちは重複しない前提。重複は項目 0（固有 ID）を読むか、バスのエラー（FB の衝突など）で気づく。確実に見つける仕組みは持たない（同時に応答すると項目 0 の応答も衝突する）（C-83）。
- 基板から送る束は、1 枚の基板がまるごと受け持つ。2 枚が同じ ID で送ると衝突するため。指令の束は、複数の基板が別々の ch を読んでよい（C-20）。
  - 例: 1 ch の MD 4 枚が、MD の ch 0〜3 の指令のフレーム（`0x218` など）を共有し、それぞれ自分の slot だけを読む。

## 3. class 0: 安全と同期

| ID | 名前 | DLC | 向き | 番号 |
|---|---|---|---|---|
| `0x000` | E-stop | 問わない | 主制御 → 全基板 | C-28 |
| `0x001` | E-stop の解除 | 3 | 主制御 → 全基板 | C-29 |
| `0x002` | SYNC | 4 | 主制御 → 全基板 | C-32 |
| `0x010`＋種類の番号 | 起動の知らせ | 0 | 基板 → 主制御 | C-36 |

### 3.1 E-stop（`0x000`）

| 決まり | 番号 |
|---|---|
| 受け手は DLC を問わず、中身を見ない | C-28 |
| リモートフレームでも E-stop として止める | C-11 |
| 受けた基板は種類ごとに決めた動作をしてラッチする | C-28 |
| ラッチは解除か電源の再投入で解ける | C-30 |
| 自分で E-stop を掛けた主制御だけが、解除するまで 10 Hz で送り続ける。受けた E-stop は送り直さない | C-31 |

- 台帳（C-28）は、E-stop を受ける時期に例外を設けていない。今の実装（node）も、起動の知らせの前（`mas_can_node_ready` の前）と起動の猶予の間に受けた E-stop でラッチする。
- 基板が再起動すると（電源の再投入のほか、項目 6 やリセットでも）、ラッチは消える。起動は電源投入と同じ流れをたどるため（7 節）。台帳は再起動でラッチが消える前提で起動の猶予を置いている（C-89）。今の実装はラッチを RAM にだけ持つ。

種類ごとの動作（止め方の詳細は種類ごとの文書）:

| 種類 | E-stop で | 番号 |
|---|---|---|
| MD | 出力を止めてラッチする。止め方は [md.md](md.md) の 4.6 | M-51 |
| サーボ | パルスを止めてラッチする（[servo.md](servo.md) の 3） | S-9 |

例（ライブラリが送る形）:

```
0x000 DLC 0
```

場面としての流れ（送り続ける、解除、送り直し）は [flows.md](flows.md) の 4。

### 3.2 E-stop の解除（`0x001`）

DLC 3 ちょうどで、署名 `"clr"` が一致したときだけ受け付ける（C-29）。リモートフレームは受けても何もしない（C-11）。

| byte | 中身 |
|---|---|
| 0 | `0x63`（`c`） |
| 1 | `0x6C`（`l`） |
| 2 | `0x72`（`r`） |

```
0x001 DLC 3 : 63 6C 72
```

- 解除の後の動作は種類ごと。MD は [md.md](md.md) の 4.3、サーボは [servo.md](servo.md) の 3。
- 解除の後に起動の猶予は掛からない（3.5）。
- 解除の前に指令を安全な値に戻すのは主制御の仕事（M-27）。主制御のライブラリは、解除のときアプリの指令を止める値に戻す（API-22）。
- 今の実装（node）では、ラッチしていない基板が解除を受けても何もしない。

主制御のライブラリの解除の送り直し（API-24）: 解除を 1 回送り、100 ms 後も FB の bit 5 が立っている基板があれば最大 3 回送り直す。台帳は、それでも残れば異常と同じ道で知らせるとしている。今のライブラリは、3 回送り直しても残るとき、何も知らせずに見張りをやめる（`Host::serviceEstop`）。

### 3.3 SYNC（`0x002`）

| byte | 中身 |
|---|---|
| 0–3 | 主制御の起動からの経過時間（uint32、µs） |

| 決まり | 番号 |
|---|---|
| DLC 4 だけを受け付ける。DLC 4 以外は捨てる | C-32 |
| 必須。指令を送るもの（PC のツールを含む）は 20 Hz で送る | C-33 |
| 複数の主制御がいるときは 1 台（時刻の親）だけが送る | C-33 |
| 主制御は時刻を送信の直前に取る | C-35 |
| 基板は受けた瞬間の自分の時計との差から時刻を換算し、周波数のずれも推定して補正する | C-35 |
| SYNC は時刻をそろえるためだけに使う。基板は SYNC が途絶えても出力を止めない。主制御が生きているかは ch ごとの指令で見る | C-90 |

- uint32 の µs なので、約 71.6 分で一周する。
- MD とサーボは時刻の欄（4 節）を使わない（C-38）。そのため MD とサーボの基板の動作は SYNC で変わらない（C-90）。
- 2 台目の主制御が SYNC を送ってしまう場合の扱いは、台帳では未定。今の実装では、主制御のライブラリ（`Host`）は SYNC を必ず 20 Hz で送り、止める手段が無い（止める関数は未決。`docs/internal/decisions/open.md`）。そのため、今のライブラリの主制御を同じ線に 2 台置くと C-33 を守れない。

例: 起動から 1234567 µs。

```
0x002 DLC 4 : 00 12 D6 87
```

### 3.4 起動の知らせ（`0x010`＋種類の番号）

| 決まり | 番号 |
|---|---|
| ID は `0x010`＋種類の番号、DLC 0 | C-36 |
| 全種類の基板が、起動したときに受け持つ種類ごとに 1 本ずつ送る | C-36 |
| 中身が空なのは、同じ種類の基板が同時に起動しても衝突しないため（同じ ID、同じ中身なら 1 本として届く） | C-36 |
| 設定の要求に応答できる状態（CAN の初期化、保存した設定の読み込み、k の読み取りが済んだ後）になってから送る。FB もその後から送り始める | C-37 |

例:

```
MD     0x010 DLC 0
サーボ 0x011 DLC 0
```

CAN-Servo 基板（サーボと MD を持つ）は、この 2 本を両方送る。

今の実装（node）は、`mas_can_node_ready` を呼んだときに MD の起動の知らせを送る待ち行列に積む。node が持たない種類（サーボ）の起動の知らせはポートが送る（[board.md](board.md)）。

### 3.5 起動の猶予

基板は起動の知らせを送ってから 200 ms の間、指令に従わない（C-89）。

| 猶予の間 | 番号 |
|---|---|
| 出力は止めたまま | C-89 |
| FB があれば bit 4（出力を止めている）を立てる | C-89、M-58 |
| 設定の要求には答える | C-89 |
| 過ぎたら次の有効な指令から動く（猶予の間に受けた指令では動かない） | C-89 |

猶予があるのは、主制御がプログラムの値（MD の刻み）を送り直す時間と、E-stop の送り直し（100 ms ごと、C-31）が届く時間を確保するため（C-89）。

- 猶予は起動の知らせから数えるものだけ。E-stop の解除の後や、指令の途絶の後には掛からない（C-89）。
- 猶予の起点は、台帳では起動の知らせを送ったとき。今の node は `mas_can_node_ready` を呼んだ時刻（起動の知らせを待ち行列に積んだ時刻）から数える。差は線に出るまでの待ちの分だけ。
- 猶予の間の止め方は [md.md](md.md) の 4.6、[servo.md](servo.md) の 3。

## 4. 時刻の欄

時刻を載せる種類が使う 2 byte の欄（C-38）。MD とサーボは使わない（C-38）。

| bit | 中身 |
|---|---|
| 15 | 同期している |
| 0–14 | 同期した時刻の下位 15 bit（µs） |

SYNC が途絶えてから「同期していない」にするまでの時間は未定。

## 5. 周期指令（class 2）の共通の規則

| 決まり | 番号 |
|---|---|
| 指令の形（MD の電流、速度、duty、位置など）は ID で表す。複数の ch を 1 フレームにまとめて送る | C-27 |
| 1 フレームが 1 束を運ぶ。同じフレームに入る ch では指令の形を混ぜない | C-39 |
| 使っていない slot には、その種類の「止める値」を入れる | C-40 |
| 1 つの束は 1 台の主制御だけが受け持つ（主制御を分けるなら ch を束の区切りで分ける）。「この欄は触らない」という値は作らない | C-76、C-78 |
| 後ろの slot が使われていなければ DLC を縮めてよい（送り手の任意。常に DLC 8 で止める値を詰めても正しい） | C-41 |
| 受け手は、自分の slot が DLC の外ならその ch の指令を受けていない扱いにする（途絶の時計は進み続ける）。奇数の DLC で半端な slot も同じ | C-42 |
| ch ごとの指令の途絶判定は 100 ms。主制御が生きているかはこれで見る | C-91 |
| 送る周期（ライブラリ）は MD の指令 100 Hz、サーボ 50 Hz | C-44 |

止める値:

| 指令 | 止める値 | 番号 |
|---|---|---|
| MD の電流、速度 | 0 | M-7 |
| MD の duty | `0x0000` | M-8 |
| サーボ | 255（`0xFF`） | S-3 |

MD の位置の指令は ID だけを予約していて、中身（止める値を含む）は未定（M-49）。

途絶したときの動作（止め方の詳細は種類ごとの文書）:

| 種類 | 途絶で | 番号 |
|---|---|---|
| MD | 出力を止める（止め方は [md.md](md.md) の 4.6）。ラッチしない | M-57 |
| サーボ | パルスを止める。ラッチしない | S-15 |

どちらも、次の有効な指令が来たらまた動く。場面としての流れは [flows.md](flows.md) の 3。

C-39 の意味: 同じ束の ch に別々の指令の形のフレームを送ると、どちらのフレームも相手の ch に止める値を入れるので、互いに止め合う。MD の ch 4 を速度、ch 5 を電流で動かすことはできない。ch を束の区切りで分ける。

### 例

MD の ch 5 に速度 100 を送る。ch 4 は使っていないので止める値 0、ch 6、7 は削って DLC 4（C-40、C-41）。

```
0x219 DLC 4 : 00 00 00 64
              └ch4┘ └ch5┘
```

同じ指令を DLC 8 で送っても正しい（ch 6、7 には止める値 0）。ch 5 に −100 なら:

```
0x219 DLC 8 : 00 00 FF 9C 00 00 00 00
```

DLC が 3 なら、ch 4 の slot（byte 0–1）はそろっているので有効、ch 5 の slot（byte 2–3）は半端なので ch 5 は指令を受けていない扱い（C-42）。

サーボの ch 10 に値 100（パルス幅 1500 µs、S-2）を送る。ch 8、9 は使っていないので 255。

```
0x231 DLC 3 : FF FF 64
              ch8 ch9 ch10
```

## 6. FB の共通の bit

| 決まり | 番号 |
|---|---|
| 状態を持つ周期データでは、bit 0「基板に異常あり」を全種類で共通の意味にする | C-45 |
| bit 0 は、異常の詳細（項目 5）のどれかの bit が立っている間 1 | C-45 |
| 基板専用の周期フレームは持たない。生存の確認は ch ごとの FB で代用する | C-15 |

- bit 0 が立ったら、主制御は設定で異常の詳細（項目 5）を読む。bit の意味は [settings.md](settings.md)。
- 詳細の bit は、主制御が 1 を書いて消すまで残る（C-67）。全部消えれば FB の bit 0 も 0 に戻る（C-45）。
- サーボには FB が無い（S-10）。

## 7. 再起動の扱い

基板が再起動すると、プログラムの値が焼いた値に戻り（C-80）、MD の位置は 0 から数え直し（M-2）、E-stop のラッチも消える。主制御は再起動に気づいて、プログラムの値を送り直す必要がある。

再起動の扱いの詳しい置き場所はこの節。場面としての流れは [flows.md](flows.md) の 5（基板の再起動）と 6（主制御だけの再起動）。

### 7.1 知らせる仕組み

再起動は 2 つで知らせる（C-69）。

| 手段 | 役目 | 番号 |
|---|---|---|
| 起動の知らせ | 早く気づくため。どの基板かは分からない | C-36、C-69 |
| 異常の詳細の bit 0「再起動した」 | 取りこぼしの受け皿。FB のある種類は、FB の bit 0 でどの基板かも分かる | C-67、C-69 |

### 7.2 基板がすること

| すること | 番号 |
|---|---|
| 起動したら異常の詳細の bit 0 を立てる。主制御が 1 を書いて消すまで残す | C-67、C-69 |
| 設定の要求に答えられるようになってから、起動の知らせを送り、FB を送り始める | C-36、C-37 |
| 起動の知らせから 200 ms は指令に従わない（起動の猶予） | C-89 |
| 保存しない項目（プログラムの値）は焼いた値で始める | C-80 |

設定の項目 6 で、主制御から基板を再起動させることもできる（C-66。[settings.md](settings.md)）。

### 7.3 主制御（ライブラリ）がすること

| すること | 番号 |
|---|---|
| 再起動に気づいたら（起動の知らせ、または FB の bit 0）、その種類のプログラムの値をほかの設定より先に送り直し、異常の詳細の bit 0 を消す | C-69、C-88 |
| 起動の知らせを受けたら、その種類の全 ch に送り直す印を付けるだけで、止めない（止めると 1 枚の再起動で線の全部が止まる） | C-94 |
| どの基板かは FB で見分ける。起動の知らせの後に最初に受けた FB で bit 0 が立っている ch を、再起動した基板とみなす。その ch は刻みを既定値（1.0）とみなし、ほかより先に書く | C-94、M-56 |
| 前から FB の bit 0 が立っていた ch は、刻みが分からないとする | C-94 |
| 異常の詳細の bit 0 で、同じ再起動をもう一度処理しない | C-94 |
| FB の bit 0 が立っている間は異常の詳細を 100 ms ごとに読み直す。起動の知らせを取りこぼしても、詳細の bit 0 で猶予が明ける前に気づくため | API-66 |
| 刻みを書けたと確かめるまで、その ch には止める値を送る | API-43 |

起動の知らせに ch を載せることはしない。同じ ID で中身が違うと衝突するため（C-94、C-36）。

今の実装（主制御のライブラリ）:

- 起動の知らせで送り直しの印を付けるのは、FB を一度でも受けた ch だけ。まだ FB を受けていない ch は、最初の FB を受けたときに刻みを書く（API-44）ので、結果は同じ。
- 異常の詳細の読み直しは、最後に読んでから 100 ms 経った後に受けた最初の FB で行う。FB が 10 ms ごとなら、およそ 110 ms おきになる。

FB の無い種類（サーボ）の生存は確かめない（S-10）。サーボの基板の再起動は起動の知らせでだけ分かる。

## 8. 基板の状態ごとの動作

上の決まりを、基板の状態ごとにまとめる。

| 状態 | 出力 | 指令 | FB（MD） | 番号 |
|---|---|---|---|---|
| k が範囲外 | 止めたまま | 受けない | 送らない | C-18 |
| 起動の知らせの前 | 止めたまま | — | 送らない | C-37、M-22、S-7 |
| 起動の猶予（200 ms） | 止めたまま | 従わない | bit 4 ＝ 1 | C-89 |
| 指令を受けている | 指令に従う | 従う | bit 4 ＝ 0 | M-22、S-7 |
| 途絶（100 ms 指令が来ない） | 止める（ラッチしない） | 次の有効な指令で動く | bit 4 ＝ 1 | C-91、M-57、S-15 |
| E-stop でラッチ中 | 止める | 解除まで従わない | bit 4、bit 5 ＝ 1 | C-28、C-30、M-51 |
| E-stop の解除の後（MD。次の指令まで） | 止める | 次の有効な指令で動く。猶予は無い（[md.md](md.md) の 4.3） | bit 4 ＝ 1 | M-27 |
| E-stop の解除の後（サーボ） | 台帳では未定（[servo.md](servo.md) の 3） | — | — | — |

止め方（ブレーキか空転か）は [md.md](md.md) の 4.6、[servo.md](servo.md) の 3。

## 9. 設定（class 4）

基板の情報を読む、値を書く、保存する、初期化する仕組みは [settings.md](settings.md) にある。基板の種類や受け持つ ch の範囲を知るのも設定で行う（[overview.md](overview.md) の 8 節）。
