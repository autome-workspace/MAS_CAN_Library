|---|---|

主制御のプログラムを書くだけの人は、この仕様書ではなく [案内](../guide/README.md) を読んでください。案内は ID やフレームを出さずに、使い方を説明しています。このページは、線の上の形をそのまま扱います。

文末の「（C-36）」などは、決定の台帳（`docs/internal/decisions/`）の番号です。台帳が決まりの正本です。「今の実装では」と書いた文は、`lib/mas` の今の動き（基板側の node と、主制御のライブラリ `Host`）です。こちらは台帳の決まりではないので、プロトコルを変えずに変わることがあります。

## 1. MAS CAN とは

MAS CAN は、ロボットの中の基板どうしを 1 本の CAN の線でつないで話させるための、部で共通の決まり（プロトコル）です。MAS は Meiji Autome Standard の略です。

ロボットには、モーターやサーボを動かす基板と、それらに指示を出してロボットを操作するマイコン（ESP32 など）が載ります。指示を出す側のマイコンを、この仕様書では**主制御**と呼びます。「制御」という言葉はほかの意味（速度の制御など）でも使うので、指示を出す側を名指すときは必ず「主制御」と呼びます。

共通の決まりが要るのは、話し方が基板ごとにばらばらだと、主制御のプログラムを基板ごとに書き分けることになるからです。CAN は、フレームが壊れずに届くことまでは保証します（壊れていれば送り手が送り直します）。しかし、届いた中身を何と読むかは決めていません。話し方をそろえておけば、主制御は 1 つのライブラリで全部の基板を扱えます。基板を作る人も、この決まりに合わせれば、主制御の側を直さずに新しい基板を足せます。

プロトコルが決めるのは、線の上の形と、外からの見え方（FB の bit、異常の詳細）だけです。保護のやり方のような基板の中の振る舞いは基板に任せ、基板ごとの資料に書きます。基板ごとに作りが違っても、主制御からは同じに見えるようにするためです（C-7）。

許可制（arming）はありません。基板は電源を入れたら動ける状態になります。大会では緊急停止ボタンで駆動電源が電気的に切れるので、プロトコルの側で許可を取る必要が無いからです（C-4）。

旧仕様（v0）とは互換がありません。v0 はタグ `v0` に残っています（C-95）。

## 2. CAN について、ここで要ること

CAN のおおよそを知っている人は、この節を飛ばしてかまいません。知っておくことは 4 つです。

- **1 本の線に全員がつながり、誰かが送ったものを全員が聞きます。** 宛先という考えはありません。受け手が「自分に関係あるか」を見て拾います。
- **1 回に送る単位を、フレームと呼びます。** フレームは、**ID**（11 bit の番号）と、0〜8 byte のデータ部でできています。データ部の長さを **DLC** と呼びます。MAS CAN は、通常の CAN（FD ではない）の 11 bit の標準 ID を使います（C-8）。
- **ID が小さいフレームほど優先されます。** 2 台が同時に送り始めたら、ID の小さいほうが線を取り、もう一方は待ってから送ります（この取り合いを調停と呼びます）。
- **ある ID を線に出すのは、1 台だけにします。** 2 台が同じ ID のフレームを同時に送ると、調停で決着がつかず、DLC かデータ部の違う bit でエラーになります。ただし、DLC とデータ部まで完全に同じなら、2 本は重なって 1 本として届き、誰も気づきません。

MAS CAN は、ID に「何についての話か」を割り当てて使います。4 つ目の性質は、決まりのあちこちに効いています。基板が送る ID は、1 枚の基板だけが送るように割り当ててあります（5 節）。逆に、起動の知らせは中身を空にして、何枚が同時に送っても重なって 1 本になるようにしてあります（8 節）。

## 3. 言葉: 主制御、基板、種類、ch、束

| 言葉 | 意味 |
|---|---|
| 主制御 | ロボットのプログラムを動かし、基板に指示を出すマイコン |
| 基板 | 指示を受けて、モーターやサーボを実際に動かす基板 |
| 種類 | 基板が動かすものの区別。今あるのは **MD**（モータードライバー）と**サーボ** |
| ch | 種類ごとに 0 から振った通し番号。MD は 0〜31、サーボは 0〜63 |
| 束 | 1 本のフレームでまとめて送る ch の組。MD は 4 ch、サーボは 8 ch |

**主制御は、相手を「種類と ch」で指します。** 主制御から見ると、MD の ch 0〜31 が並んだ列と、サーボの ch 0〜63 が並んだ別の列があります（C-13、C-14、M-1、S-1）。「MD の ch 5」と「サーボの ch 5」は別物です。種類ごとに 4 bit の**種類の番号**があり、MD が 0、サーボが 1 です（C-26）。

**基板は、ch をいくつか受け持つ入れ物です。** 基板は、ある種類の ch の連続した範囲を受け持ちます。1 枚が複数の種類の ch を持ってもかまいません（C-14）。主制御は、どの基板がどの ch を受け持つかを知らなくても、ch で指示を出せます。

| 基板の例 | 基板の種類（項目 1） | 受け持つもの |
|---|---|---|
| CAN_MD 基板 | `0x0001` | MD の ch 1 つ（C-97） |
| micro-MD 基板 | `0x0003` | MD の ch 1 つ（C-96） |
| CAN-Servo 基板 | `0x0002` | サーボの ch 8 つと MD の ch 4 つ（C-92） |
| XDrive 中継機 | `0x0004` | 速度の指令を受ける MD の ch 4 つ（M-1、M-4、C-99） |

「基板の種類」は製品の区別で、「種類の番号」（MD 0、サーボ 1）とは別の番号です。

**どの範囲を受け持つかは、基板の位置 k で決めます。** 同じ基板を何枚もつなぐので、範囲を基板ごとに決める必要があるからです。k も 0 から数えます（C-13）。

- 先頭の ch は「k × 基板の大きさ」です。基板の大きさは、受け持つ ch の数です（C-81）。例: 1 ch の MD で k が 2 なら MD の ch 2、4 ch の MD で k が 1 なら MD の ch 4〜7 です。
- k で決めるのは、主な種類の先頭の ch だけです。ほかの種類の範囲は、基板のファームが持つ規則で決めます（C-81）。
- k の決め方（DIP スイッチ、LED とボタンなど）はプロトコルで決めず、基板ごとの資料に書きます（C-75）。
- 基板は k を起動時に 1 回だけ読みます。範囲がその種類の ch の範囲からはみ出すなら、その基板は CAN に何も送らず、何も受けず、出力を止めたままにします（C-18）。
- 2 枚の基板が同じ ch を受け持たないようにするのは、組む人の責任です。重なりを確実に見つける仕組みはありません（C-83）。

番号の計算（フレーム番号、slot）は [bus.md](bus.md) の 2 にあります。

## 4. やりとりの種類と ID の区分

主制御と基板のやりとりは、次の 6 つに分かれます。どの種類の基板でも同じです。

| やりとり | 向き | ID（MD） | ID（サーボ） | いつ |
|---|---|---|---|---|
| 指令 | 主制御 → 基板 | `0x210`〜`0x22F` | `0x230`〜`0x237` | 周期的。MD 100 Hz、サーボ 50 Hz（C-44） |
| FB（フィードバック） | 基板 → 主制御 | `0x320`〜`0x33F` | 無い | 周期的。既定 100 Hz（M-47） |
| 設定 | 主制御 → 基板 → 主制御（聞いて答える） | `0x400`、`0x408` | `0x410`、`0x418` | 必要なときに 1 回ずつ |
| E-stop と解除 | 主制御 → 全基板 | `0x000`、`0x001` | 同じ | 止めるとき、解くとき |
| 起動の知らせ | 基板 → 主制御 | `0x010` | `0x011` | 基板が起動したときに 1 本 |
| 時刻合わせ（SYNC） | 主制御 → 全基板 | `0x002` | 同じ | 20 Hz（C-33） |

ID の上位 3 bit を **class** と呼び、やりとりの区分に使います。ID が小さいほど優先されるので、class の番号が小さいほど先に線を通ります（C-84）。

| class | ID の範囲 | 区分 |
|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期（E-stop、解除、SYNC、起動の知らせ） |
| 1 | `0x100`〜`0x1FF` | 予約 |
| 2 | `0x200`〜`0x2FF` | 周期指令 |
| 3 | `0x300`〜`0x3FF` | 周期データ（FB） |
| 4 | `0x400`〜`0x4FF` | 設定（要求と応答） |
| 5 | `0x500`〜`0x5FF` | 分割（MD とサーボは使わない） |
| 6 | `0x600`〜`0x6FF` | 自作 |
| 7 | `0x700`〜`0x7FF` | ファームの書き込み（予約） |

- E-stop がいちばん先に通ります。どの指令も、どの FB より先に通ります。指令と FB を別の class に分けたのは、このためです（C-23）。
- DJI のモーターが固定で使う ID は避けてあります。同じ線に DJI のモーターを載せられるようにするためです（C-24）。
- **class 3 は、基板が自分から送るデータの帯です。** 要求を受ける ID はありません。基板の種類や版は class 4 の設定で読みます（10 節）。基板ごとの周期のフレームも無く、基板が生きているかは ch ごとの FB で見ます（C-15）。

ID の一覧と作り方は [ids.md](ids.md) にあります。

## 5. 例: MD を 1 つ回す

主制御のプログラムが MD の ch 0 を duty 30% で回すと、線にはこう流れます（`examples/md_minimal` の `motor.setDuty(0.3f)`）。

```
主制御 → 基板   0x220 DLC 2 : 26 66              MD の duty の指令。ch 0〜3 の束
基板 → 主制御   0x320 DLC 5 : 82 03 20 26 66     MD の ch 0 の FB
```

**指令の `0x220` は「MD の ch 0〜3 の duty の指令」です。** 指令の ID は `0x210` ＋ 指令の番号 × 8 ＋ フレーム番号で、duty の番号は 2 なので `0x220` になります（C-25、M-6）。ch 4〜7 なら `0x221` です。指令の形（電流、速度、duty）は ID で表します（C-27）。

| byte | 値 | 意味 |
|---|---|---|
| 0–1 | `26 66` | ch 0 の slot。`0x2666` の bit 0 は 0 で空転、bit 1–15 は 4915。±16383 が ±100% なので、約 30%（M-8） |

DLC が 2 なのは、主制御が使わない ch 1〜3 の slot を削ったためです。後ろの使っていない slot は削ってよく、途中の使っていない slot には「止める値」を入れます（C-41、C-40）。

**FB の `0x320` は「MD の ch 0 の FB」です。** FB の ID は `0x320` ＋ ch なので、ch 1 なら `0x321` です（M-14）。この例は、電流だけを測れる基板の、起動が片付いた後の普段の FB です。

| byte | 値 | 意味 |
|---|---|---|
| 0 | `82` | 状態。bit 6–7 が 2 で duty に従っている。bit 1 が 1 で速度と位置が無効（M-18） |
| 1–2 | `03 20` | 電流 800。刻みが既定の 1 mA/LSB なので 0.8 A（M-7、M-56） |
| 3–4 | `26 66` | 速度が無効で電流が有効なので、ここには実際に出している duty が入る（M-15、M-16） |

FB の DLC は、測れるものによって 8、5、3 に変わります（M-15）。読み方は [md.md](md.md) の 3 にあります。

**指令は束でまとめ、FB は ch ごとに 1 本です。** 理由は、送り手の数が違うからです。

- 指令を 1 つの束に出すのは、主制御 1 台だけです（C-78、C-76）。だから 4 ch 分をまとめても、同じ ID を 2 台が出すことはありません。1 ch 1 本で送るより線を流れる本数が減り、ID も少なくて済みます。1 本の束を、複数の基板がそれぞれ自分の slot だけ読んでかまいません（C-20）。
- FB は基板がそれぞれ送ります。別々の基板の ch を 1 本にまとめると、2 枚が同じ ID で中身の違うフレームを送り、ぶつかります（2 節）。そのため、基板が送る束は 1 枚の基板がまるごと受け持つ決まりです（C-20）。それに MD の FB は 1 ch 分で最大 8 byte を使うので、何 ch 分も入りません。

**1 つの束の ch は、同じ形の指令で動かします。** 同じ束に別の形のフレームを送ると、互いの ch に止める値を入れて止め合うからです（C-39）。速度で回す ch と電流で回す ch は、別の束に置きます。

MD の FB は、指令が来ていなくても基板が周期的に送ります（M-21）。

## 6. 例: サーボを動かす

主制御のプログラムがサーボの ch 9 をパルス幅 1500 µs にすると、線にはこう流れます。

```
主制御 → 基板   0x231 DLC 2 : FF 64     サーボの指令。ch 8〜15 の束
```

| byte | 値 | 意味 |
|---|---|---|
| 0 | `FF` | ch 8。255 は「パルスを止める」で、使っていない slot に入れる止める値（S-3） |
| 1 | `64` | ch 9。値 100。パルス幅は 500 ＋ 値 × 10 µs なので 1500 µs（S-2） |

サーボの束は 8 ch で、1 ch が 1 byte です。ID は `0x230` ＋ フレーム番号なので、ch 9 は 2 本目の束 `0x231` の 2 つ目の slot に入ります（S-1）。角度からパルス幅への換算は主制御のライブラリが行い、線の上はパルス幅だけです（S-5）。

サーボには FB がありません（S-10）。基板からの返事は流れてこないので、主制御はサーボの基板が生きているかを周期的には確かめません。詳しくは [servo.md](servo.md) にあります。

## 7. 止まるとき

モーターやサーボが勝手に動き続けないように、止める仕組みが 2 つあります。

**指令が途絶えたら、基板は自分で止まります。** 基板は ch ごとに、指令が 100 ms 来なければその ch の出力を止めます（C-91）。主制御が生きているかを、指令で見ているからです。主制御のプログラムが固まっても、線が抜けても止まります。ラッチはせず、次の有効な指令が来たらまた動きます（M-57、S-15）。SYNC が途絶えても止めません。SYNC は時刻をそろえるためだけに使います（C-90）。

**E-stop は、全部の基板を止めて、止めたままにします。** 主制御が `0x000` を送ると、受けた基板は止まり、その状態を保ちます（ラッチ）。受け手は DLC も中身も見ません（C-28）。MD はブレーキで止めます。電源を切らない場面でも早く止まるようにするためです（M-51）。サーボはパルスを止めます（S-9）。

```
E-stop   0x000 DLC 0
解除     0x001 DLC 3 : 63 6C 72     "clr"
```

- 解除は DLC 3 で、署名 `"clr"` が一致したときだけ受け付けます（C-29）。ラッチは解除か、基板の電源の再投入で解けます（C-30）。
- 自分で E-stop を掛けた主制御は、解除するまで 10 Hz で送り続けます。後から起動した基板も止めるためです。ほかの送り手の E-stop を受けた主制御は、送り直しません（C-31）。
- 解除の後、MD は次の有効な指令から動きます。解除の前に指令を安全な値に戻すのは主制御の仕事です（M-27）。主制御のライブラリは、解除のときアプリの指令を止める値に戻します（API-22）。

詳しくは [bus.md](bus.md) の 3.1、3.2、5 にあります。場面としての流れは [flows.md](flows.md) の 3、4 にあります。

## 8. 電源を入れたとき

**基板は起動すると、起動の知らせを 1 本送ります。** ID は `0x010` ＋ 種類の番号で、MD は `0x010`、サーボは `0x011` です。DLC は 0 です（C-36）。サーボと MD を持つ CAN-Servo 基板は、2 本とも送ります。

```
MD       0x010 DLC 0
サーボ   0x011 DLC 0
```

起動の知らせの中身が空なのは、同じ種類の基板が同時に起動しても衝突しないためです（C-36）。電源を入れた瞬間や、電源の瞬断の後は、何枚もの基板が同時に起動します。中身が空なら、同じ ID で同じ中身なので、重なって 1 本として届きます（2 節の 4 つ目）。その代わり、どの基板が起動したかは分かりません。

**基板は、設定の要求に答えられるようになってから、起動の知らせを送ります。** CAN の初期化、保存した設定の読み込み、k の読み取りが済んだ後です。FB もその後から送り始めます（C-37）。主制御が知らせを受けてすぐ、設定を書けるようにするためです。

**起動の知らせから 200 ms は、基板は指令に従いません。** この間を起動の猶予と呼びます。出力は止めたままで、設定の要求には答えます。過ぎたら、次の有効な指令から動きます（C-89）。猶予があるのは、次の 2 つの時間を取るためです。

- 主制御が MD の**刻み**を書く時間。刻みは、電流と速度の 1 LSB が表す量です。刻みは起動のたびに既定の 1.0 に戻るので、前の刻みのつもりの指令をそのまま受けると、桁違いに動きます（M-56、C-88）。
- 主制御が送り続けている E-stop（100 ms ごと）を、動き出す前に受け取る時間（C-31）。

詳しくは [bus.md](bus.md) の 3.4、3.5 にあります。線の上の並びは [flows.md](flows.md) の 1 にあります。

## 9. 基板が再起動したとき

**動いている途中で基板が再起動すると、電源を入れたときと同じ流れになります。** 起動の知らせが出て、200 ms の猶予があります。刻みは 1.0 に戻り、MD の位置は 0 から数え直し、E-stop のラッチも消えます（C-80、M-2、C-89）。

**基板は、再起動を 2 つの方法で知らせます。** 1 つは起動の知らせで、早く気づくためです。もう 1 つは、設定の項目 5（異常の詳細）の bit 0「再起動した」で、起動の知らせを取りこぼしたときの受け皿です。bit 0 は主制御が消すまで残ります（C-100、C-69）。MD では、この bit が FB の状態の bit 0「基板に異常あり」として見えるので、どの ch の基板が再起動したかが分かります（C-45）。

**主制御は再起動に気づいても、指令を止めません。** 起動の知らせではどの基板か分からないので、止めると 1 枚の再起動で線の全部が止まってしまうからです（C-94）。主制御は、その種類の ch に刻みを送り直す印を付け、刻みをほかの設定より先に書きます（C-88、C-94）。

**主制御だけが再起動したときは、基板には前のプログラムの刻みが残っています。** そこで主制御のライブラリは、最初に FB を受けたときに刻みを書きます。書けたと確かめるまで、その ch には止める値を送ります（API-43、API-44）。

詳しくは [bus.md](bus.md) の 7 にあります。線の上の並びは [flows.md](flows.md) の 5、6 にあります。

## 10. 設定: 聞いて答える

**設定は、主制御が聞いて、基板が答えるやりとりです。** 基板の種類や版を読むこと、電流の上限のような値を読み書きすること、フラッシュへの保存に使います。

ID は種類ごとに 2 つあります。要求は `0x400` ＋ 種類の番号 × 16、応答はそれに 8 を足した ID です（C-46）。

| | 要求 | 応答 |
|---|---|---|
| MD | `0x400` | `0x408` |
| サーボ | `0x410` | `0x418` |

**宛先は、指令と同じく「種類と ch」です。** 種類は ID で、ch は byte 0 で決まります。その ch を受け持つ基板 1 枚だけが答え、受け持たない ch 宛てには誰も答えません（C-49）。基板そのものの情報も、その基板が受け持つ ch に宛てて聞きます。ch 0〜3 を受け持つ基板なら、ch 0 に聞いても ch 3 に聞いても、同じ基板が答えます。

例: MD の ch 3 を受け持つ基板に、項目 1（基板の種類）を聞きます。

```
主制御 → 基板   0x400 DLC 8 : 03 00 01 00 00 00 00 01
基板 → 主制御   0x408 DLC 8 : 03 00 01 00 03 00 01 01     micro-MD 基板（0x0003）、版 1
```

| byte | 意味 | この例 |
|---|---|---|
| 0 | ch | 3 |
| 1 | bit 6–7 が操作（0 読む、1 書く、2 保存、3 初期化）。bit 0–5 が結果（要求では 0、応答の 0 は成功） | 0（読む、成功） |
| 2 | 項目の番号 | 1（基板の種類） |
| 3–6 | 値（big-endian） | 応答で `00 03 00 01`。上位 16 bit が基板の種類、下位 16 bit が版（C-63） |
| 7 | 通し番号。応答を要求と対応させる | 1 |

（C-48、C-52、C-56）

- DLC は 8 だけを受け付けます（C-47）。2 byte 以上の値は、プロトコル全体で上位の byte が先です（C-12）。
- 主制御は、応答を受けてから次の要求を送ります（C-51）。
- 項目 0〜6 は全種類に共通です。0 確認（固有 ID）、1 基板の種類、2 ファームの版、3 プロトコルの版、4 受け持つ ch の範囲、5 異常の詳細、6 再起動です（C-60）。項目 0 の応答だけは、data 部の 8 byte すべてが固有 ID です（C-61）。

今の実装では、CAN-Servo-v1 はサーボの設定の要求（`0x410`）に答えません（[servo.md](servo.md) の 4）。フレームの形と全項目は [settings.md](settings.md) にあります。

### 線の上にどの基板がいるかを知るには

**「全員答えよ」という要求はありません。** 複数の基板が同じ ID で違う中身を同時に送ると、衝突するからです（C-83、C-36）。分かる手がかりは次の 3 つです。

- **FB が流れている ch には、MD がいます。** MD は指令が来ていなくても FB を送るので、`0x325` が聞こえれば MD の ch 5 がいます（M-21、M-14）。
- **サーボは、聞いているだけでは見えません。** FB が無いからです（S-10）。
- **どの ch が同じ基板か、何の基板かは、設定で 1 ch ずつ読みます。** 項目 4 で範囲を、項目 0 で固有 ID を、項目 1 で基板の種類を読みます（C-65、C-86）。

手順と線の上の並びは [flows.md](flows.md) の 8 にあります。PC で線を見るときの読み方は、案内の [線を見る、PC から使う](../guide/pc.md) にあります。

## 11. 値の決まり方

**基板の値は 2 種類に分かれます（C-5）。** 基板の性質（ピンの能力、ほかの種類の ch の範囲の規則、ハードウェアの限界）は、ファームに固定して基板の資料に書きます。ロボットごとに変わる値（ゲイン、電流の上限、MD の刻み）は設定の項目で、次の 3 段で決まります。例外はありません。

| 呼び名 | 置き場所 | 中身 |
|---|---|---|
| 焼いた値 | ファームの中 | 既定値 |
| 保存した値 | 基板のフラッシュ | 設定の「保存」で、そのときの値を書き込んだもの |
| 今の値 | 基板の RAM | 基板はこれで動く。起動時は保存した値（無ければ焼いた値）。主制御が書くと変わる |

**設定の項目は、機体の値とプログラムの値に分かれます（C-80）。**

| | 意味 | 保存 | 例 |
|---|---|---|---|
| 機体の値 | 機体を組んで調整すれば決まり、プログラムを書き換えても変わらない値 | できる | MD の回転方向、電流の上限（M-47）、エンコーダのカウント数と減速比（M-36）、速度ループのゲイン（M-54）。サーボのパルス幅の範囲（S-11） |
| プログラムの値 | 主制御のプログラムがどういう言葉で話すかを決める値 | できない | MD の電流と速度の刻み（M-56） |

プログラムの値は、起動すると必ず焼いた値に戻り、主制御が毎回送ります（C-80）。刻みはプログラムごとに違うので、前のプログラムの値で起動してしまわないようにするためです。

**上限は 2 段です（C-79）。** 限界はハードウェアの上限で、ファームに固定し、基板の資料に書きます。制限は使う側が設定で決める上限で、限界を超える値を書くと、基板は限界に抑えて受け付けます。例は MD の電流の上限です（M-47、M-43）。

詳しくは [settings.md](settings.md) の 1 にあります。

案内（[しくみ](../guide/host/how-it-works.md)）では、同じことを、ハードウェアの限界を 0 段目に数えて「4 段」として説明しています。中身は同じです。

## 12. プロトコルの版と互換

基板は項目 3 でプロトコルの版を返します（C-60）。値の欄 4 byte の並びは次のとおりです（C-71）。

| byte | 中身 |
|---|---|
| 3 | 大 |
| 4 | 中 |
| 5 | 小 |
| 6 | bit 6–7 が段階（0 alpha、1 beta（試験運用）、2 予約、3 正式）、bit 0–5 が X |

- X は開発用の「隠れた大」です（C-74）。
- 4 byte を整数として比べた大小が、版の新旧と一致します（C-71）。
- **大と X が一致すれば通じます。** 中、小、段階は問いません。新しい機能は、両方が持つときだけ使います（C-73）。
- ファームの違いは項目 2（ファームの版）で見分けます。X には流用しません（C-73、C-70）。
- 今の値は `lib/mas/include/mas/can/core/board.h` の `MAS_CAN_PROTOCOL_VERSION` にあります。基板側の node が自動で返すので、基板のファームには書きません（C-93）。

例: `0x010000C1` は、値の欄が `01 00 00 C1` です。版 1.0.0、段階 3（正式）、X が 1 であることを表します。

台帳は、主制御のライブラリが版の食い違いを利用者に知らせるとしています（C-73）。今のライブラリは項目 3 を読まず、版の食い違いを確かめていません。

## 13. 主制御が 2 台のとき、PC をつなぐとき

**1 つの束に指令を出すのは、1 台の主制御だけです。** 主制御を 2 台にするなら、ch を束の区切りで分けます（C-78、C-76）。

**SYNC を送るのも 1 台だけです（C-33）。** 今の実装では、`Host` は SYNC を必ず送り、止める手段がありません。そのため、今のライブラリの主制御を同じ線に 2 台置くと、この決まりを守れません。

**PC は、受信だけで線を監視できます（C-3）。** PC が主制御と一緒にいるときの扱いは、台帳では未定です（C-78）。台帳は DBC（PC の解析ツールに読ませる定義）を仕様と一緒に配布するとしていますが、今のリポジトリにはまだありません（C-3）。

主制御のライブラリ `Host` は、アプリが `can.update()` を呼ぶたびに、指令と SYNC の周期送信、刻みの書き込み、再起動の後片付けを中で行います（API-9）。何をいつ行うかは、案内の [しくみ](../guide/host/how-it-works.md) にあります。

## 15. 用語集

| 用語 | 意味 |
|---|---|
| 主制御 | 指令を送る側。ロボットのプログラムを動かすマイコン（ESP32 など） |
| 基板 | 指令を受けて動き、FB を返す側（MD の基板、サーボの基板など） |
| フレーム | CAN で 1 回に送る単位。ID と、0〜8 byte のデータ部でできている |
| DLC | フレームのデータ部の長さ（0〜8） |
| class | ID の上位 3 bit。やりとりの区分を表す。小さいほど優先（C-84） |
| 種類 | 動かすものの区別（MD、サーボ） |
| 種類の番号 | 種類ごとの 4 bit の番号。MD 0、サーボ 1。起動の知らせと設定の ID に使う（C-26） |
| 基板の種類 | 基板の製品の区別。項目 1 の上位 16 bit（C-63）。種類の番号とは別 |
| 指令の形 | MD の指令が何を表すか（電流、速度、duty、位置）。ID で区別する（C-27）。種類とは呼ばない |
| 周期指令の番号 | class 2 の ID の区画の番号。MD の電流 0、速度 1、duty 2、位置 3、サーボ 4（C-25）。種類の番号とは別 |
| ch | 種類ごとに 0 から振った通し番号。主制御はこの番号で相手を指す（C-13、C-14） |
| 束 | 1 本のフレームでまとめて送る ch の組。MD は 4 ch、サーボは 8 ch |
| フレーム番号 | ch ÷ 束の大きさ（切り捨て）。何番目の束か（C-21） |
| slot | 束の中の位置。ch を束の大きさで割った余り（C-21） |
| 基板の位置 k | 基板が受け持つ範囲を決める数。先頭の ch ＝ k × 基板の大きさ（C-81） |
| 基板の大きさ | 基板が受け持つ ch の数 |
| 指令 | 主制御が周期的に送る「今どう動くか」。class 2 |
| FB | 基板が周期的に返す状態と測った値。class 3 |
| 止める値 | 使っていない slot に入れる、止まる向きの値（MD の電流 0、速度 0、duty 0 空転、サーボ 255）（C-40、M-7、M-8、S-3）。MD では出力を止める指令ではなく、普通の値として従う。FB の bit 4 の理由に入らない（M-58） |
| 途絶 | ある ch の指令が 100 ms 届かないこと。その ch は止まる（C-91） |
| E-stop | 緊急停止の指令。`0x000`。受けた基板は止まってラッチする（C-28） |
| ラッチ | E-stop で止まった状態を保つこと。解除か、基板の再起動（電源の再投入、項目 6 など）まで続く（C-30。再起動で消える前提で起動の猶予がある、C-89） |
| SYNC | 主制御が 20 Hz で送る時刻のフレーム。`0x002`。時刻をそろえるためだけに使う（C-32、C-90） |
| 起動の知らせ | 基板が起動したときに種類ごとに 1 本送る空のフレーム。`0x010`＋種類の番号（C-36） |
| 起動の猶予 | 起動の知らせから 200 ms、基板が指令に従わない時間（C-89） |
| 設定 | 基板の値を読む、書く、保存する、初期化する仕組み。class 4。設定で読み書きする値は「項目 N」と呼ぶ |
| 項目 | 設定で読み書きする値の番号（C-58） |
| 焼いた値 | ファームの中の既定値（C-5） |
| 保存した値 | フラッシュに保存した値（C-5） |
| 今の値 | RAM の値。基板はこれで動く（C-5） |
| 機体の値 | 機体を組んで調整すれば決まる値。保存できる（C-80） |
| プログラムの値 | 主制御のプログラムの話し方を決める値（MD の刻み）。保存できず、主制御が毎回送る（C-80） |
| 刻み | MD の電流と速度の指令と FB の、1 LSB が表す量。電流の刻み（項目 48、mA/LSB）と速度の刻み（項目 49、rpm/LSB）。プログラムの値。台帳での名前は「電流の単位」「速度の単位」（M-56）、ライブラリでの名前は Resolution（`configCurrentResolution`、`configSpeedResolution`。API-14） |
| 単位 | mA、rpm、µs などのふつうの意味の単位。この仕様書では刻みの意味に使わない |
| 異常の詳細 | 項目 5。基板の異常を bit で表す。主制御が 1 を書いて消すまで残る（C-100） |
| 限界 | ハードウェアの上限。ファームに固定（C-79） |
| 制限 | 使う側が設定で決める上限。限界を超える値は限界に抑える（C-79） |
| 分割 | class 5。8 byte を超えるデータを分けて送る、他の種類のための帯。MD とサーボは使わない（C-84） |
