# 全体像

MAS CAN プロトコル v1 の仕組みを、初めての人向けに一通り説明します。最初に読む文書です。細かい形は辞書（[bus.md](bus.md)、[ids.md](ids.md)、[md.md](md.md)、[servo.md](servo.md)、[settings.md](settings.md)）に任せ、ここからリンクします。場面ごとの流れは、次に読む [flows.md](flows.md) にあります。

文末の「（C-36）」などは、決定の台帳（`docs/decisions/`）の番号です。台帳が決まりの正本です。

「今の実装では」と書いた文は、`lib/mas` の今の動き（基板側の node と、主制御のライブラリ `Host`）です。台帳の決まりではなく、プロトコルを変えずに変わることがあります。台帳で決まっていないことは「台帳では未定」と書き、今の実装の動きを添えます。

## 1. 何のプロトコルか

ロボットの中で、**主制御**が、1 本の CAN の線につないだ複数の**基板**を動かすための決まりです。主制御は、ロボットのプログラムを動かすマイコン（ESP32 など）です。基板は、モータードライバーやサーボの基板です。

- 主制御は基板に**指令**を周期的に送ります。指令は「この速度で回れ」のような、今どう動くかです。
- 基板は主制御に **FB**（フィードバック）を周期的に返します。FB には、測った電流、速度、位置と、基板の状態が載ります。
- 基板の調整値（ゲイン、上限など）は**設定**で読み書きします。
- 緊急停止（**E-stop**）と時刻合わせ（**SYNC**）は、全基板に共通です。

プロトコルが決めるのは、線の上の形と、外からの見え方（FB の bit、異常の詳細）だけです。保護のやり方のような基板の中の振る舞いは基板に任せ、基板ごとの資料に書きます。基板ごとに作りが違っても、主制御からは同じに見えるようにするためです（C-7）。

許可制（arming）はありません。電源を入れたら動ける状態になります。大会では緊急停止ボタンで駆動電源が電気的に切れるので、プロトコルの側で許可を取る必要が無いからです（C-4）。

旧仕様（v0）とは互換がありません。v0 はタグ `v0` に残っています（C-95）。

## 2. 主制御と基板

| 立場 | 何をするか | 実装 |
|---|---|---|
| 主制御 | 指令、SYNC、E-stop を送り、FB を受ける。設定を要求する | `lib/mas` の `Host`（`<mas/can.h>`） |
| 基板 | 指令を受けて動き、FB を返す。設定の要求に答える | `lib/mas` の node（`<mas/can/node.h>`）。[基板のファームの手引き](board.md) |

1 つの束（3 節で説明します）に指令を出すのは、1 台の主制御だけです。主制御を 2 台にするなら、ch を束の区切りで分けます（C-78、C-76）。

主制御を 2 台にするときは、SYNC にも気をつけてください。SYNC を送るのは 1 台だけという決まりがあります（C-33）。今の実装では、`Host` は SYNC を必ず送り、止める手段がありません（止める関数は未決です）。そのため、今のライブラリの主制御を同じ線に 2 台置くと、この決まりを守れません。

PC は受信だけで線を監視できます（C-3）。PC が主制御と一緒にいるときの扱いは、台帳では未定です（C-78）。台帳は DBC（PC の解析ツールに読ませる定義）を仕様と一緒に配布するとしていますが、今のリポジトリにはまだありません（C-3）。

## 3. 種類、ch、基板

### 種類と ch

**種類**は、動かすものの区別です（MD、サーボ）。種類ごとに 4 bit の**種類の番号**があります。MD が 0、サーボが 1 です（C-26）。2 以降は予約です。

**ch** は、種類ごとに 0 から振った通し番号です（C-13）。主制御から見ると、MD の ch 0〜31 が並んだ 1 本の列と、サーボの ch 0〜63 が並んだ別の列があります（C-14）。「MD の ch 5」と「サーボの ch 5」は別物です。

| 種類 | 種類の番号 | ch の範囲 | 束の大きさ | FB | 詳細 |
|---|---|---|---|---|---|
| MD（モータードライバー） | 0 | 0〜31（M-1） | 4 ch（M-6） | ある（M-14） | [md.md](md.md) |
| サーボ | 1 | 0〜63（S-1） | 8 ch（S-1） | 無い（S-10） | [servo.md](servo.md) |

**束**は、1 本のフレームでまとめて送る ch の組です（C-27）。MD なら ch 0〜3 が 1 束、ch 4〜7 が次の束です。束の中の位置を **slot** と呼びます。番号の計算は [bus.md](bus.md) の 2 にあります。

### 基板は ch の連続した範囲を受け持つ

基板は、ある種類の ch の**連続した範囲**を受け持つ入れ物です。1 枚が複数の種類の ch を持ってもかまいません（C-14）。

| 基板の例 | 基板の種類（項目 1） | 受け持つもの |
|---|---|---|
| micro-MD 基板 | `0x0003` | MD の ch 1 つ（C-96） |
| 足回りの中継役 | — | MD の ch 4 つ（M-1、M-4） |
| CAN-Servo 基板 | `0x0002` | サーボの ch 8 つと MD の ch 4 つ（C-92） |

「基板の種類」は製品の区別で、「種類の番号」（MD 0、サーボ 1）とは別の番号です（11 節の用語集）。

### 基板の位置 k

同じ基板を何枚も線につなぐので、どの範囲を受け持つかを基板ごとに決めます。そのための数を**基板の位置 k** と呼びます。k も 0 から数えます（C-13）。

- 先頭の ch は「k × 基板の大きさ」です。基板の大きさは、受け持つ ch の数です（C-81）。
  - 例: 1 ch の MD で k ＝ 2 なら、MD の ch 2 を受け持ちます。4 ch の MD で k ＝ 1 なら、MD の ch 4〜7 です。
- k で決めるのは、主な種類の先頭の ch だけです。1 枚が複数の種類を持つとき、ほかの種類の範囲は基板のファームが持つ規則で決めます（C-81）。
- k の決め方（DIP スイッチ、LED とスイッチなど）はプロトコルで決めず、基板ごとの資料に書きます（C-75、C-82）。
- k は起動時に 1 回だけ読みます。受け持つ範囲がその種類の ch の範囲からはみ出すなら、その基板は CAN に何も送らず、何も受けず、出力を止めたままにします（C-18）。
- 2 枚の基板が同じ ch を受け持たないようにするのは、組む人の責任です。重なりを確実に見つける仕組みはありません（C-83）。

## 4. ID と class

CAN の ID は 11 bit です（C-8）。ID の上位 3 bit を **class** と呼び、用途で分けます。CAN では ID が小さいフレームが調停に勝つので、class の番号が小さいほど優先度が高くなります（C-84）。

| class | ID の範囲 | 用途 | 向き |
|---|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期 | 主制御 → 全基板（E-stop、解除、SYNC）、基板 → 主制御（起動の知らせ） |
| 1 | `0x100`〜`0x1FF` | 予約 | — |
| 2 | `0x200`〜`0x2FF` | 周期指令 | 主制御 → 基板 |
| 3 | `0x300`〜`0x3FF` | 周期データ（FB など） | 基板 → 主制御 |
| 4 | `0x400`〜`0x4FF` | 設定（要求と応答） | 両方 |
| 5 | `0x500`〜`0x5FF` | 分割（MD とサーボは使わない） | — |
| 6 | `0x600`〜`0x6FF` | 自作 | — |
| 7 | `0x700`〜`0x7FF` | ファームの書き込み（予約） | — |

- 指令は class 2、FB は class 3 に分けます。こうすると、どの指令もどの FB より先に線を通ります（C-23）。
- DJI のモーターが固定で使う ID は避けてあります。同じ線に DJI のモーターを載せられるようにするためです（C-24）。
- **class 3（`0x300` 台）は、基板が自分から周期的に送るデータの帯です。要求を受ける ID はありません。** 基板の種類や版、受け持つ ch の範囲は、class 4 の設定で読みます（8 節）。

ID の一覧は [ids.md](ids.md) にあります。

## 5. 電源を入れてから止めるまで

主制御と基板が何をするかを、時間の順に並べます。各段の決まりは右の列の文書が詳しい置き場所で、ここでは 1 行にまとめます。線の上のバイト列まで見たいときは [flows.md](flows.md) を読んでください。

| 段 | 基板 | 主制御（ライブラリ） | 詳しく |
|---|---|---|---|
| 電源投入 | 出力を止めたまま起動する。k を読み、保存した設定を読む | — | [bus.md](bus.md) の 3.4 |
| 起動の知らせ | 設定の要求に答えられるようになったら、受け持つ種類ごとに `0x010`＋種類の番号（DLC 0）を 1 本送る。FB はその後から送る。異常の詳細の bit 0「再起動した」が立っている（FB の bit 0 として見える） | 受けたら、その種類の ch に「刻みを送り直す」印を付ける | [bus.md](bus.md) の 3.4、7 |
| 起動の猶予 | 起動の知らせから 200 ms は指令に従わない。設定の要求には答える | この間に MD の刻みを書く | [bus.md](bus.md) の 3.5 |
| 指令と FB | 猶予が明けたら、次の有効な指令から動く。FB を周期的に送る | SYNC を 20 Hz、指令を MD 100 Hz、サーボ 50 Hz で送る | [bus.md](bus.md) の 5 |
| 途絶 | ch ごとに、指令が 100 ms 来なければその ch を止める。ラッチしない | — | [bus.md](bus.md) の 5 |
| E-stop | `0x000` を受けたら止めてラッチする | `estop()` を呼んだ主制御は、解除まで 10 Hz で送り続ける | [bus.md](bus.md) の 3.1 |
| 解除 | `0x001`（`"clr"`）を受けたらラッチを解く | 解除を送り、アプリの指令を止める値に戻す | [bus.md](bus.md) の 3.2、[md.md](md.md) の 4.3 |
| 基板の再起動 | 電源投入と同じ流れ。刻みは 1.0 に戻る | 気づいたら、刻みをほかの設定より先に送り直す | [bus.md](bus.md) の 7 |
| 主制御だけの再起動 | 前のプログラムの刻みのまま。指令が途絶えれば 100 ms で止まる | 最初に FB を受けたとき、刻みを書く | [bus.md](bus.md) の 7 |

それぞれの段に、決まりの理由があります。

- **起動の知らせは中身が空です。** 同じ種類の基板が同時に起動しても、同じ ID で同じ中身なら 1 本として届き、衝突しないからです。その代わり、どの基板が起動したかは分かりません（C-36）。
- **起動の知らせは、設定の要求に答えられるようになってから送ります。** 主制御が知らせを受けてすぐ設定を書けるようにするためです（C-37）。
- **起動の猶予があるのは、主制御が刻みを書き直す時間を作るためです。** 再起動した MD は刻みが 1.0 に戻っています。そのまま前の刻みのつもりの指令を受けると、桁違いに動きます。猶予の間に主制御が刻みを書き直します。もう 1 つの理由は、主制御が送り続けている E-stop（100 ms ごと）を、猶予の間に受け取れるようにするためです（C-89、C-88、C-31）。
- **途絶で止めるのは、主制御が生きているかを指令で見ているからです。** 指令が来ているのは、上位が生きている証拠です。SYNC が途絶えても止めません。SYNC は時刻をそろえるためだけに使います（C-91、C-90、M-57、S-15）。
- **E-stop で MD はブレーキで止めます。** 電源を切らない場面でも早く止まるようにするためです（M-51、S-9、C-28）。
- **E-stop を送り続けるのは、後から起動した基板もまた止めるためです。** 再起動した基板はラッチを失っていますが、猶予の間に次の E-stop を受けて、またラッチします（C-31、C-89）。
- **解除の後に猶予はありません。** 猶予は起動の知らせから数えるものだけです。解除の前に指令を安全な値に戻すのは主制御の仕事で、ライブラリは解除のときアプリの指令を止める値に戻します（C-29、C-30、M-27、API-22）。
- **再起動に気づいても、主制御は指令を止めません。** 起動の知らせではどの基板か分からないので、止めると 1 枚の再起動で線の全部が止まってしまうからです（C-94、C-69）。
- **主制御だけが再起動したときも刻みを書きます。** 基板には前のプログラムの刻みが残っているからです。書けたと確かめるまで、その ch には止める値を送ります（API-43、API-44）。

今の実装では、主制御のライブラリが起動の知らせで印を付けるのは、FB を一度でも受けた ch だけです。まだ FB を受けていない ch は、最初の FB を受けたときに刻みを書くので、結果は同じです。主制御だけの再起動で刻みを書くのは、アプリが取っ手を作った（`can.md(ch)` を呼んだ）MD の ch です。

## 6. 設定の値の決まり方

基板の値は 2 種類あります（C-5）。

| | 例 | どこで決まるか |
|---|---|---|
| 基板の性質 | ピンの能力、他の種類の ch の範囲の規則、ハードウェアの限界 | ファームに固定。基板の資料に書く |
| ロボットごとに変わる値 | ゲイン、電流の上限、MD の刻み | 設定項目。下の 3 段で決まる |

ロボットごとに変わる値は、すべて次の 3 段で決まります。例外はありません（C-5）。

| 呼び名 | 置き場所 | 中身 |
|---|---|---|
| 焼いた値 | ファームの中 | 既定値 |
| 保存した値 | フラッシュ | 「保存」で今の値を書き込んだもの |
| 今の値 | RAM | 基板はこれで動く。起動時は保存した値（無ければ焼いた値）。主制御が書くと変わる |

設定項目は、さらに 2 つに分かれます（C-80）。

| | 意味 | 保存 | 例 |
|---|---|---|---|
| 機体の値 | 機体を組んで調整すれば決まり、プログラムを書き換えても変わらない値 | できる | MD の回転方向、電流の上限（M-47）、エンコーダのカウント数と減速比（M-36）、速度ループのゲイン（M-54）。サーボのパルス幅の範囲（S-11） |
| プログラムの値 | 主制御のプログラムがどういう言葉で話すかを決める値 | できない | MD の電流と速度の刻み（M-56） |

プログラムの値には「保存した値」の段がありません。起動すると、必ず焼いた値に戻ります。主制御が毎回送ります（C-80）。単位のような値はプログラムごとに違うので、前のプログラムの値をフラッシュに残して、それで起動してしまわないようにするためです。

上限には 2 段あります（C-79）。

- **限界**は、ハードウェアの上限です。基板の性質としてファームに固定し、基板の資料に書きます。
- **制限**は、使う側が設定で決める上限です。限界を超える値を書くと、限界に抑えて受け付けます。例は MD の電流の上限です（M-47、M-43）。

設定の仕組みと全項目は [settings.md](settings.md) にあります。

## 7. 主制御のライブラリが自動で行うこと

`lib/mas` の `Host` は、アプリが `can.update()` を呼ぶたびに、次のことを中で行います（API-9）。アプリが自分でフレームを組む必要はありません。

| すること | いつ | 番号 |
|---|---|---|
| SYNC を送る | 常に 20 Hz | C-33 |
| 指令を送る | MD 100 Hz、サーボ 50 Hz。使っていない slot には止める値を入れ、後ろの空いた slot は DLC を縮める | C-44、C-40、C-41 |
| MD の刻みを書く | 最初に FB を受けたとき（アプリが刻みを決めていない ch にも既定値 1.0 を書く）。書けたと確かめるまで、その ch には止める値を送る | API-15、API-43、API-44、API-65 |
| 異常の詳細を読む | FB の bit 0 が立っている間、100 ms ごと | API-18、API-66 |
| 異常の詳細の bit 0「再起動した」を消す | 読んで立っていたら | C-69、API-19 |
| 再起動した基板に刻みを送り直す | 起動の知らせ、または異常の詳細の bit 0 で気づいたとき。ほかの設定より先に | C-69、C-88、C-94 |
| E-stop を送り続ける | 自分で `estop()` を呼んでから `clearEstop()` まで、10 Hz。受けただけの E-stop は送り直さない | C-31、API-21、API-23 |
| E-stop の間、指令を止める値にする | 自分の E-stop でも、他の送り手の E-stop でも | API-22、API-48 |
| 解除を送り直す | 100 ms 後も FB の bit 5 が立っている基板があれば、最大 3 回 | API-24 |
| 設定の要求を 1 つずつ送る | 応答を受けてから次を送る | C-51、API-17 |

今の実装が台帳の言い方と違うところが 3 つあります。

- **異常の詳細を読み直す間隔**: 台帳は「100 ms ごと」です（API-66）。今のライブラリは、最後に読んでから 100 ms 経った後に受けた最初の FB で読み直します。FB が 10 ms ごとなら、およそ 110 ms おきになります。
- **解除を送り直しても残るとき**: 台帳は「異常と同じ道で知らせる」としています（API-24）。今のライブラリは、3 回送り直しても bit 5 が残るとき、何も知らせずに見張りをやめます。
- **FB を切った MD の ch**: 項目 35（FB の周期）を 0 にした ch の扱いは、台帳では決まっていません。今のライブラリは、その ch の刻みを確かめられないので、ready にならず、止める値を送り続けます（API-43）。ライブラリで動かす ch は、項目 35 を 0 にしないでください。

## 8. 線の上にどの基板がいるかを知るには

### 一斉に問い合わせる仕組みはありません

「線の上の基板は全員答えよ」という要求はありません。複数の基板が同じ ID で違う中身を同時に送ると、衝突するからです（C-83、C-36）。設定の要求には、宛てた ch を受け持つ基板 1 枚だけが答えます。受け持たない ch 宛てには、誰も答えません（C-49）。

class 3（`0x300` 台）に何かを送っても、答えは返りません。`0x300` 台は基板が自分から送る FB の帯で、基板の種類や版は載っていません（C-23、C-15）。

使える方法は次の 2 つです。

### 方法 1: MD の FB を聞く（MD だけ）

MD は、指令が来ていなくても FB を周期的に送ります（M-21）。FB の ID は `0x320`＋ch です（M-14）。線を聞いていれば、どの ch の MD がいるかが分かります。

| 聞こえた ID | 分かること |
|---|---|
| `0x320` | MD の ch 0 がいる |
| `0x325` | MD の ch 5 がいる |

FB では見えないものもあります。

- サーボ。FB がありません（S-10）。
- FB の周期を 0 にした MD の ch。項目 35 が 0 だと FB を送りません（M-47）。
- 起動の知らせを送る前の基板（C-37）と、k が範囲外の基板（C-18）。

FB は ch ごとで、基板ごとではありません。どの ch が同じ基板かは、方法 2 で調べます。

### 方法 2: 設定で 1 つずつ読む（どの種類でも）

種類と ch を名指しして、設定の共通の項目を読みます（C-49、C-60）。要求の ID は `0x400`＋種類の番号 × 16（MD `0x400`、サーボ `0x410`）、応答はそれに＋8（MD `0x408`、サーボ `0x418`）です（C-46）。byte 0 が ch です（C-48）。

| 項目 | 返るもの | 番号 |
|---|---|---|
| 0 | 固有 ID（64 bit）。応答だけは data 部 8 byte すべてが固有 ID | C-60、C-61、C-86 |
| 1 | 上位 16 bit ＝ 基板の種類、下位 16 bit ＝ 基板の版 | C-63 |
| 3 | プロトコルの版（9 節） | C-71 |
| 4 | 要求した種類について、受け持つ範囲。byte 3–4 ＝ 先頭の ch、byte 5–6 ＝ ch の数 | C-65 |

例: MD の ch 2 に項目 1 を読みます（通し番号 5）。答えたのは、基板の種類 `0x0001`、版 1 の基板です。

```
要求  0x400 DLC 8 : 02 00 01 00 00 00 00 05
応答  0x408 DLC 8 : 02 00 01 00 01 00 01 05
                    ch 操作 項目 └─ 値 ─┘ 通し番号
```

例: 同じ ch に項目 4 を読みます（通し番号 6）。1 ch の MD で、先頭の ch が 2、数が 1 です。

```
要求  0x400 DLC 8 : 02 00 04 00 00 00 00 06
応答  0x408 DLC 8 : 02 00 04 00 02 00 01 06
```

例: 項目 0 の応答です。固有 ID が `0x0123456789ABCDEF` のときです。ch も通し番号も載りません（C-61）。

```
応答  0x408 DLC 8 : 01 23 45 67 89 AB CD EF
```

調べる手順:

1. 種類ごとに、ch 0 から項目 4 を読みます。要求は 1 つずつ送り、応答を受けてから次を送ります（C-51）。
2. 応答が来たら、その基板の範囲（先頭の ch と数）が分かります。範囲の次の ch へ進みます。
3. 応答が来なければ、その ch を受け持つ基板がいないか、要求が捨てられたかです（C-49、C-47）。次の ch へ進みます。
4. 見つけた基板ごとに、項目 0（固有 ID）と項目 1（基板の種類）を読みます。違う種類で同じ固有 ID が返れば、同じ 1 枚の基板です。固有 ID は基板ごとに固有だからです（C-86）。

応答を何 ms 待つかは、台帳では決めていません。今の主制御のライブラリは、設定の応答を 50 ms 待ち、来なければ 2 回まで送り直します。

2 枚の基板が同じ ch を受け持っていると、どうなるでしょうか。中身が同じ応答（同じ種類の基板の項目 1、3、4 など）は 1 本として届くので、重なりに気づけません。中身が違う応答（項目 0 の固有 ID）は衝突して、バスのエラーになります（C-83）。

今の実装では、サーボの ch はこの方法で見つかりません。今の CAN-Servo-v1 は、サーボの設定の要求（`0x410`）に、共通の項目を含めて一切答えないからです（[servo.md](servo.md) の 4）。同じ基板の MD の ch（`0x400`）で項目 1 を読めば CAN-Servo 基板（`0x0002`）だと分かり、サーボの ch の範囲はその基板の資料で分かります。

基板の種類の番号の一覧と、設定のフレームの形の詳細は [settings.md](settings.md) にあります。実際のやりとりは [flows.md](flows.md) の 8 にあります。

### 起動の知らせでは分かりません

起動の知らせ（`0x010`＋種類の番号）は中身が空です。分かるのは「この種類のどれかの基板が起動した」ことだけです（C-36、C-94）。

## 9. プロトコルの版と互換

基板は項目 3 でプロトコルの版を返します（C-60）。値の欄 4 byte の並びは次のとおりです（C-71）。

| byte | 中身 |
|---|---|
| 3 | 大 |
| 4 | 中 |
| 5 | 小 |
| 6 | bit 6–7 ＝ 段階（0 alpha、1 beta（試験運用）、2 予約、3 正式）、bit 0–5 ＝ X |

- X は開発用の「隠れた大」です（C-74）。
- 4 byte を整数として比べた大小が、版の新旧と一致します（C-71）。
- **大と X が一致すれば通じます。** 中、小、段階は問いません。新しい機能は、両方が持つときだけ使います（C-73）。
- ファームの違いは項目 2（ファームの版）で見分けます。X には流用しません（C-73、C-70）。
- 今の値は `lib/mas/include/mas/can/core/board.h` の `MAS_CAN_PROTOCOL_VERSION` にあります。基板側の node が自動で返すので、基板のファームには書きません（C-93）。

例: `0x010000C1` は、値の欄が `01 00 00 C1` です。版 1.0.0、段階 3（正式）、X ＝ 1 を表します。

台帳は、主制御のライブラリが版の食い違いを利用者に知らせるとしています（C-73）。今のライブラリは項目 3 を読まず、版の食い違いを確かめていません。

## 11. 用語集

| 用語 | 意味 |
|---|---|
| 主制御 | 指令を送る側。ロボットのプログラムを動かすマイコン（ESP32 など） |
| 基板 | 指令を受けて動き、FB を返す側（MD の基板、サーボの基板など） |
| 種類 | 動かすものの区別（MD、サーボ） |
| 種類の番号 | 種類ごとの 4 bit の番号。MD 0、サーボ 1。起動の知らせと設定の ID に使う（C-26） |
| 基板の種類 | 基板の製品の区別。項目 1 の上位 16 bit（C-63）。種類の番号とは別 |
| 指令の形 | MD の指令が何を表すか（電流、速度、duty、位置）。ID で区別する（C-27）。種類とは呼ばない |
| 周期指令の番号 | class 2 の ID の区画の番号。MD の電流 0、速度 1、duty 2、位置 3、サーボ 4（C-25）。種類の番号とは別 |
| ch | 種類ごとに 0 から振った通し番号。主制御はこの番号で相手を指す（C-13、C-14） |
| 束 | 1 本のフレームでまとめて送る ch の組。MD は 4 ch、サーボは 8 ch |
| フレーム番号 | ch ÷ 束の大きさ（切り捨て）。何番目の束か（C-21） |
| slot | 束の中の位置。ch を束の大きさで割った余り（C-21） |
| 基板の位置 k | 基板が受け持つ範囲を決める数。先頭の ch ＝ k × 基板の大きさ（C-81） |
| 基板の大きさ | 基板が受け持つ ch の数 |
| 指令 | 主制御が周期的に送る「今どう動くか」。class 2 |
| FB | 基板が周期的に返す状態と測った値。class 3 |
| 止める値 | 使っていない slot に入れる、止まる向きの値（MD の電流 0、速度 0、duty 0 空転、サーボ 255）（C-40、M-7、M-8、S-3）。MD では出力を止める指令ではなく、普通の値として従う。FB の bit 4 の理由に入らない（M-58） |
| 途絶 | ある ch の指令が 100 ms 届かないこと。その ch は止まる（C-91） |
| E-stop | 緊急停止の指令。`0x000`。受けた基板は止まってラッチする（C-28） |
| ラッチ | E-stop で止まった状態を保つこと。解除か、基板の再起動（電源の再投入、項目 6 など）まで続く（C-30。再起動で消える前提で起動の猶予がある、C-89） |
| SYNC | 主制御が 20 Hz で送る時刻のフレーム。`0x002`。時刻をそろえるためだけに使う（C-32、C-90） |
| 起動の知らせ | 基板が起動したときに種類ごとに 1 本送る空のフレーム。`0x010`＋種類の番号（C-36） |
| 起動の猶予 | 起動の知らせから 200 ms、基板が指令に従わない時間（C-89） |
| 設定 | 基板の値を読む、書く、保存する、初期化する仕組み。class 4。設定で読み書きする値は「項目 N」と呼ぶ |
| 項目 | 設定で読み書きする値の番号（C-58） |
| 焼いた値 | ファームの中の既定値（C-5） |
| 保存した値 | フラッシュに保存した値（C-5） |
| 今の値 | RAM の値。基板はこれで動く（C-5） |
| 機体の値 | 機体を組んで調整すれば決まる値。保存できる（C-80） |
| プログラムの値 | 主制御のプログラムの話し方を決める値（MD の刻み）。保存できず、主制御が毎回送る（C-80） |
| 刻み | MD の電流と速度の指令と FB の、1 LSB が表す量。電流の刻み（項目 48、mA/LSB）と速度の刻み（項目 49、rpm/LSB）。プログラムの値。台帳での名前は「電流の単位」「速度の単位」（M-56）、ライブラリでの名前は Resolution（`configCurrentResolution`、`configSpeedResolution`。API-14） |
| 単位 | mA、rpm、µs などのふつうの意味の単位。この仕様書では刻みの意味に使わない |
| 異常の詳細 | 項目 5。基板の異常を bit で表す。主制御が 1 を書いて消すまで残る（C-67） |
| 限界 | ハードウェアの上限。ファームに固定（C-79） |
| 制限 | 使う側が設定で決める上限。限界を超える値は限界に抑える（C-79） |
| 分割 | class 5。8 byte を超えるデータを分けて送る、他の種類のための帯。MD とサーボは使わない（C-84） |
