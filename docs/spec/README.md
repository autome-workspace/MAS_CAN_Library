# MAS CAN プロトコル v1 仕様書

MAS のロボットで、主制御が CAN で基板（モータードライバー、サーボなど）を動かすための決まり。線の上を流れるフレームの形と、基板と主制御の動作を、正確に書いてある。

**使い方を知りたい人は、こちらではなく [案内](../guide/README.md) を読む。** この仕様書は、基板のファームを作る人、線を流れるフレームを読む人、決まりを正確に確かめたい人が、引くためのもの。

| | |
|---|---|
| プロトコルの版 | 1.0.0（基板が項目 3 で返す値は `0x010000C1`） |
| 対象の種類 | MD（モータードライバー）、サーボ |

## 文書

| [md.md](md.md) | モータードライバーの指令、FB、動作 | 引く |
| [servo.md](servo.md) | サーボの指令と動作 | 引く |
| [settings.md](settings.md) | 設定（基板の情報を読む、値を書く、保存する）と、全項目の一覧 | 引く |

bus.md から settings.md までは辞書で、1 つの決まりは 1 か所にだけ詳しく書き、ほかの文書からはリンクする。

各文書は、台帳で決まっていること（プロトコルの決まり）と、今の `lib/mas` の実装がしていること（「今の実装では」と書く）を分けて書く。台帳で未定のことは、未定と書いたうえで今の実装の動きを添える。今の実装は、プロトコルを変えずに変わることがある。

## この仕様書と台帳

決定の正本は [`docs/internal/decisions/`](../internal/decisions/)（作者の台帳）にある。この仕様書は台帳から作った読む用の文書で、各記述に台帳の番号（`C-46` など）を添えてある。食い違いを見つけたら台帳が正しいので、作者に知らせてほしい。

## 保守（リポジトリを直す人へ）

台帳（`docs/internal/decisions/` の common.md、md.md、servo.md、api.md）、`lib/mas` の core のヘッダ、`node.h`、`node.c`、`host.cpp` を変えたら、この仕様書を点検する（仕様書が「今の実装」を書いているため）。点検は [`tools/spec_check.py`](../../tools/spec_check.py) が手伝う。

```sh
python3 tools/spec_check.py          # 点検が要るところを出す
python3 tools/spec_check.py --stamp  # 点検し終えたら記録する（reviewed.txt）
```

| 確かめること | 内容 |
|---|---|
| 引用 | 仕様書が引く台帳の番号が、台帳にあって取り消されていない |
| 網羅 | 台帳（common、md、servo）の今の決定が、仕様書に引かれているか、[uncited.md](uncited.md) に理由つきで載っている |
| 鮮度 | 台帳とヘッダが、最後に点検した時から変わっていない。変わっていれば変わった決定を出す |
| コード | `core/board.h` の基板の種類とプロトコルの版が、仕様書に載っている |
| リンク | 仕様書の相対リンクの先がある |

点検の引き金は 2 つある。

- git: コミットの前に点検し、通らなければ止める。クローンごとに 1 回 `git config core.hooksPath .githooks` で有効にする。
- Claude Code: 台帳やヘッダを編集すると、点検の結果を Claude に知らせる（`.claude/settings.json`）。
