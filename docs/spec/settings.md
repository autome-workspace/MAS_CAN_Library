# 設定（class 4）

設定は、主制御が基板の値を読む、書く、基板のフラッシュに保存する、焼いた値に戻すための仕組み。基板の情報（固有 ID、基板の種類、版、受け持つ ch の範囲）もここで読む。指令（class 2）と違い、必要なときに 1 回ずつやりとりする。

- 基板の情報を `0x300` 台で取ることはできない。`0x300` 台は FB だけの帯（C-15、C-23）。基板の情報は、この文書の共通の項目 0〜4 で読む（C-60）。
- ID の一覧は [ids.md](ids.md)。項目が動作にどう効くかは [md.md](md.md) と [servo.md](servo.md)。場面としての流れ（読む、書く、保存する、再起動させる）は [flows.md](flows.md) の 7。
- 設定の項目は「項目 N」と呼ぶ。「設定」は、この仕組みの名前。

読み方: 表の「根拠」の列と文末の番号は台帳の決まり。「今の実装では」「今の node は」と書いた文は、`lib/mas` の node（基板側）と主制御のライブラリの今の動きで、台帳の決まりではない。台帳で決まっていないことは「台帳では未定」と書き、今の実装の動きを添える。

今の主制御のライブラリが送る設定の要求は、刻み（項目 48、49）を書くことと、異常の詳細（項目 5）を読んで消すことだけ。機体の値（MD の項目 32〜46、サーボの項目 32〜34）を書く API は無く、保存の API と一緒に決める（API-59）。保存、初期化、再起動、基板の情報（項目 0〜4）を読む API も無く、台帳でもまだ決めていない。それまでは、USB-CAN などで生のフレームを送って行う（例は 11 節）。

## 1. 値の決まり方

### 焼いた値、保存した値、今の値

ロボットごとに変わる値は、すべて次の順で決まる（C-5）。

| 呼び名 | 置き場所 | 決まるとき |
|---|---|---|
| 焼いた値 | ファームの中 | ファームを書き込んだとき |
| 保存した値 | 基板のフラッシュ | 保存の操作をしたとき（保存できる項目だけ） |
| 今の値 | 基板の RAM | 起動したとき、書く操作をしたとき、初期化の操作をしたとき。基板はこの値で動く |

- 起動すると、保存した値があればそれを、無ければ焼いた値を今の値にする。その後、主制御が書けば今の値が変わる（C-5）。
- 初期化の操作をすると、保存できる項目の今の値は焼いた値に戻る（C-54）。
- 基板の性質（ピンの能力、ch の範囲の規則など）は設定ではなく、ファームに固定する（C-5）。

### 機体の値とプログラムの値

設定項目は 2 つに分かれる（C-80）。

| 区分 | 中身 | 保存 | 起動したとき |
|---|---|---|---|
| 機体の値 | 機体を組んで調整すれば決まり、プログラムを書き換えても変わらない値（取り付け方、ゲイン、上限など） | できる | 保存した値、無ければ焼いた値 |
| プログラムの値 | 主制御のプログラムがどういう言葉で話すかを決める値（MD の刻みなど） | できない | 必ず焼いた値。主制御が毎回送る |

### 限界と制限

- 限界: ハードウェアの上限。ファームに固定し、基板の資料に書く。設定では変えられない（C-79）。
- 制限: 使う側の上限。設定で決める。限界を超える値を書くと限界に抑える（C-79）。

## 2. フレーム

### ID

ID ＝ `0x400`＋種類の番号 × 16＋向き × 8。向きは 0 が要求（主制御 → 基板）、1 が応答（基板 → 主制御）。下位 3 bit は予約で 0（C-46）。

| 種類 | 種類の番号 | 要求 | 応答 |
|---|---|---|---|
| MD | 0 | `0x400` | `0x408` |
| サーボ | 1 | `0x410` | `0x418` |

種類の番号は「MD かサーボか」の番号（C-26）。項目 1 で返る「基板の種類」（製品の番号）とは別物（C-63）。

### 捨てる条件

基板は次のフレームを捨て、応答しない（C-47）。

- DLC が 8 でない。
- ID の下位 3 bit が 0 でない（`0x401` など）。
- リモートフレーム（C-11）。

### data 部

DLC 8。2 byte 以上の値は上位の byte が先（big-endian）（C-12、C-48）。

| byte | 要求 | 応答 |
|---|---|---|
| 0 | ch | 要求と同じ ch |
| 1 | bit 6–7 ＝ 操作、bit 0–5 ＝ 0 | bit 6–7 ＝ 操作、bit 0–5 ＝ 結果 |
| 2 | 項目の番号（保存と初期化では範囲） | 要求と同じ |
| 3–6 | 値 | 値（[5 節](#5-結果と値の欄)） |
| 7 | 通し番号 | 要求と同じ |

項目 0 を読んだときの応答だけは形が違い、data 部 8 byte すべてが固有 ID になる（C-61）。

通し番号（byte 7）は主制御が選び、基板は要求の値を応答に写して返すだけ（C-48、C-51）。初期値や増やし方は台帳では決めていない。今の主制御のライブラリは、起動から 1 ずつ増やし（1 から）、送り直すときも新しい番号にする。

### byte 1

byte 1 ＝ 操作 × `0x40`＋結果。操作 ＝ byte 1 >> 6（上の 2 bit）、結果 ＝ byte 1 & `0x3F`（下の 6 bit）（C-48、C-52、C-56）。結果が 0〜15 のときだけ、16 進の上の桁（0、4、8、C）で操作が読める。結果 63 では上の桁が 3、7、B、F になる。

| 操作 | 番号 | 要求の byte 1 | 応答の byte 1（成功） | 応答の byte 1（失敗の例） |
|---|---|---|---|---|
| 読む | 0 | `0x00` | `0x00` | `0x01`（知らない項目）、`0x02`（その操作はできない） |
| 書く | 1 | `0x40` | `0x40` | `0x41`（知らない項目）、`0x42`（その操作はできない）、`0x43`（範囲外）、`0x44`（実現できない） |
| 保存 | 2 | `0x80` | `0x80` | `0x83`（範囲外）、`0xBF`（その他の失敗） |
| 初期化 | 3 | `0xC0` | `0xC0` | `0xC3`（範囲外）、`0xFF`（その他の失敗） |

## 3. やりとり

### 宛先

- 宛先は、種類（ID）＋ch（byte 0）で ch 1 つを指す（C-49）。
- その ch を受け持つ基板だけが応答する。受け持たない ch 宛てには、どの基板も何も返さない（C-49）。だから応答は衝突しない。
- 基板の情報（項目 0〜4）を読むときも、その基板が受け持つ ch のどれかを宛先にする。
- 束ごとの設定は、束の先頭の ch を宛先にする（C-50）。MD とサーボには束ごとの項目は無い（M-47、S-11）。

### 1 つずつ送る

1. 主制御が要求を送る。
2. 宛先の ch を受け持つ基板が応答する。
3. 主制御は応答を受けてから次の要求を送る（C-51）。

- 応答は通し番号（byte 7）で要求と対応づける（C-51）。
- 項目 0 の応答には ch も通し番号も無い（C-61）。応答の ID と、1 つずつ送ることで対応づける。
- 応答が来なければ、その ch を受け持つ基板がいない（C-49）か、要求が捨てられた（C-47）。
- 応答を何 ms 待つか、送り直すかは、台帳では決めていない。今の主制御のライブラリは 50 ms 待ち、来なければ通し番号を新しくして 2 回まで送り直す（それでも来なければ、刻みの書き込みなら `onSettingError` を結果 255 で呼ぶ。API-46。項目 5 の読み消しは知らせず、次の FB でまた読みに行く）。
- 保存と初期化では、基板はフラッシュに書き終えてから応答する。動作中でも書く（C-55）。
- フラッシュに書いている間、出力が止まる基板がある。保護のやり方と同じく基板に任せ、基板の資料に書く（C-7）。今のファームでは、CAN_MD と micro-MD は書く前にブレーキにし、CAN-Servo-v1 は全部の出力を Low にする（案内の [node の関数と欄](../guide/board/node.md) の「フラッシュ」）。

## 4. 操作

| 操作 | 番号 | 動き | byte 2 | 根拠 |
|---|---|---|---|---|
| 読む | 0 | 今の値を返す | 項目の番号 | C-52、C-85 |
| 書く | 1 | すぐ反映し、反映した後の値を返す（抑えたなら抑えた値）。動作中に書いてよいかは主制御の責任 | 項目の番号 | C-52、C-85 |
| 保存 | 2 | 範囲の中の、保存できる項目だけをフラッシュに書く | 範囲 | C-52、C-53、C-54 |
| 初期化 | 3 | 範囲の中の、保存した値を消し、保存できる項目だけを焼いた値に戻す。保存しない項目（プログラムの値）は触らない | 範囲 | C-52、C-53、C-54 |

保存と初期化の範囲（byte 2）（C-53）:

| byte 2 | 範囲 |
|---|---|
| 0 | 宛先の ch だけ |
| 1 | 宛先の ch を受け持つ基板の全 ch |
| 2〜255 | 範囲外。結果 3 を返す |

## 5. 結果と値の欄

### 結果

| 番号 | 意味 | 例 |
|---|---|---|
| 0 | 成功 | |
| 1 | 知らない項目 | 基板がその番号の項目を持たない（予約の番号を含む） |
| 2 | その操作はできない | 読むだけの項目に書いた。命令（項目 6）を読んだ |
| 3 | 範囲外 | 意味の上でありえない値を書いた（M-43、S-14）。保存と初期化の範囲が 0、1 以外（C-53）。再起動の署名が違う（C-66） |
| 4 | 実現できない | 向きが転流と一体の基板に項目 38 を書いた（M-41） |
| 5〜62 | 予約 | |
| 63 | その他の失敗 | |

基板は 1 → 2 → 3 → 4 の順に確かめ、最初に引っかかった番号を返す（C-56）。

### 値の欄（byte 3–6）

| 場面 | 要求の値の欄 | 応答の値の欄 | 根拠 |
|---|---|---|---|
| 読む、成功 | — | 今の値 | C-85 |
| 書く、成功 | 書く値 | 反映した後の値（抑えたなら抑えた値） | C-85、M-43 |
| 命令（項目 6）を書く、成功 | 署名 | 書いた値をそのまま | C-57 |
| 書くが失敗（結果 2〜4、63） | 書こうとした値 | 変わっていない今の値 | C-56 |
| 命令を読んだ（結果 2） | — | 0 | C-57 |
| 保存、初期化 | 0 | 0 | C-57 |

- 次の場面の値の欄は台帳では未定。今の node は 0 を入れる。
  - 知らない項目（結果 1）。
  - 再起動の署名が違う（結果 3）。
  - 項目 0（固有 ID）に書いた（結果 2）。今の値が 64 bit で値の欄に入らないため。

## 6. 項目の番号と型

| 番号 | 区分 | 根拠 |
|---|---|---|
| 0〜31 | 全種類に共通（7〜31 は予約） | C-58、C-60 |
| 32〜127 | 種類ごと | C-58 |
| 128〜255 | 基板固有。意味は基板ごとの資料に書く | C-58 |

- 値の型は int32、uint32、float32 のどれか。周期、電流、カウント数は整数。桁が大きく変わる値（PID ゲインなど）だけ float32（C-59）。どれも 4 byte で、上位の byte が先（C-12）。
- 型、読み書き、保存できるかは番号に持たせず、下の表で決める（C-58）。
- 基板がその番号の項目を持たなければ結果 1（C-56）。

例: float32 の 1.0 は `3F 80 00 00`、0.5 は `3F 00 00 00`。uint32 の 3000 は `00 00 0B B8`。

## 7. 共通の項目（0〜6）

全種類の基板が持つ。送る周期は共通の項目に入れない（C-60）。

| 番号 | 名前 | 型 | 読み書き | 中身 | 根拠 |
|---|---|---|---|---|---|
| 0 | 確認 | 64 bit（特別な形） | 読む | 固有 ID | C-60、C-61、C-62、C-86 |
| 1 | 基板の種類 | uint32 | 読む | 上位 16 bit ＝ 基板の種類、下位 16 bit ＝ 基板の版（1 から） | C-60、C-63 |
| 2 | ファームの版 | 4 byte | 読む | byte 3 ＝ 0、byte 4 ＝ 大、byte 5 ＝ 中、byte 6 ＝ 小 | C-60、C-70 |
| 3 | プロトコルの版 | 4 byte | 読む | byte 3 ＝ 大、byte 4 ＝ 中、byte 5 ＝ 小、byte 6 ＝ 段階と X | C-60、C-71 |
| 4 | 受け持つ ch の範囲 | 2 × uint16 | 読む | byte 3–4 ＝ 先頭の ch、byte 5–6 ＝ ch の数 | C-60、C-65 |
| 5 | 異常の詳細 | uint32（bit ごと） | 読む、書く | 立っている異常の bit。1 を書いた bit を消す | C-60、C-67 |
| 6 | 再起動 | 命令 | 書く | byte 3–5 ＝ `"rst"` | C-60、C-66 |
| 7〜31 | 予約 | | | | C-60 |

- 項目 1〜4 は基板の性質なのでファームに固定で、書けない（C-5）。

### 項目 0: 確認（固有 ID）

応答は特別な形で、data 部 8 byte すべてが固有 ID（64 bit、上位の byte が先）。ch、操作、結果、通し番号の欄は無い（C-61）。

| マイコン | 固有 ID | 根拠 |
|---|---|---|
| 96 bit の固有番号（w0、w1、w2）を持つもの | `((w2 XOR w1) << 32) \| w0` | C-62 |
| RP2040 | フラッシュの 64 bit の固有 ID をそのまま。先頭を最上位とする | C-62 |
| 上のどれでもないもの | 工場で書かれた固有の番号。64 bit より短ければ上位を 0 で埋める（ESP32 なら MAC の 48 bit）。どの番号を使うかは基板の資料に書く | C-86 |

- 固有 ID は基板ごとに固有であればよい（C-86）。1 枚の基板が複数の種類を持つなら、どの種類で読んでも同じ基板の固有 ID が返る。
- ch の受け持ちは重複しない前提。2 枚が同じ ch を受け持つと、項目 0 の応答も衝突する。重複を確実に見つける仕組みは無い（C-83）。

### 項目 1: 基板の種類

上位 16 bit ＝ 基板の種類、下位 16 bit ＝ 基板の版（1 から数える）（C-63）。

基板の種類の一覧（C-63、C-92、C-96、C-97）。`lib/mas` の `core/board.h` にも同じ一覧がある（C-93）。

| 基板の種類 | 基板 | `core/board.h` |
|---|---|---|
| `0x0000` | 予約 | `MAS_CAN_BOARD_RESERVED` |
| `0x0001` | CAN_MD 基板（STM32F042、MD 1 ch。C-97） | `MAS_CAN_BOARD_CAN_MD`（旧名 `MAS_CAN_BOARD_MD_2CH` も同じ値） |
| `0x0002` | CAN-Servo 基板（RP2040-Zero、サーボ 8 ＋ MD duty 4） | `MAS_CAN_BOARD_CAN_SERVO` |
| `0x0003` | micro-MD 基板（CH32V203K8T6、DRV8701P、MD 1 ch） | `MAS_CAN_BOARD_MICRO_MD` |

- 新しい基板の種類は、台帳（`docs/internal/decisions/common.md`）の一覧に書き足して番号を取る（C-63）。`core/board.h` も同じにする（C-93）。
- 例: micro-MD 基板の版 1 は `0x00030001`（byte 3–6 ＝ `00 03 00 01`）。`core/board.h` では `MAS_CAN_BOARD_TYPE(MAS_CAN_BOARD_MICRO_MD, 1)`。

### 項目 2: ファームの版

byte 3 ＝ 0、byte 4 ＝ 大、byte 5 ＝ 中、byte 6 ＝ 小（C-70）。ファームの区別はこの項目で行う（C-73）。

例: 0.1.0 は `00 00 01 00`。

### 項目 3: プロトコルの版

| byte | 中身 |
|---|---|
| 3 | 大 |
| 4 | 中 |
| 5 | 小 |
| 6 | bit 6–7 ＝ 段階（0 alpha、1 beta（試験運用）、2 予約、3 正式）、bit 0–5 ＝ X（開発用の「隠れた大」） |

- 4 byte を整数として比べた大小が、版の新旧と一致する（C-71）。
- 大と X が一致すれば通じる。中、小、段階は問わない（C-73）。
- 例: 1.0.0、正式、X ＝ 1 は `0x010000C1`（byte 3–6 ＝ `01 00 00 C1`）。
- `lib/mas` の node を使う基板は、この値を node が返す。ファームには書かない（C-93）。

### 項目 4: 受け持つ ch の範囲

要求の種類（ID で決まる）について返す。byte 3–4 ＝ 先頭の ch、byte 5–6 ＝ ch の数（C-65）。

例: MD の ch 3 だけを受け持つ基板は `00 03 00 01`。サーボ 8 ch（ch 0〜7）と MD 4 ch（ch 0〜3）を持つ基板は、`0x410` で読めば `00 00 00 08`、`0x400` で読めば `00 00 00 04`。

### 項目 5: 異常の詳細

uint32 の bit ごとに異常を表す（[8 節](#8-異常の詳細の-bit)）。

- 立った bit は、主制御が 1 を書いて消すまで残る（C-67）。書くと 1 を書いた bit が消え、応答の値の欄には消した後の値が入る（C-85）。
- どれかの bit が立っている間、FB のある種類は FB の「基板に異常あり」の bit を 1 にする（C-45）。
- 異常の詳細を ch ごとに持つか、基板に 1 つ持つかは、台帳では決めていない。今の node は基板に 1 つ持つ。受け持つどの ch 宛てに読んでも同じ値が返り、消すと全 ch の分が消える。

### 項目 6: 再起動

- byte 3–5 が `"rst"`（`72 73 74`）のときだけ受け付ける。基板は応答（成功）を送り終えてから再起動する（C-66）。
- 署名が違えば結果 3（C-66）。
- byte 6 の意味は台帳では未定。今の node は見ない。この文書の例は `00` にしてある。
- 再起動した基板がすること、主制御がすることは [bus.md](bus.md) の 7。

## 8. 異常の詳細の bit

### 共通（全種類）

| bit | 意味 | 根拠 |
|---|---|---|
| 0 | 再起動した | C-67、C-69 |
| 1 | 保存した設定が壊れていたので、焼いた値で起動した | C-67 |
| 2 | バスオフから復帰した（マイコンの標準の自動復帰で戻る。バスオフの仕組みが無い実装（can2040）は立てない） | C-67、C-68 |
| 3〜7 | 予約 | C-67 |
| 8〜31 | 種類ごと（下） | C-67 |

測る手段の無い基板は、その bit を立てない（C-67）。

### MD（bit 8〜）

| bit | 意味 | 根拠 |
|---|---|---|
| 8 | 過電流 | M-44 |
| 9 | 過熱 | M-44 |
| 10 | 電源電圧の低下 | M-44 |
| 11 | 電源電圧が高すぎる | M-44 |
| 12 | エンコーダの異常 | M-44 |
| 13 | ゲートドライバの異常 | M-44 |
| 14〜31 | 予約 | M-44 |

- 電流の上限（項目 33）に当たったことは入れない。FB の bit 3 で見える（M-44）。
- 異常に気づいたときの動作は基板に任せ、基板ごとの資料に書く。保護で出力を止めている間は FB の bit 4 を立てる（M-31）。

### サーボ

サーボの bit 8〜31 は決めていない。

## 9. MD の項目（32〜49）

種類の番号 0（要求 `0x400`、応答 `0x408`）。項目は全部 ch ごと（M-47）。予約の番号を除き、どれも読み書きできる。予約の番号（42〜44、47）は、今の node では読んでも書いても結果 1（知らない項目）。

| 番号 | 名前 | 型 | 単位、値 | 既定 | 保存 | 区分 | 根拠 |
|---|---|---|---|---|---|---|---|
| 32 | 回転方向の反転 | uint32 | 0 そのまま、1 反転 | 0 | できる | 機体の値 | M-47、M-41 |
| 33 | 電流の上限 | uint32 | mA | 基板の資料（ハードウェアの上限以下） | できる | 機体の値 | M-47、M-45 |
| 34 | 止めたときの止め方 | uint32 | 0 空転、1 ブレーキ | 0 | できる | 機体の値 | M-47 |
| 35 | FB の周期 | uint32 | Hz（0 ＝ 送らない）。名前は周期だが値は周波数。100 ＝ 10 ms ごと | 100 | できる | 機体の値 | M-47 |
| 36 | エンコーダ 1 回転のカウント数 | uint32 | カウント（4 逓倍した後の数） | 基板の既定 | できる | 機体の値 | M-36 |
| 37 | エンコーダの軸から出力軸までの減速比 | float32 | — | 1 | できる | 機体の値 | M-36 |
| 38 | エンコーダの向きの反転 | uint32 | 0 そのまま、1 反転 | 0 | できる | 機体の値 | M-36、M-41 |
| 39 | 速度ループの Kp | float32 | mA/rpm（電流を測れない基板は duty/rpm） | 基板の既定 | できる | 機体の値 | M-54、M-33 |
| 40 | 速度ループの Ki | float32 | 39 の単位 /s | 基板の既定 | できる | 機体の値 | M-54、M-33 |
| 41 | 速度ループの Kd | float32 | 39 の単位 × s | 基板の既定 | できる | 機体の値 | M-54、M-33 |
| 42〜44 | 予約 | | | | | | M-54 |
| 45 | 最高速度 | float32 | rpm（0 ＝ 制限なし） | 0 | できる | 機体の値 | M-38 |
| 46 | 最大加速度 | float32 | rpm/s（0 ＝ 制限なし） | 0 | できる | 機体の値 | M-38 |
| 47 | 予約 | | | | | | M-52 |
| 48 | 電流の刻み | float32 | mA/LSB（正の値） | 1.0 | できない | プログラムの値 | M-56 |
| 49 | 速度の刻み | float32 | rpm/LSB（正の値） | 1.0 | できない | プログラムの値 | M-56 |

- 速度と位置は出力軸で表す（M-2）。
- 33、45、46、PID ゲインは、48、49 によらず物理の単位で表す（M-42、M-33）。
- 39 の duty/rpm の「duty」をどの大きさで数えるか（±1.0、±16383、% など）は、台帳では未定（M-33）。
- 33 は使う側の上限で、どの指令（duty、電流、速度、位置）にも効く。ハードウェアの上限とは別物で、ハードウェアの上限は設定できず、基板の資料に書く。33 にそれを超える値を書くと抑える（M-47）。電流はモーターの巻線の電流（M-45）。
- 電流を測れない基板の 33 が何を意味するかは、台帳では未定。今の node は、ハードウェアの上限（`md_current_limit_max_ma`）を 0 にした基板では、33 に何を書いても 0 に抑えて返す。今の CAN-Servo-v1 と `examples/node_md_rp2040` がこれに当たり、33 は常に 0 を返す（焼いた値も 0）。
- 34 は止めるときの止め方（[md.md](md.md) の 4.6）。E-stop では 34 によらずブレーキで止める（M-51）。
- 34 の既定は、台帳では 0（空転。M-47）。今の node は、空転を出せない基板（`md_has_coast` ＝ false）では 34 の焼いた値を 1 にし、0 を書くと 1 に抑えて結果 0 を返す。duty の指令の bit 0 が 0 でもブレーキで出す。台帳にこの丸めは無い（M-51 が決めているのは、ブレーキを出せない基板が空転に丸める逆向きだけ）。出荷している MD の 2 枚（CAN_MD、micro-MD）はどちらも空転を出せないので、実機で 34 を読むと 1 が返る。
- 32 と 38 は別物。38 は駆動とエンコーダの符号をそろえる。32 は主制御の「正」の向きを決め、駆動と FB の両方を反転させる。設定する順は 38 → 32。向きが転流と一体の基板（BLDC）は 38 に結果 4 を返す（M-41）。
- 48、49 は指令と FB の両方に効く。保存できず、起動すると 1.0 に戻る。主制御（ライブラリと PC のツール）は指令を送る前に必ず書く。DBC は既定の刻みで表示する（M-56）。
- 48、49 の名前: 台帳では「電流の単位」「速度の単位」（M-56）、主制御のライブラリでは「Resolution」（`configCurrentResolution`、`configSpeedResolution`。API-14、API-58）。この仕様書では「刻み」と呼ぶ。
- 42〜44 は位置ループのゲインだった番号で、位置の指令を作るときに決め直す（M-54、M-49）。47 は予約（M-52）。

### 受け付ける値

2 段で受け付ける（M-43）。

| 値 | 基板の扱い | 結果 |
|---|---|---|
| 意味の上でありえない値 | 断る。今の値は変わらない | 3 |
| 基板の能力を超える値 | 上限で抑えて受け付け、抑えた後の値を返す | 0 |

意味の上でありえない値（M-43）:

| 項目 | ありえない値 |
|---|---|
| 32、34、38（0/1 の項目） | 2 以上 |
| 36（カウント数） | 0 |
| 37（減速比）、48、49（刻み） | 0 以下、NaN、無限大 |
| 39〜41（ゲイン）、45、46 | 負の値、NaN、無限大 |

- 書いた値と応答の値が違えば、主制御のライブラリが利用者に知らせる（M-43）。

## 10. サーボの項目（32〜34）

種類の番号 1（要求 `0x410`、応答 `0x418`）。項目は ch ごと（S-11）。どれも読み書きできる。

今の CAN-Servo-v1 は、サーボの設定の要求（`0x410`）に、共通の項目 0〜6 を含めて一切答えない（[servo.md](servo.md) の 4）。下の項目は台帳の決まりで、このファームでは使えない。

| 番号 | 名前 | 型 | 単位 | 既定 | 保存 | 区分 | 根拠 |
|---|---|---|---|---|---|---|---|
| 32 | パルス幅の下限 | uint32 | µs | 500 | できる | 機体の値 | S-11 |
| 33 | パルス幅の上限 | uint32 | µs | 2500 | できる | 機体の値 | S-11 |
| 34 | パルスの周期 | uint32 | µs | 20000（50 Hz） | できる | 機体の値 | S-11、S-12 |

- 基板は 32、33 の範囲でパルス幅を抑える（S-4）。
- 34 は同じ PWM の組（RP2040 のスライス、STM32 のタイマーなど）の ch で共有される。1 つの ch に書くと、同じ組の他の ch も変わる。組の分け方は基板の資料に書く（S-12）。

受け付ける値（S-14。M-43 と同じ 2 段）:

| 値 | 基板の扱い | 結果 |
|---|---|---|
| ありえない値（下限 > 上限、周期 ≦ 上限、32、33、34 のどれかに 0） | 断る | 3 |
| 基板の能力を超える値（タイマーで出せない周期など） | 出せる値に抑えて受け付け、抑えた値を返す | 0 |

- 書く順によっては途中で断られる（例: 上限より短い周期を先に書く）。主制御のライブラリが順を選ぶ（S-14）。

## 11. 例

要求と応答の 16 進のバイト列。data 部は byte 0 から順に、ch、操作と結果、項目、値（4 byte）、通し番号。

### MD の ch 3 の基板の種類を読む

ch 3 を受け持つのは micro-MD 基板（基板の種類 `0x0003`）の版 1。

```
要求  0x400 DLC 8 : 03 00 01 00 00 00 00 01
応答  0x408 DLC 8 : 03 00 01 00 03 00 01 01
```

- 要求: ch 3、読む（`0x00`）、項目 1、通し番号 `0x01`。
- 応答: 成功（`0x00`）。値 `0x00030001` ＝ 基板の種類 `0x0003`、版 1。

同じ要求を、誰も受け持たない ch 2 に送ると、応答は返らない（C-49）。

```
要求  0x400 DLC 8 : 02 00 01 00 00 00 00 02
応答  （無し）
```

### MD の ch 3 の固有 ID を読む

固有 ID が `0x1122334455667788` のとき。応答には ch も通し番号も無い（C-61）。

```
要求  0x400 DLC 8 : 03 00 00 00 00 00 00 03
応答  0x408 DLC 8 : 11 22 33 44 55 66 77 88
```

### MD の ch 3 の範囲を読む

```
要求  0x400 DLC 8 : 03 00 04 00 00 00 00 04
応答  0x408 DLC 8 : 03 00 04 00 03 00 01 04
```

- 先頭の ch 3、ch の数 1。

### 異常の詳細を読んで消す

起動した直後の基板は bit 0（再起動した）が立っている。

```
要求  0x400 DLC 8 : 03 00 05 00 00 00 00 05
応答  0x408 DLC 8 : 03 00 05 00 00 00 01 05
要求  0x400 DLC 8 : 03 40 05 00 00 00 01 06
応答  0x408 DLC 8 : 03 40 05 00 00 00 00 06
```

- 1 本目: 値 `0x00000001` ＝ bit 0 が立っている。
- 2 本目: 書く（`0x40`）で bit 0 に 1 を書く。応答の値は消した後の値 `0x00000000`。

### MD の ch 0 の電流の上限を書く

ハードウェアの上限が 10000 mA の基板。3000 mA を書く。

```
要求  0x400 DLC 8 : 00 40 21 00 00 0B B8 10
応答  0x408 DLC 8 : 00 40 21 00 00 0B B8 10
```

- 要求: ch 0、書く（`0x40`）、項目 33（`0x21`）、値 3000（`0x00000BB8`）。
- 応答: 成功。反映した後の値 3000。

ハードウェアの上限を超える 20000 mA を書くと、10000 mA に抑えて受け付ける（M-43、M-47）。

```
要求  0x400 DLC 8 : 00 40 21 00 00 4E 20 11
応答  0x408 DLC 8 : 00 40 21 00 00 27 10 11
```

- 応答: 成功（`0x40`）。値は抑えた後の 10000（`0x00002710`）。

0/1 の項目 32 に 2 を書くと、範囲外で断る（M-43）。

```
要求  0x400 DLC 8 : 00 40 20 00 00 00 02 12
応答  0x408 DLC 8 : 00 43 20 00 00 00 00 12
```

- 応答: 書く・範囲外（`0x43`）。値は変わっていない今の値 0（C-56）。

### 保存する

ch 0 だけを保存する（範囲 0）。

```
要求  0x400 DLC 8 : 00 80 00 00 00 00 00 13
応答  0x408 DLC 8 : 00 80 00 00 00 00 00 13
```

ch 0 を受け持つ基板の全 ch を保存する（範囲 1）。

```
要求  0x400 DLC 8 : 00 80 01 00 00 00 00 14
応答  0x408 DLC 8 : 00 80 01 00 00 00 00 14
```

- 応答はフラッシュに書き終えてから返る（C-55）。値の欄は要求も応答も 0（C-57）。
- 保存されるのは保存できる項目だけ。48、49 は保存されない（C-54、M-56）。

### 知らない項目を読む

項目 7（予約）を読む。

```
要求  0x400 DLC 8 : 00 00 07 00 00 00 00 15
応答  0x408 DLC 8 : 00 01 07 00 00 00 00 15
```

- 応答: 読む・知らない項目（`0x01`）。値の欄は台帳では未定（この例は今の node の出力で 0）。

### 再起動する

```
要求  0x400 DLC 8 : 00 40 06 72 73 74 00 16
応答  0x408 DLC 8 : 00 40 06 72 73 74 00 16
```

- 要求: 書く、項目 6、値 `"rst"`。byte 6 は `00`（台帳では未定。今の node は見ない）。
- 応答: 成功。値は書いた値のまま（C-57）。基板はこの応答を送り終えてから再起動する（C-66）。
- 起動し直した基板は起動の知らせ `0x010`（DLC 0）を送り（C-36）、異常の詳細の bit 0 を立てる（C-67）。

### サーボの ch 10 のパルス幅の上限を書く

2400 µs を書く。ch 10 を受け持つサーボの基板が応答する（台帳どおりの基板の場合。今の CAN-Servo-v1 は答えない。10 節）。

```
要求  0x410 DLC 8 : 0A 40 21 00 00 09 60 30
応答  0x418 DLC 8 : 0A 40 21 00 00 09 60 30
```

- 要求: ch 10（`0x0A`）、書く、項目 33（`0x21`）、値 2400（`0x00000960`）。
- 応答: 成功。反映した後の値 2400。
