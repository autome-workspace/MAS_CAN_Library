# ID の一覧

MAS CAN プロトコル v1 が使う CAN の ID を、`0x000` から `0x7FF` まで並べる。ID は 11 bit の標準 ID で、拡張 ID（29 bit）は使わない（C-8）。フレームの中身の詳細は、表の「詳しく」の列の文書にある。

読み方: 「根拠」の列は台帳の番号。「今の実装では」と書いた文は `lib/mas`（node、主制御のライブラリ、core）と既存のファームの今の動きで、台帳の決まりではない。

> **基板の情報は class 4 の設定で読む。`0x300` 台ではない。**
>
> - 基板の種類、版、受け持つ ch の範囲、固有 ID は、class 4 の設定で読む（項目 0〜4。[settings.md](settings.md)）（C-60）。
> - class 3（`0x300` 台）は、基板が自分から周期的に送るデータ（FB）だけの帯。要求を受ける ID は無く、基板の情報を載せたフレームも無い。基板専用の周期フレームは持たない（C-15、C-23）。
> - どの ch の MD がいるかは、MD の FB（`0x320`＋ch）が聞こえるかで分かる。MD は指令が来ていなくても FB を周期的に送る（M-14、M-21）。ただし FB の周期（項目 35）を 0 にした ch は送らない（M-47）。
> - サーボには FB が無い（S-10）。サーボの ch がいるかは、その ch 宛てに設定の要求（例: 項目 4 を読む）を送って確かめる。その ch を受け持つ基板だけが応答し、受け持つ基板がいなければ何も返らない（C-49）。ただし今の CAN-Servo-v1 はサーボの設定の要求（`0x410`）に一切答えないので、今はこの方法でサーボの ch を確かめられない（[servo.md](servo.md) の 4）。
> - 起動の知らせ（`0x010`＋種類の番号）は中身が空で、どの基板が起動したかは分からない（C-36）。
>
> 手順は [overview.md](overview.md) の「線の上にどの基板がいるかを知るには」。

## 用語

| 用語 | 意味 |
|---|---|
| 主制御 | 指令を送る側（ESP32 など） |
| 基板 | 指令を受けて動く側（MD の基板、サーボの基板など） |
| class | ID の上位 3 bit。番号が小さいほど優先度が高い（C-84） |
| ch | 種類ごとに 0 から数える番号（C-13、C-14）。MD は 0〜31（M-1）、サーボは 0〜63（S-1） |
| 種類の番号 | 4 bit。MD 0、サーボ 1。起動の知らせと設定の ID に使う（C-26） |
| 周期指令の番号 | class 2 の区画の番号。MD の電流 0、速度 1、duty 2、位置 3、サーボ 4。種類の番号とは別の番号（C-25、C-26） |
| 束 | 1 本のフレームにまとめて送る ch の組。MD は 4 ch（M-6）、サーボは 8 ch（S-1） |
| フレーム番号 | ch ÷ 束の大きさ（切り捨て）（C-21） |
| slot | ch を束の大きさで割った余り。フレームの中の位置（C-21） |

ほかの用語は [overview.md](overview.md) の用語集。

## class

CAN では ID が小さいフレームが調停に勝つ。上位 3 bit の class で用途を分ける（C-84）。

| class | 範囲 | 用途 | 向き | 根拠 |
|---|---|---|---|---|
| 0 | `0x000`〜`0x0FF` | 安全と同期 | 主制御 → 基板（E-stop、解除、SYNC）、基板 → 主制御（起動の知らせ） | C-84 |
| 1 | `0x100`〜`0x1FF` | 予約（高い優先度の自作の候補） | — | C-84 |
| 2 | `0x200`〜`0x2FF` | 周期指令 | 主制御 → 基板 | C-84、C-23 |
| 3 | `0x300`〜`0x3FF` | 周期データ（FB） | 基板 → 主制御 | C-84、C-23 |
| 4 | `0x400`〜`0x4FF` | 設定（要求と応答） | 両方 | C-84、C-46 |
| 5 | `0x500`〜`0x5FF` | 分割。MD とサーボは使わない | — | C-84 |
| 6 | `0x600`〜`0x6FF` | 自作 | — | C-84 |
| 7 | `0x700`〜`0x7FF` | ファームの書き込み（予約） | — | C-84 |

- 指令は class 2、FB は class 3 に分ける。どの指令もどの FB より優先される（C-23）。

### DJI の固定 ID を避ける範囲

DJI の機器が固定で使う ID は、このプロトコルでは使わない（C-24）。

| 範囲 | class |
|---|---|
| `0x1FE`〜`0x1FF` | 1 |
| `0x200`〜`0x20B` | 2 |
| `0x2FE`〜`0x2FF` | 2 |

## 全範囲の表

「向き」の「主 → 基」は主制御 → 基板、「基 → 主」は基板 → 主制御。

「予約」は、MD とサーボ以外の種類（コントローラなど）のために取ってある ID。MD とサーボの基板も主制御も使わない。自作のフレームを流したいなら class 6（`0x600`〜`0x6FF`）を使う（C-84）。

## ID の作り方

| フレーム | 式 | 根拠 |
|---|---|---|
| 周期指令（class 2） | `0x210`＋周期指令の番号 × 8＋フレーム番号 | C-25 |
| MD の指令 | `0x210`＋周期指令の番号（0〜3）× 8＋ch ÷ 4 | M-6、C-21 |
| サーボの指令 | `0x230`＋ch ÷ 8 | S-1、C-21 |
| MD の FB | `0x320`＋ch | M-14 |
| 起動の知らせ | `0x010`＋種類の番号 | C-36 |
| 設定 | `0x400`＋種類の番号 × 16＋向き × 8（向き: 0 要求、1 応答） | C-46 |

- 割り算は切り捨て。フレーム番号 ＝ ch ÷ 束の大きさ、slot ＝ ch を束の大きさで割った余り（C-21）。
- MD の slot s は byte 2s〜2s＋1 の int16（上位の byte が先）（M-6、C-12）。サーボの slot s は byte s（S-1）。

番号の表:

| 周期指令の番号 | 中身 | ID |
|---|---|---|
| 0 | MD の電流 | `0x210`〜`0x217` |
| 1 | MD の速度 | `0x218`〜`0x21F` |
| 2 | MD の duty | `0x220`〜`0x227` |
| 3 | MD の位置（予約） | `0x228`〜`0x22F` |
| 4 | サーボ | `0x230`〜`0x237` |

| 種類の番号 | 種類 | 起動の知らせ | 設定の要求 | 設定の応答 |
|---|---|---|---|---|
| 0 | MD | `0x010` | `0x400` | `0x408` |
| 1 | サーボ | `0x011` | `0x410` | `0x418` |

（C-25、C-26、C-36、C-46）

## 基板が受ける ID と送る ID

受信フィルタを作る人向け。f は基板が受け持つ ch のフレーム番号（ch ÷ 束の大きさ）。

- リモートフレームは使わず、受けても何もしない。ただし `0x000` はリモートフレームでも E-stop として止めるので、フィルタで落とさない（C-11）。
- 設定の要求の ID は種類ごとに 1 つで、宛先の ch は data 部の byte 0 にある。ID では ch を選べないので、ch は受けた後に見る。受け持たない ch 宛てには何も返さない（C-49）。
- 指令の束は、複数の基板が別々の ch を読んでよい。基板は自分の slot だけを読む（C-20）。
- MD とサーボの基板は SYNC（`0x002`）を使わない。時刻の欄を使わず（C-38）、SYNC の途絶では止めない（C-90）。

### MD の基板

| | ID | 中身 | 根拠 |
|---|---|---|---|
| 受ける | `0x000` | E-stop（DLC を問わない。リモートフレームも） | C-28、C-11 |
| 受ける | `0x001` | E-stop の解除 | C-29 |
| 受ける | `0x210`＋f、`0x218`＋f、`0x220`＋f | 電流、速度、duty の指令 | M-6 |
| 受ける | `0x228`＋f | 位置の指令（こなせない指令として扱うために受ける） | M-49、M-55 |
| 受ける | `0x400` | MD の設定の要求 | C-46 |
| 送る | `0x010` | 起動の知らせ。起動したときに 1 本 | C-36、C-37 |
| 送る | `0x320`＋ch | FB。受け持つ ch ごとに、項目 35 の周期で | M-14、M-21 |
| 送る | `0x408` | MD の設定の応答。受け持つ ch 宛ての要求にだけ | C-46、C-49 |

例: MD の ch 4〜7 を受け持つ基板（f ＝ 1）。

| | ID |
|---|---|
| 受ける | `0x000`、`0x001`、`0x211`、`0x219`、`0x221`、`0x229`、`0x400` |
| 送る | `0x010`、`0x324`〜`0x327`、`0x408` |

例: MD の ch 3 だけを受け持つ 1 ch の基板（f ＝ 0）。

| | ID |
|---|---|
| 受ける | `0x000`、`0x001`、`0x210`、`0x218`、`0x220`、`0x228`、`0x400` |
| 送る | `0x010`、`0x323`、`0x408` |

### 複数の種類を持つ基板

1 枚の基板が複数の種類の ch を持ってよい（C-14）。受ける ID と送る ID は、種類ごとの表を合わせたものになる。起動の知らせは、受け持つ種類ごとに 1 本ずつ送る（C-36）。

例: サーボ 8 ch（ch 0〜7）と MD 4 ch（ch 0〜3）を持つ基板。

| | ID |
|---|---|
| 受ける | `0x000`、`0x001`、`0x210`、`0x218`、`0x220`、`0x228`、`0x230`、`0x400`、`0x410` |
| 送る | `0x010`、`0x011`、`0x320`〜`0x323`、`0x408`、`0x418` |

## コードとの対応

`lib/mas` の `core/frame.h` に、ID の計算がある。

| ID | `core/frame.h` |
|---|---|
| `0x000`、`0x001`、`0x002` | `MAS_CAN_ID_ESTOP`、`MAS_CAN_ID_ESTOP_CLEAR`、`MAS_CAN_ID_SYNC` |
| 起動の知らせ | `MAS_CAN_ID_BOOT_BASE`＋種類の番号 |
| MD の指令 | `mas_can_md_cmd_id(周期指令の番号, ch)` |
| サーボの指令 | `mas_can_servo_cmd_id(ch)` |
| MD の FB | `mas_can_md_fb_id(ch)` |
| 設定 | `mas_can_setting_id(種類の番号, 向き)` |

core のヘッダのコメントには、台帳より前の参照が残っている。読むときは台帳が正しい。

- 参照先が `docs/internal/archive/redesign/`（凍結した記録）や旧番号（D13、D35 など）になっている。
- `core/md_frame.h` の `MAS_CAN_MD_POSITION_STOP`（位置の止める値 `0x8000`）は、取り消された決定の名残。台帳では、位置の指令の中身は止める値を含めて未定（M-49）。
