# MD のファームの直す点

台帳（`docs/decisions/`）の確認で見つかった、決定ではなく実装の問題。

- [x] （2026-10-15 済み: 消す前にブレーキにする）`App/app.c` の `flash_save` が出力を止めずにページを消去する。F042 では 20〜40 ms 割り込みが止まり、duty が出続ける（C-55 の実装。2026-10-14）
- [ ] （実機と CubeMX の .ioc で直す。生成されたコードは手で触らない）内蔵の発振器（HSI 16 MHz）で動いている。温度で ±1% 以上ずれうるので、1 Mbps の CAN には足りない。基板のセラロックに切り替える（C-10。2026-10-15）
- [x] （2026-10-15 済み）プロトコルの版（項目 3）が `0x00000000` のまま。`1.0.0-alpha.1` の `0x01000001` にする（C-71〜74。2026-10-15）
- [x] （2026-10-15 済み。CAN-Servo-v1 も）E-stop で空転にしている（`lib/mas/src/can/node.c:490`、基板側のコア）。常にブレーキにする（M-51。2026-10-15）。mini の CAN-Servo-v1 も同じコアを使うなら追いかける
- [x] （2026-10-15 済み。CAN-Servo-v1 も）起動の猶予を入れる: 起動の知らせを送ってから 200 ms は指令に従わない（C-89、基板側のコア `node.c`。2026-10-15）。mini の CAN-Servo-v1 も追いかける
- [x] （2026-10-15 済み。CAN-Servo-v1 も）SYNC の途絶で止める判定を消す（`lib/mas/src/can/node.c` の `sync_lost`、`SYNC_TIMEOUT_US`。C-90。2026-10-15）。mini の CAN-Servo-v1 も追いかける
- [ ] 電流の指令で、duty の下限が SO_MIN_ON（0.345）。オンが短いと SO の揺れで電流を測れないため、それより小さい電流は DRV8701 の打ち切り（目標の 1.5 倍）に任せている。回っていると打ち切りに届かず、duty 0.345 の速さで回り続ける。直すなら PWM の周波数を下げるか、測らずに下げる（2026-10-16、実機）
- [ ] 電流の上限の既定（項目 33）を試験のため 15 A（＝ハードウェアの上限）にしている。主制御から項目 33 を書けるようになったら（A5）、小さいモーター向けの値に下げる。ハードウェアの上限 15 A はユーザが決めた定格（検出抵抗の発熱。2026-10-16）
